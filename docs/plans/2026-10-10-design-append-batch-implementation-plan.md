# 追加设计批次需求实施计划与执行记录

## 目标

在不破坏原设计数据包流程的前提下，支持设计完成及后续状态订单通过“追加设计批次”入口上传新的压缩数据包；新批次必须全部填写打印信息后才能完成，订单回到设计完成状态，并且只为本批次数据包生成生产流转数据。

## 已确认规则

- 追加入口仅允许状态 `2030、3010、3020、3030、3040、4010、5010、5020、5030、5040、5050、6010、6020、6030、8010`，取消状态及经典案例排除。
- 原“上传设计文件”入口只用于原设计阶段；后续状态显示“追加设计批次”，两个入口不同时出现。
- 追加批次页面复用原上传页；上传完成后进入原打印信息弹窗。旧包只读，当前追加批次可填写、删除和在批次完成前继续修改。
- 一个订单同时只保留一个未完成追加批次；再次点击追加入口复用该批次，已完成后才可创建下一批次。
- 未填写打印信息的追加数据包允许删除；批次完成后数据包、打印信息、指令单和图纸均锁定。
- 完成批次要求当前批次所有数据包均存在打印信息；完成后订单状态回到 `2030`，删除全部模型/报告不改变订单状态。
- 生产记录继续按“数据包+产品”生成，新增记录只针对当前追加批次；旧生产记录不重建、不回退。
- 设计报告接口返回数组，`/design/report/link` 接收多个 `fileIds`；所有关联接口校验文件业务类型及未归属状态，失败时清理本次孤儿文件。

## 接口与数据结构

追加批次接口：

- `POST /design/package-batch?orderId=` 创建或返回未完成批次。
- `GET /design/package-batch?orderId=`、`GET /design/package-batch/{batchId}?orderId=` 查询批次。
- `POST /design/package-batch/{batchId}/complete?orderId=` 完成批次并发布限定数据包事件。
- 原数据包上传/删除/列表接口增加可选 `batchId`，追加模式必须传入。
- 打印信息 options/list/save/delete 接口增加可选 `batchId`；批次上下文返回 `editable、canSave、canDelete、allowedPackageFileIds、printInfoCompleted`。
- 指令单/图纸预览、下载、版本、修订、确认接口增加可选 `batchId`；历史包可读，非当前包不可修改。
- `DesignPackageVO` 增加批次标识和能力字段；订单详情仍返回全部数据包，历史数据 `batchId=null`。
- 生产流转卡增加 `batch_id`，追加事件携带本批次 package IDs，监听器按 package IDs 过滤。

## 实施后重点复核

1. 生产回退只发生在追加批次完成事务中，事件只包含新增 package IDs。
2. 追加批次未完成时允许继续上传/删除/修改打印信息；完成后后端接口仍拒绝写入，不能仅依赖前端只读。
3. 历史包在追加上下文中只读，但仍可查看文件、打印信息、指令单和图纸。
4. 空批次、存在无打印信息包、跨订单/跨批次 packageId、已完成/取消批次、错误文件类型和关联失败孤儿文件均有后端校验。
5. 上线前在目标库执行 SQL 前备份，并校验权限复制结果、字段索引和历史订单查询兼容性。

## 本轮文档复核结论

- 已将“未完成批次复用、完成后才创建新批次”作为唯一批次创建规则。
- 已将当前实际采用的旧接口加 `batchId` 方案与建议的新资源路径区分，后续以旧接口加批次上下文为准。
- 已补充设计报告多文件数组返回、文件类型/归属校验、孤儿文件清理以及模型/报告删除不改变订单状态的接口约束。
- 已明确追加批次不提供取消接口、未完成批次必须复用、打印信息保存不自动完成批次，以及完成前后的批次编辑边界。
- 已将状态历史、阶段同步、并发锁、生产聚合隔离和未知状态前端入口从“待闭环风险”更新为当前实现状态，并保留数据库、并发、数量、权限和回归验收项作为实施完成前的必验内容。
- 追加批次专用流程已补充按版本更新 `current_handler_id/current_handler_name`，与普通完成设计流程保持一致；验收仍需覆盖订单详情和列表展示不再遗留旧生产环节处理人。
