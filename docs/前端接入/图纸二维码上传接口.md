# 图纸二维码图片前端接入

## 接口

### 查询当前二维码

```http
GET /design/workorder/{orderId}/qr-image
```

成功时返回当前文件元数据；订单尚未上传时仍返回成功，`data` 为 `null`。

### 上传或替换二维码

```http
POST /design/workorder/{orderId}/qr-image
Content-Type: multipart/form-data
file=<二维码 PNG>
```

上传接口要求当前用户对订单有设计操作权限。文件必须满足：

- 扩展名为 `.png`，Content-Type 为 `image/png`；
- 文件头为 `89 50 4E 47 0D 0A 1A 0A`；
- 非空且不超过 5 MB。

后端使用图片 MD5 做幂等判断：与当前图片相同则直接返回当前 `fileId`，不会重复上传；图片变化时替换订单当前关联。关联关系是：

```text
file_detail.object_type = 10.21
file_detail.object_id   = orderId
```

前端不要把 `drawing_qr_image` 作为 `bizType` 传入，上传接口内部固定使用 `10.21`。

返回中的 `fileId` 应缓存到订单页面状态，但缓存不是最终依据；进入图纸页面时仍建议调用 GET 确认当前文件。

## 两个入口的调用时序

二维码查看入口：

```text
vue-qr 生成 PNG Blob/File
  -> POST qr-image 上传
  -> 缓存响应 data.fileId
  -> 展示二维码或继续原有二维码查看逻辑
```

图纸查看入口：

```text
GET qr-image
  -> data.fileId 有值：直接请求 drawing/preview-url 或 drawing/download
  -> data 为 null：可使用同一套二维码内容配置生成 PNG并POST上传，获得前端样式二维码
                 -> 也可以直接请求 drawing/preview-url 或 drawing/download，由后端生成兜底二维码
```

`preview-url` 和 `download` 都会按需生成图纸，所以两者都必须在二维码上传完成后调用。下载接口的完整地址为：

```http
GET /design/workorder/{orderId}/package/{packageId}/drawing/download
```

在线预览接口的完整地址为：

```http
GET /design/workorder/{orderId}/package/{packageId}/drawing/preview-url
```

建议封装一个 `ensureDrawingQrUploaded(orderId)`，由两个图纸入口共同调用，避免两个入口各自维护一套上传逻辑。上传失败时仍可以请求图纸接口，后端会使用旧版后端二维码逻辑兜底生成；如果业务要求图纸必须使用前端样式，再由前端提示重试上传。

## 图纸版本规则

- 自动图纸生成时读取订单当前二维码的文件字节，并把实际使用的 `fileId` 保存到 `design_drawing.qr_file_id`。
- 自动图纸的当前二维码 `fileId` 发生变化，会在下一次预览/下载时重新生成图纸。
- 历史自动图纸的 `qr_file_id` 为空、但当前二维码存在时，会触发一次补生成。
- 当前二维码暂时不存在不会使已有图纸失效；首次生成或打印数据变化需要重新生成时，后端自动使用影像查看器配置生成兜底二维码，不返回“请先上传图纸二维码图片”异常。
- 手工修订图纸是独立版本，二维码替换不会修改或自动重生成手工图纸。

二维码内容仍使用前端现有的二维码内容配置/API；本接口只接收前端渲染后的 PNG，不新增二维码内容生成接口。不要将当前登录 Token 长期写入打印二维码。
