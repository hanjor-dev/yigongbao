# 打印机共享选择与占用确认设计

## 1. 背景

现有逻辑将两类情况统一视为“打印机不可用”：

- 设备物理不可用：连接离线，或设备状态不是 `0 空闲`。
- 生产占用：设备已被其他“待打印”或“打印中”流转卡选择。

新业务需要支持多个案例在同一台打印机上批量打印。因此，“生产占用”不再是禁止选择的条件，但用户选择前必须获得提示并确认。

## 2. 目标与范围

### 2.1 目标

- 只有“连接在线且设备状态为 `0 空闲`”的打印机可以选择。
- 已被其他活跃流转卡选择的空闲打印机仍然可以选择。
- 提供独立查询接口，供前端判断是否需要弹出占用确认提示。
- 分配接口在事务和设备锁内重新检查，防止“查询时未占用，提交时已占用”的并发绕过。
- 保持同一打印机下多张流转卡批量开始、批量完成的现有流转语义。

### 2.2 不在范围内

- 不修改 WebSocket 身份认证、消息体格式或设备状态上报协议。
- 不新增报警、通知或消息推送功能。
- 不修改前端代码；本次只实现后端接口、校验和测试。
- 不允许活跃流转卡在已分配打印机后通过重复提交更换设备；现有“已分配”校验保持不变。

## 3. 核心业务规则

### 3.1 设备物理可选性

打印机同时满足以下条件时才是物理可选：

1. 设备类型为 `PRINTER_SLA`。
2. `connectionStatus == 1`。
3. `state == 0`。

非打印设备，以及 `1 工作中`、`2 打印完成`、`3 报警`、`4 暂停`、`5 准备就绪`、`6 离线`、未知状态、空状态或连接离线均不可选。占用确认不能绕过该规则。

### 3.2 生产占用

“被其他流转卡选择”定义为：

- `printDeviceId` 等于待查设备 ID。
- `isDeleted == 0`。
- 流转卡状态为 `PENDING_PRINT` 或 `PRINTING`。
- 排除当前查询上下文中的流转卡 ID。

生产占用只决定是否需要用户确认，不改变设备物理可选性。

## 4. API 设计

### 4.1 查询打印机占用状态

```http
GET /production/record/{recordId}/printer-occupation?deviceId={deviceId}
```

路径和参数：

- `recordId`：当前正在分配设备的流转卡 ID。
- `deviceId`：待检查打印机 ID，必填。

成功响应数据：

```json
{
  "occupied": true
}
```

接口处理：

1. 校验流转卡和设备存在。
2. 校验设备类型为 `PRINTER_SLA`；非打印设备返回现有 `DEVICE_TYPE_MISMATCH`。
3. 复用现有生产操作权限规则，校验用户、流转卡和打印机所属加工中心。
4. 只返回是否被其他活跃流转卡选择，不暴露其他流转卡、订单或患者信息。
5. 该结果是前端提示依据，不代替分配接口内的实时校验。

### 4.2 分配打印机

现有接口路径不变：

```http
POST /production/record/{recordId}/assign-device
```

`AssignDeviceDTO` 新增可选字段：

```json
{
  "deviceId": 123,
  "confirmOccupied": true,
  "productWeights": [],
  "material": "...",
  "printParams": "..."
}
```

- `confirmOccupied == true`：用户已明确确认共享已占用打印机。
- 未传、`null` 或 `false`：视为未确认。

分配逻辑按以下顺序执行：

1. 以行锁查询打印机，保持现有“设备 -> 流转卡”加锁顺序。
2. 设备不存在时返回现有“打印设备不存在”错误。
3. 校验设备类型为 `PRINTER_SLA`；非打印设备返回现有 `DEVICE_TYPE_MISMATCH`。
4. 校验设备必须在线且状态为 `0 空闲`，否则返回现有 `DEVICE_NOT_AVAILABLE`。
5. 以行锁查询流转卡，校验其存在、可分配状态且未重复分配。
6. 校验当前用户对流转卡和设备的生产操作权限。
7. 在设备锁内重新查询“除当前流转卡外”的生产占用。已占用且未确认时，返回新的 `PRINTER_OCCUPIED_CONFIRM_REQUIRED` 业务错误。
8. 已占用且已确认时继续执行现有产品重量、打印工序和编号生成校验。

查询后到提交前新增的占用会被第 7 步捕获，前端可根据专用错误再次提示，然后携带 `confirmOccupied=true` 重试。

## 5. 服务边界调整

### 5.1 `PrinterAvailabilityService`

将“物理可选”与“生产占用”解耦：

- 可选性方法检查设备类型为 `PRINTER_SLA`、在线且状态为 `0`。
- 强制校验方法不再接收或检查 `activeUsage`，并对“非打印设备”与“打印机当前不可用”分别返回 `DEVICE_TYPE_MISMATCH` 和 `DEVICE_NOT_AVAILABLE`。
- 打印机列表的 `available` 只表示物理可选性。
- 活跃占用不再导致列表中的 `available=false`。
- 兼容字段 `status` 与 `statusName` 与物理可选性保持一致：可选时为 `0/空闲`，不可选时为 `1/不可用`。精确设备状态继续由 `deviceState` 和 `deviceStateName` 表达。

### 5.2 占用查询服务

扩展现有 `PrinterDeviceUsageChecker`，支持判断指定设备是否被“除当前流转卡外”的活跃流转卡使用。现有批量查询能力保留，但打印机列表不再依赖该查询。

## 6. 设备状态与批量流转

本次不修改设备状态监听规则：

- 设备进入 `1 工作中`时，该设备下全部“待打印”流转卡批量进入“打印中”。
- 设备从 `1 工作中`、`2 打印完成` 或 `6 离线` 进入 `0 空闲`时，该设备下全部“打印中”流转卡批量完成。
- `3 报警 -> 0 空闲` 和 `4 暂停 -> 0 空闲` 不视为完成。
- 同一打印机下多张流转卡的开始、完成、工序时间、产品状态和订单流转继续由现有批量逻辑处理。

## 7. 错误处理

- 设备物理不可选：使用现有 `DEVICE_NOT_AVAILABLE`。
- 非 `PRINTER_SLA` 设备：使用现有 `DEVICE_TYPE_MISMATCH`。
- 设备已被其他活跃流转卡选择且未确认：新增 `PRINTER_OCCUPIED_CONFIRM_REQUIRED`，提示“打印机已被占用，请确认后重试”。
- 流转卡、设备、权限、产品重量、打印工序等其他错误沿用现有错误码和事务回滚规则。
- 占用查询失败时不伪造“未占用”结果，直接返回错误。

## 8. 并发与一致性

- 查询接口是无锁快照，用于交互提示，不承诺结果持续有效。
- 分配接口在设备行锁获取后检查设备类型和物理状态，再按顺序锁定流转卡、校验状态与权限，最后检查其他流转卡的生产占用。
- 对同一设备的并发分配会串行执行。首个未占用分配可正常通过；后续未确认请求必须获得专用确认错误。
- 携带 `confirmOccupied=true` 的请求仍需在同一事务中通过所有物理状态和业务校验。

## 9. 测试计划

### 9.1 可选性单元测试

- 在线 + `0 空闲` 时可选。
- 在线 + `0 空闲` + 已有活跃流转卡时仍可选。
- 连接离线，以及状态 `1`–`6`、空值和未知值均不可选。
- 列表中 `available`、`status`、`statusName`、`deviceState` 和 `deviceStateName` 保持一致。

### 9.2 占用查询接口测试

- 无其他活跃流转卡时返回 `occupied=false`。
- 存在其他“待打印”或“打印中”流转卡时返回 `occupied=true`。
- 排除当前流转卡，并忽略已删除或其他状态的流转卡。
- 流转卡或设备不存在、跨加工中心或角色无权时返回对应业务错误。
- 非 `PRINTER_SLA` 设备返回 `DEVICE_TYPE_MISMATCH`。
- 控制器参数绑定、必填校验和响应体结构正确。

### 9.3 分配测试

- 未占用时，未传确认参数也可正常分配。
- 已占用且未确认时返回 `PRINTER_OCCUPIED_CONFIRM_REQUIRED`，不产生任何部分写入。
- 已占用且已确认时正常分配，两张流转卡可共享同一设备。
- 非 `PRINTER_SLA` 设备即使在线、空闲且已确认，仍返回 `DEVICE_TYPE_MISMATCH`。
- 即使已确认，离线或非 `0 空闲` 设备仍返回 `DEVICE_NOT_AVAILABLE`。
- 保持现有重复分配、权限、产品重量、工序更新和正式编号生成测试。
- 并发未确认分配不能绕过确认逻辑。

### 9.4 批量状态流转回归测试

- 同一打印机下多张待打印流转卡在收到 `1 工作中` 时全部开始。
- 同一打印机下多张打印中流转卡在合法完成转换时全部完成。
- `3 -> 0` 和 `4 -> 0` 不完成任何打印中流转卡。
- 释放其中一张待打印流转卡的设备配置，不修改其他共享流转卡。

## 10. 验收标准

1. 已被其他活跃流转卡选择的在线空闲打印机在列表中仍可选。
2. 新查询接口能准确返回该设备是否被其他活跃流转卡选择。
3. 已占用打印机在未确认时不能分配，确认后可被多张流转卡共享。
4. 任何确认值都不能绕过“设备类型为 `PRINTER_SLA`、在线且状态为 `0 空闲`”的硬校验。
5. 占用查询与分配之间的并发变化不会绕过确认。
6. 同一打印机下的多张流转卡仍按现有状态规则批量开始和批量完成。
7. 现有 WebSocket 协议、设备状态码处理和非打印设备逻辑不受影响。
