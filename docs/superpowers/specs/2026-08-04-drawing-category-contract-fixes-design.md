# 图纸按产品分类拆分契约修复设计

## 目标

在不改变现有前端字段结构和接口路径的前提下，使图纸分类聚合、兼容字段、修订与确认操作严格符合《图纸按产品分类拆分对接文档》，并补齐前端可直接联调所需的完整契约说明。

## 范围

本次只修改设计模块图纸相关后端逻辑、自动化测试和前端对接文档，不修改前端代码，不处理工作区内生产排程、质检仓储和数据库脚本等无关改动。

## 后端设计

### 1. 最新图纸分组

`getLatestDrawingGroups` 批量读取数据包当前有效打印产品分类，并按以下规则返回：

- 当前存在非空分类时，只返回这些分类的最新版图纸；
- 历史 `productCategory = null` 图纸以及已从打印信息移除分类的旧图纸不再返回；
- 当前产品分类全部为空时，按纯历史数据包处理，只返回历史空分类最新版图纸；
- 继续排除软删除图纸；
- 每个包、每个分类最多返回一条最新版。

### 2. 工单详情兼容字段

- `latestDrawings` 无图纸时返回空数组，不返回 `null`；
- 仅当数据包当前实际非空产品分类数为 1 时回填 `latestDrawing`；
- 当前实际分类数大于 1 时，即使只生成了一类图纸，`latestDrawing` 也保持 `null`；
- 纯历史数据包只有一张空分类图纸时继续回填 `latestDrawing`。

分类数量使用一次批量查询计算，避免逐包查询。

### 3. 修订版上传

上传修订版前解析目标分类并查询该分类最新版，要求路径 `{id}` 与最新版 ID 完全一致。ID 不存在、属于其他包/分类或已经过期时统一抛出 `DOC_VERSION_NOT_FOUND`，不上传文件、不创建新版本。

### 4. 图纸确认

确认前解析目标分类并查询该分类最新版，要求路径 `{id}` 与最新版 ID 完全一致。只更新该最新版；历史版本、错误包或错误分类 ID 返回 `DOC_VERSION_NOT_FOUND`。

## 接口兼容

五个现有接口路径、HTTP 方法、`productCategory` 参数名和现有 VO 均不改变。成功返回格式保持不变，属于兼容性修复。

## 测试设计

采用测试先行：

1. 为历史空分类与新分类并存、已移除分类、纯历史包分别建立失败测试；
2. 为多分类只生成一张、无图纸空数组、单分类兼容字段建立失败测试；
3. 为上传修订错误/过期 ID 和确认历史版本建立失败测试；
4. 为下载、预览、版本、上传修订和确认五个 Controller 接口增加 `productCategory` 绑定与透传测试；
5. 运行设计模块完整测试及编译验证。
