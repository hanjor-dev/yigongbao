# 图纸前端二维码图片存储与嵌入设计

## 背景

当前图纸二维码由 `DrawingExcelBuilder` 使用 ZXing 在后端生成。前端二维码查看入口已经使用 `vue-qr` 生成二维码，样式和清晰度更符合实际使用需求。二维码查看入口与图纸查看入口是独立操作，用户可能先查看图纸，因此二维码图片不能只在图纸生成请求中临时上传。

## 目标

1. 前端生成二维码 PNG，并通过独立接口上传。
2. 图片先保存到现有文件系统和 `file_detail`，关联二维码业务类型及订单 ID。
3. 图纸生成时读取订单当前二维码图片，并原样嵌入每一页 Excel。
4. 图纸版本保存实际使用的二维码文件 ID，保证历史图纸可追溯。
5. 后端不再根据 URL 重新生成二维码。

## 方案

复用 `file_detail.object_type/object_id` 作为订单当前二维码的业务关联：

```text
object_type = 10.21
object_id   = orderId
```

新增独立接口：

```text
POST /design/workorder/{orderId}/qr-image
GET  /design/workorder/{orderId}/qr-image
```

POST 接收 PNG，校验当前用户对订单设计范围的写权限后，调用现有 `FileService.uploadFile` 保存文件，再通过 `unlinkByBiz("10.21", orderId)` 清理订单旧二维码关联，通过 `linkFile(fileId, "10.21", orderId)` 将新文件关联到订单。GET 校验当前用户对订单的可读权限后返回当前二维码元数据；没有当前二维码时返回成功且 `data=null`。

`design_drawing` 增加 `qr_file_id`，生成图纸时取订单当前二维码的 `fileId`，通过 `FileService.downloadToBytes` 获取图片字节，传入 `DrawingExcelBuilder.BuildContext.qrBytes`。保存图纸版本时同步保存 `qr_file_id`。

`file_detail` 中二维码的“当前文件”定义为 `object_type=10.21`、`object_id=orderId` 关联记录中按创建时间倒序的最新记录。上传前先读取 PNG 字节并计算 MD5，与当前文件的 `fileHash` 相同时直接返回当前文件，不重复上传；内容变化时先上传未关联文件，再在事务中替换业务关联。历史图纸通过 `design_drawing.qr_file_id` 持有快照，因此旧文件不能因当前关联解除而删除。

上传替换使用订单级进程内锁和事务；多实例之间不伪造数据库串行化保证，约定最后一次成功替换生效。新文件关联失败时调用 `FileService.deleteById` 清理刚上传文件；清理失败只记录运维日志。被历史图纸引用的旧文件永久保留，本次不新增自动清理任务。

## 入口时序

二维码入口：

```text
vue-qr 生成图片 -> 调用 qr-image 接口 -> 缓存 fileId
```

图纸入口：

```text
调用 GET qr-image 检查当前 fileId
  -> 没有则复用同一套前端二维码生成和 POST 上传流程
  -> 上传成功后调用图纸 preview-url 或 download
```

如果后端需要首次生成或重新生成图纸但订单没有当前二维码图片，使用现有影像查看器配置恢复生成后端兜底二维码，不因缺少前端图片返回上传要求错误。已有图纸可以继续预览/下载；手工修订图纸是独立版本，不因二维码替换而自动改写。

## 生命周期

- 订单当前二维码由 `file_detail` 关联关系表示。
- 更换二维码时更新当前关联，不删除仍被 `design_drawing.qr_file_id` 引用的历史图片。
- 图纸版本通过 `qr_file_id` 固化实际使用的二维码。
- 前端重复上传同一张图片时，后端基于 MD5 幂等复用当前文件。
- 上传失败时优先删除本次新文件；删除失败的未关联文件由运维人工清理，本次不新增自动清理任务；历史快照文件永久保留，任何清理都必须排除被 `design_drawing.qr_file_id` 引用的文件。

## 安全与校验

- 上传接口校验订单归属和操作权限。
- 只接收 PNG 图片，校验 PNG 文件头、`.png` 扩展名/Content-Type、大小上限和空文件。
- 新增独立文件业务类型，不复用图纸截图类型。
- 二维码内容仍由现有前端二维码内容配置/API统一提供，后端本次只接收前端渲染后的 PNG，不重复新增内容接口；不把前端当前登录 Token 长期写入打印二维码。
- Excel 中二维码按原图片宽高比缩放并居中限制在二维码单元格区域内；无法读取尺寸时仍使用矩形兜底锚点插入图片，不因尺寸解析失败而留空。

## 边界

当前仓库没有前端源码，只有此前构建产物不在 Git 工作树中。因此本次先完成后端接口、文件关联、图纸生成和前端接入文档；前端源码仓库需要按接口文档接入 `vue-qr` 的生成回调。

## 图纸复用规则

- 最新图纸为 AUTO 时：当前二维码 ID 非空且与 `qr_file_id` 不同会触发重新生成；`qr_file_id` 为 `NULL` 且当前二维码 ID 非空会触发一次补生成；当前二维码 ID 为 `NULL` 时不因二维码缺失使既有图纸失效。
- 如果打印数据变化或其他条件已经要求重新生成，而当前二维码 ID 为 `NULL`，则直接报缺少二维码错误，不复用旧图纸冒充新版本。
- 最新图纸为 MANUAL 时，二维码变化不修改、不重生成手工图纸。
- 已有图纸可复用时，即使当前二维码关联暂时不存在，也继续使用已有文件；只有首次生成或确实需要重新生成时才要求当前二维码存在。
- `preview-url` 和 `download` 进入同一个订单+数据包锁，只有持锁请求执行生成，其他并发请求复用生成结果；Excel 上传成功但数据库写入失败时尽力删除新文件，删除失败记录人工清理。

## 文件约束

- 最大大小：5 MB。
- 允许扩展名和 Content-Type：`.png` / `image/png`。
- 必须以 PNG 文件头 `89 50 4E 47 0D 0A 1A 0A` 开头。
- GET 无当前图片返回 `data=null`；POST 校验失败使用现有附件类型/大小错误码，图纸生成缺少二维码使用明确业务错误。
