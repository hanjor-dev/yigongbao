# 生产流转卡接单同步生产中心设计

## 背景

生产人员通过 `ProductionRecordController.downloadDataPackage` 下载设计数据包时即完成流转卡接单。当前接单事务只向 `production_record` 写入生产员 ID 和姓名，生产中心仅写入 `order_main`，导致 `production_record.processing_center_id` 和 `processing_center_name` 一直为空。

## 目标

- 接单成功时，在同一次条件更新中同步保存生产员和生产中心快照。
- 未绑定生产中心的生产员不能接单，避免继续产生归属不完整的数据。
- 保持现有悲观锁、并发认领和状态流转语义不变。

## 方案

1. 在读取当前登录用户后校验用户存在，并校验 `centerId` 非空、`centerName` 非空白。用户资料由用户管理模块维护，本次不额外查询加工中心表。
2. 校验失败时抛出稳定的业务异常，事务回滚，不更新流转卡或订单，也不返回数据包地址：用户不存在使用 `USER_NOT_FOUND`；中心 ID 缺失或名称空白使用 `PROCESSING_CENTER_NOT_FOUND`；条件认领冲突使用 `PRODUCTION_RECORD_ALREADY_CLAIMED`。
3. 在 `DESIGN_COMPLETED -> PENDING_PRINT` 的同一条条件更新中写入：
   - `producer_id`
   - `producer_name`
   - `processing_center_id`
   - `processing_center_name`
4. 流转卡条件更新必须恰好影响一行。影响零行表示该卡已经被认领（包括同一生产员重复请求），立即抛出“已被认领”异常，不再更新订单、不返回数据包地址，也不覆盖原接单人与中心。
5. 订单加工中心仍沿用首次接单时的条件更新逻辑，来源与流转卡一致，均取本次读取到的当前生产员资料快照。订单中心为空时写入该快照；订单中心已经存在时不覆盖，只更新现有操作人字段并继续成功。即使订单已有不同中心，流转卡仍记录实际接单生产员的中心，保留真实接单归属。
6. 流转卡更新、订单更新、流程推进及事件发布均保留在现有同一个事务中；任一步抛出异常都回滚本次认领。只有方法正常完成时才返回数据包地址。
7. 悲观行锁继续串行化同一流转卡的并发认领。两个不同中心用户同时请求时，只允许第一个完成条件更新的用户成功；失败方不能覆盖成功方的接单人或中心，也不能修改订单。

## 测试

- 接单成功时，验证流转卡更新包含生产中心 ID 和名称。
- 当前用户缺少中心 ID 或中心名称为空白时，分别验证返回 `PROCESSING_CENTER_NOT_FOUND`，且不执行流转卡、订单更新、不返回数据包地址。
- 当前用户不存在时，验证返回 `USER_NOT_FOUND`，且流转卡、订单均未更新。
- 条件更新影响零行时，验证不更新订单且不返回地址；覆盖同一用户重复请求及不同中心用户并发冲突语义。
- 验证订单首次归属使用与流转卡相同的用户中心快照；订单已有中心时不覆盖。
