# 订单创建时项目分类名称兜底设计

## 背景

部分历史 `rebuild_project` 数据存在 `category_code` 非空、`category_name` 为空的情况。订单创建时，`OrderDataValidator` 当前把这类数据视为系统错误，导致订单功能不可用。

## 目标

订单创建只以 `categoryCode` 作为项目分类主数据的必需条件。项目名称为空时，使用分类编码查询有效字典名称完成订单明细快照，避免历史脏数据阻断下单，同时不允许生成空分类名称的订单明细。

## 方案

在订单明细项目校验逻辑中：

1. 项目不存在或已禁用时，继续按现有规则拒绝创建。
2. `categoryCode` 为空时，拒绝创建。
3. `categoryCode` 有值且项目主数据 `categoryName` 有值时，使用项目主数据名称。
4. `categoryCode` 有值但项目主数据 `categoryName` 为空时，通过有效的 `sys_dict` 子项查询 `dict_name` 并作为订单明细分类名称。
5. 字典查询不到名称时，拒绝创建并记录项目 ID、分类编码及原因。

不信任前端提交的分类名称；订单快照始终由后端主数据或字典补齐。

## 测试

增加订单数据校验测试，覆盖：

- 项目已有分类名称时使用该名称；
- 项目分类名称为空但字典可查时成功补齐；
- 分类编码为空或字典查不到时仍拒绝创建。
