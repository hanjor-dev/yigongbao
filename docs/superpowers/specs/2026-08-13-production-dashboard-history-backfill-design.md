# 生产流转卡加工中心历史回填与生产看板修复设计

## 目标

修复历史已接单流转卡缺少 `processing_center_id`、`processing_center_name` 导致生产管理员看板统计不到数据的问题，并修复生产员、生产管理员看板中会造成“偶发无数据”或统计错位的查询逻辑。

## 已确认的业务边界

- 历史迁移只处理 `producer_id IS NOT NULL` 的已接单流转卡。
- 未接单流转卡继续保持加工中心为空，不提前分配归属。
- 当前状态卡片中的“生产中、质检中、仓储中”反映实时积压，不受所选时间范围限制。
- “我的任务/生产单总数”、已完成量和趋势统计继续受所选时间范围限制。
- 不直接执行生产数据库迁移；交付可审计、幂等、遇到歧义即终止的 SQL 脚本。

## 根因

### 历史数据

旧版 `downloadDataPackage` 接单逻辑只向 `production_record` 写入生产员 ID/姓名，未同步加工中心；生产管理员看板严格使用 `production_record.processing_center_id = 当前管理员.center_id`，因此历史记录全部被排除。

只读核验当前连接库发现：21 条有效流转卡中 19 条已接单，这 19 条加工中心 ID/名称全部为空。18 条可从订单归属恢复，剩余 1 条可从已分配打印设备恢复，当前样本不存在无法判定的数据。

### 看板查询

- 生产员按 `producer_id` 查询；生产管理员先取账号 `center_id`，再按流转卡 `processing_center_id` 查询。
- 当前阶段卡片错误地按流转卡 `create_time` 过滤。旧流转卡今天仍处于生产、质检或仓储阶段时，“今日”看板显示为 0。
- 两个策略捕获所有异常并返回空看板，数据库错误与真正无数据无法区分。
- 生产管理员未绑定加工中心时直接返回空看板，配置问题不透明。
- 管理员工作量图中“已完成”按 `create_time` 统计，而已完成卡片按 `post_processing_end_time` 统计，口径不一致。
- 星期映射、月内第 5 周、跨月自定义范围、跨年按月范围和日末小数秒存在分桶或边界错误。

## 历史迁移设计

新增 `sql/migration-production-record-processing-center-2026-08-13.sql`。

### 回填来源优先级

1. 流转卡已有 `processing_center_id`：只补空名称，不改变已有 ID。
2. `order_main.center_id`：历史接单时同步写入的订单归属，作为首选证据。
3. `device.center_id`：流转卡实际分配的打印设备所属中心。
4. `sys_user.center_id`：当前生产人绑定中心，仅作为最后兜底。

最终名称统一由有效的 `processing_center.center_name` 获取，不依赖可能为空或过期的历史名称快照。

### 安全规则

- 仅暂存有效、未删除、已接单且加工中心 ID 或名称缺失的流转卡。
- 若订单、设备、当前用户提供的非空中心 ID 不一致，脚本在更新前终止并输出冲突记录。
- 若无法解析中心，或解析到不存在、停用、已删除的中心，脚本在更新前终止。
- 事务开始后先锁定全部候选 `production_record`，再构建候选快照；更新仍附带“已接单且字段缺失”的条件，避免迁移期间并发接单或应用写入造成 ID/名称错配。
- 更新时不覆盖已有加工中心 ID；仅在 ID 为空时写入解析值，并在 ID 为空或名称空白时写入权威名称。
- 使用事务完成数据更新；更新后校验目标记录全部补齐，否则回滚并报错。
- 重复执行时目标记录数为 0，不产生二次修改。

## 看板修复设计

### 查询口径

生产员数据范围仍为 `producer_id = 当前用户ID`；生产管理员数据范围仍为 `processing_center_id = 当前管理员.center_id`。

- `myTasks` / `totalProduction`：所选时间内创建的已归属流转卡数量。
- `inProduction`、`inQc`、`inWarehouse`：当前状态实时数量，不加时间条件。
- `completed`：状态为 6030/8010，且 `post_processing_end_time` 位于所选时间范围。
- 生产趋势：继续按所选时间统计；未完成阶段按 `create_time`，已完成阶段按 `post_processing_end_time`。
- 生产员工作量：生产中为当前实时积压；已完成按 `post_processing_end_time` 和所选时间统计。

### 时间边界与分桶

- SQL 时间过滤改为左闭右开：`>= start AND < endExclusive`，避免遗漏 `23:59:59.xxx`。
- 周视图把 MySQL `DAYOFWEEK` 的周日优先顺序转换成周一至周日。
- 月视图按每 5 天一个桶。
- 月环比展示第 1 至第 5 周，不丢弃 29—31 日。
- 自定义 2—31 天统一用 `DATEDIFF(timestamp, startDate)` 计算相对日偏移，支持跨月。
- 自定义超过 31 天用 `PERIOD_DIFF` 计算相对月偏移，支持跨年。
- 两个生产策略复用一个包内查询辅助类，避免同一分桶规则维护两份。

### 错误处理

- 删除生产策略中“捕获所有异常并返回空看板”的降级；查询异常向上抛出，由统一异常处理返回错误。
- 生产管理员账号不存在、未绑定中心或中心无效时抛出明确业务异常，不返回空数组。
- 无业务数据仍返回结构完整、数值为 0 的看板。

## 测试

- 为生产员策略增加：当前状态不受时间限制、总任务仍受时间限制、查询异常向上传播的测试。
- 为生产管理员策略增加：中心缺失、中心不存在、停用、软删除时报错，以及中心隔离、当前状态实时统计、工作量完成时间口径的测试。
- 为公共分桶辅助类增加：周日/周一映射、月内第 5 周、跨月自定义日期、跨年自定义月份、左闭右开时间条件测试。
- SQL 脚本执行静态安全断言，并用当前库的只读查询验证来源覆盖和冲突规则；另外在一次性 MySQL 8 测试库完整演练成功、冲突终止、回滚、已有 ID 保留及重复执行幂等，不对业务连接库执行更新。
- 最后运行 dashboard 模块全量测试、依赖模块打包和 `git diff --check`。
