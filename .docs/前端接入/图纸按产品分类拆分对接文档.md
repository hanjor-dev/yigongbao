# 图纸按产品分类拆分——前端对接文档

## 1. 需求变化

同一个设计数据包可以包含多个产品分类。图纸按产品分类分别生成：

- 模型类产品生成一份图纸；
- 导板类产品生成一份图纸；
- 同一分类下的多个产品仍合并到同一份图纸；
- 指令单不拆分，仍按数据包生成一份，可以同时包含模型和导板。

产品分类使用产品分类字典码，当前模型类为 `17.1`、导板类为 `17.2`。不要使用项目分类 `13.1/13.2`。

## 2. 图纸接口参数变化

以下接口新增可选查询参数 `productCategory`：

| 接口 | 参数位置 | 说明 |
|---|---|---|
| `GET /api/design/workorder/{orderId}/package/{packageId}/drawing/download` | query | 图纸分类，例如 `17.1` |
| `GET /api/design/workorder/{orderId}/package/{packageId}/drawing/preview-url` | query | 图纸分类，例如 `17.2` |
| `GET /api/design/workorder/{orderId}/package/{packageId}/drawing/versions` | query | 查询指定分类的版本历史 |
| `POST /api/design/workorder/{orderId}/package/{packageId}/drawing/upload-revised/{id}` | query | 修订指定分类图纸 |
| `POST /api/design/workorder/{orderId}/package/{packageId}/drawing/confirm/{id}` | query | 确认指定分类图纸 |

示例：

```text
GET /api/design/workorder/1001/package/2001/drawing/preview-url?productCategory=17.1
GET /api/design/workorder/1001/package/2001/drawing/versions?productCategory=17.2
POST /api/design/workorder/1001/package/2001/drawing/confirm/3001?productCategory=17.1
```

### 参数使用规则

- 单分类数据包：暂时不传 `productCategory` 仍兼容旧调用方式。
- 多分类数据包：必须传 `productCategory`，否则无法确定要生成、预览、下载或确认哪一份图纸。
- 前端应优先从数据包返回的 `latestDrawings[].productCategory` 读取分类，不要根据文件名推断。
- 指令单接口不增加 `productCategory`。

## 3. 数据包详情返回变化

数据包对象新增 `latestDrawings`：

```json
{
  "id": 2001,
  "latestInstruction": {
    "id": 3101,
    "version": "A/1",
    "isConfirmed": 1
  },
  "latestDrawing": null,
  "latestDrawings": [
    {
      "id": 3001,
      "productCategory": "17.1",
      "version": "A/1",
      "templateFileId": "file-model",
      "templateFileUrl": "https://...",
      "isConfirmed": 1
    },
    {
      "id": 3002,
      "productCategory": "17.2",
      "version": "A/1",
      "templateFileId": "file-guide",
      "templateFileUrl": "https://...",
      "isConfirmed": 0
    }
  ]
}
```

字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `latestDrawings` | Array | 当前数据包各产品分类的最新版图纸 |
| `latestDrawings[].productCategory` | String | 产品分类字典码 |
| `latestDrawings[].isConfirmed` | Integer | `0` 未确认，`1` 已确认 |
| `latestDrawing` | Object/null | 兼容字段；只有单分类数据包时有值，多分类数据包不应使用该字段 |

图纸版本接口和预览接口返回对象也新增 `productCategory`。指令单返回该字段为空或不存在，前端无需处理为图纸分类。

## 4. 前端页面交互建议

建议在数据包下按分类展示图纸卡片：

```text
数据包 A
├── 指令单（模型+导板，共一份）
├── 模型类图纸（17.1）
└── 导板类图纸（17.2）
```

每个分类图纸卡片独立执行：

1. 预览：携带对应 `productCategory`；
2. 下载：携带对应 `productCategory`；
3. 查看版本：携带对应 `productCategory`；
4. 确认：携带对应 `productCategory` 和该分类图纸版本 ID；
5. 上传修订版：携带对应 `productCategory`、版本 ID 和文件。

模型类和导板类不能共用一个图纸确认状态。

## 5. 提交校验变化

设计阶段提交时，后端现在按数据包实际存在的产品分类校验：

- 每个数据包必须有打印信息；
- 每个数据包必须有一份指令单；
- 每个数据包的每个产品分类都必须有图纸；
- 每个产品分类的最新版图纸都必须确认；
- 指令单仍只需要按数据包确认一次。

因此，模型+导板案例必须完成两份图纸确认后才能提交设计阶段。

## 6. 文件名和版本规则

自动生成的图纸文件名会包含产品分类码，例如：

```text
患者姓名-17.1图纸.xlsx
患者姓名-17.2图纸.xlsx
```

图纸版本号仍按每个分类独立递增：每个分类从 `A/1` 开始；自动重新生成时覆盖当前自动版本，手动修订后再生成则创建该分类的下一版本。指令单版本号仍按数据包独立递增。

## 7. 兼容和历史数据说明

- 历史旧图纸的 `productCategory` 可能为空，代表旧版数据包级图纸；前端不要把空值当作模型类或导板类。
- 新保存的打印信息会保存产品分类快照；新生成图纸均带 `productCategory`。
- 多分类旧数据包需要重新生成分类图纸后，新的提交校验才能通过。
- 二维码、截图上传、数据包文件接口不增加分类参数。

## 8. 联调验收清单

- 单模型数据包可以正常预览、下载、确认；
- 单导板数据包可以正常预览、下载、确认；
- 模型+导板数据包返回两条 `latestDrawings`；
- 模型图纸中不出现导板产品，导板图纸中不出现模型产品；
- 模型和导板分别修订、分别生成版本；
- 只确认其中一份图纸时，设计提交仍被阻断；
- 两份图纸和一份指令单都确认后，设计提交通过；
- 生产流转卡按自身产品分类读取对应图纸；
- 同一分类多个产品仍使用同一份分类图纸。
