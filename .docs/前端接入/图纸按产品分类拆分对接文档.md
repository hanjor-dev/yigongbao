# 图纸按产品分类拆分——前端对接文档

## 1. 需求变化

同一个设计数据包可以包含多个产品分类。图纸按产品分类分别生成：

- 模型类产品生成一份图纸；
- 导板类产品生成一份图纸；
- 同一分类下的多个产品仍合并到同一份图纸；
- 指令单不拆分，仍按数据包生成一份，可以同时包含模型和导板。

产品分类使用产品分类字典码，当前模型类为 `17.1`、导板类为 `17.2`。不要使用项目分类 `13.1/13.2`。

## 2. 通用响应和错误判断

除下载成功时直接返回文件流外，其余接口统一返回：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {},
  "timestamp": 1785820800000,
  "priority": null
}
```

前端必须以响应体 `code` 判断业务是否成功。业务异常的 HTTP 状态仍为 `200`，不能只根据 HTTP 状态判断。

`priority` 用于错误提示优先级，成功响应通常为 `null`；前端业务分支不要依赖该字段。

本需求常见业务码：

| code | 含义 | 前端处理建议 |
|---:|---|---|
| `200` | 成功 | 正常处理 `data` |
| `410` | 参数错误；多分类包未传 `productCategory` 时也使用该错误码 | 提示后重新携带分类请求 |
| `767` | 尚未填写打印信息，无法生成图纸 | 引导用户先保存打印信息 |
| `768` | 指定图纸版本不存在、分类不匹配或 `{id}` 不是该分类最新版 | 刷新工单详情和版本列表，不要继续使用旧 ID |
| `771` | 设计提交校验未通过 | 展示后端返回的具体 `message` |

## 3. 图纸接口完整契约

以下五个接口新增可选查询参数 `productCategory`：

| 功能 | 方法和接口 | 请求类型 | 成功响应 |
|---|---|---|---|
| 下载图纸 | `GET /api/design/workorder/{orderId}/package/{packageId}/drawing/download` | query | 二进制文件流 |
| 预览图纸 | `GET /api/design/workorder/{orderId}/package/{packageId}/drawing/preview-url` | query | `Result<DocItem>` |
| 查询版本 | `GET /api/design/workorder/{orderId}/package/{packageId}/drawing/versions` | query | `Result<Array<DesignDocVersion>>` |
| 上传修订版 | `POST /api/design/workorder/{orderId}/package/{packageId}/drawing/upload-revised/{id}` | `multipart/form-data` + query | `Result<void>` |
| 确认图纸 | `POST /api/design/workorder/{orderId}/package/{packageId}/drawing/confirm/{id}` | query | `Result<void>` |

共同参数：

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `orderId` | path | Long | 是 | 订单 ID |
| `packageId` | path | Long | 是 | 数据包 ID |
| `productCategory` | query | String | 多分类包必填 | 产品分类字典码，例如 `17.1`、`17.2` |
| `id` | path | Long | 修订、确认接口必填 | 当前分类最新版图纸 ID，必须来自最新详情或版本响应 |

### 3.1 参数使用规则

- 单分类数据包：不传 `productCategory` 仍兼容旧调用方式，后端自动解析唯一分类。
- 多分类数据包：必须传 `productCategory`。
- 前端应从 `latestDrawings[].productCategory` 或打印信息 `items[].category` 读取分类，不要根据文件名推断。
- 修订和确认必须使用该分类当前最新版 ID；列表刷新后不要继续使用旧 ID。
- 指令单接口不增加 `productCategory`。

### 3.2 下载图纸

```text
GET /api/design/workorder/1001/package/2001/drawing/download?productCategory=17.1
```

成功响应为图纸二进制文件流，不是 JSON `Result`。前端应按 Blob 下载。后端在下载前会按需生成或更新指定分类图纸；若生成前发生业务异常，则返回统一错误对象。

### 3.3 获取预览地址

```text
GET /api/design/workorder/1001/package/2001/drawing/preview-url?productCategory=17.1
```

`data` 示例：

```json
{
  "id": 3001,
  "version": "A/1",
  "fileId": "file-model",
  "templateFileUrl": "https://...",
  "generateTime": "2026-08-04T14:00:00",
  "isConfirmed": 1,
  "productCategory": "17.1"
}
```

注意：预览对象的文件 ID 字段为 `fileId`，不是 `templateFileId`。

### 3.4 查询版本历史

```text
GET /api/design/workorder/1001/package/2001/drawing/versions?productCategory=17.2
```

`data` 是数组，元素结构：

```json
{
  "id": 3002,
  "version": "A/2",
  "versionSeq": 2,
  "sourceType": "MANUAL",
  "templateFileId": "file-guide-v2",
  "templateFileUrl": "https://...",
  "revisedFileId": null,
  "revisedFileUrl": null,
  "generateTime": "2026-08-04T14:00:00",
  "revisedUploadTime": null,
  "isConfirmed": 1,
  "productCategory": "17.2",
  "confirmTime": "2026-08-04T14:10:00"
}
```

### 3.5 上传修订版

```text
POST /api/design/workorder/1001/package/2001/drawing/upload-revised/3002?productCategory=17.2
Content-Type: multipart/form-data

file: drawing-guide-revised.xlsx
```

- 文件字段名固定为 `file`；
- `{id}` 必须是 `17.2` 当前最新版图纸 ID；
- 上传成功后创建该分类下一版本，并自动确认新版本；
- 成功响应 `data` 为 `null`，前端应重新获取工单详情或版本列表取得新 ID。

### 3.6 确认图纸

```text
POST /api/design/workorder/1001/package/2001/drawing/confirm/3001?productCategory=17.1
```

`{id}` 必须是指定分类当前最新版。成功响应 `data` 为 `null`；成功后应刷新当前分类卡片。确认历史版本会返回 `code=768`。

## 4. 工单详情和分类来源

工单详情接口：

```text
GET /api/design/workorder/{orderId}
```

图纸数据完整路径为 `response.data.packageList[].latestDrawings`。

### 4.1 数据包图纸字段

数据包对象新增 `latestDrawings`：

```json
{
  "id": 2001,
  "latestInstruction": {
    "id": 3101,
    "version": "A/1",
    "isConfirmed": 1
  },
  "latestDrawing": null,
  "latestDrawings": [
    {
      "id": 3001,
      "productCategory": "17.1",
      "version": "A/1",
      "templateFileId": "file-model",
      "templateFileUrl": "https://...",
      "isConfirmed": 1
    },
    {
      "id": 3002,
      "productCategory": "17.2",
      "version": "A/1",
      "templateFileId": "file-guide",
      "templateFileUrl": "https://...",
      "isConfirmed": 0
    }
  ]
}
```

字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `latestDrawings` | Array | 当前数据包各有效产品分类已经生成的最新版图纸；无图纸时固定为 `[]` |
| `latestDrawings[].productCategory` | String | 产品分类字典码 |
| `latestDrawings[].isConfirmed` | Integer | `0` 未确认，`1` 已确认 |
| `latestDrawing` | Object/null | 兼容字段；仅当前实际产品分类数不超过一个且已有一张图纸时有值，多分类数据包始终为 `null` |

图纸版本接口和预览接口返回对象也新增 `productCategory`。指令单返回该字段为空或不存在，前端无需处理为图纸分类。

`latestDrawings` 只返回当前打印信息中仍然有效的分类图纸：

- 数据包重新保存为 `17.1/17.2` 后，历史 `productCategory=null` 混合图纸不会继续作为分类卡片返回；
- 已经从打印信息移除分类的旧图纸不会返回；
- 纯历史数据包尚未重新保存打印信息时，可以返回一条 `productCategory=null` 的旧图纸。

### 4.2 尚未生成图纸时如何取得分类

首次进入或刚保存打印信息后，`latestDrawings` 可能是空数组。此时分类来源为打印信息接口：

```text
GET /api/design/workorder/{orderId}/package/{packageId}/print-info
```

读取 `response.data.items[].category`，例如：

```json
{
  "code": 200,
  "data": {
    "items": [
      { "id": 5001, "category": "17.1", "categoryName": "模型类" },
      { "id": 5002, "category": "17.2", "categoryName": "导板类" }
    ]
  }
}
```

字段映射关系：

```text
打印信息 items[].category  →  图纸接口 query.productCategory
```

打印信息选项接口 `GET /api/design/workorder/{orderId}/package/{packageId}/print-info/options` 的 `response.data.products[].category` 也使用同一分类字典码。前端应按分类去重后建立图纸卡片，再使用 `latestDrawings` 回填已经生成的图纸信息。

## 5. 前端页面交互建议

建议在数据包下按分类展示图纸卡片：

```text
数据包 A
├── 指令单（模型+导板，共一份）
├── 模型类图纸（17.1）
└── 导板类图纸（17.2）
```

每个分类图纸卡片独立执行：

1. 预览：携带对应 `productCategory`；
2. 下载：携带对应 `productCategory`；
3. 查看版本：携带对应 `productCategory`；
4. 确认：携带对应 `productCategory` 和该分类图纸版本 ID；
5. 上传修订版：携带对应 `productCategory`、版本 ID 和文件。

模型类和导板类不能共用一个图纸确认状态。

推荐页面数据处理顺序：

1. 获取工单详情，读取 `packageList`、`latestInstruction` 和 `latestDrawings`；
2. 对每个包获取打印信息，按 `items[].category` 去重生成应展示的分类卡片；
3. 以 `productCategory` 为键，把 `latestDrawings` 合并到对应卡片；
4. 没有匹配图纸的分类显示“尚未生成”，首次预览或下载会触发后端按需生成；
5. 每次生成、修订或确认成功后重新获取详情，不在前端自行推算版本号或确认状态。

不要仅遍历 `latestDrawings` 创建卡片，否则尚未生成图纸的分类不会显示，也无法触发首次生成。

## 6. 提交校验变化

设计阶段提交时，后端现在按数据包实际存在的产品分类校验：

- 每个数据包必须有打印信息；
- 每个数据包必须有一份指令单；
- 每个数据包的每个产品分类都必须有图纸；
- 每个产品分类的最新版图纸都必须确认；
- 指令单仍只需要按数据包确认一次。

因此，模型+导板案例必须完成两份图纸确认后才能提交设计阶段。

## 7. 文件名和版本规则

自动生成的图纸文件名会包含产品分类码，例如：

```text
患者姓名-17.1图纸.xlsx
患者姓名-17.2图纸.xlsx
```

图纸版本号仍按每个分类独立递增：每个分类从 `A/1` 开始；自动重新生成时覆盖当前自动版本，手动修订后再生成则创建该分类的下一版本。指令单版本号仍按数据包独立递增。

## 8. 兼容和历史数据说明

- 历史旧图纸的 `productCategory` 可能为空，代表旧版数据包级图纸；前端不要把空值当作模型类或导板类。
- 新保存的打印信息会保存产品分类快照；当前存在非空产品分类时，新生成图纸均带 `productCategory`。纯历史无分类包的新图纸仍可能为 `null`。
- 多分类旧数据包需要重新生成分类图纸后，新的提交校验才能通过。
- 二维码、截图上传、数据包文件接口不增加分类参数。

## 9. 联调验收清单

- 单模型数据包可以正常预览、下载、确认；
- 单导板数据包可以正常预览、下载、确认；
- 模型+导板数据包返回两条 `latestDrawings`；
- 模型图纸中不出现导板产品，导板图纸中不出现模型产品；
- 模型和导板分别修订、分别生成版本；
- 只确认其中一份图纸时，设计提交仍被阻断；
- 两份图纸和一份指令单都确认后，设计提交通过；
- 生产流转卡按自身产品分类读取对应图纸；
- 同一分类多个产品仍使用同一份分类图纸。
