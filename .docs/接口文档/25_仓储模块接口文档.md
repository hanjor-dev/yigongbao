### 25.1 仓储列表

**接口地址**：`POST /production/warehouse/list`

**是否需要认证**：是

**接口说明**：分页查询仓储流转卡汇总列表，以流转卡为维度展示产品库存状态，支持关键词模糊查询和多维度筛选。

**请求参数**（JSON Body）：

| 参数名 | 类型 | 必填 | 说明 | 默认值 |
|--------|------|------|------|--------|
| page | Integer | 否 | 页码 | 1 |
| size | Integer | 否 | 每页条数 | 10 |
| keyword | String | 否 | 关键词（模糊匹配流转卡编号、订单编号、产品名称、产品编号） | - |
| status | Integer | 否 | 流转卡状态（FlowStatusEnum值） | - |
| warehouseInTimeStart | String | 否 | 入库时间起始（yyyy-MM-dd HH:mm:ss） | - |
| warehouseInTimeEnd | String | 否 | 入库时间结束（yyyy-MM-dd HH:mm:ss） | - |
| warehouseOutTimeStart | String | 否 | 出库时间起始（yyyy-MM-dd HH:mm:ss） | - |
| warehouseOutTimeEnd | String | 否 | 出库时间结束（yyyy-MM-dd HH:mm:ss） | - |

**请求示例**：

Authorization: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx

### 25.4 产品入库

**接口地址**：`POST /production/warehouse/in/products/{productId}`

**是否需要认证**：是

**接口说明**：将指定产品标记为已入库状态。当流转卡下所有产品都入库后，自动将流转卡状态推进为"已入库"。

**路径参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| productId | Long | 是 | 产品ID |

**请求参数**（JSON Body）：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| remark | String | 否 | 入库备注 |

**请求示例**：
```json
POST /production/warehouse/in/products/123
Content-Type: application/json
Authorization: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx

{
  "remark": "质检合格，已入A库"
}
```

**响应示例**：
```json
{
  "code": 200,
  "message": "操作成功",
  "data": null,
  "timestamp": 1710392800000
}
```

**业务规则**：
- 只有状态为"待入库"的产品才能入库
- 入库后产品状态变为"已入库"
- 记录入库时间和入库人
- 当流转卡下所有产品都入库后，流转卡状态自动推进为"已入库"，并触发订单流程

**错误码**：

| 错误码 | 说明 |
|--------|------|
| 404 | 产品不存在 |
| PRODUCT_STATUS_NOT_ALLOW_WAREHOUSE_IN | 产品状态不允许入库 |

## 状态流转说明

### 产品状态流转
```
待入库(pending_warehouse_in) 
  → 入库 → 已入库(warehoused) 
  → 出库 → 已出库(warehouse_out)
```

### 流转卡状态聚合规则
- **推进到已入库**：当流转卡下所有产品都从"待入库"变为"已入库"时，流转卡状态自动推进为"已入库"（FlowStatusEnum.WAREHOUSED）
- **推进到已出库**：当流转卡下所有产品都从"已入库"变为"已出库"时，流转卡状态自动推进为"已出库"（FlowStatusEnum.WAREHOUSE_OUT）
- **订单流程触发**：流转卡状态变更后，会检查订单下所有流转卡是否都达到相同状态，如果是，则触发订单状态推进
