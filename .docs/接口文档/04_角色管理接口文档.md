## 接口列表

### 4.1 分页查询角色列表

**接口地址**：`POST /system/role/list`

**是否需要认证**：是

**接口说明**：分页查询角色列表，支持按角色名称、账户分类、状态等条件筛选。

**请求参数**（JSON Body）：

| 参数名 | 类型 | 必填 | 说明 | 默认值 |
|--------|------|------|------|--------|
| pageNum | Integer | 否 | 页码 | 1 |
| pageSize | Integer | 否 | 每页条数 | 10 |
| roleName | String | 否 | 角色名称（模糊查询） | - |
| accountType | Integer | 否 | 账户分类（1=内部用户，2=外部用户） | - |
| status | Integer | 否 | 状态（0=禁用，1=正常） | - |

**请求示例**：
```json
POST /system/role/list
Authorization: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
Content-Type: application/json

{
    "pageNum": 1,
    "pageSize": 10,
    "accountType": 1,
    "status": 1
}
```

**响应参数**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| code | Integer | 状态码，200表示成功 |
| message | String | 响应消息 |
| timestamp | Long | 时间戳 |
| data | Object | 分页数据 |
| data.records | Array | 角色列表 |
| data.total | Long | 总记录数 |
| data.size | Integer | 每页条数 |
| data.current | Integer | 当前页码 |
| data.pages | Integer | 总页数 |

**响应示例**：
```json
{
    "code": 200,
    "message": "操作成功",
    "timestamp": 1740700800000,
    "data": {
        "records": [
            {
                "id": 1,
                "roleName": "超级管理员",
                "roleCode": "super_admin",
                "roleDesc": "拥有系统所有权限",
                "accountType": 1,
                "accountTypeName": "内部用户",
                "dataScopeType": "all",
                "dataScopeTypeName": "全部",
                "status": 1,
                "statusName": "正常",
                "createTime": "2026-03-01 10:00:00"
            },
            {
                "id": 2,
                "roleName": "业务员",
                "roleCode": "salesman",
                "roleDesc": "负责医院业务拓展",
                "accountType": 2,

                "dataScopeType": "hospitals",
                "dataScopeTypeName": "医院范围",
                "status": 1,
```

### 4.3 创建角色

**是否需要认证**：是

**接口说明**：创建新角色。

**请求参数**：

| 参数名 | 类型 | 必填 | 说明 |

**请求示例**：
```json
{
    "roleName": "区域经理",
    "roleCode": "regional_manager",
    "roleDesc": "负责区域内的医院业务管理",
    "accountType": 2,
    "dataScopeType": "hospitals",
    "remark": "新增区域经理角色"
}
```

**响应参数**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| code | Integer | 状态码，200表示成功 |
| message | String | 响应消息 |
| timestamp | Long | 时间戳 |
| data | null | 无数据返回 |

**响应示例**：
```json
{
    "code": 200,
    "message": "操作成功",
    "timestamp": 1740700800000,
    "data": null
}
```

**错误码**：

| 错误码 | 说明 |
|--------|------|
| 400 | 角色编码已存在 |

## 业务说明

### 角色与账户类型

- **内部用户（accountType=1）**：公司内部员工，如管理员、技术人员等
- **外部用户（accountType=2）**：外部合作伙伴，如业务员、经销商等

### 数据权限范围

当角色的 `dataScopeType="hospitals"` 时，属于该角色的用户将受到医院范围限制，只能访问被分配给他的医院数据。其他值含义：
- `"all"`：全部数据（如 ROLE_ADMIN）
- `"org"`：本机构数据（如 ROLE_DESIGNER、ROLE_PRODUCTION、ROLE_ORG_ADMIN）
- `"self"`：仅自己的数据（如 ROLE_DOCTOR、ROLE_ORG_USER）

### 角色编码规范

角色编码是角色的唯一标识，建议使用有意义的英文缩写，如：
- `super_admin` - 超级管理员
- `admin` - 管理员
- `salesman` - 业务员
- `regional_manager` - 区域经理
