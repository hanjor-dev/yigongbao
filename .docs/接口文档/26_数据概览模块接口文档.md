## 26.1 获取角色数据概览

**接口地址**：`POST /dashboard/{roleCode}`

**是否需要认证**：是

**接口说明**：根据角色代码获取对应的数据概览内容，包括 KPI 卡片、可视化图表和待办事项。不同角色返回的数据内容和维度不同，支持预定义时间范围和自定义时间范围筛选。

**请求参数**：

| 参数名 | 类型 | 位置 | 必填 | 说明 | 可选值 |
|--------|------|------|------|------|--------|
| roleCode | String | Path | 是 | 角色代码 | salesman, designer, regional-manager, designer-manager |

**请求体参数（JSON）**：

| 参数名 | 类型 | 必填 | 说明 | 可选值 |
|--------|------|------|------|--------|
| timeRange | String | 是 | 时间范围类型 | today, week, month, quarter, year, custom |
| startDate | String | 否 | 自定义开始日期（timeRange=custom时必填） | 格式：yyyy-MM-dd |
| endDate | String | 否 | 自定义结束日期（timeRange=custom时必填） | 格式：yyyy-MM-dd |

**请求示例**：

预定义时间范围：
```http
POST /dashboard/salesman
Authorization: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
Content-Type: application/json

{
  "timeRange": "week"
}
```

自定义时间范围：
```http
POST /dashboard/salesman
Authorization: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
Content-Type: application/json

{
  "timeRange": "custom",
  "startDate": "2026-06-01",
  "endDate": "2026-06-15"
}
```

**响应参数**（Result<DashboardVO>）：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| code | Integer | 响应码，200 表示成功 |
| message | String | 响应消息 |
| data | DashboardVO | 数据概览对象 |

**DashboardVO 结构**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| cards | List<CardVO> | KPI 卡片列表 |
| charts | List<ChartVO> | 图表列表 |
| todos | List<TodoVO> | 待办事项列表 |

**CardVO 结构**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| key | String | 卡片唯一标识 |
| title | String | 卡片标题 |
| value | Object | 卡片数值（Long 或 String） |
| unit | String | 数值单位 |
| link | String | 跳转链接（可选） |

**ChartVO 结构**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| key | String | 图表唯一标识 |
| title | String | 图表标题 |
| type | String | 图表类型：line, bar, pie, funnel |
| data | Object | 图表数据（LineChartDataVO 或 PieChartDataVO） |

**LineChartDataVO 结构**（折线图/柱状图数据）：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| xAxis | List<String> | X 轴标签 |
| series | List<SeriesVO> | 数据系列 |

**SeriesVO 结构**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| name | String | 系列名称 |
| data | List<Integer> | 数据值 |

**PieChartDataVO 结构**（饼图/漏斗图数据）：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| items | List<ItemVO> | 数据项列表 |

**ItemVO 结构**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| name | String | 项目名称 |
| value | Integer | 项目数值 |

### 26.1.1 业务员（salesman）

**数据权限范围**：仅查询 `operator_id = 当前用户ID` 的订单数据。

**KPI 卡片（4个）**：

| 卡片 Key | 标题 | 查询逻辑 | 数据类型 | 单位 |
|---------|------|----------|----------|------|
| myOrders | 我的订单 | `SELECT COUNT(*) WHERE operator_id = userId AND create_time BETWEEN ? AND ?` | Long | 单 |
| pendingOrders | 待处理订单 | `SELECT COUNT(*) WHERE operator_id = userId AND status = 1040 AND create_time BETWEEN ? AND ?` | Long | 单 |
| inProgressOrders | 进行中订单 | `SELECT COUNT(*) WHERE operator_id = userId AND status NOT IN (6030, 8010, 9010) AND create_time BETWEEN ? AND ?` | Long | 单 |
| completedOrders | 已完成订单 | `SELECT COUNT(*) WHERE operator_id = userId AND status IN (6030, 8010) AND create_time BETWEEN ? AND ?` | Long | 单 |

**状态码说明**：
- 1040：数据审核驳回
- 6030：已出库
- 8010：已完成
- 9010：已取消

**图表（2个）**：

**1. 订单趋势（orderTrend）- 折线图**

- **类型**：line
- **X 轴**：根据 timeRange 动态生成
  - today: ["0时", "2时", "4时", ..., "22时"]（12个点）
  - week: ["周一", "周二", ..., "周日"]（7个点）
  - month/quarter/year: 按日期分组
- **数据系列**：1条线
  - 订单数：按 create_time 分组统计

**2. 订单阶段分布（orderPhase）- 饼图**

- **类型**：pie
- **查询逻辑**：`SELECT phase, COUNT(*) FROM order_main WHERE operator_id = userId AND create_time BETWEEN ? AND ? GROUP BY phase`
- **阶段映射**（FlowPhaseEnum）：
  - 10: 订单阶段
  - 20: 设计阶段
  - 30: 打印阶段
  - 40: 后处理阶段
  - 50: 质检阶段
  - 60: 仓储阶段
  - 80: 已完成

### 26.1.3 区域管理员（regional-manager）

**数据权限范围**：查询当前用户所在部门（dept_id）下所有业务员的订单数据。通过 `sys_user` 表查询部门内所有用户，得到 `operatorIds` 列表，然后查询 `operator_id IN (operatorIds)` 的订单。

**KPI 卡片（5个）**：

| 卡片 Key | 标题 | 查询逻辑 | 数据类型 | 单位 |
|---------|------|----------|----------|------|
| deptOrders | 部门订单 | `SELECT COUNT(*) WHERE operator_id IN (operatorIds) AND create_time BETWEEN ? AND ?` | Long | 单 |
| pendingAudit | 待审核订单 | `SELECT COUNT(*) WHERE operator_id IN (operatorIds) AND regional_audit_status = 0` | Long | 单 |
| inProgress | 进行中订单 | `SELECT COUNT(*) WHERE operator_id IN (operatorIds) AND status NOT IN (6030, 8010, 9010) AND create_time BETWEEN ? AND ?` | Long | 单 |
| completedOrders | 已完成 | `SELECT COUNT(*) WHERE operator_id IN (operatorIds) AND status IN (6030, 8010) AND create_time BETWEEN ? AND ?` | Long | 单 |
| avgOrders | 人均订单数 | `总订单数 / 部门人数`（保留1位小数） | String | 单 |

**特殊字段说明**：
- `regional_audit_status`：区域审核状态（0=待审核，1=已审核）

**图表（3个）**：

**1. 部门订单趋势（orderTrend）- 双折线图**

- **类型**：line
- **X 轴**：根据 timeRange 动态生成
- **数据系列**：2条线
  - **新提订单**：按 `create_time` 分组统计
  - **完成订单**：按 `update_time` 分组统计（`WHERE status IN (6030, 8010)`）

**2. 业务员TOP10（salesmanTop10）- 双柱状图**

- **类型**：bar
- **X 轴**：业务员姓名（operator_name）
- **查询逻辑**：
```sql
SELECT operator_id, operator_name,
  SUM(CASE WHEN status NOT IN (6030, 8010, 9010) THEN 1 ELSE 0 END) as in_progress,
  SUM(CASE WHEN status IN (6030, 8010) THEN 1 ELSE 0 END) as completed
WHERE operator_id IN (operatorIds) AND create_time BETWEEN ? AND ?
GROUP BY operator_id
ORDER BY (in_progress + completed) DESC
LIMIT 10
```
- **数据系列**：2条柱
  - 进行中
  - 已完成

**3. 提单时间分布（dailySubmissions）- 柱状图**

- **类型**：bar
- **X 轴**：日期（如 "1日", "2日", ...）
- **查询逻辑**：`SELECT DATE(create_time) as date, COUNT(*) FROM order_main WHERE operator_id IN (operatorIds) AND create_time BETWEEN ? AND ? GROUP BY date ORDER BY date`
- **数据系列**：1条柱
  - 提单数

### 26.1.4 设计管理员（designer-manager）

**数据权限范围**：查询当前用户所在部门（dept_id）下所有设计师的工单数据。如果用户没有 dept_id，则查询全部设计师数据。

**KPI 卡片（5个）**：

| 卡片 Key | 标题 | 查询逻辑 | 数据类型 | 单位 |
|---------|------|----------|----------|------|
| teamTotal | 团队工单总数 | `SELECT COUNT(*) WHERE designer_id IN (designerIds) AND status >= 2010 AND status != 9010` | Long | 单 |
| unassigned | 待分配工单 | `SELECT COUNT(*) WHERE (designer_id IS NULL OR designer_id = '')` | Long | 单 |
| designing | 设计中订单 | `SELECT COUNT(*) WHERE designer_id IN (designerIds) AND status = 2020` | Long | 单 |
| designCompleted | 设计完成订单 | `SELECT COUNT(*) WHERE designer_id IN (designerIds) AND status >= 2030 AND status != 9010` | Long | 单 |
| pendingAudit | 待审核订单 | `SELECT COUNT(*) WHERE designer_id IN (designerIds) AND (status = 1020 OR design_audit_status = 0)` | Long | 单 |

**特殊字段说明**：
- `design_audit_status`：设计审核状态（0=待审核，1=已审核）
- 状态 1020：待设计审核

**图表（2个）**：

**1. 设计师工作负载（designerWorkload）- 三柱状图**

- **类型**：bar
- **X 轴**：设计师姓名（designer_name）
- **查询逻辑**：
```sql
SELECT designer_id, designer_name,
  SUM(CASE WHEN status = 2010 THEN 1 ELSE 0 END) as pending,
  SUM(CASE WHEN status = 2020 THEN 1 ELSE 0 END) as designing,
  SUM(CASE WHEN status >= 2030 AND status != 9010 THEN 1 ELSE 0 END) as completed
WHERE designer_id IS NOT NULL AND designer_id != ''
  AND (designer_id IN (designerIds) OR designerIds为空)
GROUP BY designer_id
ORDER BY (pending + designing + completed) DESC
LIMIT 10
```
- **数据系列**：3条柱
  - 待设计
  - 设计中
  - 设计完成

**2. 工单流转漏斗图（workflowFunnel）- 漏斗图**

- **类型**：funnel
- **查询逻辑**：
  - 待设计：`COUNT(*) WHERE designer_id IN (designerIds) AND status = 2010`
  - 设计中：`COUNT(*) WHERE designer_id IN (designerIds) AND status = 2020`
  - 设计完成：`COUNT(*) WHERE designer_id IN (designerIds) AND status >= 2030 AND status != 9010`

## 异常处理

### 错误码

| 错误码 | 说明 |
|--------|------|
| 200 | 请求成功 |
| 400 | 请求参数错误（roleCode 或 timeRange 非法） |
| 401 | 未登录或 Token 失效 |
| 500 | 服务器内部错误 |

### 异常响应示例

**roleCode 不支持**：
```json
{
  "code": 400,
  "message": "不支持的角色代码: admin",
  "data": null
}
```

**未登录**：
```json
{
  "code": 401,
  "message": "未登录或 Token 已失效",
  "data": null
}
```

## 数据说明

### 时间范围（timeRange）

| 值 | 说明 | X 轴示例 |
|----|------|----------|
| today | 今日（00:00 ~ 23:59） | 0时, 2时, 4时, ..., 22时（每2小时一个点） |
| week | 本周（周一 ~ 周日） | 周一, 周二, ..., 周日 |
| month | 本月（1号 ~ 月末） | 1日, 2日, ..., 30日 |
| quarter | 本季度（首日 ~ 末日） | 按月分组 |
| year | 本年（1月1日 ~ 12月31日） | 1月, 2月, ..., 12月 |

### 空数据处理

- **图表无数据时**：返回"暂无数据"占位项，避免前端渲染异常
  - 饼图/漏斗图：`[{"name": "暂无数据", "value": 0}]`
  - 柱状图：`xAxis: ["暂无数据"], series: [{name: "...", data: [0]}]`
- **卡片无数据时**：返回 0
- **待办事项无数据时**：返回空数组 `[]`

### 数据权限

- **业务员**：只能查看自己作为 operator_id 的订单
- **设计师**：只能查看自己作为 designer_id 的工单
- **区域管理员**：查看所在部门所有业务员的订单
- **设计管理员**：查看所在部门所有设计师的工单（dept_id 为空时查看全部）

## 注意事项

1. **所有 KPI 卡片的时间范围过滤**仅应用于 `myOrders`、`completedOrders` 等需要统计时间段内数据的卡片，待审核、进行中等状态卡片通常不限制时间范围（查询当前状态）。
2. **图表数据映射**需要正确处理 SQL 查询结果与 X 轴标签的对应关系，避免数据错位。
3. **双折线图/多柱状图**的多个数据系列需要独立查询，然后合并到同一个图表结构中。
4. **枚举映射**（如 FlowPhaseEnum）需要使用 `.getName()` 方法获取中文名称，而非硬编码字符串。
5. **空数据兜底**是必须的，避免前端因空数组或 null 导致渲染异常。
