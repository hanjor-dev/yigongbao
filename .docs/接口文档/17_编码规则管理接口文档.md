## 接口列表

### 17.1 生成编码

**接口地址**：`GET /basic/code/generate/{ruleCode}`

**是否需要认证**：是

**接口说明**：根据规则编码生成一个新的流水号编码（序号自动递增）。生成后当前序号值加1。

**路径参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| ruleCode | String | 是 | 规则编码，如 HOSPITAL_NO、ORDER_NO 等 |

**请求示例**：
```http
GET /basic/code/generate/HOSPITAL_NO
Authorization: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

**响应参数**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| code | Integer | 状态码，200表示成功 |
| message | String | 响应消息 |
| timestamp | Long | 时间戳 |
| data | String | 生成的编码，如 HOS-20260330-0001 |

**响应示例**：
```json
{
    "code": 200,
    "message": "操作成功",
    "timestamp": 1740700800000,
    "data": "HOS-20260330-0001"
}
```

### 17.5 创建编码规则

**接口地址**：`POST /basic/code/rule`

**是否需要认证**：是

**接口说明**：创建新的编码规则。规则编码在同一系统中应保持唯一。

**请求参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| ruleCode | String | 是 | 规则编码（如 ORDER_NO） |
| ruleName | String | 是 | 规则名称 |
| prefix | String | 否 | 前缀 |
| dateFormat | String | 否 | 日期格式（如 yyyyMMdd） |
| seqLength | Integer | 是 | 序号长度（如 4 表示生成 0001） |
| resetType | String | 否 | 重置类型（DAY/MONTH/YEAR/NEVER） |
| step | Integer | 否 | 递增步长，默认1 |
| status | Integer | 否 | 状态（默认1，0=禁用，1=正常） |
| remark | String | 否 | 备注 |

**请求示例**：
```json
{
    "ruleCode": "ORDER_NO",
    "ruleName": "订单编号",
    "prefix": "ORD",
    "dateFormat": "yyyyMMdd",
    "seqLength": 4,
    "resetType": "DAY",
    "step": 1,
    "status": 1,
    "remark": "用于生成订单编号"
}
```

**响应参数**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| code | Integer | 状态码，200表示成功 |
| message | String | 响应消息 |
| timestamp | Long | 时间戳 |
| data | null | 无数据返回 |

**响应示例**：
```json
{
    "code": 200,
    "message": "操作成功",
    "timestamp": 1740700800000,
    "data": null
}
```

**错误码**：

| 错误码 | 说明 |
|--------|------|
| 400 | 规则编码已存在 |
| 400 | 参数校验失败（详见 message） |
| 400 | 规则编码格式不符合要求 |
| 400 | 序号长度超出有效范围 |

## 业务说明

### 编码规则组成

编码由以下部分按顺序拼接组成：`前缀 + 日期 + 序号`，各部分可按配置选择性省略。

示例：`ORD-20260330-0001`

- 前缀（prefix）：`ORD`
- 日期（dateFormat）：`20260330`（格式 yyyyMMdd）
- 序号（seqLength）：`0001`（长度为4，前补零）

### 重置类型说明

| 重置类型 | 说明 |
|----------|------|
| DAY | 每日重置序号，每日0点序号从1重新开始 |
| MONTH | 每月重置序号，每月1日序号从1重新开始 |
| YEAR | 每年重置序号，每年1月1日序号从1重新开始 |
| NEVER | 永不重置，序号持续递增 |

### 编码生成器使用规范

业务代码中调用编码生成器时，**必须使用 `CodeRuleConstants` 常量类中的常量**，禁止硬编码规则编码字符串：

```java
// 正确：使用常量
String hospitalCode = codeGeneratorService.generate(CodeRuleConstants.HOSPITAL_NO);
String orderCode = codeGeneratorService.generate(CodeRuleConstants.ORDER_NO);

// 错误：硬编码规则编码
String hospitalCode = codeGeneratorService.generate("HOSPITAL_NO");
```

### 序号池隔离

系统提供 `generateWithSeqSuffix(ruleCode, bizKey)` 方法，适用于同一业务下生成多个编码的场景。相同 `bizKey` 共享序号池，不同 `bizKey` 各自独立序号。

例如：同一订单下的多个数据包，可使用 `generateWithSeqSuffix(CodeRuleConstants.DATA_PACKAGE_NO, orderCode)` 确保序号连续。
