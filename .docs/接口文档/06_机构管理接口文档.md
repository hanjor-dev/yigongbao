### 6.1 分页查询机构列表

**接口地址**：`POST /system/org/list`

**是否需要认证**：是

**接口说明**：分页查询机构列表，支持按机构名称、机构类型、地区、状态等条件筛选。

**请求参数**（JSON Body）：

| 参数名 | 类型 | 必填 | 说明 | 默认值 |
|--------|------|------|------|--------|
| pageNum | Integer | 否 | 页码 | 1 |
| pageSize | Integer | 否 | 每页条数 | 10 |
| orgName | String | 否 | 机构名称（模糊查询） | - |
| orgType | String | 否 | 机构类型（1.1=生产企业，1.2=经销商，1.3=医疗机构，1.4=其他） | - |
| areaId | Long | 否 | 地区ID | - |
| status | Integer | 否 | 状态（0=禁用，1=正常） | - |

**请求示例**：
```json
POST /system/org/list
Authorization: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
Content-Type: application/json

{
    "pageNum": 1,
    "pageSize": 10,
    "orgType": "1.3",
    "status": 1
}
```

**响应参数**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| code | Integer | 状态码，200表示成功 |
| message | String | 响应消息 |
| timestamp | Long | 时间戳 |
| data | Object | 分页数据 |
| data.records | Array | 机构列表（OrgVO） |
| data.total | Long | 总记录数 |
| data.size | Integer | 每页条数 |
| data.current | Integer | 当前页码 |
| data.pages | Integer | 总页数 |

**响应示例**：

### 6.3 创建机构

**接口地址**：`POST /system/org`

**是否需要认证**：是

**接口说明**：创建新机构。系统自动生成机构编码。禁止创建生产企业类型（orgType="1.1"）。qualificationType=1（医疗器械）时 qualificationFile 必填。经销商（1.2）可通过 hospitalOrgIds 关联医疗机构，被关联机构必须为 orgType=1.3。

**请求参数**（JSON Body）：

| 参数名 | 类型 | 必填 | 校验规则 | 说明 |
|--------|------|------|----------|------|
| orgName | String | 是 | @NotBlank | 机构名称，全局唯一 |
| orgType | String | 是 | @NotBlank | 机构类型（1.2=经销商，1.3=医疗机构，1.4=其他；禁止1.1） |
| areaId | Long | 是 | @NotNull | 所属地区ID |
| areaName | String | 否 | - | 所属地区名称 |
| address | String | 否 | - | 详细地址 |
| contact | String | 否 | - | 联系人 |
| phone | String | 否 | @Pattern | 联系电话（手机号格式） |
| email | String | 否 | @Email | 联系邮箱 |
| creditCode | String | 否 | - | 统一社会信用代码 |
| qualificationFile | String | 条件必填 | - | 资质文件路径；qualificationType=1 时必填 |
| qualificationType | Integer | 否 | - | 资质类型（1=医疗器械，2=非医疗器械） |
| hospitalOrgIds | List\<Long\> | 否 | - | 关联医院机构ID列表（仅经销商1.2有效，被关联机构须为1.3） |
| hospitalLevel | String | 否 | - | 医院等级（字典编码，如"3.1"；仅医疗机构1.3填写） |
| hospitalType | String | 否 | - | 医院类型（字典编码，如"4.1"；仅医疗机构1.3填写） |
| remark | String | 否 | - | 备注 |

**请求示例**：
```json
POST /system/org
Authorization: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
Content-Type: application/json

{
    "orgName": "华北医疗器械经销有限公司",
    "orgType": "1.2",
    "areaId": 110000,
    "areaName": "北京市",
    "address": "北京市海淀区中关村大街1号",
    "contact": "李四",
    "phone": "13900139000",
    "email": "sales@example.com",
    "creditCode": "91110000XXXXXXXXXX",
    "qualificationFile": "https://example.com/files/cert.jpg",
    "qualificationType": 1,
    "hospitalOrgIds": [1, 3],
    "remark": "华北区域经销商"
}
```

**响应示例**：
```json
{
    "code": 200,
    "message": "操作成功",
    "timestamp": 1740700800000,
    "data": null
}
```

**错误码**：

| 错误码 | 说明 |
|--------|------|
| 400 | 参数校验失败（@NotBlank / @NotNull / @Pattern / @Email） |
| 615 | 机构名称已存在 |
| 618 | 机构类型不在字典中 |
| 620 | 不允许创建生产企业类型机构 |
| 621 | 医疗器械资质类型时资质文件必填 |

## 业务说明

### 机构类型编码

| 编码 | 名称 | 说明 |
|------|------|------|
| 1.1 | 生产企业 | 禁止通过接口创建或修改为此类型 |
| 1.2 | 经销商 | 可关联多个医疗机构（hospitalOrgIds） |
| 1.3 | 医疗机构 | 可填写医院等级（hospitalLevel）和医院类型（hospitalType） |
| 1.4 | 其他 | 通用机构类型 |

### 资质文件规则

- `qualificationType=1`（医疗器械）时，`qualificationFile` 为必填项，否则返回错误码 621。
- `qualificationType=2`（非医疗器械）时，`qualificationFile` 为可选项。

### 经销商关联医院

- 仅 `orgType=1.2`（经销商）支持 `hospitalOrgIds` 字段。
- 被关联的机构必须是 `orgType=1.3`（医疗机构），否则校验失败。

### 机构删除规则

- 采用逻辑删除（`is_deleted=1`）。
- 机构下存在关联用户时，禁止删除，返回错误码 617。

## 错误码汇总

| 错误码 | 枚举名 | 说明 |
|--------|--------|------|
| 613 | ORG_NOT_FOUND | 机构不存在 |
| 614 | ORG_DISABLED | 机构已禁用 |
| 615 | ORG_EXISTS | 机构名称已存在 |
| 616 | ORG_CODE_EXISTS | 机构编码已存在 |
| 617 | ORG_HAS_USERS | 机构下存在关联用户，无法删除 |
| 618 | ORG_TYPE_NOT_FOUND | 机构类型不在字典中 |
| 620 | ORG_TYPE_NOT_ALLOWED | 不允许操作生产企业类型机构 |
| 621 | ORG_CERT_FILE_REQUIRED | 医疗器械资质类型时资质文件必填 |
