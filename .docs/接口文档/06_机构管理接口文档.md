### 6.1 分页查询机构列表

**接口地址**：`POST /system/org/list`

**是否需要认证**：是

**接口说明**：分页查询机构列表，支持按机构名称、机构类型、地区、状态等条件筛选。结果自动排除生产企业（1.1）和未知医院（内置占位）。

**请求参数**（JSON Body）：

| 参数名 | 类型 | 必填 | 说明 | 默认值 |
|--------|------|------|------|--------|
| pageNum | Integer | 否 | 页码 | 1 |
| pageSize | Integer | 否 | 每页条数 | 10 |
| orgName | String | 否 | 机构名称（模糊查询） | - |
| orgType | String | 否 | 机构类型（字典值，1.2=经销商，1.3=医疗机构） | - |
| areaId | Long | 否 | 地区ID | - |
| status | Integer | 否 | 状态（0=禁用，1=正常） | - |

**请求示例**：
```json
POST /system/org/list
Authorization: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
Content-Type: application/json

{
    "pageNum": 1,
    "pageSize": 10,
    "orgType": "1.3",
    "status": 1
}
```

**响应参数**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| data.records | Array | 机构列表（OrgVO） |
| data.total | Long | 总记录数 |
| data.size | Integer | 每页条数 |
| data.current | Integer | 当前页码 |
| data.pages | Integer | 总页数 |

**响应示例**：
```json
{
    "code": 200,
    "message": "操作成功",
    "timestamp": 1740700800000,
    "data": {
        "records": [
            {
                "id": 4,
                "orgName": "北京协和医院",
                "orgCode": "ORG-H-0001",
                "orgType": "1.3",
                "orgTypeName": "医疗机构",
                "areaId": 110000,
                "areaName": "北京市",
                "status": 1,
                "statusName": "正常"
            }
        ],
        "total": 4,
        "size": 10,
        "current": 1,
        "pages": 1
    }
}
```

### 6.3 创建机构

**接口地址**：`POST /system/org`

**是否需要认证**：是

**接口说明**：创建新机构。系统自动生成机构编码。禁止创建生产企业类型（1.1）。`qualificationType=1` 时 `qualificationFile`（文件ID）必填，系统会校验文件真实存在。经销商（1.2）可通过 `hospitalOrgIds` 关联医疗机构，被关联机构必须为 `orgType=1.3`。

**请求参数**（JSON Body）：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| orgName | String | 是 | 机构名称，全局唯一 |
| orgType | String | 是 | 机构类型（1.2=经销商，1.3=医疗机构，1.4=其他；禁止1.1） |
| areaId | Long | 否 | 所属省级地区ID |
| address | String | 否 | 详细地址 |
| contact | String | 否 | 联系人 |
| phone | String | 否 | 联系电话（手机号格式） |
| email | String | 否 | 联系邮箱 |
| creditCode | String | 否 | 统一社会信用代码 |
| qualificationFile | String | 条件必填 | 资质文件ID（qualificationType=1 时必填） |
| qualificationType | Integer | 否 | 资质类型（1=医疗器械，2=非医疗器械） |
| hospitalOrgIds | List\<Long\> | 否 | 关联医院机构ID列表（仅经销商1.2有效） |
| hospitalLevel | String | 否 | 医院等级（字典编码，如"3.1"；仅医疗机构1.3填写） |
| hospitalType | String | 否 | 医院类型（字典编码，如"4.1"；仅医疗机构1.3填写） |
| remark | String | 否 | 备注 |

**错误码**：

| 错误码 | 说明 |
|--------|------|
| 615 | 机构名称已存在 |
| 618 | 机构类型不在字典中 |
| 620 | 不允许创建生产企业类型机构 |
| 621 | 医疗器械资质类型时资质文件必填 |

### 6.4 更新机构

**接口地址**：`PUT /system/org/{id}`

**是否需要认证**：是

**接口说明**：更新指定机构信息。机构类型（orgType）**不可修改**。`qualificationType=1` 时 `qualificationFile` 必填。

> **注意**：若更新经销商的 `hospitalOrgIds`，建议先调用 [6.4.1 预检查接口](#641-预检查经销商关联医院变更影响) 确认对业务员权限的影响。

**路径参数**：`id` — 机构ID

**请求参数**（JSON Body）：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| orgName | String | 否 | 机构名称 |
| areaId | Long | 否 | 所属省级地区ID |
| address | String | 否 | 详细地址 |
| contact | String | 否 | 联系人 |
| phone | String | 否 | 联系电话 |
| email | String | 否 | 联系邮箱 |
| creditCode | String | 否 | 统一社会信用代码 |
| qualificationFile | String | 条件必填 | 资质文件ID（qualificationType=1 时必填） |
| qualificationType | Integer | 否 | 资质类型（1=医疗器械，2=非医疗器械） |
| hospitalOrgIds | List\<Long\> | 否 | 关联医院机构ID列表（仅经销商1.2有效，全量替换） |
| hospitalLevel | String | 否 | 医院等级（字典编码） |
| hospitalType | String | 否 | 医院类型（字典编码） |
| remark | String | 否 | 备注 |

**错误码**：

| 错误码 | 说明 |
|--------|------|
| 613 | 机构不存在 |
| 615 | 机构名称已存在 |
| 620 | 不允许修改机构类型 |
| 621 | 医疗器械资质类型时资质文件必填 |

#### 6.4.1 预检查经销商关联医院变更影响

**接口地址**：`POST /system/org/{id}/hospital-change-check`

**接口说明**：更新经销商关联医院（`hospitalOrgIds`）前调用。检查被移除的医院是否影响该经销商下业务员的医院权限。若 `affected=true`，前端需展示受影响用户列表，用户确认后再提交更新。

**路径参数**：`id` — 经销商机构ID

**请求参数**（JSON Body）：新的关联医院ID列表，如 `[4, 5, 6]`

**响应参数**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| affected | Boolean | 是否有受影响用户（true=需确认，false=可直接提交） |
| removedHospitals | Array | 被移除的医院列表 |
| removedHospitals[].id | Long | 医院ID |
| removedHospitals[].orgName | String | 医院名称 |
| affectedUsers | Array | 受影响的业务员列表 |
| affectedUsers[].id | Long | 用户ID |
| affectedUsers[].realName | String | 用户姓名 |
| affectedUsers[].removedHospitalIds | Array | 该用户被移除的医院ID列表 |

**响应示例**：
```json
{
    "code": 200,
    "data": {
        "affected": true,
        "removedHospitals": [{"id": 5, "orgName": "上海市第一人民医院"}],
        "affectedUsers": [{"id": 101, "realName": "张业务员", "removedHospitalIds": [5]}]
    }
}
```

> 更新接口执行时会自动同步清理失效的用户医院权限（`sys_user_hospital`）。

### 6.5 删除机构

**接口地址**：`DELETE /system/org/{id}`

**是否需要认证**：是

**接口说明**：逻辑删除指定机构。机构下存在关联用户时不允许删除。

> **注意**：建议先调用 [6.5.1 预检查接口](#651-预检查删除机构影响) 确认影响范围，用户确认后再执行删除。

**路径参数**：`id` — 机构ID

**删除时自动清理**：
- `sys_org_hospital`：该机构作为经销商或医院的所有关联记录
- `sys_user_hospital`：该机构作为医院被分配给用户的权限记录
- `hospital_group_template_detail`：该机构作为医院加入模板的记录
- `sys_dept_org`：该机构被部门关联的记录

**错误码**：

| 错误码 | 说明 |
|--------|------|
| 613 | 机构不存在 |
| 617 | 机构下存在关联用户，无法删除 |

---

#### 6.5.1 预检查删除机构影响

**接口地址**：`GET /system/org/{id}/check-remove`

**接口说明**：删除机构前调用，返回受影响的用户和医生列表。若 `affected=true`，前端需展示影响列表并提示用户确认后再执行删除。

**路径参数**：`id` — 机构ID

**响应参数**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| affected | Boolean | 是否有受影响数据 |
| affectedUsers | Array | 机构下的用户列表（删除后账号将失去归属） |
| affectedUsers[].id | Long | 用户ID |
| affectedUsers[].realName | String | 用户姓名 |
| affectedDoctors | Array | 关联医生列表（仅医疗机构时有值） |
| affectedDoctors[].id | Long | 医生ID |
| affectedDoctors[].doctorName | String | 医生姓名 |

**响应示例**：
```json
{
    "code": 200,
    "data": {
        "affected": true,
        "affectedUsers": [{"id": 101, "realName": "张业务员"}],
        "affectedDoctors": [{"id": 201, "doctorName": "王医生"}]
    }
}
```

### 6.6 修改机构状态

**接口地址**：`PUT /system/org/{id}/status`

**是否需要认证**：是

**接口说明**：修改机构的启用/禁用状态。**禁用机构时**，系统会立即踢出该机构下所有用户的登录会话，且这些用户在机构重新启用前无法再登录。

> **注意**：禁用操作影响较大，建议先调用 [6.6.1 预检查接口](#661-预检查禁用机构影响) 确认受影响用户，用户确认后再执行禁用。

**路径参数**：`id` — 机构ID

**请求参数**（Query String）：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| status | Integer | 是 | 状态值（0=禁用，1=正常） |

**请求示例**：
```http
PUT /system/org/2/status?status=0
Authorization: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

**错误码**：

| 错误码 | 说明 |
|--------|------|
| 613 | 机构不存在 |

---

#### 6.6.1 预检查禁用机构影响

**接口地址**：`GET /system/org/{id}/check-disable`

**接口说明**：禁用机构前调用，返回受影响的用户列表。禁用后这些用户将被立即踢出会话，且无法再登录，直到机构重新启用。

**路径参数**：`id` — 机构ID

**响应参数**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| affected | Boolean | 是否有受影响用户 |
| affectedUsers | Array | 机构下的用户列表 |
| affectedUsers[].id | Long | 用户ID |
| affectedUsers[].realName | String | 用户姓名 |
| affectedDoctors | Array | 始终为空列表 |

**响应示例**：
```json
{
    "code": 200,
    "data": {
        "affected": true,
        "affectedUsers": [
            {"id": 101, "realName": "张业务员"},
            {"id": 102, "realName": "李业务员"}
        ],
        "affectedDoctors": []
    }
}
```

## 业务说明

### 机构类型编码

| 编码 | 名称 | 说明 |
|------|------|------|
| 1.1 | 生产企业 | 禁止通过接口创建或修改为此类型，列表查询自动排除 |
| 1.2 | 经销商 | 可关联多个医疗机构（hospitalOrgIds） |
| 1.3 | 医疗机构 | 可填写医院等级/类型；删除时检查关联医生 |
| 1.4 | 其他 | 通用机构类型 |

### 资质文件规则

- `qualificationType=1`（医疗器械）时，`qualificationFile`（文件ID）为必填项
- 系统会调用文件服务校验文件真实存在，保存后自动关联文件与机构

### 禁用机构联动

禁用机构时自动踢出其下所有用户会话；登录时若用户所属机构已禁用，返回 `ORG_DISABLED(614)` 错误。

### 预检查流程

| 操作 | 预检查接口 | 时机 |
|-----|-----------|------|
| 更新关联医院 | `POST /{id}/hospital-change-check` | 提交前，有 hospitalOrgIds 变更时 |
| 删除机构 | `GET /{id}/check-remove` | 点击删除按钮后，确认前 |
| 禁用机构 | `GET /{id}/check-disable` | 点击禁用按钮后，确认前 |

## 错误码汇总

| 错误码 | 枚举名 | 说明 |
|--------|--------|------|
| 613 | ORG_NOT_FOUND | 机构不存在 |
| 614 | ORG_DISABLED | 机构已禁用（登录时所属机构被禁用） |
| 615 | ORG_EXISTS | 机构名称已存在 |
| 616 | ORG_CODE_EXISTS | 机构编码已存在 |
| 617 | ORG_HAS_USERS | 机构下存在关联用户，无法删除 |
| 618 | ORG_TYPE_NOT_FOUND | 机构类型不在字典中 |
| 620 | ORG_TYPE_NOT_ALLOWED | 不允许操作生产企业类型机构或修改机构类型 |
| 621 | ORG_CERT_FILE_REQUIRED | 医疗器械资质类型时资质文件必填 |
