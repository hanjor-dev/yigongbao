## 接口列表

### 7.1 分页查询部门列表

**接口地址**：`POST /system/dept/list`

**是否需要认证**：是

**接口说明**：分页查询部门列表，支持按部门类型、部门名称、状态等条件筛选。

**请求参数**（JSON Body）：

| 参数名 | 类型 | 必填 | 说明 | 默认值 |
|--------|------|------|------|--------|
| pageNum | Integer | 否 | 页码 | 1 |
| pageSize | Integer | 否 | 每页条数 | 10 |
| deptType | Integer | 否 | 部门类型（1=内部，2=外部） | - |
| deptName | String | 否 | 部门名称（模糊查询） | - |
| status | Integer | 否 | 状态（0=禁用，1=正常） | - |

**请求示例**：
```json
POST /system/dept/list
Authorization: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
Content-Type: application/json

{
    "pageNum": 1,
    "pageSize": 10,
    "deptType": 1,
    "status": 1
}
```

**响应参数**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| code | Integer | 状态码，200表示成功 |
| message | String | 响应消息 |
| timestamp | Long | 时间戳 |
| data | Object | 分页数据 |
| data.records | Array | 部门列表（字段见 DeptVO） |
| data.total | Long | 总记录数 |
| data.size | Integer | 每页条数 |
| data.current | Integer | 当前页码 |
| data.pages | Integer | 总页数 |

**响应示例**：
```json
{
    "code": 200,
    "message": "操作成功",
    "timestamp": 1745798400000,
    "data": {
        "records": [
            {
                "id": 1,

                "leaderUserName": "张三",

            {
                "id": 2,
                "deptName": "销售部",
                "deptCode": "DEPT002",
```

### 7.3 创建部门

**接口地址**：`POST /system/dept`

**是否需要认证**：是

**接口说明**：创建新部门。系统自动生成部门编码。内部部门只能关联生产企业（orgType=1.1），外部部门只能关联经销商（orgType=1.2）。

**请求参数**（JSON Body）：

| 参数名 | 类型 | 必填 | 校验规则 | 说明 |
|--------|------|------|----------|------|
| deptName | String | 是 | @NotBlank, 最大128字符 | 部门名称，全局唯一 |
| deptType | Integer | 是 | @NotNull, 1或2 | 部门类型（1=内部，2=外部） |
| orgIds | List\<Long\> | 否 | - | 关联机构ID列表 |
| leaderUserId | Long | 否 | - | 部门负责人用户ID |
| remark | String | 否 | - | 备注 |

**请求示例**：
```json
POST /system/dept
Authorization: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
Content-Type: application/json

{
    "deptName": "产品部",
    "deptType": 1,
    "orgIds": [1, 2],
    "leaderUserId": 8,
    "remark": "负责产品设计和规划"
}
```

**响应示例**：
```json
{
    "code": 200,
    "message": "操作成功",
    "timestamp": 1745798400000,
    "data": null
}
```

**错误码**：

| 错误码 | 说明 |
|--------|------|
| 631 | 部门名称已存在 |
| 622 | 关联机构类型与部门类型不匹配（内部部门只能关联生产企业，外部部门只能关联经销商） |
| 634 | 该经销商已被其他外部部门关联 |
| 635 | 内部部门只能关联一个生产企业机构 |
| 400 | 参数校验失败 |

### 7.5 删除部门

**接口地址**：`DELETE /system/dept/{id}`

**是否需要认证**：是

**接口说明**：逻辑删除指定部门，同时级联删除 sys_dept_org 关联记录。如果部门下有关联用户，则不允许删除。

**路径参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | Long | 是 | 部门ID |

**请求示例**：
```http
DELETE /system/dept/10
Authorization: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

**响应示例**：
```json
{
    "code": 200,
    "message": "操作成功",
    "timestamp": 1745798400000,
    "data": null
}
```

**错误码**：

| 错误码 | 说明 |
|--------|------|
| 630 | 部门不存在 |
| 632 | 部门下存在用户，无法删除 |

## 业务说明

### 部门编码规则

部门编码由系统自动生成，格式为 `DEPT` + 序号。

### 部门类型与机构关联约束

部门分为内部部门和外部部门两种类型，关联机构时有严格的类型匹配要求：

| 部门类型 | 可关联机构类型 | 数量限制 | 额外约束 | 违反时错误码 |
|----------|--------------|---------|---------|------------|
| 内部（deptType=1） | 生产企业（orgType=1.1） | 最多1个 | 无 | 622/635 |
| 外部（deptType=2） | 经销商（orgType=1.2） | 不限 | 每个经销商只能属于一个外部部门 | 622/634 |

### 部门与机构的关系

- 内部部门与生产企业为多对一关系（一个内部部门关联1个生产企业，一个生产企业可有多个内部部门）
- 外部部门与经销商为一对多关系（一个外部部门可关联多个经销商，但每个经销商只能属于一个外部部门）
- 关联关系通过 `sys_dept_org` 中间表维护
- 部门名称全局唯一（不限机构范围）
- 删除部门时，`sys_dept_org` 中对应的关联记录会被级联删除

### 部门负责人

`leaderUserId` 字段用于指定部门的负责人，不强制约束，仅作为信息展示。

## 错误码汇总

| 错误码 | 常量名 | 说明 |
|--------|--------|------|
| 622 | ORG_DEPT_TYPE_MISMATCH | 关联机构类型与部门类型不匹配 |
| 630 | DEPT_NOT_FOUND | 部门不存在 |
| 631 | DEPT_EXISTS | 部门名称已存在 |
| 632 | DEPT_HAS_USERS | 部门下存在用户，无法删除 |
| 633 | DEPT_DISABLED | 部门已禁用 |
| 634 | DEPT_ORG_ALREADY_BOUND | 该经销商已被其他外部部门关联 |
| 635 | DEPT_INTERNAL_ORG_LIMIT | 内部部门只能关联一个生产企业机构 |
