## 草稿接口

### 19.1 分页查询我的草稿列表

**接口地址**：`POST /order/draft/list`

**是否需要认证**：是

**接口说明**：分页查询当前登录用户的草稿列表，仅返回未提交的草稿（已提交草稿不展示）。

**请求参数**（JSON Body）：

| 参数名 | 类型 | 必填 | 说明 | 默认值 |
|--------|------|------|------|--------|
| pageNum | Integer | 否 | 页码 | 1 |
| pageSize | Integer | 否 | 每页条数 | 10 |
| hospitalId | Long | 否 | 医院ID（筛选条件） | - |
| status | Integer | 否 | 草稿状态：1-有效，3-已过期 | - |

**请求示例**：
```json
POST /order/draft/list
Content-Type: application/json
Authorization: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx

{
    "pageNum": 1,
    "pageSize": 10
}
```

**响应参数**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| code | Integer | 状态码，200表示成功 |
| message | String | 响应消息 |
| data | Object | 分页数据 |
| data.current | Long | 当前页码 |
| data.size | Long | 每页条数 |
| data.total | Long | 总记录数 |
| data.records | Array | 草稿列表 |
| data.records[].id | Long | 草稿ID |
| data.records[].orderType | Integer | 订单类型：1-医疗器械，2-非医疗器械 |
| data.records[].orderTypeName | String | 订单类型名称 |
| data.records[].needsPhysicalDelivery | Integer | 是否需要实体交付：0-否，1-是 |
| data.records[].businessType | String | 业务类型（dict_code，如 "11.1"） |
| data.records[].orgName | String | 提单机构名称 |
| data.records[].hospitalId | Long | 医院ID |
| data.records[].hospitalName | String | 医院名称 |
| data.records[].patientName | String | 患者姓名 |
| data.records[].status | Integer | 草稿状态：1-有效，2-已提交，3-已过期 |
| data.records[].statusName | String | 草稿状态名称 |
| data.records[].itemCount | Integer | 重建项目数量 |
| data.records[].expiresAt | String | 过期时间（yyyy-MM-dd HH:mm:ss） |
| data.records[].createTime | String | 创建时间 |

**响应示例**：
```json
{
    "code": 200,
    "message": "操作成功",
    "timestamp": 1744000000000,
    "data": {
        "current": 1,
        "size": 10,
        "total": 2,
        "records": [
            {
                "id": 100,
                "orderType": 1,

                "needsPhysicalDelivery": 1,

                "orgName": "XX医疗科技有限公司",
```

### 19.3 创建或更新草稿

**接口地址**：`POST /order/draft`

**是否需要认证**：是

**接口说明**：创建新草稿或更新已有草稿。传入 `id` 字段时为更新，不传则为新增。草稿默认30天后过期（可通过系统配置 `order.draft.expire.days` 调整）。

**请求参数**（JSON Body）：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | Long | 否 | 草稿ID，更新时传入 |
| orderType | Integer | 是 | 订单类型：1-医疗器械，2-非医疗器械 |
| needsPhysicalDelivery | Integer | 是 | 是否需要实体交付：0-不需要，1-需要 |
| businessType | String | 是 | 业务类型（dict_code：11.1-业务，11.2-测试，11.3-试用，11.4-代理） |
| orgId | Long | 是 | 提单机构ID |
| orgName | String | 否 | 提单机构名称 |
| operatorName | String | 否 | 操作员姓名 |
| operatorPhone | String | 否 | 操作员电话（格式：1[3-9]xxxxxxxxx） |
| hospitalId | Long | 是 | 医院ID |
| hospitalName | String | 否 | 医院名称 |
| deptId | Long | 否 | 科室ID |
| deptName | String | 否 | 科室名称 |
| doctorId | Long | 否 | 医生ID（有则自动填充医生信息） |
| doctorName | String | 否 | 医生姓名（doctorId为空时可填，系统自动创建医生记录） |
| doctorPhone | String | 否 | 医生电话（格式：1[3-9]xxxxxxxxx） |
| patientName | String | 是 | 患者姓名 |
| patientAge | Integer | 否 | 患者年龄（0~150） |
| patientGender | String | 否 | 患者性别（dict_code：12.1-男，12.2-女） |
| isUrgent | Integer | 否 | 是否加急：0-否，1-是 |
| isPostal | Integer | 否 | 是否邮寄：0-否，1-是 |
| postalAddress | String | 否 | 邮寄地址 |
| expectedDeliveryDate | String | 否 | 期望交付时间（yyyy-MM-dd HH:mm:ss） |
| items | Array | 否 | 重建项目明细列表（草稿模式可为空） |
| items[].bodyPartId | Long | 否 | 部位ID |
| items[].bodyPartName | String | 否 | 部位名称 |
| items[].projectId | Long | 否 | 重建项目ID |
| items[].projectName | String | 否 | 重建项目名称 |
| items[].projectEstimatedHours | Number | 否 | 预计耗时（小时） |
| items[].projectDesc | String | 否 | 项目说明 |
| items[].formingRequirement | String | 否 | 成形需求 |
| items[].otherRequirement | String | 否 | 其他要求 |
| items[].sortOrder | Integer | 否 | 排序序号（未填则自动赋值） |

**请求示例**：
```json
POST /order/draft
Content-Type: application/json
Authorization: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx

{
    "orderType": 1,
    "needsPhysicalDelivery": 1,
    "businessType": "11.1",
    "orgId": 2,
    "hospitalId": 5,
    "patientName": "张三",
    "patientAge": 45,
    "patientGender": "12.1",
    "items": [
        {
            "bodyPartId": 3,
            "projectId": 15,
            "formingRequirement": "钛合金",
            "sortOrder": 1
        }
    ]
}
```

**响应参数**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| data | Long | 草稿ID |

**响应示例**：
```json
{
    "code": 200,
    "message": "操作成功",
    "timestamp": 1744000000000,
    "data": 100
}
```

**错误码**：

| 错误码 | 说明 |
|--------|------|
| 676 | 草稿不存在（更新时） |
| 679 | 只能修改自己的草稿 |
| 680 | 草稿已提交，不能修改 |

### 19.5 提交草稿转正式订单(x)

**接口地址**：`POST /order/draft/{id}/submit`

**是否需要认证**：是

**接口说明**：将草稿提交为正式订单。提交前会进行严格校验（机构、医院、患者、明细必填；若系统配置要求则影像文件也必填）。提交成功后草稿状态变为"已提交"，不可再修改。

**路径参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | Long | 是 | 草稿ID |

**请求示例**：
```
POST /order/draft/100/submit
Authorization: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

**响应参数**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| data | Long | 新创建的订单ID |

**响应示例**：
```json
{
    "code": 200,
    "message": "操作成功",
    "timestamp": 1744000000000,
    "data": 1001
}
```

**错误码**：

| 错误码 | 说明 |
|--------|------|
| 676 | 草稿不存在 |
| 679 | 只能提交自己的草稿 |
| 680 | 草稿已提交 |
| 681 | 订单明细不能为空 |
| 682 | 影像文件不能为空（系统配置开启时） |
| 682 | 免费业务审批文件不能为空（业务类型为测试/试用时） |

### 19.6 直接创建订单（直提）

**接口地址**：`POST /order`

**是否需要认证**：是

**接口说明**：直接创建正式订单，跳过草稿步骤。适用于业务员信息填写完整时的快捷提交场景。与草稿提交的区别在于：影像文件通过 `imageDataFileIds`/`imageReportFileIds` 直接传入（文件需提前上传至文件服务）。

| businessType | String | 是 | 业务类型（dict_code：11.1/11.2/11.3/11.4） |
| orgId | Long | 是 | 提单机构ID |
| orgName | String | 否 | 提单机构名称 |
| operatorName | String | 否 | 操作员姓名 |
| operatorPhone | String | 否 | 操作员电话 |
| hospitalId | Long | 是 | 医院ID |
| hospitalName | String | 否 | 医院名称 |
| deptId | Long | 否 | 科室ID |
| deptName | String | 否 | 科室名称 |
| doctorId | Long | 否 | 医生ID |
| doctorName | String | 否 | 医生姓名 |
| doctorPhone | String | 否 | 医生电话 |
| patientName | String | 是 | 患者姓名 |
| patientAge | Integer | 否 | 患者年龄（0~150） |
| patientGender | String | 否 | 患者性别（dict_code：12.1-男，12.2-女） |
| isUrgent | Integer | 否 | 是否加急：0-否，1-是 |
| isPostal | Integer | 否 | 是否邮寄：0-否，1-是 |
| postalAddress | String | 否 | 邮寄地址 |
| expectedDeliveryDate | String | 否 | 期望交付时间 |
| items | Array | 是 | 重建项目明细列表（至少1条） |
| items[].bodyPartId | Long | 是 | 部位ID |
| items[].projectId | Long | 是 | 重建项目ID |
| items[].projectEstimatedHours | Number | 否 | 预计耗时（小时） |
| items[].projectDesc | String | 否 | 项目说明 |
| items[].formingRequirement | String | 否 | 成形需求 |
| items[].otherRequirement | String | 否 | 其他要求 |
| items[].sortOrder | Integer | 否 | 排序序号 |
| imageDataFileIds | Array | 否 | 影像数据文件ID列表（CT/MRI等，dict_code=10.1） |
| imageReportFileIds | Array | 否 | 影像报告文件ID列表（dict_code=10.2） |
| approvalFileIds | Array | 否 | 免费业务审批文件ID列表（dict_code=10.20，业务类型为测试/试用时提交时必填） |

### 19.21 执行订单修改

**接口地址**：`PUT /order/modify/execute/{applyId}`

**接口说明**：对已审核通过（APPROVED）的申请执行实际修改操作。请求体为结构化 DTO（`ExecuteModifyDTO`），按申请类型分三个子结构传入；服务端根据申请类型（14.1/14.2/14.3）自动分发处理，完成后将申请状态置为 COMPLETED，并记录每个字段的变更留痕。字段名由 `sys_config` 中 `order.modify.field.config` 配置驱动，白名单外的字段名会被静默忽略。

**路径参数**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| applyId | Long | 已审核通过的申请ID |

**请求体**（`ExecuteModifyDTO`）：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| infoFields | List\<ModifyField\> | 基础信息修改字段列表（14.1，**差量**，只传要改的字段） |
| items | List\<ModifyItem\> | 重建项目列表（14.3，**全量替换**，传入即为最终状态） |
| imageDataFileIds | List\<String\> | 影像数据文件ID列表（14.2，**全量替换**，传 `null` 表示不修改，传 `[]` 表示清空） |
| imageReportFileIds | List\<String\> | 影像报告文件ID列表（14.2，**全量替换**，传 `null` 表示不修改，传 `[]` 表示清空） |

**ModifyField 结构**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| field | String | 是 | 字段名（须与 sys_config `order.modify.field.config` 中对应类型 `fields[].field` 一致） |
| value | Object | 否 | 字段新值 |

**14.1 可用字段**（`infoFields[].field` 取值范围）：

| field | label | 类型说明 |
|-------|-------|----------|
| hospitalId | 医院 | Long，修改后自动联动科室/医生验证 |
| hospitalDeptId | 科室 | Long，同上 |
| doctorId | 关联医生 | Long，同上 |
| doctorName | 医生姓名 | String，同上 |
| doctorPhone | 医生电话 | String，同上 |
| patientName | 患者姓名 | String |
| patientAge | 患者年龄 | Integer |
| patientGender | 患者性别 | String（字典编码，如 `12.1`=男） |
| isUrgent | 是否加急 | Integer（0=否，1=是） |
| isPostal | 是否邮寄 | Integer（0=否，1=是） |
| postalAddress | 邮寄地址 | String |
| expectedDeliveryDate | 期望交付时间 | String（ISO-8601，如 `2026-05-01T00:00:00`） |

> `hospitalId / hospitalDeptId / doctorId / doctorName / doctorPhone` 属于 `hospital_doctor` 分组，修改时会触发联动校验（`validateAndFillForModify`），自动填充关联冗余字段。

**ModifyItem 结构**（用于 `items` 列表）：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| orderItemId | Long | 否 | 已有项目ID；**`null` = 新增**；未出现在列表中的旧项目 = **自动删除** |
| fields | List\<ModifyField\> | 是 | 该项目的字段列表 |

**14.3 item 内可用字段**（`items[].fields[].field` 取值范围）：

| field | label | 类型说明 |
|-------|-------|----------|
| bodyPartId | 部位 | Long |
| projectId | 重建项目 | Long |
| projectDesc | 项目说明 | String |
| formingRequirement | 成形需求 | String |
| otherRequirement | 其他要求 | String |

**请求示例**：

场景一：只修改基础信息（申请类型包含 14.1）
```json
PUT /order/modify/execute/1008
Content-Type: application/json

{
    "infoFields": [
        {"field": "patientAge", "value": 45},
        {"field": "expectedDeliveryDate", "value": "2026-05-01T00:00:00"}
    ]
}
```

场景二：只替换影像文件（申请类型包含 14.2）
```json
PUT /order/modify/execute/1009
Content-Type: application/json

{
    "imageDataFileIds": ["FILE001", "FILE002"],
    "imageReportFileIds": []
}
```

场景三：只修改重建项目（申请类型包含 14.3）
```json
PUT /order/modify/execute/1010
Content-Type: application/json

{
    "items": [
        {
            "orderItemId": 2001,
            "fields": [
                {"field": "projectDesc", "value": "更新后的项目说明"}
            ]
        },
        {
            "orderItemId": null,
            "fields": [
                {"field": "bodyPartId", "value": 11},
                {"field": "projectId", "value": 6}
            ]
        }
    ]
}
```

场景四：混合申请（申请类型同时包含 14.1 + 14.3）
```json
PUT /order/modify/execute/1011
Content-Type: application/json

{
    "infoFields": [
        {"field": "patientName", "value": "张三（更新）"}
    ],
    "items": [
        {
            "orderItemId": 2001,
            "fields": [
                {"field": "bodyPartId", "value": 10},
                {"field": "projectId", "value": 5}
            ]
        }
    ]
}
```

**响应**：`Result<Void>`，`code=200` 表示执行成功。

**错误码**：

| 错误码 | 说明 |
|--------|------|
| 675 | 订单不存在 |
| 701 | 申请不存在 |
| 717 | 申请未审核通过，不可执行修改 |
| 718 | 申请已执行，禁止重复执行（幂等保护） |
| 730 | 重建项目不能为空（执行 14.3 修改且 items 字段缺失） |

## 订单修改申请前端使用指南

### 概述

订单修改申请功能允许业务员在订单提交后（phase=10 订单阶段，或 phase=20 设计阶段）对特定字段发起修改，需经管理员审核通过后方可执行实际修改。

### 涉及角色

| 角色 | 权限 |
|------|------|
| 业务员（操作员） | 发起申请、撤回申请、查看自己的申请、执行修改 |
| 管理员 | 审核申请（同意/拒绝）、查看所有待审核申请 |

### 申请类型说明

| 字典编码 | 中文名 | 可修改内容 | 可用阶段 |
|----------|--------|-----------|---------|
| 14.1 | 基础信息 | 患者姓名/年龄/性别、医生信息、医院、邮寄信息、期望交付时间 | 订单阶段（phase=10）仅 |
| 14.2 | 影像文件 | 影像数据文件列表、影像报告文件列表（整体替换） | 订单阶段（phase=10）仅 |
| 14.3 | 重建项目 | 新增/更新订单明细（部位、重建项目等） | 订单阶段 + 设计阶段 |

### 订单列表角标

订单列表接口（19.7）返回的每条记录包含以下角标字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| pendingModifyApplyStatus | String | 角标状态（null=无申请，PENDING=待审核，APPROVED=已同意待执行） |
| pendingModifyApplyId | Long | 有申请时的申请ID（用于跳转到申请详情页） |

**前端展示建议**：
- `PENDING`（待审核）：显示橙色角标，文字"审核中"
- `APPROVED`（已同意待执行）：显示绿色角标，文字"待执行"，并提示业务员尽快执行修改

### 业务员操作流程

```
[订单列表] 查看角标状态
    ↓ 无角标时，进入订单详情页
[订单详情页]
    ↓ 调用 GET /order/modify/{orderId}/applicable-types
    ↓ 检查 allowedTypes 是否非空
如果 reason=PENDING_EXISTS → 提示"已有待审核申请"，
    用 pendingApplyId 跳转查看申请详情 (GET /order/modify/apply/{applyId})
如果 reason=PHASE_NOT_ALLOWED → 提示"当前阶段不支持修改申请"
如果 allowedTypes 非空 → 显示"发起修改申请"按钮，展示可选类型
    ↓
[发起申请] POST /order/modify/{orderId}/apply
    { applyTypes: "14.1,14.3", applyReason: "..." }
    ↓
等待管理员审核（期间订单列表显示 PENDING 角标）
    ↓ 收到通知（审核同意）
[执行修改] PUT /order/modify/execute/{applyId}
    { 修改字段... }
    ↓
修改完成，留痕记录可在 POST /order/modify/{orderId}/logs 查看
```

### 管理员审核流程

```
[待审核列表] POST /order/modify/apply/pending
    ↓ 查看申请列表，点击某条进入详情
[申请详情] GET /order/modify/apply/{applyId}
    查看申请类型、申请原因、当前订单阶段/状态
    ↓
[审核] PUT /order/modify/apply/{applyId}/audit
    { action: "APPROVE" } 或 { action: "REJECT", rejectReason: "..." }
```

### 重要说明

1. **一个订单同一时间只能有一个 PENDING 申请**：发起新申请前，旧申请必须已审核或已撤回。
2. **执行修改幂等保护**：同一申请只能执行一次（COMPLETED 状态），重复调用返回 718 错误。
3. **字段范围校验**：执行修改时，传入的字段必须在申请类型允许的范围内（如申请了14.1，则不能修改 items 字段）。
4. **设计阶段限制**：phase=20（设计阶段）只允许申请 14.3 重建项目类型，不可申请 14.1/14.2。
