## 草稿接口

### 19.1 分页查询我的草稿列表

**接口地址**：`POST /order/draft/list`

**是否需要认证**：是

**接口说明**：分页查询当前登录用户的草稿列表，仅返回未提交的草稿（已提交草稿不展示）。

**请求参数**（JSON Body）：

| 参数名 | 类型 | 必填 | 说明 | 默认值 |
|--------|------|------|------|--------|
| pageNum | Integer | 否 | 页码 | 1 |
| pageSize | Integer | 否 | 每页条数 | 10 |
| hospitalId | Long | 否 | 医院ID（筛选条件） | - |
| status | Integer | 否 | 草稿状态：1-有效，3-已过期 | - |

**请求示例**：
```json
POST /order/draft/list
Content-Type: application/json
Authorization: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx

{
    "pageNum": 1,
    "pageSize": 10
}
```

**响应参数**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| code | Integer | 状态码，200表示成功 |
| message | String | 响应消息 |
| data | Object | 分页数据 |
| data.current | Long | 当前页码 |
| data.size | Long | 每页条数 |
| data.total | Long | 总记录数 |
| data.records | Array | 草稿列表 |
| data.records[].id | Long | 草稿ID |
| data.records[].orderType | Integer | 订单类型：1-医疗器械，2-非医疗器械 |
| data.records[].orderTypeName | String | 订单类型名称 |
| data.records[].needsPhysicalDelivery | Integer | 是否需要实体交付：0-否，1-是 |
| data.records[].businessType | String | 业务类型（dict_code，如 "11.1"） |
| data.records[].orgName | String | 提单机构名称 |
| data.records[].hospitalId | Long | 医院ID |
| data.records[].hospitalName | String | 医院名称 |
| data.records[].patientName | String | 患者姓名 |
| data.records[].status | Integer | 草稿状态：1-有效，2-已提交，3-已过期 |
| data.records[].statusName | String | 草稿状态名称 |
| data.records[].itemCount | Integer | 重建项目数量 |
| data.records[].expiresAt | String | 过期时间（yyyy-MM-dd HH:mm:ss） |
| data.records[].createTime | String | 创建时间 |

**响应示例**：
```json
{
    "code": 200,
    "message": "操作成功",
    "timestamp": 1744000000000,
    "data": {
        "current": 1,
        "size": 10,
        "total": 2,
        "records": [
            {
                "id": 100,
                "orderType": 1,
                "orderTypeName": "医疗器械",
                "needsPhysicalDelivery": 1,
                "businessType": "11.1",
                "orgName": "XX医疗科技有限公司",
                "hospitalId": 5,
                "hospitalName": "北京协和医院",
                "patientName": "张三",
                "status": 1,
                "statusName": "有效",
                "itemCount": 2,
                "expiresAt": "2026-05-07 10:00:00",
                "createTime": "2026-04-07 10:00:00"
```

### 19.3 创建或更新草稿

**接口地址**：`POST /order/draft`

**是否需要认证**：是

**接口说明**：创建新草稿或更新已有草稿。传入 `id` 字段时为更新，不传则为新增。草稿默认30天后过期（可通过系统配置 `order.draft.expire.days` 调整）。

**请求参数**（JSON Body）：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | Long | 否 | 草稿ID，更新时传入 |
| orderType | Integer | 是 | 订单类型：1-医疗器械，2-非医疗器械 |
| needsPhysicalDelivery | Integer | 是 | 是否需要实体交付：0-不需要，1-需要 |
| businessType | String | 是 | 业务类型（dict_code：11.1-业务，11.2-测试，11.3-试用，11.4-代理） |
| orgId | Long | 是 | 提单机构ID |
| orgName | String | 否 | 提单机构名称 |
| operatorName | String | 否 | 操作员姓名 |
| operatorPhone | String | 否 | 操作员电话（格式：1[3-9]xxxxxxxxx） |
| hospitalId | Long | 是 | 医院ID |
| hospitalName | String | 否 | 医院名称 |
| deptId | Long | 否 | 科室ID |
| deptName | String | 否 | 科室名称 |
| doctorId | Long | 否 | 医生ID（有则自动填充医生信息） |
| doctorName | String | 否 | 医生姓名（doctorId为空时可填，系统自动创建医生记录） |
| doctorPhone | String | 否 | 医生电话（格式：1[3-9]xxxxxxxxx） |
| patientName | String | 是 | 患者姓名 |
| patientAge | Integer | 否 | 患者年龄（0~150） |
| patientGender | String | 否 | 患者性别（dict_code：12.1-男，12.2-女） |
| isUrgent | Integer | 否 | 是否加急：0-否，1-是 |
| isPostal | Integer | 否 | 是否邮寄：0-否，1-是 |
| postalAddress | String | 否 | 邮寄地址 |
| expectedDeliveryDate | String | 否 | 期望交付时间（yyyy-MM-dd HH:mm:ss） |
| items | Array | 否 | 重建项目明细列表（草稿模式可为空） |
| items[].bodyPartId | Long | 否 | 部位ID |
| items[].bodyPartName | String | 否 | 部位名称 |
| items[].projectId | Long | 否 | 重建项目ID |
| items[].projectName | String | 否 | 重建项目名称 |
| items[].projectEstimatedHours | Number | 否 | 预计耗时（小时） |
| items[].projectDesc | String | 否 | 项目说明 |
| items[].formingRequirement | String | 否 | 成形需求 |
| items[].otherRequirement | String | 否 | 其他要求 |
| items[].sortOrder | Integer | 否 | 排序序号（未填则自动赋值） |

**请求示例**：
```json
POST /order/draft
Content-Type: application/json
Authorization: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx

{
    "orderType": 1,
    "needsPhysicalDelivery": 1,
    "businessType": "11.1",
    "orgId": 2,
    "hospitalId": 5,
    "patientName": "张三",
    "patientAge": 45,
    "patientGender": "12.1",
    "items": [
        {
            "bodyPartId": 3,
            "projectId": 15,
            "formingRequirement": "钛合金",
            "sortOrder": 1
        }
    ]
}
```

**响应参数**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| data | Long | 草稿ID |

**响应示例**：
```json
{
    "code": 200,
    "message": "操作成功",
    "timestamp": 1744000000000,
    "data": 100
}
```

**错误码**：

| 错误码 | 说明 |
|--------|------|
| 676 | 草稿不存在（更新时） |
| 679 | 只能修改自己的草稿 |
| 680 | 草稿已提交，不能修改 |

### 19.5 提交草稿转正式订单(x)

**接口地址**：`POST /order/draft/{id}/submit`

**是否需要认证**：是

**接口说明**：将草稿提交为正式订单。提交前会进行严格校验（机构、医院、患者、明细必填；若系统配置要求则影像文件也必填）。提交成功后草稿状态变为"已提交"，不可再修改。

**路径参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | Long | 是 | 草稿ID |

**请求示例**：
```
POST /order/draft/100/submit
Authorization: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

**响应参数**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| data | Long | 新创建的订单ID |

**响应示例**：
```json
{
    "code": 200,
    "message": "操作成功",
    "timestamp": 1744000000000,
    "data": 1001
}
```

**错误码**：

| 错误码 | 说明 |
|--------|------|
| 676 | 草稿不存在 |
| 679 | 只能提交自己的草稿 |
| 680 | 草稿已提交 |
| 681 | 订单明细不能为空 |
| 682 | 影像文件不能为空（系统配置开启时） |
| 682 | 免费业务审批文件不能为空（业务类型为测试/试用时） |

## 订单接口

### 19.6 直接创建订单（直提）

**接口地址**：`POST /order`

**是否需要认证**：是

**接口说明**：直接创建正式订单，跳过草稿步骤。适用于业务员信息填写完整时的快捷提交场景。与草稿提交的区别在于：影像文件通过 `imageDataFileIds`/`imageReportFileIds` 直接传入（文件需提前上传至文件服务）。

**请求参数**（JSON Body）：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| orderType | Integer | 是 | 订单类型：1-医疗器械，2-非医疗器械 |
| needsPhysicalDelivery | Integer | 是 | 是否需要实体交付：0-不需要，1-需要 |
| businessType | String | 是 | 业务类型（dict_code：11.1/11.2/11.3/11.4） |
| orgId | Long | 是 | 提单机构ID |
| orgName | String | 否 | 提单机构名称 |
| operatorName | String | 否 | 操作员姓名 |
| operatorPhone | String | 否 | 操作员电话 |
| hospitalId | Long | 是 | 医院ID |
| hospitalName | String | 否 | 医院名称 |
| deptId | Long | 否 | 科室ID |
| deptName | String | 否 | 科室名称 |
| doctorId | Long | 否 | 医生ID |
| doctorName | String | 否 | 医生姓名 |
| doctorPhone | String | 否 | 医生电话 |
| patientName | String | 是 | 患者姓名 |
| patientAge | Integer | 否 | 患者年龄（0~150） |
| patientGender | String | 否 | 患者性别（dict_code：12.1-男，12.2-女） |
| isUrgent | Integer | 否 | 是否加急：0-否，1-是 |
| isPostal | Integer | 否 | 是否邮寄：0-否，1-是 |
| postalAddress | String | 否 | 邮寄地址 |
| expectedDeliveryDate | String | 否 | 期望交付时间 |
| items | Array | 是 | 重建项目明细列表（至少1条） |
| items[].bodyPartId | Long | 是 | 部位ID |
| items[].projectId | Long | 是 | 重建项目ID |
| items[].projectEstimatedHours | Number | 否 | 预计耗时（小时） |
| items[].projectDesc | String | 否 | 项目说明 |
| items[].formingRequirement | String | 否 | 成形需求 |
| items[].otherRequirement | String | 否 | 其他要求 |
| items[].sortOrder | Integer | 否 | 排序序号 |
| imageDataFileIds | Array | 否 | 影像数据文件ID列表（CT/MRI等，dict_code=10.1） |
| imageReportFileIds | Array | 否 | 影像报告文件ID列表（dict_code=10.2） |
| approvalFileIds | Array | 否 | 免费业务审批文件ID列表（dict_code=10.20，业务类型为测试/试用时提交时必填） |

**请求示例**：
```json
POST /order
Content-Type: application/json
Authorization: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

**路径参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | Long | 是 | 订单ID |

```
POST /order/1001/resubmit
Authorization: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

### 经典案例处理流程说明

#### 1. 标记流程

```
前端发起标记请求
    ↓
校验订单状态（必须phase=80已完成）
    ↓
校验是否已标记（防止重复标记）
    ↓
更新订单字段（is_classic_case=1，记录标记时间、人、备注）
    ↓
发布ClassicCaseMarkedEvent事件
    ↓
三个监听器同步执行文件迁移：
  - OrderClassicCaseFileListener（order_file表文件）
  - DesignClassicCaseFileListener（设计阶段文件）
  - ProductionClassicCaseFileListener（生产阶段文件）
    ↓
所有文件迁移成功 → 返回成功
任一文件迁移失败 → 事务回滚 → 返回失败
```

#### 2. 文件迁移机制

**迁移方式**：同步执行（非异步），保证操作原子性

**迁移范围**：
- Order模块：order_file表关联的所有文件
- Design模块：设计数据包、STL模型、设计报告、指令单、图纸等
- Production模块：生产相关文件

**迁移路径**：
- 原路径：各业务目录（如 `package_file/202606/xxx.stl`）
- 新路径：`classic-cases/{orderCode}/{filename}`

**操作细节**：
- 使用x-file-storage框架的move()方法
- 先保存新文件记录 → 删除旧文件记录
- 迁移失败自动回滚

#### 3. 数据保护机制

**应用层保护**：
- 所有文件上传/删除操作前调用`checkNotClassicCase()`方法
- 检查订单的is_classic_case字段，若为1则抛出异常

**数据库层保护**：
- 数据库触发器：`prevent_delete_classic_case_stl`
- 拦截file_detail表的逻辑删除操作
- 保护条件：ext='stl' AND path LIKE '%classic-cases/%'
- 抛出SQL错误阻止删除

**保护范围**：
- 订单主表数据
- 订单明细数据
- 所有关联文件（重点保护STL模型）

#### 4. 注意事项

1. **订单状态要求**：只能标记phase=80（已完成）的订单
2. **不可重复标记**：已标记的订单不允许再次标记
3. **操作不可逆**：标记后无法取消（数据永久保护）
4. **文件路径变更**：标记后文件URL会改变，前端需重新获取
5. **响应时间**：文件迁移可能需要几秒到十几秒，前端应显示加载状态
6. **Design和Production模块**：也需移除监听器的@Async注解，确保同步执行
