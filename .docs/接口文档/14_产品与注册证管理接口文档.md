## 产品管理

> **数据模型说明**：产品采用「产品 + 规格」两层结构。产品按大类管理（如骨模型、导板），规格独立维护并关联注册证。

### 14.1 分页查询产品列表

**接口地址**：`POST /basic/product/page`

**是否需要认证**：是

**接口说明**：分页查询产品列表，支持按产品名称、分类、状态等条件筛选。

**请求参数**（JSON Body）：

| 参数名 | 类型 | 必填 | 说明 | 默认值 |
|--------|------|------|------|--------|
| pageNum | Integer | 否 | 页码 | 1 |
| pageSize | Integer | 否 | 每页条数 | 10 |
| productName | String | 否 | 产品名称（模糊查询） | - |
| category | String | 否 | 产品大类 dict_code（精确匹配） | - |
| status | Integer | 否 | 状态（0=禁用，1=正常） | - |

**请求示例**：
```json
POST /basic/product/page
Content-Type: application/json
Authorization: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx

{
    "pageNum": 1,
    "pageSize": 10,
    "productName": "骨模型",
    "status": 1
}
```

**响应示例**：
```json
{
    "code": 200,
    "message": "操作成功",
    "timestamp": 1740700800000,
    "data": {
        "records": [
            {
                "id": 1,
                "productName": "PEEK骨模型",
                "category": "17.1",
                "categoryName": "模型类",
                "status": 1,
                "statusName": "正常",
                "remark": "PEEK材料骨模型",
                "createTime": "2026-04-15 10:00:00",
                "createBy": 1
            }
        ],
        "total": 1,
        "size": 10,
        "current": 1,
        "pages": 1
    }
}
```

### 14.4 创建产品

**接口地址**：`POST /basic/product`

**是否需要认证**：是

**接口说明**：创建新产品。产品名称全局唯一。**注意：若提供 `category`，则 `categoryName` 也必须提供**（模块架构约束，basic 模块无法依赖 system 模块的字典服务）。

**请求参数**（JSON Body）：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| productName | String | 是 | 产品名称 |
| category | String | 否 | 产品大类 dict_code |
| categoryName | String | 条件必填 | 大类名称（若提供 category 则必填） |
| remark | String | 否 | 备注 |

**请求示例**：
```json
POST /basic/product
Content-Type: application/json
Authorization: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx

{
    "productName": "PEEK骨模型",
    "category": "17.1",
    "categoryName": "模型类",
    "remark": "PEEK材料骨模型"
}
```

**响应示例**：
```json
{
    "code": 200,
    "message": "操作成功",
    "timestamp": 1740700800000,
    "data": null
}
```

**错误码**：

| 错误码 | 说明 |
|--------|------|
| 400 | 产品名称不能为空 |
| 410 | 缺少参数：产品类型名称（提供 category 时必须同时提供 categoryName） |
| 649 | 产品名称已存在 |

### 14.8 创建产品规格

**接口地址**：`POST /basic/product/{id}/spec`

**是否需要认证**：是

**接口说明**：在指定产品下创建规格。同一产品下规格名称唯一。

**路径参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | Long | 是 | 产品ID |

**请求参数**（JSON Body）：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| specName | String | 是 | 规格名称 |
| certId | Long | 否 | 关联注册证ID |
| certNo | String | 否 | 注册证号（冗余） |
| sort | Integer | 否 | 排序（默认0） |
| status | Integer | 否 | 状态（默认1=正常） |
| remark | String | 否 | 备注 |

**请求示例**：
```json
POST /basic/product/1/spec
Content-Type: application/json
Authorization: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx

{
    "specName": "47mm",
    "certId": 100,
    "certNo": "GZZJ-2026-0001",
    "sort": 1
}
```

**响应示例**：
```json
{
    "code": 200,
    "message": "操作成功",
    "timestamp": 1740700800000,
    "data": null
}
```

**错误码**：

| 错误码 | 说明 |
|--------|------|
| 648 | 产品不存在 |
| 743 | 同一产品下规格名称已存在 |

## 业务说明

### 产品与规格关系

产品采用**两层结构**：
- **产品（Product）**：按大类管理，如「骨模型」「导板」
- **规格（ProductSpec）**：每个产品下可有多条规格，每条规格独立关联注册证

**级联关系**：
```
选择产品 → 过滤规格列表（只显示该产品下的规格）
选择规格 → 自动带出注册证号
```

### 删除约束

- **产品删除**：产品下存在规格时拒绝删除（错误码 741）
- **规格删除**：规格被打印信息（design_product 表）引用时拒绝删除（错误码 744）

### 产品分类

产品分类（category）使用字典管理（dict_type_code=17），存储 dict_code（如 17.1）。
