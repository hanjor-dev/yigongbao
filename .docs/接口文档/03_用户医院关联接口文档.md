### 3.2 分配用户医院范围（覆盖式）

**接口地址**：`PUT /system/user/{userId}/hospitals`

**是否需要认证**：是

**接口说明**：为指定用户分配可访问的医院范围。采用覆盖式更新，传入的医院ID列表将完全替换原有的分配。

**路径参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| userId | Long | 是 | 用户ID |

**请求参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| hospitalIds | Array | 是 | 医院ID列表（覆盖式） |

**请求示例**：
```json
{
    "hospitalIds": [1, 2, 3, 5]
}
```

**响应参数**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| code | Integer | 状态码，200表示成功 |
| message | String | 响应消息 |
| timestamp | Long | 时间戳 |
| data | null | 无数据返回 |

**响应示例**：
```json
{
    "code": 200,
    "message": "操作成功",
    "timestamp": 1740700800000,
    "data": null
}
```

**业务说明**：
- 此接口为覆盖式更新，传入空数组将清空用户的所有医院分配
- 建议在调用此接口前先调用"获取可分配医院列表"接口，让管理员选择

## 业务说明

### 医院范围权限机制

1. **角色级别**：角色的 `hospitalScopeEnabled` 字段控制是否启用医院范围限制
2. **用户级别**：每个用户可分配不同的医院访问权限
3. **数据隔离**：启用医院范围后，用户只能操作被分配的医院数据

### 权限校验流程

1. 管理员A（有多家医院权限）可以为用户B分配任何一家或多家的医院
2. 用户B登录后只能看到被分配的医院
3. 用户B创建订单时，只能选择被分配的医院

### 典型使用场景

1. **业务员管理**：为业务员分配其负责的医院范围
2. **订单创建**：用户创建订单时，只能从自己有权限的医院中选择
3. **模板分配**：使用模板快速为用户分配一组医院
