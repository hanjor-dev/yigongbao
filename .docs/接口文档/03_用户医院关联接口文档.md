# 03_用户医院关联接口文档

## 基本信息

| 项目 | 说明 |
|------|------|
| 所属模块 | system（系统管理） |
| Controller | UserHospitalController、HospitalScopeController |
| 请求前缀 | /system/user/{userId}/hospitals、/system/hospital-scope |
| 认证要求 | 需要登录认证 |

> **重要说明**：系统中"医院"不再是独立实体，而是 `sys_org` 表中 `orgType="1.3"` 的机构记录。所有接口中的 `hospitalId` 均引用 `sys_org.id`（其中 `orgType=1.3`），响应字段使用机构字段名（`orgName`、`orgCode` 等）。

### 3.1 查询用户已分配的医院列表

**接口地址**：`GET /system/user/{userId}/hospitals`

**是否需要认证**：是

**路径参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| userId | Long | 是 | 用户ID |

**请求示例**：
```http
GET /system/user/1/hospitals
Authorization: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

**响应参数**：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| code | Integer | 状态码，200表示成功 |

| data | Array | 医院（机构）列表，见 OrgVO 结构 |

### 3.2 分配用户医院范围（覆盖式）

**接口地址**：`PUT /system/user/{userId}/hospitals`

**是否需要认证**：是

**接口说明**：为指定用户分配可访问的医院范围。采用覆盖式更新，传入的 `hospitalIds` 列表将完全替换原有分配。`hospitalIds` 中的每个值均为 `sys_org.id`（`orgType=1.3`）。

**路径参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| userId | Long | 是 | 用户ID |

**请求参数（JSON Body）**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| hospitalIds | List\<Long\> | 是 | 医院ID列表，值为 sys_org.id（orgType=1.3），覆盖式更新 |

**请求示例**：
```json
{
    "hospitalIds": [1, 2, 3, 5]
}
```

**响应示例**：
```json
{
    "code": 200,
    "message": "操作成功",
    "timestamp": 1740700800000,
    "data": null
}
```

**业务说明**：
- 覆盖式更新，传入空数组将清空用户的所有医院分配
- 建议调用前先通过 3.3 接口获取可分配医院列表供管理员选择

**接口地址**：`GET /system/user/{userId}/hospitals/template/{templateId}`

**是否需要认证**：是

**接口说明**：预览指定模板内预设的医院列表。管理员选择模板后可预览内容，并可基于此列表微调后提交分配。

**路径参数**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| userId | Long | 是 | 用户ID（保持路由一致性） |
| templateId | Long | 是 | 模板ID |

**请求示例**：
```http
GET /system/user/1/hospitals/template/10
```

## 业务说明

### 医院概念说明

系统中"医院"不再是独立的数据表或模块，而是 `sys_org`（机构表）中 `orgType="1.3"` 的记录。`sys_user_hospital` 关联表中的 `hospitalId` 字段存储的是 `sys_org.id`。

### 医院范围权限机制

1. **角色级别**：角色的 `dataScopeType` 字段控制数据权限范围，值为 `"hospitals"` 时启用医院范围限制
2. **用户级别**：每个用户可通过 `sys_user_hospital` 表分配不同的医院访问权限
3. **数据隔离**：启用医院范围后，用户只能操作被分配的医院数据

### 权限校验流程

1. 管理员A（有多家医院权限）可为用户B分配任意一家或多家医院
2. 用户B登录后只能看到被分配的医院
3. 用户B创建订单时，只能选择被分配的医院

### 典型使用场景

1. **业务员管理**：为业务员分配其负责的医院范围
2. **订单创建**：用户创建订单时，只能从自己有权限的医院中选择
3. **模板分配**：使用模板快速为用户批量分配一组医院
