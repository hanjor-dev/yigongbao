# 加工中心与设备管理 — Apifox 全流程手动测试文档

> **适用工具**：Apifox（WebSocket 测试需使用 Apifox 的 WebSocket 功能）
> **服务地址**：`http://localhost:8080`
> **WebSocket 地址**：`ws://localhost:8080/api/basic/ws/device`
> **文档目的**：按测试流程逐步验证加工中心 CRUD、设备管理、WebSocket 推送、在线/离线状态管理的完整功能。
> **前置条件**：MySQL 8 运行于 localhost:3307，Redis 运行于 localhost:6379，应用以 dev profile 启动。

---

## 一、前置准备：登录鉴权

### 步骤 1：用户登录

| 项目 | 内容 |
|---|---|
| 方法 | POST |
| 路径 | `/api/system/auth/login` |
| Content-Type | `application/json` |

**请求体：**
```json
{
  "loginType": "PASSWORD",
  "username": "admin",
  "password": "Admin@123"
}
```

**操作：** 复制响应中的 `data.tokenValue`，在 Apifox 中设置为全局变量 `token`，后续所有 HTTP 请求 Header 中添加：
```
Authorization: {{token}}
```

> WebSocket 接口无需携带 token。

## 二、加工中心管理测试

### 场景 A：正常创建加工中心

#### 步骤 A-1：创建加工中心（北京）

| 项目 | 内容 |
|---|---|
| 方法 | POST |
| 路径 | `/api/basic/processing-center` |

**请求体：**
```json
{
  "centerCode": "BJ001",
  "centerName": "北京加工中心",
  "contactPerson": "张三",
  "contactPhone": "13800138000",
  "address": "北京市朝阳区xxx",
  "deviceIdRanges": "[{\"start\":\"P001\",\"end\":\"P099\"}]",
  "remark": "主要加工中心"
}
```

**预期响应：**
```json
{"code": 200, "message": "操作成功", "data": 1}
```

**操作：** 记录返回的 `data`（加工中心 ID），后续步骤使用。

## 四、WebSocket 设备状态推送测试

> **Apifox 操作**：新建请求 → 选择 WebSocket → URL 填入 `ws://localhost:8080/api/basic/ws/device` → Connect

---

### 场景 N：正常推送（加工中心存在）

**前置条件：** 数据库中存在名为"北京加工中心"且状态为启用的记录，`deviceIdRanges` 为 `[{"start":"P001","end":"P050"}]`（场景 E 更新后）。

**推送消息：**
```json
{
  "centerName": "北京加工中心",
  "devices": [
    {"id": "P001", "state": 0},
    {"id": "P010", "state": 1},
    {"id": "P050", "state": 0}
  ]
}
```

**预期服务端响应：**
```json
{"code": 200, "message": "success"}
```

**验证：** 查询数据库 `device` 表，P001、P010、P050 三条记录应存在（自动创建），`connection_status=1`，`last_heartbeat` 为当前时间。

---

### 场景 O：推送包含越界设备ID

**推送消息：**
```json
{
  "centerName": "北京加工中心",
  "devices": [
    {"id": "P001", "state": 0},
    {"id": "P099", "state": 1}
  ]
}
```

**说明：** P099 超出北京中心当前范围（P001~P050）。

**预期响应：** `code: 200`（P001 正常处理）。

**验证：** 数据库中 P099 不存在，服务端日志出现 WARN：`设备ID不在加工中心允许范围内，跳过: deviceId=P099`。

---

### 场景 P：推送到不存在的加工中心

**推送消息：**
```json
{
  "centerName": "不存在的中心",
  "devices": [
    {"id": "P001", "state": 0}
  ]
}
```

**预期服务端响应：**
```json
{"code": 404, "message": "加工中心不存在或已禁用"}
```

---

### 场景 Q：推送到已禁用的加工中心

**前置条件：** 先通过 PUT 接口将上海加工中心 `status` 改为 0（禁用）。

**推送消息：**
```json
{
  "centerName": "上海加工中心",
  "devices": [
    {"id": "P100", "state": 0}
  ]
}
```

**预期响应：**
```json
{"code": 404, "message": "加工中心不存在或已禁用"}
```

---

### 场景 R：连续推送模拟心跳（状态变更）

先推送 P001 为占用：
```json
{
  "centerName": "北京加工中心",
  "devices": [{"id": "P001", "state": 1}]
}
```

再推送 P001 为空闲：
```json
{
  "centerName": "北京加工中心",
  "devices": [{"id": "P001", "state": 0}]
}
```

**验证：** 查询 `device_state_log` 表，应有一条 `old_state=1, new_state=0, change_type=auto` 的变更记录。

---

### 场景 S：断开连接触发设备离线

**步骤：**
1. 建立 WebSocket 连接并推送一次（场景 N），确认 P001、P010、P050 的 `connection_status=1`
2. 在 Apifox 中点击 **Disconnect** 断开连接

**预期：** 数据库中北京加工中心下所有设备的 `connection_status` 变为 0（离线）。

**验证 SQL：**
```sql
SELECT device_id, connection_status FROM device WHERE center_id = 1;
```

## 七、测试流程总览

```
登录获取 Token
    ↓
创建北京加工中心（BJ001，P001~P099）
创建上海加工中心（SH001，P100~P199）
    ↓
验证重复编码 → 409
验证范围重叠 → 410
    ↓
手动创建 WASH_CONTAINER 设备
验证手动创建 PRINTER_SLA → 410
    ↓
WebSocket 连接
推送北京中心设备（P001/P010/P050）→ 自动创建，200
推送越界设备（P099）→ 跳过，日志 WARN
推送不存在中心 → 404
    ↓
连续推送验证状态变更日志
    ↓
断开 WebSocket → 设备自动离线
```
