## 三、第一阶段：字典管理

### 3.1 阶段目标

完成通用字典数据的管理能力建设，作为所有业务模块的基础数据支撑。

### 3.2 设计方案

#### 3.2.1 设计思路

采用**单表树形结构**设计，通过父级/子级关系实现层级结构，相比传统两表分离方案更灵活：

- **字典类型** = 根节点（parent_id = 0）
- **字典数据** = 根节点的子节点
- **支持多级** = 可扩展任意层级

#### 3.2.2 表结构设计

```sql
-- 字典表（单表树形结构）
-- 编码规则：根节点=1/2/3，子节点=1.1/1.2，二级子节点=1.1.1/1.1.2，以此类推
CREATE TABLE sys_dict (
    id              BIGINT          NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    parent_id       BIGINT          DEFAULT 0 COMMENT '父级ID（0表示根节点/字典类型）',
    dict_code       VARCHAR(32)      NOT NULL COMMENT '字典编码（层级数字，如：1、1.1、1.1.1）',
    dict_name       VARCHAR(128)    NOT NULL COMMENT '字典名称',
    dict_value      VARCHAR(256)    DEFAULT NULL COMMENT '字典值（叶子节点使用）',
    level           INT             DEFAULT 1 COMMENT '层级（1=字典类型，2=字典数据，3+=扩展层级）',
    sort            INT             DEFAULT 0 COMMENT '排序（同级内排序）',
    status          TINYINT         DEFAULT 1 COMMENT '状态（0=禁用，1=正常）',
    remark          VARCHAR(512)    DEFAULT NULL COMMENT '备注说明',

    -- 通用字段（继承 BaseEntity）
    create_time     DATETIME        DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time     DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    create_by       BIGINT          DEFAULT NULL COMMENT '创建人ID',
    update_by       BIGINT          DEFAULT NULL COMMENT '更新人ID',
    is_deleted      TINYINT         DEFAULT 0 COMMENT '是否删除（0=否，1=是）',

    PRIMARY KEY (id),
    UNIQUE KEY uk_dict_code (dict_code),
    KEY idx_parent_id (parent_id),
    KEY idx_level (level),
    KEY idx_is_deleted (is_deleted)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='字典表';
```

#### 3.3.3 统一下拉查询接口

为了统一前端下拉框/树形选择器的数据来源，提供统一的地区和字典下拉接口：

```java
// 树形结构（支持无限层级）
GET /api/system/select/tree
    ?type=area                    // 地区
    &parentId=0                  // 父级行政代码（0=省份）
    // 或
    ?type=dict                    // 字典
    &code=user_status             // 字典编码

// 下拉选项（叶子节点，用于表单选择）
GET /api/system/select/options
    ?type=area                    // 地区
    &parentId=330000              // 父级行政代码
    // 或
    ?type=dict                    // 字典
    &code=user_status             // 字典编码
```

**统一响应格式（SelectTreeVO）**：

```json
{
  "id": 1,
  "name": "浙江省",
  "value": "330000",
  "parentId": 0,
  "level": 1,
  "children": []
}
```

**接口说明**：

| 参数 | 说明 |
|------|------|
| type | 数据类型：area=地区、dict=字典 |
| parentId | 父级ID（地区传行政代码，字典传字典ID） |
| code | 字典编码（type=dict时必填） |

#### 4.2.1.4 业务逻辑设计

**机构编码自动生成规则**

```
1. 根据机构类型获取对应的编码前缀（从字典【机构编码前缀】查询）
   - 生产企业 -> ORG-P-
   - 经销商 -> ORG-D-
   - 医疗机构 -> ORG-H-
   - 其他 -> ORG-O-

2. 查询该前缀下最大的序号
   - 例如：ORG-P-001 -> maxSeq = 1

3. 生成新编码：新前缀 + (maxSeq + 1).toString().padLeft(3, '0')
   - 例如：ORG-P-002
```

**删除机构校验规则**

```
删除前检查该机构下是否有账户：
- 查询 sys_user 表中 org_id = 当前机构ID 的记录数
- 如果 > 0，则禁止删除，抛出业务异常
```

##### 4.2.2.3 业务逻辑设计

**部门编码自动生成规则**

```
1. 编码格式：DEPT-{序号}
2. 序号规则：使用3位数字，不足前面补0
   - 例如：DEPT-001, DEPT-002, ...
3. 生成逻辑：
   - 查询 sys_dept 表中最大的 dept_code
   - 解析序号 + 1
   - 格式化输出
```

**部门名称唯一性校验**

```
1. 同一机构下部门名称必须唯一
2. 校验逻辑：
   - 查询 sys_dept 表中 dept_name = 输入名称 AND org_id = 所属机构 AND is_deleted = 0
   - 如果存在，则抛出业务异常"该机构下已存在同名部门"
```

**删除部门校验规则**

```
删除前检查该部门下是否有账户：
- 查询 sys_user 表中 dept_id = 当前部门ID AND is_deleted = 0 的记录数
- 如果 > 0，则禁止删除，抛出业务异常"该部门下仍有用户，无法删除"
```

**停用部门业务规则**

```
1. 停用部门不影响已关联该部门的用户登录和使用
2. 创建/编辑用户时，已停用的部门不可被选择
3. 停用时更新 status = 0
```

##### 4.2.3.3 冗余字段设计

为避免 N+1 查询问题，用户表采用**冗余字段**设计：

| 冗余字段 | 来源表 | 说明 |
|---------|-------|------|
| org_name | sys_org.org_name | 所属机构名称 |
| dept_name | sys_dept.dept_name | 所属部门名称 |
| role_name | sys_role.role_name | 关联角色名称 |
| role_code | sys_role.role_code | 关联角色编码 |

**冗余字段维护时机**：
- **新增用户**：保存时根据 orgId/deptId/roleId 查询对应名称并存储
- **更新用户**：当 orgId/deptId/roleId 发生变化时，同步更新冗余字段
- **查询列表**：无需关联查询，直接返回冗余字段，大幅提升查询性能

##### 5.2.1.4 配置键枚举（SystemConfigKeyEnum）

为避免魔法值，定义 `SystemConfigKeyEnum` 枚举类集中管理配置键：

```java
package com.yigongbao.common.enums;

/**
 * 系统配置键枚举
 * 集中管理系统配置键名，避免魔法值和键名不一致问题
 *
 * @author hanjor
 * @date 2026-03-18
 */
@Getter
@AllArgsConstructor
public enum SystemConfigKeyEnum {

    // ==================== 安全配置 ====================
    /**
     * 默认密码
     * 新用户初始密码
     */
    DEFAULT_PASSWORD("default.password", "默认密码"),

    /**
     * 最大连续登录失败次数
     * 连续失败后锁定账号
     */
    LOGIN_MAX_FAILURES("login.max.failures", "最大连续登录失败次数"),

    /**
     * 登录锁定时长（分钟）
     * 自动解锁时间
     */
    LOGIN_LOCK_DURATION("login.lock.duration", "登录锁定时长"),

    /**
     * 短信发送间隔（秒）
     * 同一手机号发送间隔
     */
    SMS_SEND_INTERVAL("sms.send.interval", "短信发送间隔"),

    // ==================== 系统配置 ====================
    /**
     * 系统名称
     */
    SYSTEM_NAME("system.name", "系统名称"),

    /**
     * 文件上传最大大小（字节）
     */
    MAX_UPLOAD_SIZE("max.upload.size", "文件上传最大大小");

    /**
     * 配置键
     */
    private final String key;

    /**
     * 配置名称（用于日志和错误提示）
     */
    private final String name;
}
```

##### 5.2.1.5 业务代码中使用配置的方式

在业务代码中获取系统配置值有两种方式：

**方式一：使用枚举类（推荐）**

```java
/**
 * 用户 Service 实现类
 *
 * @author hanjor
 * @date 2026-03-14
 */
@Service
@RequiredArgsConstructor
@Slf4j
public class UserServiceImpl extends ServiceImpl<UserMapper, UserEntity> implements UserService {

    private final ConfigService configService;
    private final PasswordEncoder passwordEncoder;

    /**
     * 创建用户
     */
    @Override
    @Transactional(rollbackFor = Exception.class)
    public void createUser(CreateUserDTO dto) {
        // 从系统配置中获取默认密码
        String configPassword = configService.getConfigValue(SystemConfigKeyEnum.DEFAULT_PASSWORD.getKey());
        // 如果未配置，则使用默认值
        String rawPassword = StringUtils.isBlank(configPassword) ? "123456" : configPassword;
        // 加密密码
        entity.setPassword(passwordEncoder.encode(rawPassword));
        // ... 其他逻辑
    }
}
```

**方式二：直接使用字符串（不推荐）**

```java
// 不推荐：使用魔法值
String password = configService.getConfigValue("default.password");
```

> **推荐**：使用 `SystemConfigKeyEnum` 枚举类，可以获得更好的类型安全和代码提示。

##### 5.2.1.6 配置层级说明

项目中存在两套配置体系，适用于不同场景：

| 配置类型 | 定义位置 | 适用场景 | 示例 |
|---------|---------|---------|------|
| 静态配置 | `application.yml` / `@ConfigurationProperties` | 几乎不会变更的配置 | 数据库连接、Redis连接 |
| 动态配置 | `sys_config` 表 + `SystemConfigKeyEnum` | 需要动态调整的参数 | 默认密码、登录锁定次数、上传文件大小限制 |

**选择原则**：
- 大多数场景使用静态配置（启动时加载，性能好）
- 只有需要运行时动态调整的参数才使用动态配置（数据库查询，有性能开销）
