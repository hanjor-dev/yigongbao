## 三、数据权限验证

### 3.1 权限过滤机制

**核心原则**：所有数据权限过滤基于 `sys_role.data_scope_type`，不依赖账户类型或机构类型。

| 数据权限类型 | salesman（经销商） | salesman-self（自营） | 过滤逻辑 |
|-------------|-------------------|----------------------|---------|
| ALL | ❌ | ❌ | 全部可见 |
| ORG | ❌ | ❌ | 本机构 |
| DEPT | ❌ | ❌ | 本部门 |
| **HOSPITALS** | **✅** | **✅** | **关联医院** |
| SELF | ❌ | ❌ | 本人 |

**实现代码**：`OrderQueryHelper.buildDataScopeCondition()`

```java
if (scopeType == DataScopeTypeEnum.HOSPITALS) {
    // 查询用户关联的医院ID列表
    List<Long> hospitalIds = userHospitalService.getHospitalIdsByUserId(userId);
    // 过滤条件：order_main.hospital_id IN (...)
    wrapper.in(OrderMainEntity::getHospitalId, hospitalIds);
}
```

**结论**：salesman 和 salesman-self 数据权限类型相同，过滤逻辑完全一致，无需修改。

---

### 3.2 医院权限校验

**机制**：通过 `sys_org_hospital` 表维护机构与医院的关联关系。

| 机构类型 | 关联表 | 说明 |
|---------|-------|------|
| 经销商（1.2） | sys_org_hospital | 已有逻辑 |
| **服务商（1.4）** | **sys_org_hospital** | **需维护关联** |

**OrderDataValidator.validateHospitalScope()**

```java
// 查询用户关联的医院权限
List<Long> userHospitalIds = userHospitalService.getHospitalIdsByUserId(user.getId());
// 校验订单医院是否在权限范围内
if (!userHospitalIds.contains(order.getHospitalId())) {
    throw new BusinessException(HOSPITAL_NOT_IN_SCOPE);
}
```

**实现路径**：
```
user.org_id → sys_org_hospital.org_id → hospital_id
```

**服务商适配**：
- 前端：机构管理界面支持服务商关联医院
- 数据：服务商创建后维护 `sys_org_hospital` 关联
- 逻辑：无需代码修改，表结构已支持

## 五、架构兼容性分析

### 5.1 核心设计原则验证

**原则1：基于角色的权限控制（RBAC）**
- ✅ 所有权限判断基于 `sys_role.data_scope_type`
- ✅ 业务逻辑不直接判断账户类型或机构类型
- ✅ salesman-self 作为新角色，完全融入现有RBAC体系

**原则2：数据权限动态过滤**
- ✅ 查询条件基于 `data_scope_type` 动态构建
- ✅ 医院权限通过 `sys_org_hospital` 表维护
- ✅ 不存在硬编码的机构类型过滤

**原则3：业务规则配置化**
- ✅ 业务类型限制通过代码逻辑实现（可扩展）
- ✅ 机构-医院关联通过数据表维护（灵活）
- ✅ 角色-资源权限通过 `sys_role_resource` 配置

### 5.2 扩展性评估

**新增机构类型的通用流程**（以服务商为例验证）：
1. 新增字典项（`sys_dict`）→ ✅ 已实施
2. 新增角色（`sys_role`）→ ✅ 已实施
3. 配置角色权限（`sys_role_resource`）→ ✅ 已实施
4. 调整机构类型校验逻辑 → ✅ 已实施（部门、用户模块）
5. 业务模块适配 → ✅ 无需修改（架构自动兼容）

**结论**：现有架构设计良好，新机构类型扩展成本低，无需大规模重构。

### 6.2 运维建议

**服务商机构创建流程**：
1. 系统管理员创建服务商机构（机构类型选择"服务商"）
2. **必须**在机构管理界面维护"关联医院"（`sys_org_hospital`）
3. 创建企业部门并关联服务商机构（`sys_dept_org`）
4. 创建业务员（自营）用户，选择服务商关联的企业部门

**医院权限验证**：
```sql
-- 检查服务商是否维护医院关联
SELECT o.org_name, COUNT(oh.hospital_id) AS hospital_count
FROM sys_org o
LEFT JOIN sys_org_hospital oh ON o.id = oh.org_id AND oh.is_deleted = 0
WHERE o.org_type = '1.4' AND o.is_deleted = 0
GROUP BY o.id, o.org_name;
-- hospital_count = 0 表示未维护，需提醒管理员
```

### 6.3 监控建议

**关键指标**：
- 服务商创建后未维护医院关联的数量
- 业务员（自营）创建订单的业务类型分布
- 服务商订单占总订单比例

**异常检测**：
- 业务员（自营）尝试创建"测试"类型订单（应被拦截）
- 业务员（自营）创建订单时医院不在权限范围内
