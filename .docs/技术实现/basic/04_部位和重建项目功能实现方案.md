# 04_部位和重建项目功能实现方案

## 一、功能概述

### 1.1 模块定位

部位（BodyPart）和重建项目（RebuildProject）是医工宝系统中用于支撑 3D 重建业务的核心基础数据模块。它们共同构成了一套从"身体区域"到"具体重建项目"的标准化管理体系。

- **部位**：管理身体部位的树形结构（最多 2 级：身体区域 → 具体部位），用于将重建项目按身体维度进行归类。设计师编号字段用于自动匹配设计师。
- **重建项目**：管理重建项目的树形结构（部位 → 重建项目 → 子重建项目），每个项目包含标准价格、加急价格、预计耗时、成形需求模板等信息，是订单报价和工时统计的基础数据。

两者的核心价值在于：**建立标准化的重建业务字典体系，为 ERP 订单提供部位选择、项目定价、工时估算等基础支撑**。

### 1.2 核心设计决策

| # | 决策内容 | 说明 |
|---|---------|------|
| 1 | 部位层级限制 | 最多 2 级（身体区域 → 具体部位），避免层级过深 |
| 2 | 重建项目关联部位 | 项目通过 `body_part_id` 关联部位，一个项目归属于一个部位 |
| 3 | 重建项目层级 | 最多 2 级（重建项目 → 子重建项目），子项目继承父项目的部位 |
| 4 | 部位编码 | 系统自动生成，顶级格式 `BP_XXX`，子级格式 `BP_X_XXX` |
| 5 | 重建项目编码 | 系统自动生成，格式 `RP_{bodyPartId}_XXX`，子级继承父项目前缀 |
| 6 | 部位设计器编号 | 设计师编号字段（如 A/B/C）用于自动匹配设计师，非必填 |
| 7 | 删除逻辑 | 部位：检查是否有子部位；重建项目：检查是否有子项目 |
| 8 | 归属模块 | 位于 `basic/bodyPart` 和 `basic/rebuildProject`，作为基础数据供 ERP 模块引用 |

### 1.3 功能清单

#### 部位（BodyPart）

| 功能 | 说明 |
|------|------|
| 获取部位树形结构 | 查询所有部位，构建树形结构返回（不限状态） |
| 获取部位下拉选项 | 仅返回启用状态的部位，供前端 select 组件使用 |
| 查询部位详情 | 根据 ID 查询部位详细信息，包含父级名称 |
| 创建部位 | 自动生成编码，校验同级名称唯一性 |
| 更新部位 | 支持修改名称、设计师编号、排序、状态、备注 |
| 删除部位 | 检查是否有子部位，有子部位时禁止删除 |
| 修改部位状态 | 启用/停用切换（状态值 0/1） |

#### 重建项目（RebuildProject）

| 功能 | 说明 |
|------|------|
| 获取项目树形结构 | 查询所有项目，构建树形结构返回（不限状态），按部位分组展示，支持按分类筛选 |
| 根据部位ID获取项目 | 查询指定部位下的项目树，支持按分类筛选 |
| 获取项目下拉选项 | 按部位分组，仅返回启用状态的项目，支持按分类筛选 |
| 查询项目详情 | 根据 ID 查询项目详细信息，包含部位名称和父项目名称 |
| 创建项目 | 自动生成编码，校验部位存在性、同级名称唯一性 |
| 更新项目 | 支持修改名称、部位、层级、价格、耗时、模板等全部字段 |
| 删除项目 | 检查是否有子项目，有子项目时禁止删除 |
| 修改项目状态 | 启用/停用切换（状态值 0/1） |

## 二、数据库设计

### 2.1 表结构

#### 2.1.1 rebuild_body_part 重建部位表

```sql
CREATE TABLE rebuild_body_part (
    id              BIGINT          NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    parent_id       BIGINT          NOT NULL DEFAULT 0 COMMENT '父级ID（0=顶级身体区域）',
    name            VARCHAR(100)    NOT NULL COMMENT '部位名称',
    code            VARCHAR(50)     NOT NULL COMMENT '部位编码',
    level           INT             NOT NULL DEFAULT 1 COMMENT '层级（1=身体区域，2=具体部位）',
    designer_code   VARCHAR(10)     DEFAULT NULL COMMENT '设计师编号（如A/B/C）',
    sort            INT             NOT NULL DEFAULT 0 COMMENT '排序',
    status          TINYINT         DEFAULT 1 COMMENT '状态（0=禁用，1=正常）',
    remark          VARCHAR(512)    DEFAULT NULL COMMENT '备注说明',

    -- 通用字段
    create_time     DATETIME        DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time     DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    create_by       BIGINT          DEFAULT NULL COMMENT '创建人ID',
    update_by       BIGINT          DEFAULT NULL COMMENT '更新人ID',
    is_deleted      TINYINT         DEFAULT 0 COMMENT '是否删除（0=否，1=是）',

    PRIMARY KEY (id),
    UNIQUE KEY uk_body_part_code (code),
    KEY idx_body_part_parent_id (parent_id),
    KEY idx_body_part_level (level),
    KEY idx_body_part_status (status)
) COMMENT '重建部位表';
```

#### 2.1.2 rebuild_project 重建项目表

```sql
CREATE TABLE rebuild_project (
    id                    BIGINT          NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    body_part_id          BIGINT          NOT NULL COMMENT '关联部位ID（FK → rebuild_body_part.id）',
    parent_id             BIGINT          NOT NULL DEFAULT 0 COMMENT '父项目ID（0=顶级重建项目）',
    name                  VARCHAR(100)    NOT NULL COMMENT '项目名称',
    code                  VARCHAR(50)     NOT NULL COMMENT '项目编码',
    level                 INT             NOT NULL DEFAULT 1 COMMENT '层级（1=重建项目，2=子重建项目）',
    standard_price        DECIMAL(10,2)   DEFAULT NULL COMMENT '标准价格（元）',
    urgent_price          DECIMAL(10,2)   DEFAULT NULL COMMENT '加急价格（元）',
    category_code         VARCHAR(20)     DEFAULT NULL COMMENT '项目分类编码（字典 dict_code=13，如 13.1=模型）',
    category_name         VARCHAR(50)     DEFAULT NULL COMMENT '项目分类名称（冗余字段，与字典 dict_name 一致）',
    estimated_hours       DECIMAL(8,2)    DEFAULT NULL COMMENT '预计耗时（小时，支持小数）',
    description           TEXT            DEFAULT NULL COMMENT '项目说明模板',
    forming_requirements  TEXT            DEFAULT NULL COMMENT '成形需求模板',
    sort                  INT             NOT NULL DEFAULT 0 COMMENT '排序',
    status                TINYINT         DEFAULT 1 COMMENT '状态（0=禁用，1=正常）',
    remark                VARCHAR(500)    DEFAULT NULL COMMENT '备注说明',

    -- 通用字段
    create_time           DATETIME        DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time           DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    create_by             BIGINT          DEFAULT NULL COMMENT '创建人ID',
    update_by             BIGINT          DEFAULT NULL COMMENT '更新人ID',
    is_deleted            TINYINT         DEFAULT 0 COMMENT '是否删除（0=否，1=是）',

    PRIMARY KEY (id),
    UNIQUE KEY uk_project_code (code),
    KEY idx_project_body_part_id (body_part_id),
    KEY idx_project_parent_id (parent_id),
    KEY idx_project_level (level),
    KEY idx_project_status (status)
) COMMENT '重建项目表';
```

| 索引名 | 字段 | 类型 | 说明 |

### 2.4 外键关系

| 关系 | 字段 | 指向 | 说明 |
|------|------|------|------|
| 部位自关联 | parent_id | rebuild_body_part.id | 部位表自身层级关系，外键约束已省略保持灵活性 |

| 项目自关联 | parent_id | rebuild_project.id | 项目表自身层级关系，外键约束已省略保持灵活性 |

## 三、接口规范

### 3.1 API 路径

#### 部位接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/basic/body-part/tree` | 部位树形结构（不限状态） |
| GET | `/api/basic/body-part/options` | 部位下拉选项（仅启用状态） |
| GET | `/api/basic/body-part/{id}` | 部位详情 |

| POST | `/api/basic/rebuild-project` | 创建项目 |
| PUT | `/api/basic/rebuild-project/{id}` | 更新项目 |
| DELETE | `/api/basic/rebuild-project/{id}` | 删除项目 |
| PUT | `/api/basic/rebuild-project/{id}/status` | 修改状态 |

## 四、核心逻辑

### 4.1 部位编码生成规则

部位编码由系统自动生成，格式根据父级不同而变化：

```
生成逻辑：
1. 判断 parentId：
   - parentId = 0（顶级身体区域）：前缀为 "BP"
   - parentId > 0（有父级部位）：前缀为父级部位的 code（不含序号部分）
2. 查询当前最大编码（以该前缀 + "_" 开头）
3. 提取序号部分（如 BP_001 中的 "001"）
4. 序号 +1，格式化为 3 位补零字符串
5. 拼接生成新编码

示例：
- 顶级编码：BP_001 → BP_002 → BP_003 ...
- 子级编码：BP_001_001 → BP_001_002 → BP_001_003 ...
  （父级为 BP_001 时，子级前缀取父级 code 的 "BP_001" 部分）
```

### 4.2 重建项目编码生成规则

项目编码格式为 `RP_{bodyPartId}_{XXX}` 或继承父项目前缀：

```
生成逻辑：
1. 判断 parentId：
   - parentId = 0（顶级重建项目）：前缀为 "RP_{bodyPartId}"
   - parentId > 0（有父项目）：前缀为父项目的 code
2. 查询当前最大编码（以该前缀 + "_" 开头）
3. 提取序号部分（如 RP_1_001 中的 "001"）
4. 序号 +1，格式化为 3 位补零字符串
5. 拼接生成新编码

示例：
- 顶级编码：RP_1_001 → RP_1_002 → RP_1_003 ...
- 子级编码：RP_1_001_001 → RP_1_001_002 → RP_1_001_003 ...
  （父项目为 RP_1_001 时，子项目前缀取父项目 code 的 "RP_1_001" 部分）

特点：
- 顶级项目编码包含部位 ID（如 RP_1_XXX 表示归属于部位 1 的项目）
- 子级项目继承父项目完整前缀，形成层级编码体系
```

### 4.3 树形结构构建逻辑

#### 部位树形构建

```
buildTree(list) 逻辑：
1. 查询所有部位记录（不限状态），按 sort 升序、createTime 降序排列
2. 按 parentId 分组，建立 Map<Long, List<BodyPartVO>>
3. 遍历列表，将 children 设置为对应 parentId 的子节点列表
4. 筛选 parentId 为 0 或 null 的记录作为根节点返回
```

#### 重建项目树形构建

```
buildTree(list) 逻辑：
1. 查询所有项目记录（不限状态），按 sort 升序、createTime 降序排列
2. 按 parentId 分组，建立 Map<Long, List<RebuildProjectVO>>
3. 遍历列表，将 children 设置为对应 parentId 的子节点列表
4. 筛选 parentId 为 0 或 null 的记录作为根节点返回

buildOptionTree(voList, bodyPartNameMap) 逻辑（按部位分组）：
1. 按 bodyPartId 分组，建立 Map<Long, List<RebuildProjectVO>>
2. 遍历分组，每个分组构建一棵子树
3. 子树构建方式同上
4. 每个分组顶层节点作为 RebuildProjectOptionVO 的 children
```

### 4.4 分类筛选逻辑

```
buildQueryWrapper(bodyPartId, categoryCode) 查询条件构建：
1. bodyPartId 条件：非空时添加 eq 精确匹配条件
2. categoryCode 条件：非空时添加 eq 精确匹配条件（字典 dict_code=13，如 "13.1"）
3. 两个条件可以独立使用，也可以组合使用

说明：
- categoryCode 传入时为精确匹配（如 "13.1" 只匹配"模型"类项目）
- options 接口的分类筛选仅影响该项目本身，子项目不受父项目 categoryCode 影响
- tree 接口和 by-body-part 接口的分类筛选均为同一逻辑

重建项目分类字典（dict_code=13）：
- 13.1 = 模型
- 13.2 = 导板
- 13.3 = 假体
- 13.4 = 其他
```

### 4.5 唯一性校验

#### 部位名称校验

| 校验范围 | 说明 |
|---------|------|
| 同级唯一 | 同一部位下（相同 parentId），部位名称不能重复 |
| 跨级允许 | 不同父级下可以有相同名称（如两个不同的父级下都有"下颌骨"） |

#### 重建项目名称校验

| 校验范围 | 说明 |
|---------|------|
| 同级唯一 | 同一父项目下（相同 parentId），项目名称不能重复 |
| 跨级允许 | 不同父级下可以有相同名称 |

### 4.6 删除校验

#### 部位删除

```
removeBodyPart(id) 逻辑：
1. 查询部位是否存在，不存在则抛出异常
2. 调用 hasChildren(id) 检查是否有子部位
3. 若有子部位，抛出 DATA_HAS_CHILDREN 异常，禁止删除
4. 执行逻辑删除
```

#### 重建项目删除

```
removeProject(id) 逻辑：
1. 查询项目是否存在，不存在则抛出异常
2. 调用 hasChildren(id) 检查是否有子项目
3. 若有子项目，抛出 DATA_HAS_CHILDREN 异常，禁止删除
4. 执行逻辑删除
```

### 4.7 层级判断逻辑

#### 部位层级判断

```
创建部位时 level 设置逻辑：
- parentId = 0 → level = 1（身体区域）
- parentId > 0 → level = 2（具体部位）

系统限制：
- 不允许创建 3 级及以下层级（前端可控制）
- 2 级部位下不能创建子部位
```

#### 重建项目层级判断

```
创建项目时 level 设置逻辑：
- parentId = 0 → level = 1（重建项目）
- parentId > 0 → level = 2（子重建项目）

系统限制：
- 不允许创建 3 级及以下层级
- 2 级子项目下不能再创建子项目
```

### 5.3 业务场景说明

```
部位和重建项目在 ERP 订单中的典型使用场景：

1. 订单创建时，医生选择：
   - 部位：先选身体区域（如"颌面"），再选具体部位（如"下颌骨"）
   - 项目：根据选中的部位，筛选出该部位下的重建项目列表
   - 可按分类快速定位：如只显示"模型"或"导板"类项目
   - 项目详情：展示标准价格、加急价格、预计耗时

2. 订单报价时：
   - 根据选中的项目，获取 standardPrice 或 urgentPrice
   - 根据 estimatedHours 估算工时

3. 设计师匹配时：
   - 根据选中部位的 designerCode，自动匹配对应设计师

关键点：
- 部位为项目提供"归类维度"，便于按身体区域组织项目
- 项目为订单提供"计价维度"，每个项目有明确的价格和工时
- 两者均为只读基础数据，订单只引用不修改
```
