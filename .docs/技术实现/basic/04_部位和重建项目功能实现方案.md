# 04_部位和重建项目功能实现方案

## 一、功能概述

### 1.1 模块定位

部位（BodyPart）和重建项目（RebuildProject）是医工宝系统中用于支撑 3D 重建业务的核心基础数据模块。它们共同构成了一套从"具体部位"到"重建项目"的标准化管理体系。

- **部位**：管理身体部位的平级列表（每条记录即为一个具体部位，如"颅骨"、"颌面"、"颈椎"），名称全局唯一，用于将重建项目按身体维度进行归类。
- **重建项目**：管理重建项目的树形结构（重建项目 → 子重建项目），每个项目包含标准价格、加急价格、预计耗时、成形需求模板等信息，是订单报价和工时统计的基础数据。

两者的核心价值在于：**建立标准化的重建业务字典体系，为 ERP 订单提供部位选择、项目定价、工时估算等基础支撑**。

### 1.2 核心设计决策

| # | 决策内容 | 说明 |
|---|---------|------|
| 1 | 重建项目关联部位 | 项目通过 `body_part_id` 关联部位，一个项目归属于一个部位 |
| 2 | 重建项目层级 | 最多 2 级（重建项目 → 子重建项目），子项目继承父项目的部位 |
| 3 | 重建项目编码 | 系统自动生成，由 `CodeGeneratorService` 统一分配 |
| 4 | 部位名称唯一性 | 全局唯一，不限范围 |
| 5 | 删除逻辑 | 部位：直接删除；重建项目：检查是否有子项目 |
| 6 | 归属模块 | 位于 `basic/bodyPart` 和 `basic/rebuildProject`，作为基础数据供 ERP 模块引用 |

### 1.3 功能清单

#### 部位（BodyPart）

| 功能 | 说明 |
|------|------|
| 获取部位平级列表 | 查询所有部位，返回平级列表，按 sort 升序、createTime 降序 |
| 查询部位详情 | 根据 ID 查询部位详细信息 |
| 创建部位 | 自动生成编码，校验全局名称唯一性 |
| 更新部位 | 支持修改名称、排序、状态、备注 |
| 删除部位 | 逻辑删除，无子节点限制 |
| 修改部位状态 | 启用/停用切换（状态值 0/1） |

#### 重建项目（RebuildProject）

| 功能 | 说明 |
|------|------|
| 获取项目树形结构 | 查询所有项目，构建树形结构返回（不限状态），按部位分组展示，支持按分类筛选和名称关键字搜索 |
| 根据部位ID获取项目 | 查询指定部位下的项目树，支持按分类筛选和名称关键字搜索 |
| 获取完整部位-项目树形结构 | 三层嵌套（部位→项目→子项目），仅含有项目的部位，支持按部位过滤、按分类筛选和名称关键字搜索 |
| 查询项目详情 | 根据 ID 查询项目详细信息，包含部位名称和父项目名称 |
| 创建项目 | 自动生成编码，校验部位存在性、同级名称唯一性 |
| 更新项目 | 支持修改名称、部位、层级、价格、耗时、模板等全部字段 |
| 删除项目 | 检查是否有子项目，有子项目时禁止删除 |
| 修改项目状态 | 启用/停用切换（状态值 0/1） |

## 二、数据库设计

### 2.1 表结构

#### 2.1.1 rebuild_body_part 重建部位表

```sql
CREATE TABLE rebuild_body_part (
    id              BIGINT          NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    name            VARCHAR(100)    NOT NULL COMMENT '部位名称（全局唯一）',
    code            VARCHAR(50)     NOT NULL COMMENT '部位编码（系统自动生成）',
    sort            INT             NOT NULL DEFAULT 0 COMMENT '排序',
    status          TINYINT         DEFAULT 1 COMMENT '状态（0=禁用，1=正常）',
    remark          VARCHAR(512)    DEFAULT NULL COMMENT '备注说明',

    -- 通用字段
    create_time     DATETIME        DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time     DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    create_by       BIGINT          DEFAULT NULL COMMENT '创建人ID',
    update_by       BIGINT          DEFAULT NULL COMMENT '更新人ID',
    is_deleted      TINYINT         DEFAULT 0 COMMENT '是否删除（0=否，1=是）',

    PRIMARY KEY (id),
    KEY idx_body_part_status (status)
) COMMENT '重建部位表';

-- 函数唯一索引（MySQL 8.0+），支持逻辑删除后重建同名部位
CREATE UNIQUE INDEX uk_body_part_code
    ON rebuild_body_part ((CASE WHEN is_deleted = 0 THEN code ELSE NULL END));
```

#### 2.1.2 rebuild_project 重建项目表

```sql
CREATE TABLE rebuild_project (
    id                    BIGINT          NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    body_part_id          BIGINT          NOT NULL COMMENT '关联部位ID（FK → rebuild_body_part.id）',
    parent_id             BIGINT          NOT NULL DEFAULT 0 COMMENT '父项目ID（0=顶级重建项目）',
    name                  VARCHAR(100)    NOT NULL COMMENT '项目名称',
    code                  VARCHAR(50)     NOT NULL COMMENT '项目编码',
    level                 INT             NOT NULL DEFAULT 1 COMMENT '层级（1=重建项目，2=子重建项目）',
    standard_price        DECIMAL(10,2)   DEFAULT NULL COMMENT '标准价格（元）',
    urgent_price          DECIMAL(10,2)   DEFAULT NULL COMMENT '加急价格（元）',
    category_code         VARCHAR(20)     DEFAULT NULL COMMENT '项目分类编码（字典 dict_code=13，如 13.1=模型）',
    category_name         VARCHAR(50)     DEFAULT NULL COMMENT '项目分类名称（冗余字段，与字典 dict_name 一致）',
    estimated_hours       DECIMAL(8,2)    DEFAULT NULL COMMENT '预计耗时（小时，支持小数）',
    description           TEXT            DEFAULT NULL COMMENT '项目说明模板',
    forming_requirements  TEXT            DEFAULT NULL COMMENT '成形需求模板',
    sort                  INT             NOT NULL DEFAULT 0 COMMENT '排序',
    status                TINYINT         DEFAULT 1 COMMENT '状态（0=禁用，1=正常）',
    specialty             VARCHAR(64)     DEFAULT NULL COMMENT '专业方向字典编码（单值，如 7.1；关联 sys_dict；用于自动匹配设计师）',
    remark                VARCHAR(500)    DEFAULT NULL COMMENT '备注说明',

    -- 通用字段
    create_time           DATETIME        DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time           DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    create_by             BIGINT          DEFAULT NULL COMMENT '创建人ID',
    update_by             BIGINT          DEFAULT NULL COMMENT '更新人ID',
    is_deleted            TINYINT         DEFAULT 0 COMMENT '是否删除（0=否，1=是）',

    PRIMARY KEY (id),
    UNIQUE KEY uk_project_code (code),
    KEY idx_project_body_part_id (body_part_id),
    KEY idx_project_parent_id (parent_id),
    KEY idx_project_level (level),
    KEY idx_project_status (status)
) COMMENT '重建项目表';
```

## 四、核心逻辑

### 4.1 部位编码生成规则

部位编码由 `CodeGeneratorService` 自动生成，使用规则 key `CodeRuleConstants.BODYPART_NO`，格式为 `BP-XXXX`（如 `BP-0001`、`BP-0002`）。

### 4.2 重建项目编码生成规则

项目编码由 `CodeGeneratorService` 自动生成，使用规则 key `CodeRuleConstants.PROJECT_NO`，格式为 `RP-XXXX`（如 `RP-0001`、`RP-0002`）。

### 4.3 树形结构构建逻辑

#### 重建项目树形构建

```
buildTree(list) 逻辑：
1. 查询所有项目记录（不限状态），按 sort 升序、createTime 降序排列
2. 按 parentId 分组，建立 Map<Long, List<RebuildProjectVO>>
3. 遍历列表，将 children 设置为对应 parentId 的子节点列表
4. 筛选 parentId 为 0 或 null 的记录作为根节点返回
```

#### 完整部位-项目树形构建（listFullTree）

```
listFullTree(categoryCode, bodyPartId, keyword) 逻辑：
1. 查询所有启用部位（status=1），可按 bodyPartId 精确过滤，按 sort 升序
2. 查询所有启用项目（status=1），可按 categoryCode/keyword/bodyPartId 过滤，按 bodyPartId+sort 升序
   - keyword 非空时：SQL 添加 LIKE %keyword% 条件，只返回名称匹配的项目
3. 按 bodyPartId 将项目分组：Map<Long, List<RebuildProjectEntity>>
4. 为每个部位构建项目子树：
   a. 取该部位的项目列表，按 parentId 分组
   b. 构建 children 关系
   c. 筛选 parentId=0 的项目作为根节点
5. 仅当部位有根节点时，才生成 BodyPartProjectTreeVO 并加入结果
6. 整个过程仅 2 次数据库查询，按部位分组在内存中完成
```

### 4.4 分类筛选与关键字搜索逻辑

```
buildQueryWrapper(bodyPartId, categoryCode, keyword) 查询条件构建：
1. bodyPartId 条件：非空时添加 eq 精确匹配条件
2. categoryCode 条件：非空时添加 eq 精确匹配条件（字典 dict_code=13，如 "13.3"）
3. keyword 条件：非空时添加 LIKE %keyword% 模糊匹配条件（匹配项目 name 字段）
4. 三个条件可以独立使用，也可以任意组合

说明：
- categoryCode 传入时为精确匹配（如 "13.3" 只匹配"假体"类项目）
- keyword 传入时为模糊匹配，仅匹配项目本身名称，不做跨层级扩展
- full-tree 接口有 keyword 时，无匹配项目的部位不出现在结果中
- tree、by-body-part、full-tree 接口的筛选条件均由同一个 buildQueryWrapper 构建

重建项目分类字典（dict_code=13）：
- 13.1 = 模型
- 13.2 = 导板
- 13.3 = 假体
- 13.4 = 其他
```

### 4.5 唯一性校验

#### 部位名称校验

| 校验范围 | 说明 |
|---------|------|
| 全局唯一 | 整个部位表内名称不能重复（与父级无关） |

#### 重建项目名称校验

| 校验范围 | 说明 |
|---------|------|
| 同级唯一 | 同一父项目下（相同 parentId），项目名称不能重复 |
| 跨级允许 | 不同父级下可以有相同名称 |

### 4.6 删除校验

#### 部位删除

```
removeBodyPart(id) 逻辑：
1. 查询部位是否存在，不存在则抛出异常
2. 执行逻辑删除
```

#### 重建项目删除

```
removeProject(id) 逻辑：
1. 查询项目是否存在，不存在则抛出异常
2. 调用 hasChildren(id) 检查是否有子项目
3. 若有子项目，抛出 DATA_HAS_CHILDREN 异常，禁止删除
4. 执行逻辑删除
```

### 4.7 重建项目层级判断

```
创建项目时 level 设置逻辑：
- parentId = 0 → level = 1（重建项目）
- parentId > 0 → level = 2（子重建项目）

系统限制：
- 不允许创建 3 级及以下层级
- 2 级子项目下不能再创建子项目
```

### 5.3 业务场景说明

```
部位和重建项目在 ERP 订单中的典型使用场景：

1. 订单创建时，医生选择：
   - 部位：从平级列表中选择具体部位（如"颅骨"）
   - 项目：根据选中的部位，筛选出该部位下的重建项目列表
   - 可按分类快速定位：如只显示"模型"或"假体"类项目
   - 项目详情：展示标准价格、加急价格、预计耗时

2. 订单报价时：
   - 根据选中的项目，获取 standardPrice 或 urgentPrice
   - 根据 estimatedHours 估算工时

3. 设计师匹配时：
   - 根据选中重建项目的 specialty 字段，自动匹配对应专业方向设计师

关键点：
- 部位为项目提供"归类维度"，便于按身体部位组织项目
- 项目为订单提供"计价维度"，每个项目有明确的价格和工时
- 两者均为只读基础数据，订单只引用不修改
```
