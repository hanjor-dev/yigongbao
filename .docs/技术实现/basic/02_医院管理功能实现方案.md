# 02_医院管理功能实现方案

## 一、功能概述

### 1.1 模块定位

医院（Hospital）是医工宝系统中的核心基础数据模块，主要用于 ERP 订单创建时指定"客户"概念。医院与重建项目、产品、科室之间没有直接业务关联，仅作为业务对象的引用载体。

### 1.2 核心设计决策

| # | 决策内容 | 说明 |
|---|---------|------|
| 1 | 表名规范 | 医院表名为 `hospital`（无模块前缀） |
| 2 | 删除功能 | 当前阶段不提供删除接口，仅支持 CRUD + 状态切换，管理员操作失误可通过状态切换替代删除 |
| 3 | 医院编码 | 系统自动生成，格式为 `HOS-XXX`（如 HOS-001），不可修改 |
| 4 | 地区冗余字段 | 存储 `area_name` 和 `full_area_name`，避免每次查询时关联地区表 |
| 5 | 字典关联 | 医院等级（`hospital_level`）和医院类型（`hospital_type`）复用 `sys_dict` 表中字典数据 |
| 6 | 归属模块 | 位于 `basic/hospital`，作为基础数据供 system 模块引用 |

### 1.3 功能清单

| 功能 | 说明 |
|------|------|
| 分页查询医院列表 | 支持按名称、地区、等级、类型、状态多条件筛选 |
| 查询医院详情 | 根据 ID 查询单条医院信息 |
| 创建医院 | 自动生成编码，填充地区冗余字段 |
| 更新医院 | 支持修改基本信息，地区变更时自动刷新冗余字段 |
| 修改医院状态 | 启用/停用切换（状态值 0/1） |
| 获取医院下拉选项 | 无分页，供前端 select 组件使用 |

## 二、数据库设计

### 2.1 表结构

```sql
CREATE TABLE hospital (
    id                  BIGINT          NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    hospital_name       VARCHAR(128)    NOT NULL COMMENT '医院名称',
    hospital_code       VARCHAR(32)     NOT NULL COMMENT '医院编码（系统唯一，自动生成）',
    area_id             BIGINT          NOT NULL COMMENT '所属地区ID',
    area_name           VARCHAR(64)     COMMENT '地区名称（冗余，精确到区）',
    full_area_name      VARCHAR(256)    COMMENT '完整地区路径（省-市-区）',
    hospital_level      TINYINT         COMMENT '医院等级（字典：dict_code=3）',
    hospital_type       TINYINT         COMMENT '医院类型（字典：dict_code=4）',
    contact             VARCHAR(32)     NOT NULL COMMENT '联系人',
    phone               VARCHAR(32)     NOT NULL COMMENT '联系电话',
    email               VARCHAR(64)     COMMENT '电子邮箱',
    address             VARCHAR(256)    COMMENT '详细地址',
    credit_code         VARCHAR(32)     COMMENT '统一社会信用代码',
    business_license    VARCHAR(512)   COMMENT '营业执照路径',
    status              TINYINT         DEFAULT 1 COMMENT '状态（0=禁用，1=正常）',
    remark              VARCHAR(512)    COMMENT '备注说明',
    create_time         DATETIME        DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time         DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    create_by           BIGINT          DEFAULT NULL COMMENT '创建人ID',
    update_by           BIGINT          DEFAULT NULL COMMENT '更新人ID',
    is_deleted          TINYINT         DEFAULT 0 COMMENT '是否删除（0=否，1=是）',
    PRIMARY KEY (id),
    UNIQUE KEY uk_hospital_code (hospital_code),
    UNIQUE KEY uk_hospital_name (hospital_name),
    KEY idx_hospital_area_id (area_id),
    KEY idx_hospital_level (hospital_level),
    KEY idx_hospital_type (hospital_type),
    KEY idx_hospital_status (status)
) COMMENT '医院表';
```

| hospital_code | VARCHAR(32) | 是 | 医院编码（系统唯一，自动生成，如 HOS-001） |
| area_id | BIGINT | 是 | 所属地区 ID（关联 sys_area.id） |
| area_name | VARCHAR(64) | 否 | 地区名称（冗余，精确到区） |
| full_area_name | VARCHAR(256) | 否 | 完整地区路径（冗余，如"中国,浙江,杭州市,上城区"） |
| hospital_level | TINYINT | 否 | 医院等级（字典：dict_code=3） |
| hospital_type | TINYINT | 否 | 医院类型（字典：dict_code=4） |
| contact | VARCHAR(32) | 是 | 联系人 |
| phone | VARCHAR(32) | 是 | 联系电话 |
| email | VARCHAR(64) | 否 | 电子邮箱 |
| address | VARCHAR(256) | 否 | 详细地址 |
| credit_code | VARCHAR(32) | 否 | 统一社会信用代码 |
| business_license | VARCHAR(512) | 否 | 营业执照路径 |
| status | TINYINT | 是 | 状态（0=禁用，1=正常，默认 1） |
| remark | VARCHAR(512) | 否 | 备注说明 |

| update_time | DATETIME | 是 | 更新时间（自动填充） |
| create_by | BIGINT | 是 | 创建人 ID（自动填充） |

### 2.3 索引设计

| 索引名 | 字段 | 类型 | 说明 |
|--------|------|------|------|
| uk_hospital_code | hospital_code | UNIQUE | 医院编码唯一索引 |
| uk_hospital_name | hospital_name | UNIQUE | 医院名称唯一索引 |
| idx_hospital_area_id | area_id | KEY | 地区查询索引 |
| idx_hospital_level | hospital_level | KEY | 医院等级查询索引 |
| idx_hospital_type | hospital_type | KEY | 医院类型查询索引 |

### 2.4 外键关系

| 关系 | 字段 | 指向 | 说明 |

| 地区关联 | area_id | sys_area.id | 地区为只读基础数据，此处不加外键约束，保持灵活性 |

## 四、核心逻辑

### 4.1 编码生成规则

医院编码格式为 `HOS-XXX`，由系统自动生成，不可修改：

```
生成逻辑：
1. 查询当前最大编码（以 "HOS-" 开头，按编码倒序取第一条）
2. 提取序号部分（如 HOS-001 中的 "001"）
3. 序号 +1，格式化为 3 位补零字符串
4. 示例：HOS-001 → HOS-002 → HOS-003 ...

特点：
- 不使用 UUID 或雪花 ID，保证编码简短可读
- 序号连续递增，便于人工识别和追溯
- 不支持自定义编码，确保系统唯一性
```

### 4.2 地区信息填充逻辑

医院创建/更新时，系统自动填充地区冗余字段：

```
fillAreaInfo(entity) 逻辑：
1. 根据 areaId 查询 sys_area 地区实体
2. entity.areaName = area.name（地区名称，如"东城区"）
3. entity.fullAreaName = area.mergerName（完整路径，如"中国,北京,北京市,东城区"）
4. 若地区 ID 无效，抛出业务异常

更新场景：
- 仅当 DTO 中 areaId 发生变化时才重新填充地区信息
- 避免不必要的地区表查询开销
```

### 4.3 唯一性校验

| 字段 | 校验范围 | 说明 |
|------|---------|------|
| hospital_name | 全局唯一 | 创建时检查、更新时排除自身 |
| hospital_code | 全局唯一 | 系统自动生成，理论上不会重复 |

### 4.4 状态管理

- **默认状态**：新建医院状态默认为 `1`（正常）
- **状态切换**：通过单独的状态接口修改，不支持在更新接口中修改状态
- **停用影响**：停用后的医院仍存在于数据库，但前端下拉列表默认不展示（可通过参数筛选）

### 5.2 具体关联

| 关联模块 | 关联方式 | 作用 |
|---------|---------|------|
| Area（basic/area） | AreaService 注入 HospitalServiceImpl | 医院创建/更新时查询地区信息，填充冗余字段 |
| HospitalGroupTemplate（basic） | 无直接依赖 | 模板明细表通过 hospital_id 关联医院 |

| Dict（system/dict） | 字典编码 3=医院等级，4=医院类型 | 医院等级和类型的显示名称通过字典服务获取 |

## 六、错误码

| 错误码 | 说明 | 触发场景 |
|--------|------|---------|
| 604 | 医院不存在 | 根据 ID 查询时医院不存在 |
| 605 | 医院已停用 | 业务规则校验时医院状态为禁用 |
| 606 | 医院名称已存在 | 创建/更新时医院名称重复 |
| 400 | 参数错误 | 状态值不合法、地区 ID 无效 |
