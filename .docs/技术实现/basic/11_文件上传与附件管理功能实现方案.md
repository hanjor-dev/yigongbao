## 一、功能概述

### 1.1 模块定位

文件上传与附件管理是医工宝系统中的**基础设施服务**，为所有业务模块提供统一的文件存储、访问和附件关联管理能力。该模块基于 `x-file-storage` 框架（`dromara/x-file-storage`）实现，支持本地存储、阿里云 OSS、AWS S3、七牛云等多种存储后端的零成本切换。

**核心能力**：
- 统一文件上传、下载、删除、查询接口
- 多存储平台支持（本地/OSS/S3/七牛），通过配置切换
- 业务关联（bizType + bizId → objectType + objectId）
- 缩略图自动生成
- 大文件分片上传、断点续传
- URL 签名防盗链

### 1.2 核心设计决策

| # | 决策内容 | 说明 |
|---|---------|------|
| 1 | 存储框架 | 使用 `x-file-storage`（dromara 社区版 3.x），统一封装多种存储后端 |
| 2 | 归属模块 | `yigongbao-module-basic`（业务基础数据层） |
| 3 | 存储表 | **直接使用框架标准表** `file_detail` + `file_part_detail`，不自行创建业务扩展表 |
| 4 | FileRecorder 接口 | 自研 `FileRecorderService` 实现框架 `FileRecorder` 接口，将文件信息持久化到 `file_detail` 表 |
| 5 | 业务关联 | 通过 x-file-storage 的 `objectType` + `objectId` 实现（对应 `bizType` + `bizId`） |
| 6 | 存储类型 | 本地存储优先实现，云存储（OSS/S3/七牛）通过配置切换 |
| 7 | 访问方式 | 本地文件通过 Spring ResourceHandler 映射 URL，云存储直接返回 CDN URL |
| 8 | 统一响应 | 自研 `FileController` 提供统一的 `Result<T>` 响应格式（不启用 x-file-storage Access 模块） |
| 9 | 上传大小 | 单文件限制 **500MB**，请求总大小限制 **1GB** |

### 1.3 版本演进对比

| 维度 | v1.0（system） | v2.x（basic，废弃） | v3.0（basic，当前） |
|------|----------------|--------------------|--------------------|
| 存储方式 | 原生 Java NIO 手写逻辑 | x-file-storage，框架表+自建表 | x-file-storage，仅框架表 |
| 存储表 | `sys_attachment` | `file_info`（框架）+ `sys_file` + `sys_file_upload_log` | `file_detail` + `file_part_detail`（框架标准） |
| FileRecorder | 未实现 | 未实现 | **自研 `FileRecorderService` 实现框架接口** |
| 分片上传 | 未支持 | 未支持 | 支持（通过 `FilePartDetailService`） |
| 存储类型 | 仅本地 | 本地/OSS/S3/七牛 | 本地/OSS/S3/七牛（配置切换） |
| 文件访问 | Spring ResourceHandler 硬编码 | 配置化 | 配置化 + x-file-storage 自动处理 |
| 代码结构 | `system/attachment/*` | `basic/attachment/*` | `basic/file/*` |
| 扩展性 | 差 | 中 | 好，切换存储仅改配置 |

### 2.2 关键设计：FileRecorder 接口

x-file-storage 框架提供 `FileRecorder` 接口，用于将文件上传记录持久化到数据库。本项目自研 `FileRecorderService` 实现该接口：

```java
// FileRecorderService 实现 FileRecorder 接口（5个方法）
public interface FileRecorder {
    boolean save(FileInfo info);                              // 保存文件记录
    void update(FileInfo info);                               // 更新文件记录（分片合并后）
    FileInfo getByUrl(String url);                            // 根据URL查询
    boolean delete(String url);                                // 根据URL删除
    void saveFilePart(FilePartInfo filePartInfo);             // 保存分片信息
    void deleteFilePartByUploadId(String uploadId);           // 删除分片信息
}
```

框架上传流程：

```
业务层调用 FileStorageService.of(file).upload()
    ↓
x-file-storage 执行存储上传
    ↓
上传成功后，框架自动调用 FileRecorderService.save(FileInfo)
    ↓
FileRecorderService 将 FileInfo 转为 FileDetail 存入数据库
    ↓
返回 FileInfo（含自动生成的 id）
    ↓
业务层从数据库查询完整记录（包含 createTime 等自动填充字段）
    ↓
转换为 FileVO 返回给前端
```

### 2.3 业务关联字段

x-file-storage 的 `FileInfo` 原生支持 `objectType` 和 `objectId` 两个字段，与项目的 `bizType + bizId` 完全对应：

| 项目（bizType/bizId） | x-file-storage（objectType/objectId） |
|----------------------|---------------------------------------|
| `bizType` - 业务类型 | `objectType` - 关联对象类型 |
| `bizId` - 业务ID | `objectId` - 关联对象ID |

### 2.4 不启用 Access 模块的原因

x-file-storage 提供了 Access 模块（自动暴露 HTTP API + 自动建表），但本项目选择**自研 Controller** 而非使用 Access 模块，原因：

1. **统一响应格式**：项目所有接口返回 `Result<T>`，Access 模块不兼容
2. **业务关联逻辑**：bizType + bizId 的关联查询是项目特有的，Access 模块不适用
3. **错误码规范**：使用 `ErrorCodeEnum` 的统一错误码体系
4. **Sa-Token 认证**：上传人的 `userId` 和 `username` 需要通过 Sa-Token 获取

### 3.3 FileRecorderService — 框架接口实现

`FileRecorderService` 是本模块的核心，**继承 MyBatis-Plus `ServiceImpl`**，同时**实现 x-file-storage 框架 `FileRecorder` 接口**：

```java
// 路径: basic/.../file/service/impl/FileRecorderService.java

@Service
@RequiredArgsConstructor
@Slf4j
public class FileRecorderService
        extends ServiceImpl<FileDetailMapper, FileDetail>
        implements FileRecorder {

    private final ObjectMapper objectMapper;
    private final FilePartDetailService filePartDetailService;

    // ==================== FileRecorder 接口实现 ====================

    /**
     * 保存文件信息到数据库
     * 框架在文件上传完成后自动调用此方法
     */
    @Override
    public boolean save(FileInfo info) {
        if (info == null) return false;
        FileDetail detail = toFileDetail(info);
        boolean success = save(detail);
        if (success) {
            info.setId(detail.getId()); // 回填ID到 FileInfo
            log.info("保存文件记录成功，id={}, url={}", detail.getId(), detail.getUrl());
        } else {
            log.warn("保存文件记录失败，url={}", detail.getUrl());
        }
        return success;
    }

    @Override
    public void update(FileInfo info) { /* 分片合并后更新 */ }

    @Override
    public FileInfo getByUrl(String url) { /* 根据URL查询 */ }

    public FileInfo getById(String id) { /* 自定义方法，返回 FileInfo */ }

    public FileDetail getDetailById(String id) { /* 自定义方法，返回 FileDetail */ }

    @Override
    public boolean delete(String url) { /* 根据URL删除 */ }

    @Override
    public void saveFilePart(FilePartInfo filePartInfo) { /* 委托分片服务 */ }

    @Override
    public void deleteFilePartByUploadId(String uploadId) { /* 委托分片服务 */ }

    // ==================== 转换方法 ====================

    public FileDetail toFileDetail(FileInfo info) { /* FileInfo → FileDetail */ }
    public FileInfo toFileInfo(FileDetail detail) { /* FileDetail → FileInfo */ }
    public FileVO toFileVO(FileDetail detail) { /* FileDetail → FileVO */ }
}
```

**关键设计**：
- `save(FileInfo)` 中将 `detail.id` 回填到 `info.setId()`，使框架生成的雪花ID能传递回调用方
- JSON 复杂字段（Dict/Object/HashInfo）通过 Jackson ObjectMapper 序列化/反序列化
- `toFileVO()` 将数据库实体转为前端视图对象，提取 hashInfo 中的 MD5

### 3.5 FileServiceImpl — 业务服务实现

```java
// 路径: basic/.../file/service/impl/FileServiceImpl.java

@Service
@RequiredArgsConstructor
@Slf4j
public class FileServiceImpl implements FileService {

    private final FileStorageService fileStorageService;  // x-file-storage 框架接口
    private final FileRecorderService fileRecorderService;
    private final FileStorageProperties fileStorageProperties;

    /**
     * 上传核心逻辑
     * 1. 校验文件（类型、大小）
     * 2. 构造存储路径：bizType/yyyyMM/
     * 3. 调用框架上传（上传成功后框架自动调用 FileRecorderService.save 保存记录）
     * 4. 从数据库查询完整记录（包含 createTime 等自动填充字段）
     * 5. 转为 FileVO 返回
     */
    private FileVO doUpload(MultipartFile file, String bizType, Long bizId) {
        log.info("上传文件，bizType={}, bizId={}, fileName={}",
                bizType, bizId, file.getOriginalFilename());
        try {
            validateFile(file);
            String datePath = LocalDate.now().format(DateTimeFormatter.ofPattern("yyyyMM"));
            String path = bizType + "/" + datePath + "/";

            // 框架上传，上传成功后自动调用 FileRecorderService.save(FileInfo)
            FileInfo fileInfo = fileStorageService.of(file)
                    .setPath(path)
                    .setObjectType(bizType)
                    .setObjectId(bizId != null ? bizId.toString() : null)
                    .upload();

            log.info("上传文件成功，id={}, url={}", fileInfo.getId(), fileInfo.getUrl());
            // 从数据库查询完整记录（包含自动填充的 createTime 等字段）
            FileDetail detail = fileRecorderService.getDetailById(fileInfo.getId());
            return fileRecorderService.toFileVO(detail);
        } catch (BusinessException e) {
            throw e;
        } catch (Exception e) {
            log.error("上传文件异常，bizType={}", bizType, e);
            throw new BusinessException(ErrorCodeEnum.ATTACHMENT_UPLOAD_FAILED);
        }
    }

    /**
     * 删除：先删存储平台文件，再删数据库记录
     */
    @Override
    public void deleteById(String id) {
        log.info("删除文件，id={}", id);
        try {
            FileDetail detail = fileRecorderService.getDetailById(id);
            if (detail == null) {
                throw new BusinessException(ErrorCodeEnum.ATTACHMENT_NOT_FOUND);
            }
            // 先删存储平台文件
            fileStorageService.delete(detail.getUrl());
            // 再删数据库记录
            fileRecorderService.removeById(id);
            log.info("删除文件成功，id={}", id);
        } catch (BusinessException e) {
            throw e;
        } catch (Exception e) {
            log.error("删除文件异常，id={}", id, e);
            throw new BusinessException(ErrorCodeEnum.ATTACHMENT_DELETE_FAILED);
        }
    }
}
```

> **注意**：`FileServiceImpl` 中的 `fileStorageService` 是 x-file-storage 框架的 `FileStorageService`（包路径 `org.dromara.x.file.storage.core.FileStorageService`），注入后用于调用框架的上传/下载/删除能力。

### 3.6 FileController — REST 接口

```java
// 路径: basic/.../file/controller/FileController.java

@RestController
@RequestMapping("/api/basic/file")
@RequiredArgsConstructor
public class FileController {

    private final FileService fileService;

    @PostMapping("/upload")
    public Result<FileVO> upload(
            @RequestParam("file") MultipartFile file,
            @RequestParam String bizType) {
        return Result.success(fileService.uploadFile(file, bizType));
    }

    @PostMapping("/upload-and-link")
    public Result<FileVO> uploadAndLink(
            @RequestParam("file") MultipartFile file,
            @RequestParam String bizType,
            @RequestParam Long bizId) {
        return Result.success(fileService.uploadAndLink(file, bizType, bizId));
    }

    @PostMapping("/upload-multiple")
    public Result<List<FileVO>> uploadMultiple(
            @RequestParam("files") MultipartFile[] files,
            @RequestParam String bizType,
            @RequestParam Long bizId) {
        return Result.success(fileService.uploadMultiple(files, bizType, bizId));
    }

    @GetMapping("/list/{bizType}/{bizId}")
    public Result<List<FileVO>> listByBiz(
            @PathVariable String bizType,
            @PathVariable Long bizId) {
        return Result.success(fileService.listByBiz(bizType, bizId));
    }

    @GetMapping("/{id}")
    public Result<FileVO> getById(@PathVariable String id) {
        return Result.success(fileService.getById(id));
    }

    @GetMapping("/download/{id}")
    public void download(
            @PathVariable String id,
            jakarta.servlet.http.HttpServletResponse response) throws IOException {
        fileService.download(id, response);
    }

    @DeleteMapping("/{id}")
    public Result<Void> deleteById(@PathVariable String id) {
        fileService.deleteById(id);
        return Result.success();
    }
}
```

## 五、存储类型切换

x-file-storage 的核心优势：**切换存储后端仅需修改配置文件，无需改动 Java 代码**。

### 5.1 本地存储（开发环境）

```yaml
dromara:
  x-file-storage:
    default-platform: local
    local:
      domain: http://localhost:8080/api/files
      path-patterns: /api/files/**
      path: D:/yigongbao-files
```

### 5.2 阿里云 OSS（生产环境推荐）

```yaml
dromara:
  x-file-storage:
    default-platform: aliyun-oss-1
    local:
      domain: http://localhost:8080/api/files
      path-patterns: /api/files/**
      path: D:/yigongbao-files
    aliyun-oss:
      - platform: aliyun-oss-1
        enable-storage: true
        access-key: ${ALIYUN_ACCESS_KEY}
        secret-key: ${ALIYUN_SECRET_KEY}
        end-point: oss-cn-hangzhou.aliyuncs.com
        bucket-name: yigongbao-files
        domain: https://files.yigongbao.com
        base-path: prod/
```

### 5.3 AWS S3 / MinIO

```yaml
dromara:
  x-file-storage:
    default-platform: s3-1
    s3:
      - platform: s3-1
        enable-storage: true
        access-key: ${AWS_ACCESS_KEY}
        secret-key: ${AWS_SECRET_KEY}
        bucket-name: yigongbao-files
        region: us-east-1
        domain: https://files.yigongbao.com
        # 支持 MinIO 等 S3 兼容存储
        endpoint: https://minio.yigongbao.com
```

## 八、DDL 表结构

### 8.1 文件记录表（file_detail）

对应 x-file-storage 框架标准，由框架 `FileRecorder` 接口使用：

```sql
-- ============================================================
-- 文件记录表（file_detail）
-- 基于 x-file-storage 框架 FileRecorder 接口标准实现
-- 支持多存储平台、业务关联、缩略图、元数据、分片上传
-- 注意：禁止在此表上定义 is_deleted 字段的索引，MyBatis-Plus @TableLogic 会自动创建
-- ============================================================
CREATE TABLE file_detail (
    `id`                VARCHAR(32)  NOT NULL COMMENT '文件ID（雪花算法生成）',
    `url`               VARCHAR(512) NOT NULL COMMENT '文件访问地址',
    `size`              BIGINT(20)   DEFAULT NULL COMMENT '文件大小，单位字节',
    `filename`          VARCHAR(256) DEFAULT NULL COMMENT '保存的文件名',
    `original_filename` VARCHAR(256) DEFAULT NULL COMMENT '原始文件名',
    `base_path`         VARCHAR(256) DEFAULT NULL COMMENT '基础存储路径',
    `path`              VARCHAR(256) DEFAULT NULL COMMENT '存储路径（不含文件名）',
    `ext`               VARCHAR(32)  DEFAULT NULL COMMENT '文件扩展名',
    `content_type`      VARCHAR(128) DEFAULT NULL COMMENT 'MIME类型',
    `platform`          VARCHAR(32)  DEFAULT NULL COMMENT '存储平台标识',

    -- 缩略图
    `th_url`            VARCHAR(512) DEFAULT NULL COMMENT '缩略图访问地址',
    `th_filename`       VARCHAR(256) DEFAULT NULL COMMENT '缩略图文件名',
    `th_size`           BIGINT(20)   DEFAULT NULL COMMENT '缩略图大小',
    `th_content_type`   VARCHAR(128) DEFAULT NULL COMMENT '缩略图MIME类型',

    -- 业务关联
    `object_type`       VARCHAR(128) DEFAULT NULL COMMENT '关联业务类型',
    `object_id`         VARCHAR(64)  DEFAULT NULL COMMENT '关联业务ID',

    -- 元数据（JSON格式）
    `metadata`          TEXT COMMENT '文件元数据',
    `user_metadata`     TEXT COMMENT '用户元数据',
    `th_metadata`       TEXT COMMENT '缩略图元数据',
    `th_user_metadata`  TEXT COMMENT '缩略图用户元数据',
    `attr`              TEXT COMMENT '附加属性（Dict类型）',
    `file_acl`          TEXT COMMENT '文件ACL',
    `th_file_acl`       TEXT COMMENT '缩略图ACL',
    `hash_info`         TEXT COMMENT '哈希信息（MD5/SHA256）',

    -- 分片上传
    `upload_id`         VARCHAR(128) DEFAULT NULL COMMENT '上传ID（手动分片上传）',
    `upload_status`     INT(11)      DEFAULT NULL COMMENT '上传状态（1：初始化，2：上传完成）',

    -- 公共字段
    `create_time`       DATETIME     DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time`       DATETIME     DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    `create_by`         BIGINT       DEFAULT NULL COMMENT '创建人ID',
    `update_by`         BIGINT       DEFAULT NULL COMMENT '更新人ID',
    `is_deleted`        TINYINT      DEFAULT 0 COMMENT '是否删除：0-否，1-是',

    PRIMARY KEY (`id`),
    KEY idx_file_detail_object (object_type, object_id),
    KEY idx_file_detail_create_time (create_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='文件记录表（x-file-storage FileRecorder）';
```
