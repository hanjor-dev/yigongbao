# 03_医院组合模板功能实现方案

## 一、功能概述

### 1.1 模块定位

医院组合模板（HospitalGroupTemplate）是医工宝系统的基础数据模块，用于将多个医院打包成一个可复用的"模板"。管理员在给用户分配医院范围时，可以通过选择模板快速批量设置，无需逐个勾选医院，从而大幅提升工作效率。

模板的核心价值在于：**简化医院范围分配操作，支持批量预设和快速复用**。

### 1.2 核心设计决策

| # | 决策内容 | 说明 |
|---|---------|------|
| 1 | 模板与医院的关系 | N:1（一个模板包含多个医院，一个医院可属于多个模板） |
| 2 | 模板明细表设计 | 单独一张 `hospital_group_template_detail` 表，极简设计，不继承 BaseEntity |
| 3 | 医院关联 | 明细表通过 `hospital_id` 关联 `hospital` 表，无外键约束 |
| 4 | 模板编码 | 系统自动生成，格式为 `TPL-HOS-XXX`（如 TPL-HOS-001） |
| 5 | 删除逻辑 | 删除模板时级联删除明细表数据 |
| 6 | 归属模块 | 位于 `basic/hospitalGroupTemplate`，作为基础数据供 system 模块引用 |

### 1.3 功能清单

| 功能 | 说明 |
|------|------|
| 分页查询模板列表 | 支持按名称、状态筛选，列表展示包含医院数量 |
| 查询模板详情 | 根据 ID 查询单条模板信息，包含医院明细列表（带医院详细信息） |
| 创建模板 | 自动生成编码，批量保存医院明细 |
| 更新模板 | 支持修改基本信息和医院列表（医院列表为覆盖式更新） |
| 删除模板 | 物理删除模板，级联删除明细表数据 |
| 修改模板状态 | 启用/停用切换（状态值 0/1） |
| 获取模板下拉选项 | 无分页，供前端 select 组件使用（含医院数量显示） |

## 二、数据库设计

### 2.1 表结构

#### 2.1.1 hospital_group_template 医院组合模板主表

```sql
CREATE TABLE hospital_group_template (
    id                  BIGINT          NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    template_name       VARCHAR(64)     NOT NULL COMMENT '模板名称',
    template_code       VARCHAR(32)     NOT NULL COMMENT '模板编码（系统唯一，自动生成）',
    template_desc       VARCHAR(256)    COMMENT '模板描述',
    status              TINYINT         DEFAULT 1 COMMENT '状态（0=禁用，1=正常）',
    remark              VARCHAR(512)    COMMENT '备注说明',
    create_time         DATETIME        DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time         DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    create_by           BIGINT          DEFAULT NULL COMMENT '创建人ID',
    update_by           BIGINT          DEFAULT NULL COMMENT '更新人ID',
    is_deleted          TINYINT         DEFAULT 0 COMMENT '是否删除（0=否，1=是）',
    PRIMARY KEY (id),
    UNIQUE KEY uk_template_code (template_code),
    UNIQUE KEY uk_template_name (template_name),
    KEY idx_template_status (status)
) COMMENT '医院组合模板表';
```

#### 2.1.2 hospital_group_template_detail 医院组合模板明细表

```sql
CREATE TABLE hospital_group_template_detail (
    id                  BIGINT          NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    template_id         BIGINT          NOT NULL COMMENT '模板ID（FK → hospital_group_template.id）',
    hospital_id         BIGINT          NOT NULL COMMENT '医院ID（FK → hospital.id）',
    create_time         DATETIME        DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    PRIMARY KEY (id),
    UNIQUE KEY uk_template_hospital (template_id, hospital_id),
    KEY idx_template_detail_template_id (template_id),
    KEY idx_template_detail_hospital_id (hospital_id)
) COMMENT '医院组合模板明细表';
```

### 2.2 字段说明

#### 主表字段

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | BIGINT | 是 | 主键（自增） |
| template_name | VARCHAR(64) | 是 | 模板名称（唯一） |
| template_code | VARCHAR(32) | 是 | 模板编码（系统唯一，自动生成，如 TPL-HOS-001） |
| template_desc | VARCHAR(256) | 否 | 模板描述 |
| status | TINYINT | 是 | 状态（0=禁用，1=正常，默认 1） |
| remark | VARCHAR(512) | 否 | 备注说明 |
| create_time | DATETIME | 是 | 创建时间（自动填充） |
| update_time | DATETIME | 是 | 更新时间（自动填充） |
| create_by | BIGINT | 是 | 创建人 ID（自动填充） |
| update_by | BIGINT | 是 | 更新人 ID（自动填充） |
| is_deleted | TINYINT | 是 | 是否删除（逻辑删除，默认 0） |

#### 明细表字段

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | BIGINT | 是 | 主键（自增） |
| template_id | BIGINT | 是 | 模板 ID |
| hospital_id | BIGINT | 是 | 医院 ID |
| create_time | DATETIME | 是 | 创建时间（自动填充） |

> **设计说明**：明细表不继承 `BaseEntity`，采用极简设计。原因：明细表仅记录关联关系，父表已有 `create_by`、`update_by` 等公共字段；明细表无排序需求，无状态字段，无需逻辑删除。

### 2.3 索引设计

| 表 | 索引名 | 字段 | 类型 | 说明 |
|----|--------|------|------|------|
| 主表 | uk_template_code | template_code | UNIQUE | 模板编码唯一索引 |
| 主表 | uk_template_name | template_name | UNIQUE | 模板名称唯一索引 |
| 主表 | idx_template_status | status | KEY | 状态查询索引 |
| 明细表 | uk_template_hospital | (template_id, hospital_id) | UNIQUE | 同一模板下医院不重复 |
| 明细表 | idx_template_detail_template_id | template_id | KEY | 模板维度查询索引 |
| 明细表 | idx_template_detail_hospital_id | hospital_id | KEY | 医院维度查询索引 |

## 四、核心逻辑

### 4.1 编码生成规则

模板编码格式为 `TPL-HOS-XXX`，由系统自动生成，不可修改：

```
生成逻辑：
1. 查询当前最大编码（以 "TPL-HOS-" 开头，按编码倒序取第一条）
2. 提取序号部分（如 TPL-HOS-001 中的 "001"）
3. 序号 +1，格式化为 3 位补零字符串
4. 示例：TPL-HOS-001 → TPL-HOS-002 → TPL-HOS-003 ...

与医院编码的区别：
- 医院编码前缀：HOS-
- 模板编码前缀：TPL-HOS-
- 两者互不冲突，独立序号体系
```

### 4.2 模板明细查询逻辑

查询模板详情时，明细列表需要展示医院的详细信息，核心逻辑如下：

```
getDetails(templateId) 逻辑：
1. 根据 templateId 查询明细表，获取所有 hospital_id 列表
2. 批量查询 hospital 表（selectBatchIds），获取医院实体列表
3. 遍历明细记录，匹配医院信息填充到 VO：
   - detailVO.hospitalName = hospital.hospitalName
   - detailVO.hospitalCode = hospital.hospitalCode
   - detailVO.fullAreaName = hospital.fullAreaName
   - detailVO.contact = hospital.contact
   - detailVO.phone = hospital.phone
4. hospitalLevelName 字段需要在 system 模块中通过字典服务填充（basic 不依赖 dict）
```

### 4.3 医院列表更新逻辑

更新模板时，医院列表采用**覆盖式更新**策略：

```
updateTemplate(id, dto) 逻辑：
1. 查询模板是否存在，不存在则抛出异常
2. 校验模板名称唯一性（排除自身）
3. BeanUtils.copyProperties 复制基本字段
4. 若 dto.hospitalIds != null：
   a. detailMapper.deleteByTemplateId(id)  删除所有旧明细
   b. saveDetails(id, hospitalIds)  批量插入新明细
5. 更新主表记录

覆盖式更新的优点：
- 前端无需计算差异，后端直接替换
- 简化前端逻辑，提升操作效率
- 适合医院数量不多（几十到几百）的场景
```

### 4.4 医院数量统计

列表展示时需要显示每个模板包含的医院数量，通过 `detailMapper.countByTemplateId()` 统计：

```
实现方式：
- toVOWithCount(entity)：列表转换时统计医院数量
- toSimpleVO(entity)：下拉选项转换时统计医院数量
- 两者都调用 detailMapper.countByTemplateId()

注意：
- 统计的是明细表记录数，非去重医院数（明细表已通过 UNIQUE KEY 保证不重复）
- 性能问题：N+1 查询风险，模板数量多时需优化
```

### 5.2 与用户医院分配的关系

```
医院组合模板在用户权限体系中的作用：

管理员给用户分配医院范围时：
1. 方式一：直接勾选医院
   - 调用 /api/system/user/{userId}/hospitals（PUT）传入选中的 hospitalIds
2. 方式二：通过模板快速分配
   - 调用 /api/basic/hospitalGroupTemplate/options 获取可用模板列表
   - 选择模板后，调用 /api/basic/hospitalGroupTemplate/{id} 获取模板明细
   - 获取 hospitalIds 列表
   - 调用 /api/system/user/{userId}/hospitals（PUT）完成分配
   - 管理员可在模板分配后手动增删个别医院

关键点：
- 模板本身不关联用户，模板只存储"哪些医院可以打包"
- 用户的实际医院范围由 sys_user_hospital 表决定
- 模板只是分配操作时的"快捷工具"
```

### 5.3 具体关联

| 关联模块 | 关联方式 | 作用 |
|---------|---------|------|
| Hospital（basic/hospital） | HospitalMapper 注入 | 查询医院基础数据，填充明细列表的医院详细信息 |
| User（system/user） | system 模块调用 basic 接口 | 用户分配医院范围时，通过模板快速选择 |
| Dict（system/dict） | 无直接依赖 | 模板明细的 hospitalLevelName 需要通过字典服务获取（由调用方填充） |

## 六、错误码

| 错误码 | 说明 | 触发场景 |
|--------|------|---------|
| 656 | 医院组合模板不存在 | 根据 ID 查询时模板不存在 |
| 657 | 医院组合模板已停用 | 业务规则校验时模板状态为禁用 |
| 658 | 医院组合模板名称已存在 | 创建/更新时模板名称重复 |
| 659 | 该模板已被用户使用，无法删除 | 删除时模板已被用户关联 |
| 400 | 参数错误 | 状态值不合法、未选择医院 |
