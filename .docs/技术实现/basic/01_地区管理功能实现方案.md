# 01_地区管理功能实现方案

## 一、功能概述

### 1.1 模块定位

地区管理（Area）是医工宝系统的基础数据模块，用于存储和管理中国省/市/区三级行政区划数据。该模块不提供增删改操作，仅对外提供查询能力，数据来源于权威的 [cnarea_2023](https://github.com/kakuilan/china_area_mysql) 数据库。

地区数据是医院管理的基础支撑字段，医院在创建或更新时通过 `areaId` 关联地区，地区信息（地区名称、完整路径）作为冗余字段存储于医院表中。

### 1.2 核心设计决策

| # | 决策内容 | 说明 |
|---|---------|------|
| 1 | 数据来源 | cnarea_2023，不自行维护数据 |
| 2 | 增删改能力 | 不提供，仅提供查询（只读场景） |
| 3 | Entity 设计 | 不继承 `BaseEntity`，不含通用字段（无 id 关联、无创建人/更新人需求） |
| 4 | 归属模块 | 从 `system/basedata/area` 迁移至 `basic/area`，因为地区属于通用基础数据 |
| 5 | API 入口 | 查询 API 保留在 `system/basedata/SelectController` 下，作为系统级统一下拉查询入口 |

### 1.3 功能清单

| 功能 | 说明 |
|------|------|
| 获取省份列表 | 查询 `parent_code = 0` 的省级行政区 |
| 根据父级查询子地区 | 根据父级行政代码查询市/区县列表 |
| 获取地区树形结构 | 从指定节点向下递归构建树（默认从根节点开始） |

## 二、数据库设计

### 2.1 表结构

地区表 `sys_area` 与 [cnarea_2023](https://github.com/kakuilan/china_area_mysql) 表结构完全一致：

```sql
CREATE TABLE sys_area (
    id                  BIGINT          NOT NULL AUTO_INCREMENT COMMENT '主键',
    level               TINYINT         NOT NULL COMMENT '层级（1=省/直辖市，2=市，3=区/县）',
    parent_code         BIGINT          NOT NULL DEFAULT 0 COMMENT '父级行政代码',
    area_code           BIGINT          NOT NULL DEFAULT 0 COMMENT '行政代码（国家标准）',
    zip_code            INT             NOT NULL DEFAULT 0 COMMENT '邮政编码',
    city_code           CHAR(6)         NOT NULL DEFAULT '' COMMENT '区号',
    name                VARCHAR(50)     NOT NULL DEFAULT '' COMMENT '名称',
    short_name          VARCHAR(50)     NOT NULL DEFAULT '' COMMENT '简称',
    merger_name         VARCHAR(50)     NOT NULL DEFAULT '' COMMENT '组合名',
    pinyin              VARCHAR(30)     NOT NULL DEFAULT '' COMMENT '拼音',
    lng                 DECIMAL(10,6)   NOT NULL DEFAULT 0 COMMENT '经度',
    lat                 DECIMAL(10,6)   NOT NULL DEFAULT 0 COMMENT '纬度',
    PRIMARY KEY (id),
    UNIQUE KEY uk_sys_area_code (area_code),
    KEY idx_sys_area_parent_code (parent_code),
    KEY idx_sys_area_level (level)
) COMMENT '地区表（省市区）';
```

### 2.2 字段说明

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | BIGINT | 主键（自增） |
| level | TINYINT | 层级：1=省/直辖市，2=市，3=区/县 |
| parent_code | BIGINT | 父级行政代码（根节点为 0） |
| area_code | BIGINT | 国家标准行政代码（如 110000=北京市） |
| zip_code | INT | 邮政编码 |
| city_code | CHAR(6) | 区号 |
| name | VARCHAR(50) | 行政区划名称 |
| short_name | VARCHAR(50) | 简称（如"北京"） |
| merger_name | VARCHAR(50) | 组合名（完整路径，如"中国,北京,北京市,朝阳区"） |
| pinyin | VARCHAR(30) | 拼音 |
| lng | DECIMAL(10,6) | 经度 |
| lat | DECIMAL(10,6) | 纬度 |

### 2.3 索引设计

| 索引名 | 字段 | 类型 | 说明 |
|--------|------|------|------|
| uk_sys_area_code | area_code | UNIQUE | 行政代码唯一索引 |
| idx_sys_area_parent_code | parent_code | KEY | 父级查询索引 |
| idx_sys_area_level | level | KEY | 层级查询索引 |

## 三、接口规范

### 3.1 API 路径

地区查询 API 统一位于 `system/basedata/SelectController` 下：

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/system/select/provinces` | 获取省份列表 |
| GET | `/api/system/select/cities/{parentCode}` | 根据父级行政代码查询子地区 |
| GET | `/api/system/select/area-tree` | 获取完整地区树形结构 |
| GET | `/api/system/select/area-tree/{parentCode}` | 获取指定节点下的地区树形结构 |

> **注意**：AreaService 本身不提供独立 Controller，查询入口统一由 `SelectController` 封装，对前端保持 API 稳定性。

## 四、核心逻辑

### 4.1 树形结构构建

地区数据通过 `parent_code → area_code` 的关系构建树形结构，核心算法为递归：

```
算法说明：
1. 查询所有地区数据，按 area_code 升序排列
2. 根据传入的 parentCode 确定根节点（默认 parentCode = 0）
3. 递归构建子树：
   - 筛选 parentCode = 当前节点 areaCode 的所有子节点
   - 对每个子节点递归调用构建子树
   - 按 areaCode 升序排序
4. 若子节点列表为空，则 children = null（而非空数组）
```

### 4.2 层级说明

| level | 含义 | parent_code | 示例 |
|-------|------|-------------|------|
| 1 | 省/直辖市/自治区 | 0 | 北京市、浙江省 |
| 2 | 市/区 | 对应省级 area_code | 杭州市、广州市 |
| 3 | 区/县 | 对应市级 area_code | 上城区、朝阳区 |

### 4.3 与医院模块的关联

医院表中存储了地区相关字段：

| 医院表字段 | 说明 |
|-----------|------|
| area_id | 关联地区表主键 ID |
| area_name | 地区名称（冗余，精确到区） |
| full_area_name | 完整地区路径（从 merger_name 获取，如"中国,浙江,杭州市,上城区"） |

在医院创建/更新时，通过 `AreaService.getById(areaId)` 查询地区实体，填充上述冗余字段。

## 六、错误码

地区模块本身不涉及业务异常（只读），错误码复用通用定义：

| 错误码 | 说明 | 触发场景 |
|--------|------|---------|
| 400 | 参数错误 | 传入无效的父级行政代码 |
| 500 | 服务器错误 | 数据库查询异常 |
