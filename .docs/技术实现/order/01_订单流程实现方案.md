## 二、模块架构设计

### 2.1 模块定位

`yigongbao-module-order` 是医工宝系统的订单业务模块，负责：
1. 订单的创建、修改、删除、查询
2. 订单状态机管理（阶段流转、状态变更）
3. 草稿管理（独立表存储，提交后转入正式订单）
4. 订单文件关联管理
5. 订单审核流程管理

### 2.3 多模块架构策略

#### 2.3.1 背景与目标

当前只实现订单阶段（ORDER Phase），但系统中还存在设计阶段（DESIGN）和生产阶段（PRODUCTION）。为避免未来模块臃肿、维护困难、团队协作冲突等问题，采用**按阶段拆分独立模块**的策略。

#### 2.3.2 整体模块规划

```
yigongbao-parent/
│
├── yigongbao-common/                          # 公共层（所有模块共享）
│   └── src/main/java/com/yigongbao/common/
│       ├── enums/                             # 枚举（跨模块共享）
│       │   ├── OrderPhaseEnum.java           # 阶段枚举（ORDER/DESIGN/PRODUCTION）
│       │   ├── OrderStatusEnum.java          # 状态枚举
│       │   ├── OrderActionEnum.java          # 动作枚举
│       │   ├── OrderBusinessTypeEnum.java    # 业务类型（字典编码）
│       │   ├── OrderPatientGenderEnum.java   # 患者性别
│       │   ├── OrderTypeEnum.java            # 订单类型
│       │   └── FileBizTypeEnum.java          # 已有
│       ├── constant/                          # 常量
│       │   ├── CodeRuleConstants.java        # 编码常量
```

#### 2.3.3 核心问题分析与解决方案

##### 问题 1：枚举存放位置

| 枚举 | 当前位置 | 建议位置 | 原因 |
|------|----------|----------|------|
| `OrderPhaseEnum` | order 模块 | `yigongbao-common` | 所有阶段模块都需引用 |
| `OrderStatusEnum` | order 模块 | `yigongbao-common` | 各阶段都有状态 |
| `OrderActionEnum` | order 模块 | `yigongbao-common` | 各阶段都有动作 |
| `OrderBusinessTypeEnum` | order 模块 | `yigongbao-common` | 字典编码可复用 |
| `OrderPatientGenderEnum` | order 模块 | `yigongbao-common` | 字典编码可复用 |

**实施**：在创建 `yigongbao-module-order` 前，先将上述枚举迁移到 `yigongbao-common`。

##### 问题 2：状态转换规则存放位置

**场景**：阶段流转是跨模块的，例如 ORDER → DESIGN 需要验证阶段转换规则。

**方案**：将规则接口定义在 `common`，具体规则实现可在各模块中。

```java
// common/rules/PhaseTransitionRule.java
public interface PhaseTransitionRule {
    boolean canTransition(String fromPhase, String toPhase);
    List<String> getAvailableActions(String currentPhase, String currentStatus);
}

// common/rules/OrderPhaseTransitionRules.java
@Component
public class OrderPhaseTransitionRules implements PhaseTransitionRule {
    @Override
    public boolean canTransition(String fromPhase, String toPhase) {
        // ORDER -> DESIGN, DESIGN -> PRODUCTION 等规则
    }
}
```

##### 问题 3：跨模块数据查询

**场景**：
- 设计阶段需要查询订单信息（order_code、患者姓名等）
- 生产阶段需要查询设计结果

**方案**：使用 OpenFeign 远程调用

```java
// yigongbao-module-design 中
@FeignClient("yigongbao-module-order")
public interface OrderFeignClient {
    @GetMapping("/api/order/{orderCode}")
    OrderMainVO getByOrderCode(@PathVariable String orderCode);
}
```

**注意**：
1. 需要在 `yigongbao-boot` 中引入 OpenFeign 依赖
2. 启用 `@EnableFeignClients` 注解
3. 模块间不直接依赖对方的服务类，通过 Feign 接口解耦

##### 问题 4：避免循环依赖

**原则**：
- 所有业务模块都只依赖 `yigongbao-common`
- 模块之间通过 Feign/MQ 解耦，不直接依赖
- 禁止：order → design 且 design → order

```
✅ 正确：order → common ← design
✅ 正确：order → common, design → common
✅ 正确：order 通过 Feign 调用 design
❌ 错误：order → design 且 design → order
```

##### 问题 5：模块间数据关联

**场景**：`design_project` 表需要关联 `order_main` 的数据（order_code 等）。

**方案**：只存储 `order_code` 作为外键关联，通过 Feign 查询完整信息。

```sql
-- design_project 表设计
CREATE TABLE `design_project` (
    `id` BIGINT NOT NULL AUTO_INCREMENT,
    `order_code` VARCHAR(50) NOT NULL COMMENT '订单编号',
    `order_id` BIGINT COMMENT '订单ID（冗余字段，便于查询）',
    -- ...
);
```

#### 2.3.4 当前阶段实施计划

**立即执行（Phase 1 - 订单阶段）**：

1. **迁移枚举到 common**：将 `OrderPhaseEnum`、`OrderStatusEnum`、`OrderActionEnum`、`OrderBusinessTypeEnum`、`OrderPatientGenderEnum` 迁移到 `yigongbao-common`
2. **创建 order 模块**：创建 `yigongbao-module-order` 模块骨架
3. **pom.xml 更新**：在父 pom 中添加 `yigongbao-module-order` 模块；在 `yigongbao-boot` 中添加依赖
4. **状态机规则**：保持在 order 模块中，但引用 common 中的枚举

**后续阶段（设计/生产）**：

5. **创建 design 模块**：创建 `yigongbao-module-design` 模块
6. **创建 production 模块**：创建 `yigongbao-module-production` 模块
7. **引入 OpenFeign**：在 boot 模块中引入 Feign 依赖
8. **跨模块调用**：设计模块通过 Feign 查询订单信息

### 3.2 核心表设计

#### 3.2.1 订单草稿表（order_draft）

```sql
CREATE TABLE `order_draft` (
    `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    `operator_id` BIGINT NOT NULL COMMENT '操作员ID（创建人）',

    -- 订单类型
    `order_type` TINYINT NOT NULL COMMENT '1-医疗器械，2-非医疗器械，3-服务',
    `business_type` VARCHAR(20) NOT NULL COMMENT '业务类型（字典 dict_code：11.1-业务，11.2-测试，11.3-试用，11.4-代理）',

    -- 机构信息
    `org_id` BIGINT NOT NULL COMMENT '提单机构ID',
    `org_name` VARCHAR(200) COMMENT '提单机构名称',
    `operator_name` VARCHAR(100) COMMENT '操作员姓名',
    `operator_phone` VARCHAR(20) COMMENT '操作员电话',

    -- 医院与科室
    `hospital_id` BIGINT COMMENT '医院ID',
    `hospital_name` VARCHAR(200) COMMENT '医院名称',
    `dept_id` BIGINT COMMENT '科室ID',
    `dept_name` VARCHAR(100) COMMENT '科室名称',

    -- 医生/患者信息
    `doctor_id` BIGINT COMMENT '医生ID',
    `doctor_name` VARCHAR(100) COMMENT '医生姓名',
    `doctor_phone` VARCHAR(20) COMMENT '医生电话',
    `patient_name` VARCHAR(100) COMMENT '患者姓名',
    `patient_age` INT COMMENT '患者年龄',
    `patient_gender` VARCHAR(20) COMMENT '患者性别（字典 dict_code：12.1-男，12.2-女）',

    -- 业务信息
    `is_urgent` TINYINT DEFAULT 0 COMMENT '是否加急：0-否，1-是',
    `is_postal` TINYINT DEFAULT 0 COMMENT '是否邮寄：0-否，1-是',
    `postal_address` TEXT COMMENT '邮寄地址',

    -- 时效信息
    `expected_delivery_date` DATETIME COMMENT '期望交付时间',

    -- 有效期管理
    `expires_at` DATETIME NOT NULL COMMENT '过期时间（创建时间+30天）',
    `status` TINYINT DEFAULT 1 COMMENT '状态：1-有效，2-已提交，3-已过期',

    -- 公共字段
    `create_time` DATETIME DEFAULT CURRENT_TIMESTAMP,
    `update_time` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    `create_by` BIGINT,
    `update_by` BIGINT,
    `is_deleted` TINYINT DEFAULT 0,

    PRIMARY KEY (`id`),
    KEY `idx_order_draft_operator_id` (`operator_id`),
    KEY `idx_order_draft_status` (`status`),
    KEY `idx_order_draft_expires_at` (`expires_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单草稿表';
```

**设计要点**：
1. **无订单编号**：草稿阶段不生成编号，提交时由 CodeGeneratorService 生成
2. **无 phase/status**：草稿阶段不需要状态机，提交后转入正式订单
3. **expires_at**：用于30天过期管理
4. **operator_id**：索引字段，用于查询"我的草稿"

```java
public void validateSubmitPreconditions(Long orderId) {

    boolean imageRequired = Boolean.parseBoolean(

        // 校验影像数据（dict_code=10.1）和影像报告（dict_code=10.2）是否已上传
        boolean hasImageData = checkFileCategory(orderId, FileBizTypeEnum.IMAGE_DATA);

        if (!hasImageData) {

        }
        if (!hasImageReport) {
            throw new BusinessException(ErrorCodeEnum.ORDER_FILE_REQUIRED, "请上传影像报告");
        }
    }
}
```

### 7.1 草稿提交流程

```
1. 用户点击"提交草稿"
      ↓
2. 校验前置条件
   ├── 校验必填字段（org_id, hospital_id, patient_name 等）
   ├── 校验 order_item_draft 至少1条
   └── 校验 file_detail 中存在 file_category=10.1（影像数据）和 10.2（影像报告）
      ↓
3. 生成订单编号（CodeGeneratorService）
      ↓
4. 开启事务
   ├── 创建 order_main（从 order_draft 复制）
   ├── 创建 order_item（从 order_item_draft 批量复制）
   ├── 创建/更新 order_file（关联到 order_main）
   ├── 更新 file_detail（object_type 更新为 order_main）
   ├── 更新 order_draft.status = 2（已提交）
   └── 记录状态历史（CREATE 动作）
      ↓
5. 提交事务
      ↓
6. 返回订单ID和订单编号
```

### 7.2 10分钟修改窗口期判断

```java
/**
 * 判断订单是否在提交后10分钟内
 */
public boolean isWithinModifyWindow(OrderMainEntity order) {
    if (order == null) return false;
    // 提交时间 + 10分钟 > 当前时间
    return order.getCreateTime()
        .plusMinutes(10)
        .isAfter(LocalDateTime.now());
}

/**
 * 判断用户是否可以修改订单
 */
public boolean canModify(Long orderId, Long currentUserId) {
    OrderMainEntity order = orderMapper.selectById(orderId);
    if (order == null) return false;

    // 1. 公司管理员可以直接修改
    if (hasAdminRole(currentUserId)) return true;

    // 2. 提单人或区域管理员，且在10分钟内
    if (isSubmitterOrRegionalManager(order, currentUserId)) {
        return isWithinModifyWindow(order);
    }

    return false;
}
```

## 十、异常处理

### 9.1 业务异常

使用 `BusinessException` 抛出业务异常，指定明确的错误码：

```java
// 抛出业务异常
throw new BusinessException(ErrorCodeEnum.ORDER_NOT_FOUND);
throw new BusinessException(ErrorCodeEnum.ORDER_STATUS_TRANSITION_ERROR);
throw new BusinessException(ErrorCodeEnum.ORDER_FILE_REQUIRED, "影像数据");
```

### 9.2 全局异常处理

统一使用 `GlobalExceptionHandler` 处理异常：

```java
// Controller 不处理异常，由 GlobalExceptionHandler 捕获
@PostMapping
public Result<Void> create(@Validated @RequestBody CreateOrderDTO dto) {
    orderService.createOrder(dto);
    return Result.success();
}
```
