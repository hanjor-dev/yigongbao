## 一、设计背景与目标

### 1.1 需求来源

基于三个核心业务流程文档的综合分析：
- 《业务流程1_订单创建.md》- 订单模块需求分析
- 《业务流程2_工单设计.md》- 工单设计阶段需求分析
- 《业务流程3_生产管理.md》- 生产管理模块需求分析

**核心设计理念**：
> "订单是唯一的数据实体，贯穿整个业务流程。工单和生产单都是订单在不同阶段的'状态表现'，而非独立数据。"

### 1.2 设计目标

1. **单一订单实体**：所有订单类型（医疗器械、非医疗器械、服务）共用同一订单数据
2. **阶段 + 状态管理**：通过 `phase` + `status` 组合精确定位流程节点
3. **完整流程追溯**：每次状态变更都记录历史，支持审计和统计
4. **清晰的代码结构**：状态转换规则集中定义，代码结构清晰易维护
5. **适度灵活性**：新增/删除状态只需修改一处，便于后续流程调整

### 1.3 设计方案选择

经过深入分析，我们对比了三种方案：

| 方案 | 描述 | 优点 | 缺点 | 适用场景 |
|------|------|------|------|----------|
| 方案A | 保持原设计 | 实现简单 | 逻辑分散，难以维护 | 需求非常稳定 |
| **方案B** | **数据库驱动** | **灵活可配置** | **需要维护配置表** | **需求频繁变化** |
| 方案C | 改进的枚举驱动 | 类型安全、结构清晰 | 需重新部署 | 偶尔改动 |

**最终选择：方案C（改进的枚举驱动方案）**

理由：
- 流程偶尔改动，但可接受部署更新
- 保持枚举类型安全，IDE 提供代码补全
- 代码结构清晰，新增状态只需修改一处
- 未来如需更灵活，可平滑升级为方案B

## 二、设计方案优化要点

### 2.1 原方案问题分析

#### 问题一：状态转换逻辑分散

原设计中，状态转换校验分散在三个位置：

```
OrderPhaseStatusMapping.getValidStatuses()      ← 有效状态列表
OrderStateMachine.validatePhaseTransition()    ← 阶段转换规则
OrderStateMachine.validateStatusTransition()   ← 阶段内状态转换
```

**问题**：新增/删除状态需要同时修改这三处，容易遗漏。

#### 问题二：switch 语句过长

`OrderStateMachine.validateStatusTransition()` 中的 switch 语句长达 170 行，包含 6 个阶段的转换规则。

**问题**：难以阅读和维护，容易引入 bug。

#### 问题三：表结构过于全面

原设计包含 12 张表，涵盖完整业务流程的每个细节。

**问题**：第一期实施工作量过大，可以区分核心功能与扩展功能分期实施。

### 2.2 优化方案

#### 优化一：状态转换规则集中定义

采用 **Map 数据结构** 集中定义所有转换规则，替代分散的 switch 语句：

```java
/**
 * 订单阶段转换规则
 * 定义阶段之间的跳转关系
 * Key: 当前阶段 → Value: 可跳转的目标阶段集合
 */
private static final Map<OrderPhaseEnum, Set<OrderPhaseEnum>> PHASE_TRANSITIONS = Map.of(
    OrderPhaseEnum.ORDER,      Set.of(OrderPhaseEnum.ORDER, OrderPhaseEnum.DESIGN),
    OrderPhaseEnum.DESIGN,     Set.of(OrderPhaseEnum.ORDER, OrderPhaseEnum.PRODUCTION, OrderPhaseEnum.COMPLETED),
    OrderPhaseEnum.PRODUCTION, Set.of(OrderPhaseEnum.QC),
    OrderPhaseEnum.QC,         Set.of(OrderPhaseEnum.WAREHOUSE, OrderPhaseEnum.PRODUCTION), // 返工可回到生产
    OrderPhaseEnum.WAREHOUSE,   Set.of(OrderPhaseEnum.COMPLETED),
    OrderPhaseEnum.COMPLETED,   Set.of() // 已完成不可跳转
);
```

```java
/**
 * 阶段内状态转换规则
 * 定义每个阶段内的状态流转关系
 * Key: (阶段, 当前状态) → Value: 可跳转的目标状态集合
 */
private static final Map<StatusKey, Set<OrderStatusEnum>> STATUS_TRANSITIONS = Map.ofEntries(
    // ========== 订单阶段 ==========
    entry(statusKey(ORDER, DRAFT), Set.of(PENDING_AUDIT)),
    entry(statusKey(ORDER, PENDING_AUDIT), Set.of(AUDIT_PASSED, AUDIT_REJECTED)),
    entry(statusKey(ORDER, AUDIT_PASSED), Set.of(PENDING_AUDIT)), // 撤回
    entry(statusKey(ORDER, AUDIT_REJECTED), Set.of(PENDING_AUDIT, DRAFT)),
    
    // ========== 设计阶段 ==========
    entry(statusKey(DESIGN, PENDING_DESIGN), Set.of(DESIGNING)),
    entry(statusKey(DESIGN, DESIGNING), Set.of(DESIGN_COMPLETED, PENDING_DESIGN)),
    entry(statusKey(DESIGN, DESIGN_COMPLETED), Set.of(DESIGN_REVIEW_PENDING)),
    entry(statusKey(DESIGN, DESIGN_REVIEW_PENDING), Set.of(DESIGN_REVIEW_PASSED, DESIGN_REVIEW_REJECTED)),
    entry(statusKey(DESIGN, DESIGN_REVIEW_REJECTED), Set.of(DESIGNING, DESIGN_COMPLETED)),
    
    // ... 其他阶段
);
```

**优势**：
- 规则集中在一处，便于查看全貌
- 新增状态只需在一处添加映射
- 可以生成可视化的状态流转图

#### 优化二：区分核心表与扩展表

| 类型 | 表 | 说明 | 实施阶段 |
|------|-----|------|----------|
| **核心表** | order | 订单主表 | 第一期 |
| | order_item | 订单明细表 | 第一期 |
| | order_file | 订单文件表 | 第一期 |
| | order_status_history | 状态历史表 | 第一期 |
| **扩展表** | order_design_info | 设计信息表 | 第二期 |
| | order_instruction | 指令单表 | 第二期 |
| | order_drawing | 图纸表 | 第二期 |
| | order_production_record | 生产作业记录表 | 第二期 |
| | order_qc_record | 质检记录表 | 第二期 |
| | order_audit_record | 审核记录表 | 第二期 |
| | order_modify_record | 修改申请记录表 | 第二期 |
| | order_sign_record | 电子签名记录表 | 第二期 |

**优势**：
- 第一期聚焦核心功能，降低实施风险
- 扩展功能可以独立迭代
- 便于评估开发优先级

### 4.2 状态枚举（OrderStatusEnum）

```java
package com.yigongbao.common.enums;

/**
 * 订单状态枚举
 * 定义每个阶段内的具体状态
 *
 * 状态码分段设计：
 * - 10-19: 订单阶段
 * - 20-29: 设计阶段
 * - 30-39: 打印阶段
 * - 40-49: 后处理阶段
 * - 50-59: 质检阶段
 * - 60-69: 仓储阶段
 * - 70-79: 确认阶段（服务订单特有）
 * - 80: 已完成
 *
 * 【重要】状态码不可重复，不同阶段独占不同码段
 *
 * @author hanjor
 * @date 2026-03-30
 */
@Getter
@AllArgsConstructor
public enum OrderStatusEnum {

    // ==================== 订单阶段（10-19）====================
    DRAFT(10, "草稿"),
    PENDING_DATA_AUDIT(11, "数据待审核"),
    DATA_AUDIT_PASSED(12, "数据审核通过"),
    DATA_AUDIT_REJECTED(13, "数据审核不通过"),

    // ==================== 设计阶段（20-29）====================
    DESIGNING(21, "设计中"),
    DESIGN_COMPLETED(22, "设计完成"),
    DESIGN_REVIEWING(23, "设计审核中"),
    DESIGN_REVIEW_PASSED(24, "设计审核通过"),  // 【不可见状态】审核通过后自动跳转，不在前端显示
    DESIGN_REVIEW_REJECTED(25, "设计审核不通过"),

    // ==================== 打印阶段（30-39）====================
    PENDING_PRINT(31, "待打印"),
    PRINTING(32, "打印中"),
    PRINT_COMPLETED(33, "打印完成"),

    // ==================== 后处理阶段（40-49）====================
    POST_PROCESSING(41, "后处理中"),

    // ==================== 质检阶段（50-59）====================
    QC_IN_PROGRESS(51, "质检中"),
    QC_PASSED(52, "质检合格"),
    QC_FAILED(53, "质检不合格"),
    REWORK(54, "返工"),  // 【注意】SCRAPPED报废状态已废弃，质检不合格仅允许返工

    // ==================== 仓储阶段（60-69）====================
    WAREHOUSE_IN(61, "入库中"),
    WAREHOUSED(62, "已入库"),

    // ==================== 确认阶段（70-79，服务订单专用）====================
    AWAITING_CONFIRM(71, "待客户确认"),

    // ==================== 已完成（80）====================
    COMPLETED(80, "已完成");

    private final Integer code;
    private final String name;

    /**
     * 根据code获取枚举
     */
    public static OrderStatusEnum getByCode(Integer code) {
        if (code == null) return null;
        return Arrays.stream(values())
            .filter(e -> e.code.equals(code))
            .findFirst()
            .orElse(null);
    }

    /**
     * 判断状态是否属于指定阶段
     */
    public boolean belongsTo(OrderPhaseEnum phase) {
        if (phase == null) return false;
        // 状态码分段与阶段码对应关系：
        // 阶段码 1 -> 码段 10-19
        // 阶段码 2 -> 码段 20-29
        // ...
        int codePrefix = this.code / 10;
        // 阶段码 7（确认阶段）对应码段 70-79
        if (phase == OrderPhaseEnum.CONFIRM) {
            return this.code >= 70 && this.code < 80;
        }
        // 阶段码 8（已完成）对应码段 80
        if (phase == OrderPhaseEnum.COMPLETED) {
            return this.code == 80;
        }
        return codePrefix == phase.getCode();
    }
}
```

## 五、状态转换规则设计（方案C核心）

### 5.1 设计思路

采用 **规则即数据** 的设计思想，将状态转换规则定义为静态 Map 数据结构，而非散落在多处的方法调用。

**核心组件**：

1. **OrderPhaseTransitionRules** - 阶段转换规则
2. **OrderStatusTransitionRules** - 阶段内状态转换规则
3. **OrderStateMachine** - 状态机核心（调用规则校验）

### 5.2 阶段转换规则

```java
package com.yigongbao.module.order.service.rules;

/**
 * 订单阶段转换规则
 * 定义阶段之间的跳转关系
 *
 * 设计原则：
 * - 阶段通常只能向前推进（ORDER → DESIGN → ... → COMPLETED）
 * - 驳回操作可以回到上一阶段（DESIGN → ORDER）
 * - 返工操作可以回到打印阶段（QC → PRINT）
 * - 服务订单不经过打印/后处理/质检/仓储阶段
 *
 * 医疗器械/非医疗器械流程：
 *   ORDER → DESIGN → PRINT → POST_PROCESSING → QC → WAREHOUSE → COMPLETED
 *
 * 服务订单流程：
 *   ORDER → DESIGN → CONFIRM → COMPLETED
 *
 * @author hanjor
 * @date 2026-03-30
 */
public class OrderPhaseTransitionRules {
    
    /**
     * 阶段转换规则
     * Key: 当前阶段 → Value: 可跳转的目标阶段集合
     */
    private static final Map<OrderPhaseEnum, Set<OrderPhaseEnum>> PHASE_TRANSITIONS = Map.of(
        // 订单阶段：保持在订单阶段，或进入设计阶段
        ORDER, Set.of(ORDER, DESIGN),

        // 设计阶段：可以驳回订单阶段，或进入打印阶段（医疗器械/非医疗器械）
        // 或进入确认阶段（服务订单）
        DESIGN, Set.of(ORDER, PRINT, CONFIRM),

        // 打印阶段：只能进入后处理阶段
        PRINT, Set.of(POST_PROCESSING),

        // 后处理阶段：只能进入质检阶段
        POST_PROCESSING, Set.of(QC),

        // 质检阶段：可以进入仓储阶段，或返工回到打印阶段
        QC, Set.of(WAREHOUSE, PRINT),

        // 仓储阶段：只能进入已完成
        WAREHOUSE, Set.of(COMPLETED),

        // 确认阶段（服务订单）：只能进入已完成
        CONFIRM, Set.of(COMPLETED),

        // 已完成：不可跳转
        COMPLETED, Set.of()
    );
    
    /**
     * 判断阶段转换是否合法
     *
     * @param fromPhase 当前阶段
     * @param toPhase   目标阶段
     * @param orderType 订单类型（用于判断服务订单是否可进入生产/质检/仓储）
     * @return 是否合法
     */
    public static boolean isValidPhaseTransition(
            OrderPhaseEnum fromPhase,
            OrderPhaseEnum toPhase,
            OrderTypeEnum orderType) {
        
        // 已完成状态不可跳转
        if (fromPhase == COMPLETED) {
            return false;
        }
        
        // 服务订单不能进入打印/后处理/质检/仓储阶段
        if (orderType == SERVICE) {
            if (toPhase == PRINT || toPhase == POST_PROCESSING
                || toPhase == QC || toPhase == WAREHOUSE) {
                return false;
            }
        }
        
        // 校验阶段转换是否在允许范围内
        Set<OrderPhaseEnum> allowedPhases = PHASE_TRANSITIONS.getOrDefault(fromPhase, Set.of());
        return allowedPhases.contains(toPhase);
    }
    
    /**
     * 获取指定阶段的下一个默认阶段
     * 用于阶段推进时的自动跳转
     *
     * @param currentPhase 当前阶段
     * @param orderType    订单类型
     * @return 下一个阶段，如果没有则返回null
     */
    public static OrderPhaseEnum getNextPhase(OrderPhaseEnum currentPhase, OrderTypeEnum orderType) {
        return switch (currentPhase) {
            case ORDER -> DESIGN;
            case DESIGN -> orderType == SERVICE ? CONFIRM : PRINT;
            case PRINT -> POST_PROCESSING;
            case POST_PROCESSING -> QC;
            case QC -> WAREHOUSE;
            case WAREHOUSE -> COMPLETED;
            case CONFIRM -> COMPLETED;
            case COMPLETED -> null;
        };
    }
}
```

### 5.3 阶段内状态转换规则

```java
package com.yigongbao.module.order.service.rules;

/**
 * 订单阶段内状态转换规则
 * 定义每个阶段内的状态流转关系
 *
 * 【核心改进】：所有转换规则集中定义，清晰易维护
 * 新增/删除状态只需修改此文件
 *
 * 【设计审核通过的不可见状态】：
 * - DESIGN_REVIEW_PASSED(24) 为不可见状态
 * - 审核通过后系统自动将订单推进到下一阶段
 * - order_status_history 表中仍记录完整的审核通过动作，便于追溯
 * - 前端不显示"设计审核通过"这个状态
 *
 * @author hanjor
 * @date 2026-03-30
 */
public class OrderStatusTransitionRules {

    /**
     * 状态转换规则
     * Key: (阶段, 当前状态) → Value: 可跳转的目标状态集合
     */
    private static final Map<StatusKey, Set<OrderStatusEnum>> STATUS_TRANSITIONS;

    static {
        Map<StatusKey, Set<OrderStatusEnum>> transitions = new HashMap<>();

        // ==================== 订单阶段状态转换（10-19）====================
        // 草稿 → 提交后进入数据待审核
        transitions.put(statusKey(ORDER, DRAFT), Set.of(PENDING_DATA_AUDIT));

        // 数据待审核 → 数据审核通过或被拒
        transitions.put(statusKey(ORDER, PENDING_DATA_AUDIT),
            Set.of(DATA_AUDIT_PASSED, DATA_AUDIT_REJECTED));

        // 数据审核通过 → 可撤回重审
        transitions.put(statusKey(ORDER, DATA_AUDIT_PASSED), Set.of(PENDING_DATA_AUDIT));

        // 数据审核不通过 → 可重新提交
        // 【重要】撤回草稿不再允许，直接重新提交审核
        transitions.put(statusKey(ORDER, DATA_AUDIT_REJECTED), Set.of(PENDING_DATA_AUDIT));

        // ==================== 设计阶段状态转换（20-29）====================
        // 设计中 → 完成设计
        transitions.put(statusKey(DESIGN, DESIGNING), Set.of(DESIGN_COMPLETED));

        // 设计完成 → 提交设计审核
        transitions.put(statusKey(DESIGN, DESIGN_COMPLETED), Set.of(DESIGN_REVIEWING));

        // 设计审核中 → 审核通过或被拒
        transitions.put(statusKey(DESIGN, DESIGN_REVIEWING),
            Set.of(DESIGN_REVIEW_PASSED, DESIGN_REVIEW_REJECTED));

        // 设计审核不通过 → 重新设计
        transitions.put(statusKey(DESIGN, DESIGN_REVIEW_REJECTED), Set.of(DESIGNING));

        // ==================== 打印阶段状态转换（30-39）====================
        // 待打印 → 开始打印
        transitions.put(statusKey(PRINT, PENDING_PRINT), Set.of(PRINTING));

        // 打印中 → 完成打印
        transitions.put(statusKey(PRINT, PRINTING), Set.of(PRINT_COMPLETED));

        // 打印完成 → 自动进入后处理阶段（用户点击"完成打印"后系统自动推进阶段）
        // 注意：PRINT_COMPLETED 作为可见状态，阶段切换由 OrderPhaseTransitionRules.getNextPhase 处理

        // ==================== 后处理阶段状态转换（40-49）====================
        // 后处理中 → 完成后处理（自动进入质检阶段）
        transitions.put(statusKey(POST_PROCESSING, POST_PROCESSING), Set.of(QC_IN_PROGRESS));

        // ==================== 质检阶段状态转换（50-59）====================
        // 质检中 → 合格或不合格
        transitions.put(statusKey(QC, QC_IN_PROGRESS), Set.of(QC_PASSED, QC_FAILED));

        // 质检合格 → 进入入库
        transitions.put(statusKey(QC, QC_PASSED), Set.of(WAREHOUSE_IN));

        // 质检不合格 → 【仅允许返工，不再允许报废】
        transitions.put(statusKey(QC, QC_FAILED), Set.of(REWORK));

        // 返工 → 回到待打印
        transitions.put(statusKey(QC, REWORK), Set.of(PENDING_PRINT));

        // ==================== 仓储阶段状态转换（60-69）====================
        // 入库中 → 完成入库
        transitions.put(statusKey(WAREHOUSE, WAREHOUSE_IN), Set.of(WAREHOUSED));

        // 已入库 → 订单完成
        transitions.put(statusKey(WAREHOUSE, WAREHOUSED), Set.of(COMPLETED));

        // 确认阶段状态转换（70-79，服务订单专用）
        // 待客户确认 → 完成（用户确认）
        transitions.put(statusKey(CONFIRM, AWAITING_CONFIRM), Set.of(COMPLETED));

        STATUS_TRANSITIONS = Map.copyOf(transitions);
    }

    /**
     * 判断状态转换是否合法
     *
     * @param phase         当前阶段
     * @param currentStatus 当前状态
     * @param targetStatus  目标状态
     * @param orderType     订单类型
     * @return 是否合法
     */
    public static boolean isValidStatusTransition(
            OrderPhaseEnum phase,
            OrderStatusEnum currentStatus,
            OrderStatusEnum targetStatus,
            OrderTypeEnum orderType) {

        // 获取当前状态允许的下一状态集合
        Set<OrderStatusEnum> allowedStatuses = STATUS_TRANSITIONS.get(
            statusKey(phase, currentStatus));

        if (allowedStatuses == null || allowedStatuses.isEmpty()) {
            return false;
        }

        // 特殊处理：设计审核通过后的跳转根据订单类型不同（不可见状态）
        if (currentStatus == DESIGN_REVIEW_PASSED) {
            if (orderType == SERVICE) {
                return targetStatus == AWAITING_CONFIRM;
            } else {
                return targetStatus == PENDING_PRINT;
            }
        }

        return allowedStatuses.contains(targetStatus);
    }

    /**
     * 获取当前状态允许的下一状态集合
     *
     * @param phase         当前阶段
     * @param currentStatus 当前状态
     * @param orderType     订单类型
     * @return 允许的目标状态集合
     */
    public static Set<OrderStatusEnum> getAllowedNextStatuses(
            OrderPhaseEnum phase,
            OrderStatusEnum currentStatus,
            OrderTypeEnum orderType) {

        Set<OrderStatusEnum> allowed = new HashSet<>();

        // 获取基础允许状态
        Set<OrderStatusEnum> baseAllowed = STATUS_TRANSITIONS.get(
            statusKey(phase, currentStatus));
        if (baseAllowed != null) {
            allowed.addAll(baseAllowed);
        }

        // 特殊处理：设计审核通过（不可见状态）
        if (currentStatus == DESIGN_REVIEW_PASSED) {
            allowed.remove(DESIGN_REVIEW_PASSED); // 移除自身
            if (orderType == SERVICE) {
                allowed.add(AWAITING_CONFIRM);
            } else {
                allowed.add(PENDING_PRINT);
            }
        }

        return Collections.unmodifiableSet(allowed);
    }

    /**
     * 获取阶段的有效状态列表
     * 用于校验目标状态是否属于指定阶段
     *
     * 【注意】：
     * - DESIGN_REVIEW_PASSED 不在列表中（不可见状态）
     * - AWAITING_CONFIRM 仅服务订单可见
     *
     * @param phase     阶段
     * @param orderType 订单类型
     * @return 有效状态集合
     */
    public static Set<OrderStatusEnum> getValidStatusesForPhase(
            OrderPhaseEnum phase, OrderTypeEnum orderType) {

        return switch (phase) {
            // 订单阶段：所有订单类型都相同
            case ORDER -> Set.of(DRAFT, PENDING_DATA_AUDIT, DATA_AUDIT_PASSED, DATA_AUDIT_REJECTED);

            // 设计阶段：所有订单类型都相同
            // 注意：DESIGN_REVIEW_PASSED 为不可见状态，不包含在可见状态列表中
            case DESIGN -> Set.of(DESIGNING, DESIGN_COMPLETED, DESIGN_REVIEWING,
                DESIGN_REVIEW_REJECTED, AWAITING_CONFIRM);

            // 打印阶段：仅医疗器械和非医疗器械
            case PRINT -> orderType == SERVICE
                ? Set.of()
                : Set.of(PENDING_PRINT, PRINTING, PRINT_COMPLETED);

            // 后处理阶段：仅医疗器械和非医疗器械
            case POST_PROCESSING -> orderType == SERVICE
                ? Set.of()
                : Set.of(POST_PROCESSING);

            // 质检阶段：仅医疗器械和非医疗器械
            case QC -> orderType == SERVICE
                ? Set.of()
                : Set.of(QC_IN_PROGRESS, QC_PASSED, QC_FAILED, REWORK);

            // 仓储阶段：仅医疗器械和非医疗器械
            case WAREHOUSE -> orderType == SERVICE
                ? Set.of()
                : Set.of(WAREHOUSE_IN, WAREHOUSED);

            // 确认阶段：仅服务订单
            case CONFIRM -> orderType == SERVICE
                ? Set.of(AWAITING_CONFIRM)
                : Set.of();

            // 已完成阶段：所有订单类型都相同
            case COMPLETED -> Set.of(COMPLETED);
        };
    }

    /**
     * 创建状态键（用于Map的key）
     */
    private static StatusKey statusKey(OrderPhaseEnum phase, OrderStatusEnum status) {
        return new StatusKey(phase, status);
    }

    /**
     * 状态键内部类
     * 用于作为Map的key
     */
    private record StatusKey(OrderPhaseEnum phase, OrderStatusEnum status) {}
}
```

### 5.4 状态机核心服务

```java
package com.yigongbao.module.order.service;

import com.yigongbao.common.enums.*;
import com.yigongbao.common.exception.BusinessException;
import com.yigongbao.module.order.service.rules.OrderPhaseTransitionRules;
import com.yigongbao.module.order.service.rules.OrderStatusTransitionRules;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Service;

import java.util.Set;

/**
 * 订单状态机核心服务
 * 负责校验订单状态转换的合法性
 * 
 * 【设计原则】：
 * - 状态转换规则定义在 OrderPhaseTransitionRules 和 OrderStatusTransitionRules 中
 * - 本类仅负责调用规则进行校验，不包含具体规则逻辑
 * - 规则即数据，便于维护和扩展
 *
 * @author hanjor
 * @date 2026-03-30
 */
@Service
@Slf4j
public class OrderStateMachine {
    
    /**
     * 校验状态转换是否合法
     *
     * @param order         订单实体
     * @param targetPhase   目标阶段
     * @param targetStatus  目标状态
     * @throws BusinessException 非法转换时抛出
     */
    public void validateTransition(
            OrderEntity order,
            OrderPhaseEnum targetPhase,
            OrderStatusEnum targetStatus) {
        
        OrderPhaseEnum currentPhase = OrderPhaseEnum.getByCode(order.getPhase());
        OrderStatusEnum currentStatus = OrderStatusEnum.getByCode(order.getStatus());
        OrderTypeEnum orderType = OrderTypeEnum.getByCode(order.getOrderType());
        
        log.info("校验状态转换，orderId={}, currentPhase={}, currentStatus={}, targetPhase={}, targetStatus={}",
            order.getId(), currentPhase, currentStatus, targetPhase, targetStatus);
        
        // 1. 校验目标阶段是否有效
        if (targetPhase == null || targetStatus == null) {
            throw new BusinessException("目标阶段或状态不能为空");
        }
        
        // 2. 校验目标状态是否属于目标阶段
        Set<OrderStatusEnum> validStatuses = OrderStatusTransitionRules
            .getValidStatusesForPhase(targetPhase, orderType);
        if (!validStatuses.contains(targetStatus)) {
            throw new BusinessException("目标状态不属于目标阶段");
        }
        
        // 3. 校验阶段转换是否合法
        if (!OrderPhaseTransitionRules.isValidPhaseTransition(currentPhase, targetPhase, orderType)) {
            throw new BusinessException("阶段转换不合法");
        }
        
        // 4. 校验阶段内状态转换是否合法
        if (currentPhase == targetPhase) {
            // 同阶段内状态转换
            if (!OrderStatusTransitionRules.isValidStatusTransition(
                    currentPhase, currentStatus, targetStatus, orderType)) {
                throw new BusinessException("状态转换不合法");
            }
        } else {
            // 跨阶段转换：校验目标阶段的初始状态是否正确
            OrderStatusEnum expectedInitialStatus = getInitialStatusForPhase(targetPhase);
            if (targetStatus != expectedInitialStatus) {
                // 允许跳过初始状态的情况（如驳回直接回到上一阶段）
                if (!isAllowedToSkipInitialStatus(currentPhase, targetPhase, currentStatus)) {
                    throw new BusinessException("跨阶段转换时，目标状态应为该阶段的初始状态");
                }
            }
        }
        
        log.info("状态转换校验通过");
    }
    
    /**
     * 获取指定阶段的初始状态
     */
    private OrderStatusEnum getInitialStatusForPhase(OrderPhaseEnum phase) {
        return switch (phase) {
            case ORDER -> OrderStatusEnum.DRAFT;
            case DESIGN -> OrderStatusEnum.DESIGNING;  // 设计阶段初始为"设计中"
            case PRINT -> OrderStatusEnum.PENDING_PRINT;
            case POST_PROCESSING -> OrderStatusEnum.POST_PROCESSING;
            case QC -> OrderStatusEnum.QC_IN_PROGRESS;
            case WAREHOUSE -> OrderStatusEnum.WAREHOUSE_IN;
            case CONFIRM -> OrderStatusEnum.AWAITING_CONFIRM;
            case COMPLETED -> OrderStatusEnum.COMPLETED;
        };
    }

    /**
     * 判断是否允许跳过阶段初始状态
     * 通常是驳回操作允许直接回到上一阶段
     */
    private boolean isAllowedToSkipInitialStatus(
            OrderPhaseEnum currentPhase,
            OrderPhaseEnum targetPhase,
            OrderStatusEnum currentStatus) {

        // 设计审核不通过 → 回到设计阶段继续设计
        if (currentPhase == DESIGN && targetPhase == DESIGN
            && currentStatus == DESIGN_REVIEW_REJECTED) {
            return true;
        }

        // 数据审核不通过 → 重新提交审核
        if (currentPhase == ORDER && targetPhase == ORDER
            && currentStatus == DATA_AUDIT_REJECTED) {
            return true;
        }

        // 数据审核通过 → 撤回重审
        if (currentPhase == ORDER && targetPhase == ORDER
            && currentStatus == DATA_AUDIT_PASSED) {
            return true;
        }

        // 返工 → 回到待打印（跨阶段转换：质检 → 打印）
        if (currentPhase == QC && targetPhase == PRINT
            && currentStatus == REWORK) {
            return true;
        }

        return false;
    }
    
    /**
     * 获取当前状态允许的操作
     * 用于前端展示可执行的操作按钮
     *
     * @param order 订单实体
     * @return 允许的操作列表
     */
    public Set<OrderActionEnum> getAllowedActions(OrderEntity order) {
        OrderPhaseEnum currentPhase = OrderPhaseEnum.getByCode(order.getPhase());
        OrderStatusEnum currentStatus = OrderStatusEnum.getByCode(order.getStatus());
        OrderTypeEnum orderType = OrderTypeEnum.getByCode(order.getOrderType());

        Set<OrderActionEnum> actions = new java.util.HashSet<>();

        // 根据当前状态添加允许的操作
        switch (currentStatus) {
            // ==================== 订单阶段 ====================
            case DRAFT -> {
                actions.add(OrderActionEnum.SUBMIT_ORDER);
                actions.add(OrderActionEnum.CANCEL);
            }
            case PENDING_DATA_AUDIT -> {
                actions.add(OrderActionEnum.DATA_AUDIT_PASS);
                actions.add(OrderActionEnum.DATA_AUDIT_REJECT);
                actions.add(OrderActionEnum.WITHDRAW);
            }
            case DATA_AUDIT_PASSED -> {
                // 数据审核通过后可撤回重审
                actions.add(OrderActionEnum.WITHDRAW);
            }
            case DATA_AUDIT_REJECTED -> {
                // 数据审核不通过后可重新提交
                actions.add(OrderActionEnum.RESUBMIT);
            }

            // ==================== 设计阶段 ====================
            case DESIGNING -> {
                actions.add(OrderActionEnum.SUBMIT_DESIGN);
            }
            case DESIGN_COMPLETED -> {
                // 设计完成待提交审核（如果需要手动提交）
                actions.add(OrderActionEnum.SUBMIT_DESIGN);
            }
            case DESIGN_REVIEWING -> {
                actions.add(OrderActionEnum.DESIGN_REVIEW_PASS);
                actions.add(OrderActionEnum.DESIGN_REVIEW_REJECT);
            }
            case DESIGN_REVIEW_REJECTED -> {
                // 设计审核不通过后可重新开始设计
                actions.add(OrderActionEnum.START_DESIGN);
            }
            // 注意：DESIGN_REVIEW_PASSED 为不可见状态，不在前端显示

            // ==================== 服务订单确认阶段 ====================
            case AWAITING_CONFIRM -> {
                // 仅服务订单显示客户确认按钮
                if (orderType == SERVICE) {
                    actions.add(OrderActionEnum.USER_CONFIRM);
                }
            }

            // ==================== 打印阶段（仅医疗器械/非医疗器械）====================
            case PENDING_PRINT -> {
                if (orderType != SERVICE) {
                    actions.add(OrderActionEnum.START_PRINT);
                }
            }
            case PRINTING -> {
                actions.add(OrderActionEnum.COMPLETE_PRINT);
            }
            // PRINT_COMPLETED 为过渡状态，用户点击后系统自动推进

            // ==================== 后处理阶段 ====================
            case POST_PROCESSING -> {
                // 后处理完成自动进入质检
                actions.add(OrderActionEnum.COMPLETE_POST_PROCESSING);
            }

            // ==================== 质检阶段（仅医疗器械/非医疗器械）====================
            case QC_IN_PROGRESS -> {
                actions.add(OrderActionEnum.QC_PASS);
                actions.add(OrderActionEnum.QC_FAIL);
            }
            case QC_FAILED -> {
                // 【重要】质检不合格仅允许返工，不再允许报废
                actions.add(OrderActionEnum.REWORK);
            }
            case REWORK -> {
                // 返工状态可查看，当前不需要额外操作
            }

            // ==================== 仓储阶段（仅医疗器械/非医疗器械）====================
            case WAREHOUSE_IN -> {
                actions.add(OrderActionEnum.COMPLETE_WAREHOUSE_IN);
            }

            default -> {}
        }

        return actions;
    }
}
```

### 5.5 新增/修改状态的操作示例

#### 示例：新增"设计暂停"状态

**只需修改 `OrderStatusTransitionRules` 一处：**

```java
// 1. 在 OrderStatusEnum 中添加新状态
DESIGN_PAUSED(26, "设计暂停"),

// 2. 在 OrderStatusTransitionRules 中添加转换规则
// 设计中 → 可以暂停
transitions.put(statusKey(DESIGN, DESIGNING), 
    Set.of(DESIGN_COMPLETED, PENDING_DESIGN, DESIGN_PAUSED));

// 设计暂停 → 可以继续设计
transitions.put(statusKey(DESIGN, DESIGN_PAUSED), Set.of(DESIGNING));

// 3. 在 OrderStateMachine.getAllowedActions() 中添加操作
case DESIGN_PAUSED -> {
    actions.add(OrderActionEnum.RESUME_DESIGN);
}
```

**无需修改**：
- `OrderPhaseTransitionRules`
- `OrderStateMachine.validateTransition()` 中的 switch 语句

### 7.1 状态转换服务调用

```java
/**
 * 提交订单
 *
 * @param orderId 订单ID
 */
@Override
@Transactional(rollbackFor = Exception.class)
public void submitOrder(Long orderId) {
    log.info("提交订单，orderId={}", orderId);

    OrderEntity order = orderMapper.selectById(orderId);
    if (order == null) {
        throw new BusinessException(ErrorCodeEnum.DATA_NOT_FOUND);
    }

    // 校验状态转换：ORDER.DRAFT → ORDER.PENDING_DATA_AUDIT
    orderStateMachine.validateTransition(
        order,
        OrderPhaseEnum.ORDER,
        OrderStatusEnum.PENDING_DATA_AUDIT
    );

    // 执行状态更新
    OrderPhaseEnum oldPhase = OrderPhaseEnum.getByCode(order.getPhase());
    OrderStatusEnum oldStatus = OrderStatusEnum.getByCode(order.getStatus());
    
    order.setPhase(OrderPhaseEnum.ORDER.getCode());
    order.setStatus(OrderStatusEnum.PENDING_DATA_AUDIT.getCode());
    orderMapper.updateById(order);

    // 记录状态历史
    orderStatusHistoryService.recordTransition(
        order,
        oldPhase, OrderPhaseEnum.ORDER,
        oldStatus, OrderStatusEnum.PENDING_DATA_AUDIT,
        OrderActionEnum.SUBMIT_ORDER,
        "提交订单"
    );

    log.info("订单提交成功，orderId={}", orderId);
}
```

## 十、设计优势总结

### 10.1 相比原方案的改进

| 维度 | 原方案 | 改进后（方案C） |
|------|--------|-----------------|
| 状态转换规则 | 分散在3处 | 集中在2个规则类 |
| 代码结构 | 170行switch语句 | Map数据结构，规则即数据 |
| 新增状态 | 修改3处 | 仅修改1处 |
| 表结构 | 12张表一次实施 | 4张核心表 + 8张扩展表分期实施 |
| 代码可读性 | 较难理解全貌 | 规则一目了然 |

### 10.2 方案C的核心优势

1. **规则集中**：所有转换规则定义在 `OrderStatusTransitionRules` 中，新增/修改状态只需改动一处
2. **类型安全**：仍然使用枚举，IDE 提供代码补全和类型检查
3. **易于测试**：规则是纯数据，可以轻松测试所有转换路径
4. **可视化友好**：规则结构清晰，可以生成状态流转图
5. **可扩展**：未来如需更灵活，可平滑升级为数据库驱动方案

### 10.3 灵活性评估

| 变更场景 | 需修改位置 | 工作量 |
|----------|------------|--------|
| 新增状态 | OrderStatusTransitionRules + OrderStatusEnum | 小 |
| 删除状态 | OrderStatusTransitionRules + OrderStatusEnum | 小 |
| 调整状态流转顺序 | OrderStatusTransitionRules | 小 |
| 新增阶段 | OrderPhaseTransitionRules + OrderPhaseEnum + OrderStatusTransitionRules | 中 |
| 删除阶段 | 同上 | 中 |

## 十一、状态修改操作手册

本章节详细说明在系统运行后，如何对订单状态进行新增、修改、删除等操作，以及相应的代码修改指引。

### 11.1 代码修改原则

**核心原则**：所有状态转换规则集中在 `OrderStatusTransitionRules` 类中定义，新增/修改状态只需修改一处。

```
修改优先级：
1. OrderStatusTransitionRules.java  ← 状态转换规则（必须）
2. OrderStatusEnum.java            ← 状态枚举（新增/删除状态时必须）
3. OrderActionEnum.java           ← 动作枚举（新增动作时必须）
4. OrderStateMachine.java         ← 操作映射（新增状态时必须）
```

### 11.2 场景一：新增状态

#### 场景1.1：在现有阶段中新增一个状态

**场景描述**：在设计阶段中新增"设计暂停"状态，设计中可以暂停，暂停后可以继续。

**修改步骤**：

**Step 1：添加状态枚举**

```java
// 文件：OrderStatusEnum.java
// 在设计阶段状态区域添加（注意保持状态码顺序）

// ==================== 设计阶段（20-29）====================
PENDING_DESIGN(20, "待设计"),
DESIGNING(21, "设计中"),
DESIGN_PAUSED(22, "设计暂停"),      // 【新增】注意：原22改为21，新状态码需要往后顺延
DESIGN_COMPLETED(23, "设计完成"),   // 【顺延】原22→23
DESIGN_REVIEW_PENDING(24, "设计待审核"), // 【顺延】原23→24
DESIGN_REVIEW_PASSED(25, "设计审核通过"), // 【顺延】原24→25
DESIGN_REVIEW_REJECTED(26, "设计审核不通过"); // 【顺延】原25→26
```

**Step 2：更新状态转换规则**

```java
// 文件：OrderStatusTransitionRules.java
// static 块中添加新的转换规则

// 设计中 → 完成设计、取消、或暂停
transitions.put(statusKey(DESIGN, DESIGNING), Set.of(
    DESIGN_COMPLETED,
    PENDING_DESIGN,
    DESIGN_PAUSED  // 【新增】新增：设计中可以暂停
));

// 【新增】设计暂停 → 可以继续设计
transitions.put(statusKey(DESIGN, DESIGN_PAUSED), Set.of(DESIGNING));

// 注意：如果状态码顺延，需要同步修改其他地方的引用
```

**Step 3：更新 getValidStatusesForPhase 方法**

```java
// 文件：OrderStatusTransitionRules.java
// 在 getValidStatusesForPhase 方法中添加新状态

case DESIGN -> Set.of(
    PENDING_DESIGN,
    DESIGNING,
    DESIGN_PAUSED,  // 【新增】
    DESIGN_COMPLETED,
    DESIGN_REVIEW_PENDING,
    DESIGN_REVIEW_PASSED,
    DESIGN_REVIEW_REJECTED,
    PENDING_CONFIRM
);
```

**Step 4：添加动作枚举（可选）**

```java
// 文件：OrderActionEnum.java
// 如果新状态需要特定动作，添加动作枚举

PAUSE_DESIGN("PAUSE_DESIGN", "暂停设计"),
RESUME_DESIGN("RESUME_DESIGN", "继续设计"),
```

**Step 5：更新状态机操作映射**

```java
// 文件：OrderStateMachine.java
// 在 getAllowedActions 方法中添加操作映射

case DESIGNING -> {
    actions.add(OrderActionEnum.SUBMIT_DESIGN);
    actions.add(OrderActionEnum.PAUSE_DESIGN);  // 【新增】
}

case DESIGN_PAUSED -> {  // 【新增】
    actions.add(OrderActionEnum.RESUME_DESIGN);
}
```

**Step 6：更新后续状态码引用**

如果状态码顺延，需要同步修改以下位置：
- `OrderStatusTransitionRules` 中所有使用旧状态码的地方
- `OrderStateMachine` 中所有使用旧状态码的地方

#### 场景1.2：新增跨阶段的状态

**场景描述**：新增"生产挂起"状态，当生产过程中出现问题时挂起，挂起后可继续或取消。

**修改步骤**：

**Step 1：添加状态枚举**

```java
// ==================== 质检阶段（40-49）====================
QC_IN_PROGRESS(40, "质检中"),          // 【顺延】原40→40

// ... 以此类推，所有后续阶段的状态码都需要顺延
```

**Step 2：更新阶段转换规则**

```java
// 文件：OrderPhaseTransitionRules.java
// 质检阶段是从生产阶段进入的，如果生产完成状态码变了，需要检查
```

**Step 4：同步更新后续状态码**

这是跨阶段新增最复杂的地方，需要顺延所有受影响的状态码。

### 11.3 场景二：删除状态

#### 场景2.1：删除一个状态（不影响其他状态码）

**场景描述**：删除"设计审核"环节，设计师完成设计后直接进入生产，无需审核。

**修改步骤**：

**Step 1：确定是否有状态码冲突**

由于删除 DESIGN_REVIEW_PENDING(23)、DESIGN_REVIEW_PASSED(24)、DESIGN_REVIEW_REJECTED(25)，需要决定：
- **方案A**：保持空码（不推荐，可能混淆）
- **方案B**：状态码顺延填补空缺（推荐）

**方案B的操作步骤**：

**Step 1：修改枚举**

```java
// 文件：OrderStatusEnum.java
// 删除审核相关状态，保留状态码顺序

// ==================== 设计阶段（20-29）====================
PENDING_DESIGN(20, "待设计"),
DESIGNING(21, "设计中"),
DESIGN_COMPLETED(22, "设计完成"),  // 原来的23，去掉了"待审核"
// 【删除】原 DESIGN_REVIEW_PENDING(23)
// 【删除】原 DESIGN_REVIEW_PASSED(24)
// 【删除】原 DESIGN_REVIEW_REJECTED(25)
// 保留22作为最后一个设计阶段状态
```

**Step 2：修改状态转换规则**

```java
// 文件：OrderStatusTransitionRules.java

// 设计完成 → 直接进入待生产（跳过审核）
transitions.put(statusKey(DESIGN, DESIGN_COMPLETED), Set.of(PENDING_PRODUCTION));

// 【删除】所有与审核相关的转换规则
// transitions.remove(statusKey(DESIGN, DESIGN_REVIEW_PENDING));
// transitions.remove(statusKey(DESIGN, DESIGN_REVIEW_PASSED));
```

### 11.8 常见问题处理

#### 问题1：状态码不连续

**问题描述**：删除某个状态后，出现状态码间隙（如 22 被删除，后面的码不连续）。

**解决方案**：
- **保持不连续**：如果业务上不影响，可以保持不连续（推荐，简单）
- **重新编码**：如果需要连续编码，必须全部重新编号，工作量大

#### 问题2：状态码冲突

**问题描述**：新增状态时，与其他阶段的状态码冲突。

**解决方案**：
- 重新规划状态码分配，预留空间
- 例如：每个阶段预留 20 个状态码（0-19 保留给更细粒度的子状态）

#### 问题3：历史数据兼容性

**问题描述**：修改状态后，历史订单的状态如何处理。

**解决方案**：
- 数据库中的状态码保持不变（数字不变，名称可以更新）
- 新代码需要兼容旧数据
- 可以编写数据迁移脚本批量更新

#### 问题4：并发修改冲突

**问题描述**：两个管理员同时修改同一订单的状态。

**解决方案**：
- 在 `OrderStateMachine.validateTransition()` 中添加乐观锁检查
- 或在 Service 层添加分布式锁

### 11.9 最佳实践

1. **状态码预留空间**：设计时为每个阶段预留足够的状态码，避免后续调整
2. **避免频繁修改状态码**：状态码一旦确定，尽量通过新增状态而非修改状态码
3. **保持向后兼容**：修改时考虑历史数据兼容性
4. **及时更新文档**：修改后同步更新本手册和代码注释
5. **充分测试**：修改状态后必须进行全面的回归测试
