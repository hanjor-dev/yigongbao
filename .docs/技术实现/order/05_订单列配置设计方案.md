# 订单列配置设计方案

**文档版本**：1.0  
**创建时间**：2026-04-13  
**涉及文件**：`sql/init.sql`

---

## 一、问题背景

`sys_config` 表中 `order.column.config` 配置项存在两个独立问题：

### 问题 A：格式与代码不匹配（配置实际不生效）

`init.sql` 存储的是旧格式：
```json
{"id":true,"orderNo":true,"hospitalName":true,"patientName":true,"statusName":true,"createTime":true}
```

而代码 `OrderQueryHelper.getSystemDefaultColumnConfig()` 使用：
```java
objectMapper.readValue(configJson, OrderColumnConfigVO.class)
```

`OrderColumnConfigVO` 的结构为：
```json
{
  "module": "order",
  "columns": [{"field":"...", "label":"...", "visible":true, "sort":1, "width":null, "fixed":null}]
}
```

两者格式不匹配，反序列化后 `columns=null`，**系统默认列配置完全失效**。

### 问题 B：字段不完整且有错误

- 仅配置了 6 个字段，`OrderListVO` 有 30+ 个可显示字段
- `orderNo` 字段名错误，`OrderListVO` 实际字段名为 `orderCode`
- 缺少操作列 `action`（前端表格的操作按钮列）

---

## 二、设计决策

### 2.1 列配置的职责边界

列配置（`order.column.config`）是**纯前端渲染控制**，不影响后端返回数据：

- 后端接口始终返回完整的 `OrderListVO`，包括 `id`、`hospitalId` 等所有字段
- 列配置仅告诉前端"渲染哪些列、以什么顺序渲染"
- 未配置为列的字段（如 `id`）前端仍可使用，用于行点击跳转等操作

### 2.2 排除字段规则

以下类型字段不纳入列配置：

| 规则 | 字段示例 | 原因 |
|------|----------|------|
| 主键/外键 ID | `id`, `orgId`, `hospitalId`, `doctorId` 等 | 不在列表中渲染，前端内部使用 |
| 原始枚举码值 | `orderType`, `businessType`, `patientGender`, `phase`, `status` | 对应的 `xxxName` 翻译字段已纳入 |
| 角标辅助字段 | `pendingModifyApplyStatus`, `pendingModifyApplyId` | 角标叠加在 `orderCode` 列上，前端硬编码处理 |

### 2.3 操作列（action）设计

`action` 不是数据字段，但是前端表格的实体列，纳入列配置的原因：
- 用户需要控制操作列是否可见
- 用户需要控制操作列在顺序中的位置
- 保持所有可见列行为一致，避免"特殊硬编码列"

### 2.4 fixed 属性

默认配置中所有列 `fixed: null`，不预设任何固定列。`fixed` 属性由用户自行配置保存（如将操作列固定右侧）。列配置的核心是 **sort 顺序管理**。

## 四、变更范围

**只修改 `sql/init.sql` 一处**：将 `order.column.config` 的 `config_value` 替换为符合 `OrderColumnConfigVO` 格式的完整 JSON。

代码层面无需改动：
- `OrderColumnConfigVO` 结构已正确
- `getSystemDefaultColumnConfig()` 反序列化逻辑已正确
- `getColumnConfig()` 优先级逻辑（用户配置 > 系统默认 > null）已正确
