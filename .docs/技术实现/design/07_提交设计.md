## 一、任务概述

实现设计提交功能，包括驳回后继续修改和提交前校验两个场景。状态流转通过 `FlowFacade.executeFlow` 完成。

## 二、涉及接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `POST /design/workorder/{orderId}/start` | POST | 开始设计（原有） |
| `POST /design/workorder/{orderId}/continue-design` | POST | 驳回后继续修改 |
| `POST /design/workorder/{orderId}/submit-design` | POST | 提交设计 |

## 三、业务逻辑

### 3.1 开始设计（原有）

- 前置状态：2010 待设计
- 目标状态：2020 设计中
- 记录 `designStartTime`
- 校验：当前用户必须是分配设计师

### 3.2 驳回后继续修改（新增）

- 前置状态：2060 设计审核不通过
- 目标状态：2020 设计中
- 调用 `FlowActionEnum.CONTINUE_DESIGN`
- 校验：当前用户必须是分配设计师

**流模块变更**：
- `FlowActionEnum` 新增 `CONTINUE_DESIGN("CONTINUE_DESIGN", "继续修改")`
- `FlowStatusTransitionRules.getTargetStatus()`：`CONTINUE_DESIGN → DESIGN_IN_PROGRESS(2020)`
- `FlowStatusTransitionRules.getAvailableActions()`：`DESIGN_REVIEW_REJECTED` 分支改为 `List.of(CONTINUE_DESIGN)`

### 3.3 提交设计

- 前置状态：2020 设计中
- 目标状态：2040 设计审核中
- 调用 `FlowActionEnum.SUBMIT_DESIGN`
- 记录 `designSubmitTime`
- 校验：当前用户必须是分配设计师，且通过 9 项完整性校验

## 四、提交校验项（SubmitCheckVO）

| 字段 | 校验项 | 说明 |
|------|--------|------|
| `hasPackage` | 已上传打印文件数据包 | 必填 |
| `hasPrintInfo` | 打印信息完整填写（每包至少一行） | 必填 |
| `hasInstruction` | 指令单已生成 | 必填 |
| `hasDrawing` | 图纸已生成 | 必填 |
| `hasModel` | 可视化模型文件已上传 | 必填 |
| `hasReport` | 设计报告已上传 | 必填 |
| `hasRevisedDocs` | 保留字段，始终为 `true`，不参与校验 | 废弃，见下方说明 |
| `hasDrawingConfirmed` | 每包最新版图纸 `is_confirmed=1` | 必填 |
| `hasInstructionConfirmed` | 每包最新版指令单 `is_confirmed=1` | 必填 |

**确认可通过两条路径满足**，后端不区分模式，统一检查 `is_confirmed` 字段：
- **在线路径**：手动调用 `POST .../confirm/{id}` 接口
- **离线路径**：上传修订版文件（`upload-revised`），系统自动置 `isConfirmed=1`

`design.mode` 配置仅供前端 UI 使用（如是否显示 viewer 入口），后端提交校验与之完全解耦。

**`hasRevisedDocs` 废弃说明**：原用于离线模式校验 `revisedFileId` 是否非空，现已被 `hasDrawingConfirmed` + `hasInstructionConfirmed` 替代。字段保留但始终返回 `true`，不阻止提交。

**`canSubmit` 失败原因字符串（优先级顺序）**：

1. 请先上传打印文件数据包
2. 请完善数据包的打印信息
3. 请生成指令单
4. 请生成图纸
5. 请上传可视化模型文件
6. 请上传设计报告
7. 请确认图纸
8. 请确认指令单

**设计模式读取**：通过 `ConfigService.getConfigValue(SystemConfigKeyEnum.DESIGN_MODE.getKey())` 读取，值返回给前端 `designMode` 字段供 UI 展示，后端不做模式分支处理。

## 五、关键实现细节

### `buildSubmitCheck(Long orderId, Integer designMode)` 说明

`designMode` 参数传入但不用于任何校验分支，仅透传给调用方（`getWorkorderDetail` 将其写入 VO 返回给前端）。

第 8、9 步（图纸/指令单确认）取每包最新版记录方式：按 `versionSeq DESC` 全量查询，使用 `LinkedHashMap + putIfAbsent` first-wins 模式取每包首条（即最新版）。

### `canSubmit` 的失败原因字符串

优先级顺序见上表，最后两条确认项排在最后，确保设计师先生成文件再确认。
