## 一、任务概述

实现设计提交功能，包括驳回后继续修改和提交前校验两个场景。状态流转通过 `FlowFacade.executeFlow` 完成。

## 三、业务逻辑

### 3.1 开始设计（原有）

- 前置状态：2010 待设计
- 目标状态：2020 设计中
- 记录 `designStartTime`
- 校验：当前用户必须是分配设计师

### 3.2 驳回后继续修改（新增）

- 前置状态：2060 设计审核不通过
- 目标状态：2020 设计中
- 调用 `FlowActionEnum.CONTINUE_DESIGN`
- 校验：当前用户必须是分配设计师

**流模块变更**：
- `FlowActionEnum` 新增 `CONTINUE_DESIGN("CONTINUE_DESIGN", "继续修改")`
- `FlowStatusTransitionRules.getTargetStatus()`：`CONTINUE_DESIGN → DESIGN_IN_PROGRESS(2020)`
- `FlowStatusTransitionRules.getAvailableActions()`：`DESIGN_REVIEW_REJECTED` 分支改为 `List.of(CONTINUE_DESIGN)`

### 3.3 提交设计

- 前置状态：2020 设计中
- 目标状态：2040 设计审核中
- 调用 `FlowActionEnum.SUBMIT_DESIGN`
- 记录 `designSubmitTime`
- 校验：当前用户必须是分配设计师，且通过 7 项完整性校验

## 四、提交校验项（SubmitCheckVO）

| 字段 | 校验项 | 必填条件 |
|------|--------|----------|
| `hasPackage` | 已上传打印文件数据包 | 必填 |
| `hasPrintInfo` | 打印信息完整填写（每包至少一行） | 必填 |
| `hasInstruction` | 指令单已生成 | 必填 |
| `hasDrawing` | 图纸已生成 | 必填 |
| `hasModel` | 可视化模型文件已上传 | 必填 |
| `hasReport` | 设计报告已上传 | 必填 |
| `hasRevisedDocs` | 每包的最新版指令单和图纸都有修订版文件 | 线下模式（OFFLINE）必填 |

**设计模式读取**：通过 `ConfigService.getConfigValue(SystemConfigKeyEnum.DESIGN_MODE.getKey())` 读取，值为 `DesignModeEnum.OFFLINE(1)` 时启用第 7 项校验。读取失败默认按线下模式处理。

**修订版文件判断逻辑**：
- 按包遍历，每包找出 `versionSeq` 最大的指令单和图纸（first-wins collector）
- 检查这两份文件的 `revisedFileId` 是否非空
- 任意一包不满足则 `hasRevisedDocs = false`

## 五、关键实现细节

### `buildSubmitCheck(Long orderId, Integer designMode)` 变更

原签名 `buildSubmitCheck(Long orderId)`，新增 `designMode` 参数。

`getWorkorderDetail` 调用时先读取配置，传入 `buildSubmitCheck`：

```java
Integer designMode = getDesignMode();
vo.setDesignMode(designMode);
vo.setSubmitCheck(buildSubmitCheck(orderId, designMode));
```

**注意**：`Set<Long> packageIds` 声明必须在 `if (!packages.isEmpty())` 块之外，以便第 7 项校验代码复用。

### `canSubmit` 失败原因字符串

优先级顺序：无数据包 → 打印信息不完整 → 无指令单 → 无图纸 → 无可视化模型 → 无设计报告 → 修订版文件缺失。
