# 指令单/图纸生成与管理

> **任务序号**：5
> **状态**：已完成
> **前置依赖**：04_打印信息管理

---

## 一、任务概述

实现生产指令单和图纸的生成（Excel 模板填充）、版本历史查询、修订版上传功能。文件下载统一通过 `GET /basic/file/download/{fileId}` 完成，版本列表接口返回 `templateFileId` / `revisedFileId` 供前端调用。

**模板格式**：Excel（.xlsx），存放于 `yigongbao-boot/src/main/resources/template/`：
- `生产指令单.xlsx`
- `图纸.xlsx`

---

## 二、涉及接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/design/workorder/{orderId}/package/{packageId}/instruction/generate` | POST | 生成指令单 |
| `/design/workorder/{orderId}/package/{packageId}/drawing/generate` | POST | 生成图纸 |
| `/design/workorder/{orderId}/package/{packageId}/instruction/versions` | GET | 查询指令单历史版本列表 |
| `/design/workorder/{orderId}/package/{packageId}/drawing/versions` | GET | 查询图纸历史版本列表 |
| `/design/workorder/{orderId}/package/{packageId}/instruction/upload-revised/{id}` | POST | 上传修订版指令单（multipart，自动确认） |
| `/design/workorder/{orderId}/package/{packageId}/drawing/upload-revised/{id}` | POST | 上传修订版图纸（multipart，自动确认） |
| `/design/workorder/{orderId}/package/{packageId}/instruction/confirm/{id}` | POST | 手动确认指令单（在线路径） |
| `/design/workorder/{orderId}/package/{packageId}/drawing/confirm/{id}` | POST | 手动确认图纸（在线路径） |

## 三、业务逻辑

### 3.1 生成逻辑（generateInstruction / generateDrawing）

两个接口逻辑完全对称，各自独立：

1. **权限校验**：订单状态为 `DESIGN_IN_PROGRESS(2020)` 或 `DESIGN_REVIEW_REJECTED(2060)`，当前用户是订单的 `designerId`
2. **前置校验**：该包下 `design_product` 记录数 > 0（打印信息已填写），否则报错 `PRINT_INFO_REQUIRED(750)`
3. **版本号策略**：指令单和图纸版本序号**各自独立**。通过 `getLatestVersion(packageId)` 取最新版记录，判断两种情况：
   - 最新版 `revisedFileId == null`（**未封版**）：覆盖该记录的模板文件，版本号不变
   - 最新版 `revisedFileId` 非空（**已封版**）或无任何历史记录：新建版本记录，seq = 上一版 seq + 1（首次为 1），版本字符串 `"A/" + seq`
4. **Excel 填充**：`InstructionExcelBuilder` / `DrawingExcelBuilder` 分别生成 byte[]
5. **文件存储**：通过 `FileService.uploadBytes(bytes, filename, bizType)` 上传，获取 FileVO（含 fileId + fileUrl）
6. **记录写入**：
   - 新版本场景：插入新记录（各历史版本均保留）
   - 覆盖场景：更新当前版本记录的 `templateFileId`、`templateFileUrl`、`generateTime`
7. **返回**：`DocItemVO`（id、version、fileId、templateFileUrl、generateTime）

### 3.2 版本管理

- `design_instruction` / `design_drawing` 按**封版策略**管理记录：
  - 上传修订版前（`revisedFileId == null`）：重新生成只覆盖当前记录的模板文件，版本号不变
  - 上传修订版后（`revisedFileId` 非空，即"封版"）：下次生成才新建记录，版本序号 +1
- 查询版本列表按 `version_seq DESC` 排序，最新版在前
- 版本列表返回 `templateFileId`（模板版）和 `revisedFileId`（修订版，可为 null）供前端下载
- 下载通过 `GET /basic/file/download/{fileId}` 统一实现，无需在设计模块单独提供下载接口

### 3.3 指令单 Excel 填充（InstructionExcelBuilder）

**模板结构**（生产指令单.xlsx）：
- 行1：标题"生产指令单"（A1:I1 合并）
- 行2：编号（A2:B2）、版本号（G2:I2）
- 行3：基本信息区段标题
- 行4-5：订单编号、客户名称、联系人（取 `order.doctorName`）、数据包编号、医院、预交货时间
- 行6：生产产品信息表格标题
- 行7：表头（序号、注册证号、产品名称、数据文件名称、型号规格、材质、数量、时效、颜色）
- 行8：序号"1"（首行）
- 行9-25：**纵向合并的大格子**（产品信息数据区域，需动态展开）
- 行26-29：产品标识、包装数量、患者姓名、是否邮寄、时间、邮寄地址、备注
- 行30：签名行（指令/日期、复核/日期）

**BuildContext 字段**：

| 字段 | 来源 | 说明 |
|------|------|------|
| `List<ProductRow> rows` | `expandProductRows(products)` | 每个 product×file 组合为一行 |
| `productMark` | `design_package` | 产品标识 |
| `packQuantity` | `design_package` | 包装数量 |
| `remark` | `design_package` | 备注 |

**ProductRow 字段**：`certNo`、`productName`、`packageFileName`、`specName`、`materialName`、`quantity`、`isUrgent`（Integer，0=普通/1=加急，**逐行独立**）、`colorName`

**动态行展开步骤**：
1. 加载模板 `classpath:template/生产指令单.xlsx`
2. 填充固定信息区（B4、E4、G4、B5、D5、G5 等）
3. 移除行9-25的合并区域（`sheet.removeMergedRegion`）
4. 设 n = rows.size()；原区域有 17 行
   - 若 n ≤ 17：逐行写入，多余行清空
   - 若 n > 17：`sheet.shiftRows(26, lastRow, n - 17)` 下移，插入新行并复制第8行样式
5. 按序写入每行：序号、注册证号、产品名称、数据文件名称、型号规格、材质、数量、时效（取 `row.isUrgent`）、颜色
6. 填充底部区域（`productMark`、`packQuantity`、`remark` 等，行26-30 偏移后的位置）
7. 覆盖版本号：G2 单元格写入 `"版本号：" + version`

### 3.4 图纸 Excel 填充（DrawingExcelBuilder）

**模板结构**（图纸.xlsx，共 42 行 × 16 列）：
- 第一页布局：4 列 × 3 行 = 12 个格位，右上角（M1:P10）为二维码位置，剩余 11 个内容格位
- 每个格位包含：序号行、文件名称行、产品名称行、大面积图片留白区
- 底部（行37-42）：备注、数据包编号、订单编号、设计/日期、审核/日期、公司名称

**BuildContext 字段**：`List<ProductRow> rows`，每个 product×file 组合为一行。

**ProductRow 字段**：`packageFileName`、`productName`

**填充步骤**：
1. 加载模板
2. 按 rows 遍历，每条对应一个槽位：填入 `packageFileName`（文件名称）、`productName`（产品名称，图片区留空）
3. 填充 footer：数据包编号、订单编号
4. 超过 11 条时**分页**：复制整个 Sheet 为 Sheet2、Sheet3...，更新页码文本"第X页/共Y页"
5. 写出 byte[]

### 3.5 修订版上传与自动确认

- 接收设计师上传的 multipart 文件（xlsx/pdf 等）
- 校验权限（同生成逻辑）
- 通过 `{id}` 路径参数定位具体版本记录
- 通过 `FileService.uploadFile(file, bizType)` 上传，更新该记录的 `revisedFileId`、`revisedFileUrl`、`revisedUploadTime`
- **上传修订版后自动确认**：`isConfirmed=1`、`confirmTime=now`。上传修订版本身即代表设计师已线下审阅认可，无需额外确认操作。

### 3.6 确认接口（confirm）

手动确认路径，供设计师在不上传修订版的情况下（如在线预览满意后）确认文件内容：

- `POST .../drawing/confirm/{id}` → `isConfirmed=1`、`confirmTime=now`
- `POST .../instruction/confirm/{id}` → `isConfirmed=1`、`confirmTime=now`
- 若之后重新生成，`isConfirmed` 自动重置为 0，需再次确认

**文件命名规则**：生成时按 `"指令单-{packageCode}.xlsx"` / `"图纸-{packageCode}.xlsx"` 命名，与内部编码（如 ZL-0001）无关。

## 四、数据结构

### 4.1 响应 VO

**DocItemVO**（生成接口返回）
```java
@Data
public class DocItemVO {
    private Long id;
    private String version;
    private String fileId;            // 模板文件ID，用于前端下载
    private String templateFileUrl;
    private LocalDateTime generateTime;
}
```

**DesignDocVersionVO**（版本列表通用）
```java
@Data
public class DesignDocVersionVO {
    private Long id;
    private String version;
    private Integer versionSeq;
    private String templateFileId;    // 模板版文件ID
    private String templateFileUrl;
    private String revisedFileId;     // 修订版文件ID（可为null）
    private String revisedFileUrl;
    private LocalDateTime generateTime;
    private LocalDateTime revisedUploadTime;
    private Integer isConfirmed;      // 0=未确认，1=已确认
    private LocalDateTime confirmTime;
}
```

## 六、架构分层

```
DesignDocController
    └── DesignDocService（接口+实现）
            ├── InstructionExcelBuilder     // helper包，专职 POI 填充逻辑
            ├── DrawingExcelBuilder         // helper包，专职 POI 填充逻辑
            ├── FileService                 // 统一文件上传（uploadBytes / uploadFile）
            ├── DesignProductFileService    // 查询产品-文件关联，构造 ProductRow
            ├── DesignInstructionService    // 持久化
            └── DesignDrawingService        // 持久化
```

**行展开方法**：`DesignDocServiceImpl` 通过 `expandProductRows(products)` 和 `expandDrawingRows(products)` 将产品列表展开为行列表，每个 product×file 组合生成一个 `ProductRow`（一个文件 = 一条 Excel 行）。产品-文件关联由注入的 `DesignProductFileService` 查询。
