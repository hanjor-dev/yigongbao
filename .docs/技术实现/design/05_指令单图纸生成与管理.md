# 指令单/图纸生成与管理

> **任务序号**：5
> **状态**：已完成
> **前置依赖**：04_打印信息管理

---

## 一、任务概述

实现生产指令单和图纸的生成（Excel 模板填充）、版本历史查询、模板版下载、上传修订版功能。

**模板格式**：Excel（.xlsx），存放于 `yigongbao-boot/src/main/resources/template/`：
- `生产指令单.xlsx`
- `图纸.xlsx`

---

## 二、涉及接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/design/workorder/{orderId}/package/{packageId}/generate-docs` | POST | 同时生成指令单 + 图纸 |
| `/design/workorder/{orderId}/package/{packageId}/instruction/versions` | GET | 查询指令单历史版本列表 |
| `/design/workorder/{orderId}/package/{packageId}/instruction/download/{id}` | GET | 按版本ID下载指令单（模板版） |
| `/design/workorder/{orderId}/package/{packageId}/instruction/upload-revised` | POST | 上传修订版指令单（multipart） |
| `/design/workorder/{orderId}/package/{packageId}/drawing/versions` | GET | 查询图纸历史版本列表 |
| `/design/workorder/{orderId}/package/{packageId}/drawing/download/{id}` | GET | 按版本ID下载图纸（模板版） |
| `/design/workorder/{orderId}/package/{packageId}/drawing/upload-revised` | POST | 上传修订版图纸（multipart） |

## 三、业务逻辑

### 3.1 生成逻辑（generateDocs）

1. **权限校验**：订单状态为 `DESIGN_IN_PROGRESS(2020)` 或 `DESIGN_REVIEW_REJECTED(2060)`，当前用户是订单的 `designerId`
2. **前置校验**：该包下 `design_product` 记录数 > 0（打印信息已填写），否则报错 `PRINT_INFO_REQUIRED(750)`
3. **版本号计算**：查询该包下最大 `version_seq`，新版 = max + 1，版本字符串 = `"A/" + seq`（首次为 `A/1`）
4. **Excel 填充**：`InstructionExcelBuilder` 和 `DrawingExcelBuilder` 分别生成 byte[]
5. **文件存储**：通过 `x-file-storage` 上传，获取 fileId + fileUrl（objectType = `10.7` 指令单，`10.8` 图纸）
6. **记录插入**：分别插入 `design_instruction` 和 `design_drawing` 新记录（保留历史，不逻辑删除旧记录）
7. **返回**：`GenerateDocsResultVO`（两个文件的 id、version、templateFileUrl）

### 3.2 版本管理

- `design_instruction` / `design_drawing` 每次生成均插入新记录，不覆盖旧记录
- 查询版本列表按 `version_seq DESC` 排序，最新版在前
- `template_file_url`：系统生成的填充版文件
- `revised_file_url`：设计师上传的修订版文件（可为空）

### 3.3 指令单 Excel 填充（InstructionExcelBuilder）

**模板结构**（生产指令单.xlsx）：
- 行1：标题"生产指令单"（A1:I1 合并）
- 行2：编号（A2:B2）、版本号（G2:I2）
- 行3：基本信息区段标题
- 行4-5：订单编号、客户名称、联系人、数据包编号、医院、预交货时间
- 行6：生产产品信息表格标题
- 行7：表头（序号、注册证号、产品名称、数据文件名称、型号规格、材质、数量、时效、颜色）
- 行8：序号"1"（首行）
- 行9-25：**纵向合并的大格子**（产品信息数据区域，需动态展开）
- 行26-29：产品标识、包装数量、患者姓名、是否邮寄、时间、邮寄地址、备注
- 行30：签名行（指令/日期、复核/日期）

**动态行展开步骤**：
1. 加载模板 `classpath:template/生产指令单.xlsx`
2. 填充固定信息区（B4、E4、G4、B5、D5、G5 等）
3. 移除行9-25的合并区域（`sheet.removeMergedRegion`）
4. 设 n = productList.size()；原区域有 17 行
   - 若 n ≤ 17：逐行写入，多余行清空
   - 若 n > 17：`sheet.shiftRows(26, lastRow, n - 17)` 下移，插入新行并复制第8行样式
5. 按序写入每行：序号、注册证号、产品名称、数据文件名称、型号规格、材质、数量、时效、颜色
6. 填充底部区域（行26-30 偏移后的位置）
7. 覆盖版本号：G2 单元格写入 `"版本号：" + version`

### 3.4 图纸 Excel 填充（DrawingExcelBuilder）

**模板结构**（图纸.xlsx，共 42 行 × 16 列）：
- 第一页布局：4 列 × 3 行 = 12 个格位，右上角（M1:P10）为二维码位置，剩余 11 个内容格位
- 每个格位包含：序号行、文件名称行、产品名称行、大面积图片留白区
- 底部（行37-42）：备注、数据包编号、订单编号、设计/日期、审核/日期、公司名称

**填充步骤**：
1. 加载模板
2. 按 productList 遍历，每条对应一个槽位：填入文件名称、产品名称（图片区留空）
3. 填充 footer：数据包编号、订单编号
4. 超过 11 条时**分页**：复制整个 Sheet 为 Sheet2、Sheet3...，更新页码文本"第X页/共Y页"
5. 写出 byte[]

### 3.5 修订版上传

- 接收设计师上传的 multipart 文件（xlsx/pdf 等）
- 校验权限（同生成逻辑）
- 通过 `{id}` 路径参数定位具体版本记录
- 通过 x-file-storage 上传，更新该记录的 `revised_file_id`、`revised_file_url`、`revised_upload_time`

## 四、数据结构

### 4.1 响应 VO

**GenerateDocsResultVO**
```java
@Data
public class GenerateDocsResultVO {
    private DocItemVO instruction;  // 指令单
    private DocItemVO drawing;      // 图纸
}
```

**DocItemVO**
```java
@Data
public class DocItemVO {
    private Long id;
    private String version;
    private String templateFileUrl;
    private LocalDateTime generateTime;
}
```

**DesignDocVersionVO**（版本列表通用）
```java
@Data
public class DesignDocVersionVO {
    private Long id;
    private String version;
    private Integer versionSeq;
    private String templateFileUrl;
    private String revisedFileUrl;
    private LocalDateTime generateTime;
    private LocalDateTime revisedUploadTime;
}
```

### 4.2 请求 DTO

**UploadRevisedDTO**（上传修订版，通过 `@RequestParam MultipartFile` 接收，无需单独 DTO）

## 五、错误码

| 错误码 | 枚举 | 说明 |
|--------|------|------|
| 740 | DESIGN_OPERATOR_NOT_ALLOWED | 非设计师或订单状态不允许 |
| 750 | PRINT_INFO_REQUIRED | 打印信息未填写，无法生成 |
| 751 | DOC_VERSION_NOT_FOUND | 指定版本记录不存在 |
