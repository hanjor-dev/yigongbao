## 三、数据权限规则

### 3.1 权限过滤逻辑

设计工单按 `designer_id`（设计师）过滤，与订单列表按 `create_by`（创建人）过滤的语义不同。

| 数据范围类型 | 过滤逻辑 |
|-------------|---------|
| SELF | `designer_id = 当前用户ID` |
| DEPT | `designer_id IN (同部门所有用户ID)` |
| ORG | `designer_id IN (同机构所有用户ID)` |
| HOSPITALS | **降级为 SELF**（设计师不按医院分配，返回仅自己的工单） |
| ALL | 无限制 |

### 3.2 固定过滤条件

- `phase = 20`（仅查询设计阶段订单）
- `is_deleted = 0`

### 3.3 实现说明

DEPT 和 ORG 类型需要先查询同部门/同机构的用户ID列表，再用 `IN` 条件过滤：

```java
// DEPT: 查询同部门用户
List<Long> deptUserIds = userService.listUserIdsByDeptId(currentUserDeptId);
wrapper.in(OrderMainEntity::getDesignerId, deptUserIds);

// ORG: 查询同机构用户
List<Long> orgUserIds = userService.listUserIdsByOrgId(currentUserOrgId);
wrapper.in(OrderMainEntity::getDesignerId, orgUserIds);
```

### 3.4 UserService 扩展方法（本任务新增）

当前 UserService 缺少按部门/机构查询用户ID列表的方法，需新增：

```java
/**
 * 根据部门ID查询用户ID列表
 *
 * @param deptId 部门ID
 * @return 该部门下所有用户的ID列表
 */
List<Long> listUserIdsByDeptId(Long deptId);

/**
 * 根据机构ID查询用户ID列表
 *
 * @param orgId 机构ID
 * @return 该机构下所有用户的ID列表
 */
List<Long> listUserIdsByOrgId(Long orgId);
```

**实现位置**：`yigongbao-module-system` 的 `UserService` / `UserServiceImpl`

### 5.2 提交校验状态（SubmitCheckVO）

```java
public class SubmitCheckVO {
    
    private Boolean hasPackage;              // 是否已上传数据包
    private Boolean hasPrintInfo;            // 是否已填写打印信息（所有数据包）
    private Boolean hasInstruction;          // 是否已生成指令单（所有数据包）
    private Boolean hasDrawing;              // 是否已生成图纸（所有数据包）
    private Boolean hasModel;                // 是否已上传可视化模型
    private Boolean hasReport;               // 是否已上传设计报告
    private Boolean canSubmit;               // 是否可以提交（全部为 true）
    private String blockReason;              // 不可提交的原因（首个未满足项）
}
```

**校验逻辑**：

| 校验项 | 查询方式 |
|--------|---------|
| hasPackage | `SELECT COUNT(*) FROM design_package WHERE order_id = ?` > 0 |
| hasPrintInfo | 每个数据包都有至少一条 design_product 记录 |
| hasInstruction | 每个数据包都有 design_instruction 记录 |
| hasDrawing | 每个数据包都有 design_drawing 记录 |
| hasModel | `SELECT COUNT(*) FROM design_model WHERE order_id = ?` > 0 |
| hasReport | `SELECT COUNT(*) FROM file_detail WHERE object_type = '10.5' AND object_id = ?` > 0 |

**blockReason 生成规则**（按优先级）：

1. 未上传数据包 → "请先上传打印文件数据包"
2. 打印信息不完整 → "请完善数据包的打印信息"
3. 指令单未生成 → "请生成指令单"
4. 图纸未生成 → "请生成图纸"
5. 未上传可视化模型 → "请上传可视化模型文件"
6. 未上传设计报告 → "请上传设计报告"

|---------|---------|:------:|

### 6.4 获取逻辑

```java
public DesignColumnConfigVO getColumnConfig() {
    Long userId = getCurrentUserId();
    UserEntity user = userService.getById(userId);
    
    // 优先返回用户个人配置
    if (StrUtil.isNotBlank(user.getDesignColumnSettings())) {
        return parseJson(user.getDesignColumnSettings());
    }
    
    // 返回系统默认配置
    String configJson = configService.getConfigValue(
        SystemConfigKeyEnum.DESIGN_COLUMN_CONFIG.getKey());
    return parseJson(configJson);
}
```

## 十、设计决策记录

| 决策 | 选项 | 选择 | 原因 |
|------|------|------|------|
| 数据权限过滤字段 | create_by / designer_id | designer_id | 设计师关心分配给自己的工单 |
| HOSPITALS 降级处理 | 报错 / 降级为 SELF | 降级为 SELF | 设计师不按医院分配，静默降级更友好 |
| 列表筛选范围 | 全阶段 / 仅设计阶段 | 仅设计阶段 | 设计师无需查看后续阶段 |
| 设计进度展示 | 百分比 / 文字 / 图标 / 仅状态 | 仅状态 | 简化列表，进度明细在详情页 |
| 详情返回方式 | 一次性聚合 / 分批请求 | 分批请求 | 避免接口过重 |
| 列配置 VO | 复用 OrderColumnConfigVO / 独立 | 独立 | 字段内容不同，独立更清晰 |
| Helper 实现 | 抽取公共基类 / 独立实现 | 独立实现 | 语义不同，独立更简单 |
| 默认排序 | 加急+交付时间 / 创建时间 | 创建时间 DESC | 简单直观，自定义排序由前端控制 |
