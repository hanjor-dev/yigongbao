# 设计文件上传处理

> **任务序号**：3
> **状态**：已完成
> **前置依赖**：02_design模块初始化

---

## 一、任务概述

实现设计阶段三类文件的上传、删除功能：
1. **打印文件数据包**：压缩包直接上传 + 自动解析包内文件列表
2. **可视化模型文件**：前端先上传到 FileController，再调用 link 接口关联（支持批量）
3. **设计报告**：前端先上传到 FileController，再调用 link 接口关联

---

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/design/package/upload?orderId=` | POST | 上传打印文件数据包 |
| `/api/design/package/{packageId}?orderId=` | DELETE | 删除数据包 |
| `/api/design/packages?orderId=` | GET | 获取数据包列表 |
| `/api/design/models/link` | POST | 批量关联可视化模型 |
| `/api/design/model/{modelId}?orderId=` | DELETE | 删除可视化模型 |
| `/api/design/models?orderId=` | GET | 获取可视化模型列表 |
| `/api/design/report/link` | POST | 关联设计报告 |
| `/api/design/report/{fileId}?orderId=` | DELETE | 删除设计报告 |
| `/api/design/report?orderId=` | GET | 获取设计报告 |

## 三、三类文件处理逻辑

### 3.1 打印文件数据包

**上传流程**：
1. 接收压缩包文件（支持 ZIP/RAR/7Z）
2. 调用 FileService 存储压缩包
3. 生成数据包编号：`{订单编号}-{序号}`（使用 CodeRuleConstants.DATA_PACKAGE_NO）
4. 解析压缩包内文件列表（不解压到磁盘，仅读取元数据）
5. 按扩展名白名单过滤，只保留允许的文件类型
6. 写入 design_package 和 design_package_file 表

**删除流程**：
1. 校验数据包是否存在且属于当前工单
2. 检查是否有关联的打印产品信息（design_product），若有则禁止删除
3. 删除 design_package_file 记录（逻辑删除）
4. 删除 design_package 记录（逻辑删除）
5. 删除存储的压缩包文件

**扩展名白名单配置**：
- 配置键：`design.package.allowed_extensions`（SystemConfigKeyEnum.DESIGN_PACKAGE_ALLOWED_EXTENSIONS）
- 默认值：`.stl,.obj,.ply,.3mf,.gcode,.ctb,.cbddlp`
- 存储于 sys_config 表，运行时可调整

### 3.2 可视化模型文件

**关联流程**（批量接收 fileIds，非直接上传）：
1. 前端先调用 `/api/file/upload` 上传文件（可批量），获取 fileId 列表
2. 前端调用 `/api/design/models/link` 传入 orderId 和 fileIds（LinkFilesDTO）
3. 后端校验工单状态和操作权限
4. 后端批量校验文件是否存在
5. 后端循环调用 FileService.linkFile 关联文件到业务（bizType=10.6）
6. 后端批量写入 design_model 表（只存 orderId 和 fileId）
7. 后端返回 `List<DesignModelVO>`（文件详情从 FileVO 填充）

**删除流程**：
1. 校验文件是否存在且属于当前工单
2. 删除 design_model 记录
3. 删除存储的文件

**说明**：无数量限制，一个工单可上传多个可视化模型。

### 3.3 设计报告

**关联流程**（接收 fileId，非直接上传）：
1. 前端先调用 `/api/file/upload` 上传文件，获取 fileId
2. 前端调用 `/api/design/report/link` 传入 orderId 和 fileIds（取第一个）
3. 后端校验工单状态和操作权限
4. 后端校验文件是否存在
5. 后端删除旧报告（每工单仅一份）
6. 后端调用 FileService.linkFile 关联文件到业务（bizType=10.5）
7. 后端返回 FileVO

**说明**：复用现有 file_detail 表，object_type 区分，每工单一份。

## 四、压缩包解析

### 4.1 支持格式

| 格式 | 扩展名 | 解析库 |
|------|--------|--------|
| ZIP | .zip | java.util.zip（JDK 内置） |
| RAR | .rar | junrar（需引入依赖） |
| 7Z | .7z | commons-compress（已有） |

### 4.2 解析策略

- **不解压到磁盘**：仅读取压缩包内的文件列表元数据
- **提取信息**：文件名、文件大小、相对路径
- **过滤逻辑**：按扩展名白名单过滤，跳过目录项

### 4.3 工具类设计

```java
/**
 * 压缩包解析工具类
 */
public class ArchiveParserUtil {
    
    /**
     * 解析压缩包，返回文件列表
     * @param inputStream 压缩包输入流
     * @param fileName 文件名（用于判断格式）
     * @param allowedExtensions 允许的扩展名集合
     * @return 文件信息列表
     */
    public static List<ArchiveFileInfo> parse(
        InputStream inputStream, 
        String fileName, 
        Set<String> allowedExtensions
    );
}

/**
 * 压缩包内文件信息
 */
@Data
public class ArchiveFileInfo {
    private String fileName;      // 文件名（不含路径）
    private String filePath;      // 包内完整路径
    private Long fileSize;        // 文件大小（字节）
    private String extension;     // 扩展名
}
```

## 六、权限与校验

| 校验项 | 说明 |
|--------|------|
| 工单状态 | 仅「设计中」或「设计审核不通过」状态可操作 |
| 操作人 | 仅当前设计师（order.designer_id）可操作 |
| 文件格式 | 数据包必须是 ZIP/RAR/7Z，其他拒绝 |
| 文件大小 | 单文件不超过系统配置限制（默认 500MB） |

## 八、系统配置

配置通过 `SystemConfigKeyEnum` 统一管理，兜底默认值在 `DefaultConfigProperties` 和 `application.yml` 中配置。

| 配置键 | SystemConfigKeyEnum | 默认值 | 说明 |
|--------|---------------------|--------|------|
| `design.package.allowed_extensions` | DESIGN_PACKAGE_ALLOWED_EXTENSIONS | `.stl,.obj,.ply,.3mf,.gcode,.ctb,.cbddlp` | 数据包允许的文件扩展名 |
| `design.package.max_size_mb` | DESIGN_PACKAGE_MAX_SIZE_MB | `500` | 数据包最大大小（MB） |
| `design.model.max_size_mb` | DESIGN_MODEL_MAX_SIZE_MB | `200` | 可视化模型最大大小（MB） |
| `design.report.max_size_mb` | DESIGN_REPORT_MAX_SIZE_MB | `50` | 设计报告最大大小（MB） |
