# 图纸在线截图填充功能

> **任务序号**：09
> **状态**：已完成
> **前置依赖**：05_指令单图纸生成与管理

---

## 一、任务概述

在原有"线下修订上传"流程基础上，引入在线 viewer 标注截图能力，实现完全在线的图纸填充：

1. 设计师在前端 viewer 中查看3D模型、完成标注后截图
2. 前端调用截图上传接口，将截图与指定 `DesignPackageFile`（数据包内文件）绑定
3. 每个 `DesignPackageFile` 最多一张有效截图（upsert 语义：新截图覆盖旧截图）
4. 生成图纸时，后端自动将对应截图嵌入 Excel 对应槽位的图片格区域

原有"手动上传修订版"路径（`upload-revised`）保留，两条路径并存。

## 二、数据库设计

### 新增表：`design_package_file_screenshot`

```sql
CREATE TABLE design_package_file_screenshot (
    id                  BIGINT          NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    package_file_id     BIGINT          NOT NULL COMMENT '关联 design_package_file.id',
    file_id             VARCHAR(64)     NOT NULL COMMENT '截图文件ID（关联 file_detail.id）',
    create_time         DATETIME        DEFAULT NULL COMMENT '创建时间',
    update_time         DATETIME        DEFAULT NULL COMMENT '更新时间',
    create_by           BIGINT          DEFAULT NULL COMMENT '创建人ID',
    update_by           BIGINT          DEFAULT NULL COMMENT '更新人ID',
    is_deleted          TINYINT         DEFAULT 0 COMMENT '是否删除（0=否，1=是）',
    PRIMARY KEY (id),
    KEY idx_design_pkg_file_screenshot_file_id (package_file_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='数据包文件截图关联表';

-- 每个 package_file 只允许一条有效截图（函数索引兼容逻辑删除）
CREATE UNIQUE INDEX uk_design_pkg_file_screenshot_pkg_file_id
    ON design_package_file_screenshot
    ((CASE WHEN is_deleted = 0 THEN package_file_id ELSE NULL END));
```

**关系说明**：`design_package_file` ←→ `design_package_file_screenshot`，一对一（最多一条 `is_deleted=0` 的记录）。旧截图的 `file_detail` 记录保留（不物理删除），只替换关联。

## 四、核心实现

### 4.1 新增文件枚举

`FileBizTypeEnum.IMAGE_SCREENSHOT`（code=`image_screenshot`，dictCode=`10.18`）：截图文件专用业务类型，无格式/大小限制（服务端不做校验，由前端控制）。

### 4.2 截图 upsert 逻辑

```
saveScreenshot(packageId, packageFileId, file):
  1. 校验 packageFileId 存在且 packageId 匹配（跨包操作报错）
  2. fileService.uploadFile(file, IMAGE_SCREENSHOT.getDictCode())
  3. 查询 design_package_file_screenshot WHERE package_file_id = ? AND is_deleted = 0
     - 存在 → updateById（更新 file_id）
     - 不存在 → save（新增）
  4. 返回 ScreenshotVO
```

旧截图的 `file_detail` 记录不删除，`design_package_file_screenshot` 的 `file_id` 直接指向新截图。

### 4.3 生成图纸时自动嵌图

`DesignDocServiceImpl.generateDrawing()` 改造步骤：

```
1. 查询打印产品列表 → 批量查包内文件（listByProductIds）
2. 取所有 packageFileId，批量查 design_package_file_screenshot
3. 按 file_id 批量下载截图字节（downloadToBytes，失败时 warn 跳过，不阻断生成）
4. 构建 DrawingExcelBuilder.ProductRow，填充 screenshotBytes
5. DrawingExcelBuilder.build() 在对应槽位嵌入截图
```

截图下载失败（文件不存在或存储平台故障）时，该槽位不嵌图，图纸照常生成（仅记录 warn 日志）。

### 4.4 DrawingExcelBuilder 图片嵌入

每个槽位由 `SLOT_COORDS[slot]` 定义：`{fileNameRow, fileNameCol, productNameRow, productNameCol}`。

图片锚点计算：
- `colStart = productNameCol`（槽位左边列）
- `colEnd = fileNameCol + 1`（槽位右边列 + 1）
- `rowStart = productNameRow + 1`（产品名行下一行）
- `rowEnd = rowStart + 10`（向下10行，覆盖槽位主体区域）

图片格式自动判断：文件头 `89 50 4E 47` → PNG，否则 → JPEG。

使用 `XSSFDrawing.createPicture(XSSFClientAnchor, pictureIdx)`，锚点类型 `MOVE_AND_RESIZE`（跟随行列缩放）。

## 七、注意事项

- **截图不做格式校验**：前端 viewer 输出 PNG/JPG，后端仅读文件头判断格式用于 POI，不拒绝其他格式（会被当作 JPEG 处理）
- **旧截图文件不删除**：`file_detail` 记录保留，`design_package_file_screenshot.file_id` 指向最新截图，旧文件成为孤儿记录（后续可定期清理）
- **嵌图失败不阻断生成**：`loadScreenshotBytes` 中单个文件下载失败只记录 warn，不抛出异常，确保图纸生成始终成功
- **函数唯一索引**：`uk_design_pkg_file_screenshot_pkg_file_id` 保证同一 `package_file_id` 只有一条未删除记录，兼容 `@TableLogic` 逻辑删除的多次 upsert
