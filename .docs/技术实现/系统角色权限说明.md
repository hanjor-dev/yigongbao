## 详细权限说明

### 1. 超级管理员（admin）

**角色定位**：系统维护专用，拥有全部权限

**菜单权限**：
- ✅ 全部菜单（一级 + 二级）

**按钮权限**：
- ✅ 全部按钮权限

**适用场景**：
- 系统初始化和配置
- 系统底层维护
- 应急处理

---

### B. 使用说明

#### 1. 角色分配原则

- **业务线人员**（业务员、区域管理员）：按机构和部门分配，数据权限受限
- **企业内部人员**（设计、生产、质检、仓储）：可查看全部数据，按职能分配权限
- **管理层人员**（公司管理员）：拥有全部业务权限
- **系统维护人员**（超级管理员）：仅用于系统维护，不参与日常业务

#### 2. 权限配置注意事项

1. **新角色创建**：在 `sys_role` 表中插入角色记录
2. **权限分配**：在 `sys_role_resource` 表中关联菜单和按钮
3. **权限验证**：使用 `@RequirePermission` 注解进行权限校验
4. **权限缓存**：权限信息会缓存在 Redis 中，修改后需清除缓存

#### 3. 数据权限说明

| 数据范围类型 | 说明 | 适用角色 |
|-------------|------|---------|
| all | 全部数据 | 超级管理员、企业内部角色、公司管理员 |
| dept | 本部门数据 | 区域管理员 |
| hospitals | 关联医院数据 | 业务员 |
| self | 个人数据 | 设计师 |

#### 4. 常见问题

**Q1：如何新增角色？**
- 在 `sys_role` 表插入角色记录
- 在 `sys_role_resource` 表配置菜单和按钮权限
- 执行数据库脚本后重启应用

**Q2：如何修改现有角色权限？**
- 修改 `sys_role_resource` 表中的权限关联
- 清除 Redis 中的权限缓存
- 用户重新登录后生效

**Q3：按钮权限如何生效？**
- 前端根据按钮权限代码显示/隐藏按钮
- 后端通过 `@RequirePermission` 注解验证权限
- 缺少权限时返回 403 错误
