# 机构管理功能实现方案

## 一、背景与概述

### 1.1 业务背景

机构管理是医工宝系统的基础数据管理模块，用于集中管理系统中的各类组织机构。机构作为医工宝系统的核心基础数据之一，主要用于 ERP 订单创建时指定"客户"和"供应商"概念，支撑业务流程的正常流转。

机构模块的核心定位是**业务关联载体**，机构与重建项目、产品等业务对象之间没有直接业务关联，仅作为业务对象中人员信息、归属信息的引用载体。

### 1.2 机构类型说明

系统支持四种机构类型，使用字符串编码标识：

| 机构类型 | 类型值 | 说明 | 典型场景 |
|---------|-------|------|---------|
| 生产企业 | "1.1" | 产品制造商/委托方 | 器械生产厂家、药品生产企业 |
| 经销商 | "1.2" | 产品代理商/经销商 | 各级经销商、代理商 |
| 医疗机构 | "1.3" | 医院、诊所等 | 终端使用客户、维修服务对象 |
| 其他 | "1.4" | 其他类型机构 | 科研单位、检测机构等 |

> 注意：生产企业（"1.1"）**禁止通过接口创建或修改**，仅作为系统内置类型存在。

### 1.3 核心功能特性

| 特性 | 说明 |
|-----|------|
| CRUD 完整操作 | 支持机构的创建、查询、更新、删除 |
| 分页与多条件筛选 | 支持按机构名称、类型、地区、状态进行分页查询 |
| 机构名称唯一性校验 | 确保同一机构名称不重复 |
| 自动编码生成 | 根据机构类型自动生成唯一机构编码（ORG-X-001 格式） |
| 字典数据联动 | 与字典模块联动，填充机构类型、医院等级、医院类型等名称 |
| 机构下用户检查 | 删除机构时检查是否有关联用户，防止误删 |
| 状态管理 | 支持机构启用/禁用状态切换 |
| 经销商-医院关联 | 经销商（"1.2"）可关联多个医疗机构，通过 sys_org_hospital 表维护 |
| 资质文件管理 | 支持资质文件上传，医疗器械类资质文件必填 |

## 二、数据库设计

### 2.1 主表结构

**表名**：`sys_org`

```sql
CREATE TABLE sys_org (
    id                  BIGINT          NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    org_name            VARCHAR(128)    NOT NULL COMMENT '机构名称',
    org_code            VARCHAR(32)     NOT NULL COMMENT '机构编码',
    org_type            VARCHAR(10)     NOT NULL COMMENT '机构类型（1.1=生产企业，1.2=经销商，1.3=医疗机构，1.4=其他）',
    area_id             BIGINT          COMMENT '所属地区ID',
    area_name           VARCHAR(64)     COMMENT '所属地区名称（冗余存储）',
    address             VARCHAR(256)    COMMENT '详细地址',
    contact             VARCHAR(32)     NOT NULL COMMENT '联系人',
    phone               VARCHAR(32)     NOT NULL COMMENT '联系电话',
    email               VARCHAR(64)     COMMENT '联系邮箱',
    credit_code         VARCHAR(32)     COMMENT '统一社会信用代码',
    qualification_file  VARCHAR(512)    COMMENT '资质文件（存储路径/URL）',
    qualification_type  TINYINT         COMMENT '资质类型（1=医疗器械，2=非医疗器械）',
    hospital_level      VARCHAR(32)     COMMENT '医院等级（医疗机构专用）',
    hospital_type       VARCHAR(32)     COMMENT '医院类型（医疗机构专用）',
    status              TINYINT         DEFAULT 1 COMMENT '状态（0=禁用，1=正常）',
    remark              VARCHAR(512)    COMMENT '备注说明',

    -- 通用字段（BaseEntity）
    create_time         DATETIME        DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time         DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    create_by           BIGINT          DEFAULT NULL COMMENT '创建人ID',
    update_by           BIGINT          DEFAULT NULL COMMENT '更新人ID',
    is_deleted          TINYINT         DEFAULT 0 COMMENT '是否删除（0=否，1=是）',

    PRIMARY KEY (id),
    KEY idx_sys_org_type (org_type),
    KEY idx_sys_org_area_id (area_id),
    KEY idx_sys_org_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='机构表';

-- 函数唯一索引（兼容逻辑删除）
CREATE UNIQUE INDEX uk_org_code
    ON sys_org ((CASE WHEN is_deleted = 0 THEN org_code ELSE NULL END));
CREATE UNIQUE INDEX uk_org_name
    ON sys_org ((CASE WHEN is_deleted = 0 THEN org_name ELSE NULL END));
```

### 2.2 经销商-医院关联表

**表名**：`sys_org_hospital`

经销商（"1.2"）与医疗机构（"1.3"）之间的多对多关联表。

```sql
CREATE TABLE sys_org_hospital (
    id                  BIGINT          NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    distributor_org_id  BIGINT          NOT NULL COMMENT '经销商机构ID',
    hospital_org_id     BIGINT          NOT NULL COMMENT '医疗机构ID',
    PRIMARY KEY (id),
    KEY idx_sys_org_hospital_distributor (distributor_org_id),
    KEY idx_sys_org_hospital_hospital (hospital_org_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='经销商-医院关联表';
```

### 2.4 索引设计

### 4.1 接口列表

| 方法 | 路径 | 说明 | 登录要求 |
|-----|------|------|---------|
| POST | `/api/system/org/list` | 分页查询机构列表 | 是 |
| GET | `/api/system/org/{id}` | 根据ID查询机构详情 | 是 |
| POST | `/api/system/org` | 创建机构 | 是 |
| PUT | `/api/system/org/{id}` | 更新机构 | 是 |
| DELETE | `/api/system/org/{id}` | 删除机构 | 是 |
| PUT | `/api/system/org/{id}/status` | 修改机构状态 | 是 |
| GET | `/api/system/org/all` | 全量查询机构列表（用于下拉选择） | 是 |

### 4.2 接口详细设计

#### 4.2.1 分页查询机构列表

**请求方式**：`POST /api/system/org/list`（POST + JSON body）

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
|-----|------|-----|------|
| pageNum | Integer | 否 | 页码，默认 1 |
| pageSize | Integer | 否 | 每页条数，默认 10 |
| orgName | String | 否 | 机构名称（模糊查询） |
| orgType | String | 否 | 机构类型（精确查询，如 "1.3"） |
| areaId | Long | 否 | 地区ID（精确查询） |
| status | Integer | 否 | 状态（精确查询） |

**查询逻辑**：机构名称模糊查询，其余字段精确查询，按 `create_time` 降序。

#### 4.2.2 创建机构

**请求方式**：`POST /api/system/org`

**请求体**（`CreateOrgDTO`）：

| 字段 | 类型 | 必填 | 说明 |
|-----|------|-----|------|
| orgName | String | 是 | 机构名称 |
| orgType | String | 是 | 机构类型（"1.2"/"1.3"/"1.4"，禁止传 "1.1"） |
| areaId | Long | 否 | 所属地区ID |
| areaName | String | 否 | 所属地区名称 |
| address | String | 否 | 详细地址 |
| contact | String | 是 | 联系人 |
| phone | String | 是 | 联系电话 |
| email | String | 否 | 联系邮箱 |
| creditCode | String | 否 | 统一社会信用代码 |
| qualificationFile | String | 条件必填 | 资质文件路径；qualificationType=1 时必填 |
| qualificationType | Integer | 否 | 资质类型：1=医疗器械，2=非医疗器械 |
| hospitalLevel | String | 否 | 医院等级（医疗机构专用） |
| hospitalType | String | 否 | 医院类型（医疗机构专用） |
| hospitalOrgIds | List\<Long\> | 否 | 关联医院机构ID列表（经销商专用） |
| remark | String | 否 | 备注说明 |

**失败响应**：
- `code=620`：禁止创建生产企业类型
- `code=621`：医疗器械资质文件必填
- `code=615`：机构名称已存在
- `code=618`：机构类型不存在

#### 4.2.3 更新机构

**请求方式**：`PUT /api/system/org/{id}`

**业务规则**：
- `orgCode` 不可修改
- 禁止将机构类型修改为生产企业（"1.1"）
- `orgName` 更新时检查是否与其他机构重复
- 经销商的 `hospitalOrgIds` 更新时先删除旧关联再插入新关联

#### 4.2.4 删除机构

**请求方式**：`DELETE /api/system/org/{id}`

**业务规则**：
- 删除前检查该机构下是否有用户（`sys_user.org_id`）
- 删除时清理 `sys_org_hospital` 中该机构作为经销商或医院的所有关联记录
- 使用逻辑删除（`isDeleted=1`）

**失败响应**：
- `code=617`：该机构下存在用户，无法删除

#### 4.2.5 修改机构状态

**请求方式**：`PUT /api/system/org/{id}/status`

| 参数 | 类型 | 必填 | 说明 |
|-----|------|-----|------|
| status | Integer | 是 | 0=禁用，1=正常 |

## 五、核心业务逻辑

### 5.1 机构编码自动生成

机构编码格式为 `ORG-{类型前缀}-{序号}`，序号为 3 位数字，从 001 开始自动递增。

**编码规则**：

| 机构类型 | 类型前缀 | 示例 |
|---------|---------|------|
| 生产企业（"1.1"） | ORG-P- | ORG-P-001 |
| 经销商（"1.2"） | ORG-D- | ORG-D-001 |
| 医疗机构（"1.3"） | ORG-H- | ORG-H-001 |
| 其他（"1.4" 及默认） | ORG-O- | ORG-O-001 |

**生成逻辑**（基于 orgType 字符串匹配）：

```java
private String generateOrgCode(String orgType) {
    String prefix = switch (orgType) {
        case "1.1" -> "ORG-P-";
        case "1.2" -> "ORG-D-";
        case "1.3" -> "ORG-H-";
        default    -> "ORG-O-";
    };
    // 查询当前前缀下最大序号，递增生成
    ...
}
```

### 5.2 生产企业禁止创建/修改

创建和更新时均校验 orgType，禁止操作生产企业类型：

```java
if ("1.1".equals(dto.getOrgType())) {
    throw new BusinessException(ErrorCodeEnum.ORG_TYPE_NOT_ALLOWED);
}
```

### 5.3 资质文件条件必填

当 `qualificationType = 1`（医疗器械）时，`qualificationFile` 必须提供：

```java
if (Integer.valueOf(1).equals(dto.getQualificationType())
        && StrUtil.isBlank(dto.getQualificationFile())) {
    throw new BusinessException(ErrorCodeEnum.ORG_CERT_FILE_REQUIRED);
}
```

### 5.4 经销商-医院关联维护

经销商（"1.2"）创建/更新时，通过 `sys_org_hospital` 表维护与医疗机构的多对多关联：

- **创建**：保存机构后，批量插入 `(distributorOrgId, hospitalOrgId)` 记录
- **更新**：先删除该经销商的所有旧关联，再插入新关联
- **删除**：清理该机构作为经销商（`distributor_org_id = id`）和作为医院（`hospital_org_id = id`）的所有关联记录

### 5.5 删除前用户关联检查

```java
if (userMapper.countByOrgId(id) > 0) {
    throw new BusinessException(ErrorCodeEnum.ORG_HAS_USERS);
}
```

### 5.6 字典名称自动填充

查询时自动填充字典名称字段：

| 字典编码常量 | 填充字段 | 说明 |
|-------------|---------|------|
| `DictCodeConstants.ORG_TYPE` | orgTypeName | 机构类型名称 |
| `DictCodeConstants.HOSPITAL_LEVEL` | hospitalLevelName | 医院等级名称 |
| `DictCodeConstants.HOSPITAL_TYPE` | hospitalTypeName | 医院类型名称 |

## 九、字段设计说明

### 9.1 orgType 字符串编码设计

`org_type` 使用 VARCHAR(10) 存储字符串编码（"1.1"/"1.2"/"1.3"/"1.4"），而非整数枚举。这样设计便于后续扩展子类型（如 "1.2.1" 区域经销商），同时与字典表的 `dict_value` 字段直接对应，无需转换。

### 9.2 冗余字段

| 冗余字段 | 来源 | 说明 |
|---------|------|------|
| `area_name` | 地区表 name | 避免每次查询关联地区表 |

### 9.3 医疗机构专用字段

当 `org_type = "1.3"` 时生效：

| 字段 | 类型 | 说明 |
|-----|------|------|
| `hospital_level` | VARCHAR(32) | 医院等级，关联字典 |
| `hospital_type` | VARCHAR(32) | 医院类型，关联字典 |

### 9.4 资质文件字段

| 字段 | 类型 | 说明 |
|-----|------|------|
| `qualification_file` | VARCHAR(512) | 资质文件路径/URL |
| `qualification_type` | TINYINT | 1=医疗器械（此时 qualification_file 必填），2=非医疗器械 |

## 十一、常见问题与注意事项

### 11.1 机构编码不可修改

机构编码由系统自动生成，`UpdateOrgDTO` 中不包含 `orgCode` 字段，`BeanUtils.copyProperties` 时已排除。

### 11.2 生产企业的处理

生产企业（"1.1"）只能通过 SQL 初始化数据写入，不能通过接口创建或将其他机构修改为该类型。违反时抛出 `ORG_TYPE_NOT_ALLOWED(620)`。

### 11.3 删除机构的前置条件

1. 机构本身必须存在
2. 该机构下不能有用户（`sys_user.org_id`）
3. 删除后自动清理 `sys_org_hospital` 中的所有关联记录（无论作为经销商还是医院）

### 11.4 逻辑删除与唯一索引

`org_name` 和 `org_code` 使用函数唯一索引（MySQL 8.0+ 特性），已删除记录（`is_deleted=1`）不占用唯一索引槽位，支持同名机构删除后重建。H2 测试环境中省略函数索引定义。

### 11.5 经销商关联医院

只有 `org_type = "1.2"`（经销商）的机构才能关联医院。关联数据存储在 `sys_org_hospital` 表，与主表独立维护，删除机构时级联清理。
