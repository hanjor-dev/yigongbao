# 机构管理功能实现方案

## 一、背景与概述

### 1.1 业务背景

机构管理是医工宝系统的基础数据管理模块，用于集中管理系统中的各类组织机构。机构作为医工宝系统的核心基础数据之一，主要用于 ERP 订单创建时指定"客户"和"供应商"概念，支撑业务流程的正常流转。

机构模块的核心定位是**业务关联载体**，机构与重建项目、产品等业务对象之间没有直接业务关联，仅作为业务对象中人员信息、归属信息的引用载体。

### 1.2 机构类型说明

系统支持四种机构类型，通过字典表管理：

| 机构类型 | 类型值 | 说明 | 典型场景 |
|---------|-------|------|---------|
| 生产企业 | 1 | 产品制造商/委托方 | 器械生产厂家、药品生产企业 |
| 经销商 | 2 | 产品代理商/经销商 | 各级经销商、代理商 |
| 医疗机构 | 3 | 医院、诊所等 | 终端使用客户、维修服务对象 |
| 其他 | 4+ | 其他类型机构 | 科研单位、检测机构等 |

### 1.3 核心功能特性

| 特性 | 说明 |
|-----|------|
| CRUD 完整操作 | 支持机构的创建、查询、更新、删除 |
| 分页与多条件筛选 | 支持按机构名称、类型、地区、状态进行分页查询 |
| 机构名称唯一性校验 | 确保同一机构名称不重复 |
| 自动编码生成 | 根据机构类型自动生成唯一机构编码（ORG-X-001 格式） |
| 字典数据联动 | 与字典模块联动，填充机构类型、医院等级、医院类型等产品线名称 |
| 机构下用户检查 | 删除机构时检查是否有关联用户，防止误删 |
| 状态管理 | 支持机构启用/禁用状态切换 |

## 二、数据库设计

### 2.1 表结构

**表名**：`sys_org`

**设计说明**：机构表采用扁平化设计，存储机构的基本信息和扩展信息。

```sql
CREATE TABLE sys_org (
    id                  BIGINT          NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    org_name            VARCHAR(128)    NOT NULL COMMENT '机构名称',
    org_code            VARCHAR(32)     NOT NULL COMMENT '机构编码',
    org_type            TINYINT         NOT NULL COMMENT '机构类型（1=生产企业，2=经销商，3=医疗机构）',
    area_id             BIGINT          COMMENT '所属地区ID',
    area_name           VARCHAR(64)     COMMENT '所属地区名称（冗余存储）',
    address             VARCHAR(256)    COMMENT '详细地址',
    contact             VARCHAR(32)     NOT NULL COMMENT '联系人',
    phone               VARCHAR(32)     NOT NULL COMMENT '联系电话',
    email               VARCHAR(64)     COMMENT '联系邮箱',
    credit_code         VARCHAR(32)     COMMENT '统一社会信用代码',
    business_license    VARCHAR(512)    COMMENT '营业执照（存储路径/URL）',
    agent_area          VARCHAR(64)     COMMENT '代理区域（经销商）',
    agent_product_line  VARCHAR(256)    COMMENT '代理产品线（多个用逗号分隔）',
    hospital_level      TINYINT         COMMENT '医院等级（医疗机构）',
    hospital_type       TINYINT         COMMENT '医院类型（医疗机构）',
    status              TINYINT         DEFAULT 1 COMMENT '状态（0=禁用，1=正常）',
    remark              VARCHAR(512)    COMMENT '备注说明',

    -- 通用字段（BaseEntity）
    create_time         DATETIME        DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time         DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    create_by           BIGINT          DEFAULT NULL COMMENT '创建人ID',
    update_by           BIGINT          DEFAULT NULL COMMENT '更新人ID',
    is_deleted          TINYINT         DEFAULT 0 COMMENT '是否删除（0=否，1=是）',

    PRIMARY KEY (id),
    UNIQUE KEY uk_org_code (org_code),           -- 机构编码唯一索引
    UNIQUE KEY uk_org_name (org_name),           -- 机构名称唯一索引
    KEY idx_org_type (org_type),                 -- 机构类型索引
    KEY idx_area_id (area_id),                    -- 地区ID索引
    KEY idx_status (status)                       -- 状态索引
);
```

## 五、核心业务逻辑

### 5.1 机构编码自动生成

机构编码格式为 `ORG-{类型前缀}-{序号}`，序号为 3 位数字，从 001 开始自动递增。

**编码规则**：

| 机构类型 | 类型前缀 | 示例 |
|---------|---------|------|
| 生产企业 | ORG-P- | ORG-P-001, ORG-P-002 |
| 经销商 | ORG-D- | ORG-D-001, ORG-D-002 |
| 医疗机构 | ORG-H- | ORG-H-001, ORG-H-002 |
| 其他 | ORG-O- | ORG-O-001, ORG-O-002 |

**生成算法**：

```java
// OrgServiceImpl.java - generateOrgCode 方法
private String generateOrgCode(Integer orgType) {
    // 1. 根据类型确定前缀
    String prefix = switch (String.valueOf(orgType)) {
        case "1" -> "ORG-P-";  // 生产企业
        case "2" -> "ORG-D-";  // 经销商
        case "3" -> "ORG-H-";  // 医疗机构
        default -> "ORG-O-";   // 其他
    };

    // 2. 查询当前前缀下的最大序号
    LambdaQueryWrapper<OrgEntity> wrapper = new LambdaQueryWrapper<>();
    wrapper.likeRight(OrgEntity::getOrgCode, prefix)
            .orderByDesc(OrgEntity::getOrgCode)
            .last("LIMIT 1");
    OrgEntity lastOrg = getOne(wrapper);

    // 3. 解析序号并生成新编码
    int maxSeq = 0;
    if (lastOrg != null) {
        String seqStr = lastOrg.getOrgCode().replace(prefix, "");
        maxSeq = Integer.parseInt(seqStr);
    }
    return prefix + String.format("%03d", maxSeq + 1);
}
```

### 5.2 机构名称唯一性校验

创建和更新时都会进行机构名称唯一性校验：

```java
// 创建时校验
if (isOrgNameExists(dto.getOrgName())) {
    throw new BusinessException(ErrorCodeEnum.ORG_EXISTS);
}

// 更新时校验（排除自身）
if (StrUtil.isNotBlank(dto.getOrgName()) && !dto.getOrgName().equals(entity.getOrgName())) {
    if (isOrgNameExistsExcludingId(dto.getOrgName(), id)) {
        throw new BusinessException(ErrorCodeEnum.ORG_EXISTS);
    }
}
```

### 5.3 机构类型字典校验

创建机构时，会验证 `orgType` 是否在字典表中存在：

```java
// OrgServiceImpl.java - isOrgTypeValid 方法
private boolean isOrgTypeValid(Integer orgType) {
    if (orgType == null) {
        return false;
    }
    List<DictVO> dictList = dictService.listByTypeCode(DictCodeConstants.ORG_TYPE);
    return dictList.stream()
            .anyMatch(d -> Objects.equals(d.getDictValue(), String.valueOf(orgType)));
}
```

### 5.4 字典名称自动填充

查询机构列表和详情时，会自动填充字典名称字段：

| 字典编码 | 填充字段 | 说明 |
|---------|---------|------|
| DictCodeConstants.ORG_TYPE | orgTypeName | 机构类型名称 |
| DictCodeConstants.HOSPITAL_LEVEL | hospitalLevelName | 医院等级名称 |
| DictCodeConstants.HOSPITAL_TYPE | hospitalTypeName | 医院类型名称 |
| DictCodeConstants.AGENT_PRODUCT_LINE | agentProductLineNames | 代理产品线名称（逗号分隔） |
| StatusConstants | statusName | 状态名称 |

### 5.5 删除前用户关联检查

删除机构前，会检查该机构下是否有用户，防止误删：

```java
// OrgServiceImpl.java - removeOrg 方法
if (hasUsers(id)) {
    log.warn("该机构下存在用户，无法删除，id={}", id);
    throw new BusinessException(ErrorCodeEnum.ORG_HAS_USERS);
}

// OrgServiceImpl.java - hasUsers 方法
private boolean hasUsers(Long orgId) {
    return userMapper.countByOrgId(orgId) > 0;
}
```

`countByOrgId` 方法使用 `@Select` 注解直接查询：

```java
// UserMapper.java
@Select("SELECT COUNT(*) FROM sys_user WHERE org_id = #{orgId} AND is_deleted = 0")
Long countByOrgId(Long orgId);
```

## 十一、常见问题与注意事项

### 11.1 机构编码是否可修改

机构编码由系统自动生成，**不支持手动修改**。在 `UpdateOrgDTO` 中未包含 `orgCode` 字段，`BeanUtils.copyProperties` 时已排除该字段。

### 11.2 删除机构的限制条件

删除机构前必须满足以下条件：
- 机构本身必须存在
- 该机构下**不能有用户**（`sys_user.org_id`）

如果机构下有关联用户，需要先删除或迁移用户，再删除机构。

### 11.3 字典数据依赖

机构模块依赖字典模块的字典数据，包括：
- 机构类型（DictCodeConstants.ORG_TYPE）
- 医院等级（DictCodeConstants.HOSPITAL_LEVEL）
- 医院类型（DictCodeConstants.HOSPITAL_TYPE）
- 代理产品线（DictCodeConstants.AGENT_PRODUCT_LINE）

使用机构模块前，需要确保字典表中有对应的字典数据。

### 11.4 逻辑删除说明

机构模块使用逻辑删除（`isDeleted=1`），删除操作不会物理删除数据，只会标记 `is_deleted` 字段。

### 11.5 机构名称唯一性

机构名称（`org_name`）是全局唯一的，不允许两个机构使用相同的名称。这是通过数据库唯一索引 `uk_org_name` 约束的。
