# 08_鉴权功能实现方案

## 一、模块概述

鉴权模块是医工宝系统安全体系的核心模块，负责处理用户的登录认证、Token 管理、登出操作和密码修改等功能。该模块整合了 Sa-Token 框架作为认证基础设施，结合系统的用户管理、资源管理和系统配置模块，构建起完整的身份认证和权限控制体系。

### 1.1 核心能力

- 用户名密码登录认证
- Token 管理与自动续期
- 用户登出
- 当前用户信息获取（含菜单树和权限列表）
- 密码修改
- 登录失败锁定机制
- 登录日志记录
- 公共接口的认证放行

## 二、数据库设计

### 2.1 登录日志表（sys_login_log）

```sql
CREATE TABLE sys_login_log (
    id              BIGINT          NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    user_id         BIGINT          COMMENT '用户ID',
    username        VARCHAR(64)     COMMENT '用户名',
    ip              VARCHAR(64)     COMMENT '登录IP',
    user_agent      VARCHAR(512)    COMMENT 'User-Agent（浏览器/设备信息）',
    login_time      TIMESTAMP       NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '登录时间',
    login_status    TINYINT         NOT NULL COMMENT '登录结果（1=成功，0=失败）',
    fail_reason     VARCHAR(256)    COMMENT '失败原因',

    PRIMARY KEY (id),
    KEY idx_login_user_id (user_id),
    KEY idx_login_time (login_time)
);
```

### 4.2 登录核心流程

```
登录（login）
  │
  ├─0. 获取客户端信息
  │    ├─ IP地址：从请求头 X-Forwarded-For / X-Real-IP / remoteAddr 获取
  │    └─ User-Agent：从请求头获取
  │
  ├─1. 查询用户
  │    └─ userMapper.selectByUsername(username)
  │         ├─ 用户不存在 → 记录失败日志 → 抛出 USERNAME_OR_PASSWORD_ERROR(641)
  │         └─ 用户存在 → 继续
  │
  ├─2. 校验用户状态
  │    └─ user.status == 0（禁用）
  │         └─ 是 → 记录失败日志 → 抛出 USER_DISABLED(601)
  │
  ├─3. 校验账户是否锁定
  │    └─ isAccountLocked(user)
  │         ├─ 计算剩余锁定时间
  │         ├─ 记录失败日志
  │         └─ 抛出 ACCOUNT_LOCKED(640)，提示 X 分钟后重试
  │
  ├─4. 校验密码
  │    └─ passwordEncoder.matches(rawPassword, encryptedPassword)
  │         ├─ 不匹配 → handleLoginFailure → 抛出 PASSWORD_ERROR(603)
  │         └─ 匹配 → 继续
  │
  ├─5. 登录成功处理
  │    └─ resetLoginFailCount(user)
  │         ├─ loginFailCount = 0
  │         ├─ lockTime = null
  │         └─ 更新用户记录
  │
  ├─6. 执行 Sa-Token 登录
  │    └─ StpUtil.login(userId)
  │         └─ 生成 Token，返回 token 值
  │
  ├─7. 记录登录成功日志
  │    └─ saveLoginLog(userId, username, ip, userAgent, 1, null)
  │
  └─8. 构建并返回 LoginVO
       └─ { token, user, menus, permissions }
```

### 4.3 登录失败处理流程

```
处理登录失败（handleLoginFailure）
  │
  ├─1. 记录失败日志
  │    └─ saveLoginLog(userId, username, ip, userAgent, 0, "密码错误")
  │
  ├─2. 递增失败计数
  │    └─ newFailCount = user.loginFailCount + 1
  │
  ├─3. 判断是否达到锁定阈值
  │    └─ getMaxLoginFailures() → 从系统配置获取（默认 5 次）
  │
  │    ├─ newFailCount >= maxFailures
  │    │    ├─ 锁定账户
  │    │    │    ├─ user.loginFailCount = newFailCount
  │    │    │    └─ user.lockTime = LocalDateTime.now()
  │    │    └─ 更新用户记录
  │    │
  │    └─ newFailCount < maxFailures
  │         └─ 仅更新失败计数
  │
  └─4. 抛出异常
       └─ 抛出 PASSWORD_ERROR(603)
```

### 4.4 账户锁定与自动解锁

```
判断账户是否锁定（isAccountLocked）
  │
  ├─1. 检查 lockTime 是否为空
  │    └─ null → 未锁定，返回 false
  │
  └─2. 检查锁定是否已过期
       └─ lockTime + lockDuration > now
            ├─ 是 → 已锁定，返回 true
            └─ 否 → 自动解锁，返回 false

锁定时长（lockDuration）：从系统配置 login.lock.duration 获取（默认 15 分钟）
```

## 六、密码修改流程

```
修改密码（changePassword）
  │
  ├─1. 获取当前登录用户ID
  │    └─ StpUtil.getLoginIdAsLong()
  │
  ├─2. 查询用户信息
  │    └─ userMapper.selectById(userId)
  │         └─ null → 抛出 USER_NOT_FOUND(600)
  │
  ├─3. 校验旧密码
  │    └─ passwordEncoder.matches(oldPassword, user.password)
  │         └─ 不匹配 → 抛出 OLD_PASSWORD_ERROR(625)
  │
  ├─4. 校验新旧密码不能相同
  │    └─ passwordEncoder.matches(newPassword, user.password)
  │         └─ 相同 → 抛出 OLD_PASSWORD_ERROR(625)
  │
  ├─5. 更新密码
  │    └─ user.password = passwordEncoder.encode(newPassword)
  │    └─ userMapper.updateById(user)
  │
  └─6. 记录日志
       └─ log.info("修改密码成功，userId={}", userId)
```

### 7.2 Sa-Token 配置详解

```java
@Configuration
@ConditionalOnProperty(name = "satoken.interceptor.enable",
                         havingValue = "true", matchIfMissing = true)
public class SaTokenConfig implements WebMvcConfigurer {

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        // 注册 Sa-Token 拦截器
        var registration = registry.addInterceptor(
            new SaInterceptor(handle -> StpUtil.checkLogin())
        );
        registration.addPathPatterns("/**");  // 拦截所有路径

        // 放行路径
        registration.excludePathPatterns(
            "/static/**",
            "/favicon.ico",
            "/common/**",
            "/error",
            "/test/**",
            "/api/system/auth/login",
            "/api/system/auth/logout",
            "/api/system/auth/info",
            "/api/system/auth/password",
            "/api/system/config/public",
            "/doc.html",
            "/swagger-ui/**",
            "/v3/api-docs/**"
        );
    }
}
```

**配置说明**：

- `matchIfMissing = true`：默认启用认证拦截
- 测试环境可通过 `satoken.interceptor.enable: false` 禁用
- 拦截器通过 `StpUtil.checkLogin()` 验证登录状态

## 九、数据范围权限体系

### 9.1 概述

数据范围权限（Data Scope Permission）是医工宝系统中用于控制用户可见业务数据范围的机制，与接口权限（Resource/Permission）共同构成完整的 RBAC 权限体系。

| 权限类型 | 作用层级 | 控制内容 | 实现位置 |
|---------|---------|---------|---------|
| **接口权限** | 功能控制 | 用户能否访问某个功能/菜单/按钮 | `sys_resource` + `sys_role_resource` |
| **数据范围权限** | 数据可见性 | 用户能看哪些具体数据（机构/部门/医院等） | `sys_user_hospital` + 业务查询条件 |

### 9.2 数据范围类型定义

数据范围由 `DataScopeConstants` 常量类定义，共 5 种类型：

```java
public final class DataScopeConstants {

    // ==================== 数据范围 ====================

    /**
     * 全部数据
     * 适用于：系统超级管理员，可访问所有数据
     */
    public static final int ALL = 1;

    /**
     * 本机构数据
     * 适用于：机构管理员，只能访问本机构的数据
     */
    public static final int ORG = 2;

    /**
     * 仅自己
     * 适用于：普通用户，只能访问自己创建的数据
     */
    public static final int SELF = 3;

    /**
     * 医院范围
     * 适用于：业务员等，需要精确到具体医院的权限
     * 数据范围由 sys_user_hospital 表决定
     */
    public static final int HOSPITALS = 4;

    /**
     * 部门范围
     * 适用于：部门负责人，只能访问本部门的数据
     */
    public static final int DEPT = 5;
}
```

### 9.3 数据范围权限模型

```
┌─────────────────────────────────────────────────────────────────────────┐
│                           角色（sys_role）                                │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │  hospital_scope_enabled → replaced by data_scope_type                     │   │
│  │                                                                  │   │
│  │  data_scope_type = "org"/"self"（不启用医院范围）                │   │
│  │    → 用户的医院范围由其他数据范围类型决定（ORG/DEPT/SELF）       │   │
│  │                                                                  │   │
│  │  data_scope_type = "hospitals"（启用医院范围）                   │   │
│  │    → 用户的具体医院范围由 sys_user_hospital 表决定               │   │
│  │    → 同一角色下，不同用户可有完全不同的医院范围                   │   │
│  └─────────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                        用户-医院关联（sys_user_hospital）                  │
│  ┌─────────────────────────────────────────────────────────────────┐   │
│  │                                                                  │   │
│  │   用户表（sys_user）    关联表                医院表（hospital）   │   │
│  │  ┌──────────┐        ┌────────────────┐      ┌──────────┐     │   │
│  │  │ user_id=1 │──────▶│ user_id=1      │      │ id=1     │     │   │
│  │  │ username  │        │ hospital_id=1  │◀─────│ 医院A    │     │   │
│  │  │ role_id=4│        │ user_id=2      │      │ id=2     │     │   │
│  │  └──────────┘        │ hospital_id=2  │◀─────│ 医院B    │     │   │
│  │  ┌──────────┐        └────────────────┘      └──────────┘     │   │
│  │  │ user_id=2 │◀─────── user_id=2                                │   │
│  │  │ username  │        │ hospital_id=3                            │   │
│  │  │ role_id=4 │◀─────  │ hospital_id=5                            │   │
│  │  └──────────┘                                                     │   │
│  │                                                                  │   │
│  │  说明：                                                          │   │
│  │  - 用户1（业务员A）：可访问医院A、医院B                          │   │
│  │  - 用户2（业务员B）：可访问医院B、医院C、医院D                  │   │
│  │  - 虽然两人角色相同（role_id=4），但医院范围完全不同             │   │
│  │  - 业务查询时，通过 user_id → sys_user_hospital → hospital_id  │   │
│  │    自动添加过滤条件                                              │   │
│  └─────────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────────┘
```

### 9.4 医院范围权限启用条件

```
用户能分配医院范围的前提条件（必须同时满足）：
  │
  ├─1. 用户关联的角色 data_scope_type = "hospitals"
  │    └─ 由 RoleEntity.dataScopeType 字段控制
  │
  └─2. 管理员在创建/编辑用户时传入了 hospitalIds 参数
       └─ 由 CreateUserDTO.hospitalIds / UpdateUserDTO.hospitalIds 控制

结论：
- data_scope_type != "hospitals" → 用户无法分配医院范围（前端不显示医院选择）
- data_scope_type = "hospitals" + hospitalIds 传入 → 用户获得医院范围权限
```

### 9.5 业务数据查询流程

```
业务模块查询数据时（如 ERP 订单查询）：

1. 获取当前登录用户
   └─ StpUtil.getLoginIdAsLong()

2. 查询用户信息（包含角色和机构）
   └─ UserMapper.selectById(userId)

3. 判断医院范围权限是否启用
   │
   ├─ 角色 data_scope_type = "hospitals"
   │    ├─ 获取用户关联的医院ID列表
   │    │    └─ UserHospitalService.getHospitalIdsByUserId(userId)
   │    │         └─ 返回 List<Long>: [1, 2, 3]
   │    │
   │    └─ SQL 添加过滤条件：
   │         WHERE hospital_id IN (1, 2, 3)
   │
   ├─ 角色 data_scope_type = "org"
   │    ├─ 获取用户所属机构ID
   │    │    └─ user.orgId
   │    │
   │    └─ SQL 添加过滤条件：
   │         WHERE org_id = #{orgId}
   │
   ├─ 角色 data_scope_type = "dept"（DEPT 类型）
   │    ├─ 获取用户所属部门ID
   │    │    └─ user.deptId
   │    │
   │    └─ SQL 添加过滤条件：
   │         WHERE dept_id = #{deptId}
   │
   └─ 角色 data_scope_type = "self"
        ├─ 获取当前用户ID
        │    └─ user.id
        │
        └─ SQL 添加过滤条件：
             WHERE create_by = #{userId}
```

### 9.6 医院范围权限应用场景

```
场景1：经销商业务员
  角色：ROLE_SALES（data_scope_type = "hospitals"）
  场景：业务员负责多家医院的销售工作
  权限配置：
    - 用户A：关联医院 医院A、医院B、医院C
    - 用户B：关联医院 医院B、医院D、医院E
  效果：用户A只能查看自己在A/B/C医院的订单，用户B只能查看B/D/E的订单

场景2：医疗机构医生
  角色：ROLE_DOCTOR（data_scope_type = "self"）
  场景：医生只能查看自己所属医院的数据
  权限配置：
    - data_scope_type = "self"
  效果：用户只能查看医院A的数据

场景3：系统管理员
  角色：ROLE_ADMIN（data_scope_type = "all"）
  场景：管理员需要查看所有数据
  权限配置：
    - data_scope_type = "all"
  效果：用户可查看所有数据，无任何数据范围限制
```

// 获取客户端 IP（支持多级代理）
private String getClientIp() {
    String ip = request.getHeader("X-Forwarded-For");
    if (ip == null || ip.isEmpty() || "unknown".equalsIgnoreCase(ip)) {
        ip = request.getHeader("X-Real-IP");
    }
    if (ip == null || ip.isEmpty() || "unknown".equalsIgnoreCase(ip)) {
        ip = request.getRemoteAddr();
    }
    // 多级代理时取第一个IP
    if (ip != null && ip.contains(",")) {
        ip = ip.split(",")[0].trim();
    }
    return ip;
}

// 获取 User-Agent
private String getUserAgent() {
    return request.getHeader("User-Agent");
}

## 十二、安全设计

### 12.1 密码安全

- 使用 BCryptPasswordEncoder 加密，强度 `$2a$10$`（默认强度 10）
- 密码校验使用 `matches()` 方法，防止时序攻击
- 不存储明文密码

### 12.2 Token 安全

- Token 存储在 HTTP Header `Satoken` 中（非 Cookie）
- Token 默认有效期 30 天（Sa-Token 默认配置）
- 登出时调用 `StpUtil.logout()` 使 Token 失效

### 12.3 账户安全

- 连续登录失败达到阈值后自动锁定
- 锁定后自动解锁（基于时间）
- 登录成功自动重置失败计数
