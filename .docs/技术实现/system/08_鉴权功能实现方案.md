# 08_鉴权功能实现方案

## 一、模块概述

鉴权模块是医工宝系统安全体系的核心模块，负责处理用户的登录认证、Token 管理、登出操作和密码修改等功能。该模块整合了 Sa-Token 框架作为认证基础设施，结合系统的用户管理、资源管理和系统配置模块，构建起完整的身份认证和权限控制体系。

### 1.1 核心能力

- 两种登录方式：账号密码（PASSWORD）、手机验证码（PHONE）
- PASSWORD 登录支持用户名或邮箱两种账号格式（系统自动识别，统一走 PASSWORD 类型）
- 行为验证码校验（PASSWORD 登录时可选，由自实现 `ImageCaptchController` 封装 tianai-captcha 提供）
- 短信/邮件验证码发送与校验（忘记密码支持手机号/邮箱二选一）
- Token 管理与自动续期
- 用户登出
- 当前用户信息获取（含菜单树和权限列表）
- 密码修改
- 忘记密码：发送验证码 + 重置密码
- 登录失败锁定机制
- 登录日志记录（含登录方式）
- 公共接口的认证放行

## 二、数据库设计

### 2.1 登录日志表（sys_login_log）

```sql
CREATE TABLE sys_login_log (
    id              BIGINT          NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    user_id         BIGINT          COMMENT '用户ID',
    username        VARCHAR(64)     COMMENT '用户名',
    login_type      VARCHAR(16)     COMMENT '登录方式（PASSWORD/PHONE/EMAIL）',
    ip              VARCHAR(64)     COMMENT '登录IP',
    user_agent      VARCHAR(512)    COMMENT 'User-Agent（浏览器/设备信息）',
    login_time      TIMESTAMP       NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '登录时间',
    login_status    TINYINT         NOT NULL COMMENT '登录结果（1=成功，0=失败）',
    fail_reason     VARCHAR(256)    COMMENT '失败原因',

    PRIMARY KEY (id),
    KEY idx_login_user_id (user_id),
    KEY idx_login_time (login_time)
);
```

### 3.2 请求/响应示例

**生成行为验证码**

```
POST /api/image-captch/genCaptcha?type=SLIDER
```

响应（统一 `Result` 包装）：
```json
{
  "code": 200,
  "data": {
    "id": "d5a9f3e2-...",

    "backgroundImage": "data:image/png;base64,...",
    "templateImage": "data:image/png;base64,...",
    "backgroundImageWidth": 320,
    "backgroundImageHeight": 160
  }
}
```

> `type` 不传时默认 `SLIDER`，可选值：`SLIDER`、`ROTATE`、`WORD_IMAGE_CLICK`、`CONCAT`。

**校验行为验证码**

```json
POST /api/image-captch/check
{
  "id": "d5a9f3e2-...",
  "data": {
    "trackList": [...],
    "startSlidingTime": 1714000000000,
    "endSlidingTime": 1714000003000,

    "bgImageHeight": 160,
    "percentagex": 0.875,
    "percentagey": 0.5
  }
}
```

校验成功后 id 即失效，`repData.id` 即登录时传入的 `captchaKey`。

**账号密码登录（含行为验证码）**

```json
POST /api/system/auth/login
{
  "loginType": "PASSWORD",
  "principal": "admin",
  "credential": "123456",
  "captchaKey": "d5a9f3e2-...",
  "captchaTrack": {
    "trackList": [...],
    "startSlidingTime": 1714000000000,
    "endSlidingTime": 1714000003000,
    "trackLength": 280,
    "bgImageWidth": 320,
    "bgImageHeight": 160,
    "sliderImageWidth": 60,
    "sliderImageHeight": 60,
    "percentagex": 0.875,
    "percentagey": 0.5
  }
}
```

> `captchaKey` 和 `captchaTrack` 为可选字段，过渡期内不传则跳过行为验证码校验。

**账号密码登录（用邮箱作为账号）**

```json
POST /api/system/auth/login
{
  "loginType": "PASSWORD",
  "principal": "admin@example.com",
  "credential": "123456"
}
```

> `principal` 传入邮箱格式时，系统自动按 `email` 字段查询用户；传入非邮箱格式时按 `username` 字段查询。

**账号密码登录（兼容旧格式）**

```json
POST /api/system/auth/login
{
  "username": "admin",
  "password": "123456"
}
```

> 旧格式通过 `@JsonSetter` 自动映射为 `principal/credential/loginType=PASSWORD`，行为完全一致。

**手机验证码登录**

```json
POST /api/system/auth/login
{
  "loginType": "PHONE",
  "principal": "13800000001",
  "credential": "123456"
}
```

**LoginDTO 字段说明**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| loginType | String | 是 | 登录方式：PASSWORD / PHONE |
| principal | String | 是 | 登录主体：用户名或邮箱（PASSWORD）/ 手机号（PHONE） |
| credential | String | 是 | 凭据：密码（PASSWORD）/ 短信验证码（PHONE） |
| captchaKey | String | 否 | 行为验证码 id（由 `GET /image-captch/genCaptcha` 返回的 `repData.id`，PASSWORD 登录时建议传入） |
| captchaTrack | ImageCaptchaTrack | 否 | 行为验证码轨迹数据（captchaKey 有值时必传） |
| username | String | 否 | 兼容旧格式，等价于 principal（PASSWORD 登录） |
| password | String | 否 | 兼容旧格式，等价于 credential |

**登录成功响应（LoginVO）**

```json
{
  "code": 200,
  "data": {
    "token": "xxxx-xxxx-xxxx-xxxx"
  }
}
```

> `login()` 仅返回 token。菜单、权限等完整信息通过 `GET /system/auth/info` 获取。

|------|------|------|------|
| captchaType | String | 是 | 登录场景仅支持 PHONE |


## 四、登录认证流程

### 4.1 账号密码登录（PASSWORD）

```
login(dto) → loginType=PASSWORD
  │
  ├─0. 获取客户端 IP / User-Agent
  │
  ├─1. 校验滑动验证码（captchaKey 和 captchaTrack 均不为空时才校验）
  │    └─ verifySliderCaptcha(captchaKey, captchaTrack)
  │         └─ imageCaptchaApplication.matching(captchaKey, captchaTrack)
  │              └─ !isSuccess() → 抛出 CAPTCHA_GRAPHIC_ERROR(774)
  │
  ├─2. 查询用户（principal 自动识别：邮箱格式走 selectByEmail，否则走 selectByUsername）
  │    └─ userMapper.selectByEmail/selectByUsername(principal)
  │         └─ null → 记录失败日志 → 抛出 USERNAME_OR_PASSWORD_ERROR(608)
  │
  ├─3. 校验用户状态
  │    └─ status=0 → 记录失败日志 → 抛出 USER_DISABLED(602)
  │
  ├─4. 校验账户是否锁定
  │    └─ isAccountLocked(user) → 抛出 ACCOUNT_LOCKED(609)
  │
  ├─5. 校验密码
  │    └─ passwordEncoder.matches(credential, user.password)
  │         └─ 不匹配 → handleLoginFailure → 抛出 PASSWORD_ERROR(605)
  │
  └─6. 登录成功 → buildLoginSuccess(user, ip, ua, PASSWORD)
```

### 4.2 手机验证码登录（PHONE）

```
login(dto) → loginType=PHONE
  │
  ├─0. 获取客户端 IP / User-Agent
  │
  ├─1. 校验验证码
  │    └─ captchaService.verifyCaptcha(LOGIN, PHONE, principal, credential)
  │         ├─ key 不存在或已过期 → 抛出 CAPTCHA_EXPIRED(639)
  │         ├─ 尝试次数超过 5 次 → 抛出 CAPTCHA_EXPIRED(639)（作废）
  │         └─ 不匹配 → 记录失败次数 → 抛出 CAPTCHA_ERROR(640)
  │
  ├─2. 查询用户（按手机号）
  │    └─ userMapper.selectByPhone(principal)
  │         └─ null → 记录失败日志 → 抛出 USER_NOT_FOUND(600)
  │
  ├─3. 校验用户状态
  │    └─ status=0 → 记录失败日志 → 抛出 USER_DISABLED(602)
  │
  ├─4. 校验账户是否锁定
  │    └─ isAccountLocked(user) → 抛出 ACCOUNT_LOCKED(609)
  │
  └─5. 登录成功 → buildLoginSuccess(user, ip, ua, PHONE)
```

### 4.3 登录成功处理（buildLoginSuccess）

```
buildLoginSuccess(user, ip, ua, loginType)
  │
  ├─1. 重置登录失败计数（PASSWORD 登录路径才有此步）
  │    └─ loginFailCount=0, lockTime=null → updateById
  │
  ├─2. Sa-Token 登录
  │    └─ StpUtil.login(userId)
  │
  ├─3. 记录登录成功日志
  │    └─ saveLoginLog(userId, username, ip, ua, loginType, 1, null)
  │
  └─4. 返回 LoginVO { token }
```

### 4.4 行为验证码流程

**生成（前端调用自实现接口，内部委托 tianai-captcha）：**

```
GET /image-captch/genCaptcha?type=SLIDER
  │
  └─ ImageCaptchController → imageCaptchaApplication.generateCaptcha(type)
       ├─ 生成背景图（含缺口）+ 滑块图
       ├─ 生成唯一 id（captchaKey）
       ├─ 将校验数据存入 Redis（key 前缀 captcha:，TTL 120s）
       └─ 返回原生 ApiResponse<ImageCaptchaVO>（repCode/repData 格式）
```

**独立校验（可选，前端提交登录前预校验）：**

```
POST /image-captch/check  { id, data }
  │
  └─ ImageCaptchController → imageCaptchaApplication.matching(id, data)
       ├─ 校验成功 → 返回 { id }，id 即失效
       └─ 校验失败 → 返回错误响应
```

**登录内隐式校验（captchaKey 和 captchaTrack 均不为空时触发）：**

```
verifySliderCaptcha(captchaKey, captchaTrack)
  │
  └─ imageCaptchaApplication.matching(captchaKey, captchaTrack)
       ├─ 校验轨迹数据与 Redis 中存储的缺口坐标误差是否在阈值内
       └─ !isSuccess() → 抛出 CAPTCHA_GRAPHIC_ERROR(774)
```

### 4.5 登录失败处理流程（handleLoginFailure）

```
handleLoginFailure(user, ip, ua, loginType, failReason)
  │
  ├─1. 记录失败日志
  │
  ├─2. 递增失败计数
  │    └─ newFailCount = user.loginFailCount + 1
  │
  ├─3. 判断是否达到锁定阈值（login.max.failures，默认 5）
  │    ├─ >= 阈值 → 设置 lockTime=now，更新用户
  │    └─ < 阈值 → 仅更新失败计数
  │
  └─4. 抛出 PASSWORD_ERROR(605)
```

### 4.6 账户锁定与自动解锁

```
isAccountLocked(user)
  │
  ├─ lockTime=null → 返回 false（未锁定）
  └─ lockTime + lockDuration > now → 返回 true（仍在锁定）
       否则 → 返回 false（锁定已过期，自动解锁）

锁定时长：login.lock.duration 系统配置（默认 15 分钟）
```

## 五、验证码服务（CaptchaService）

> 注意：CaptchaService 仅处理**短信/邮箱验证码**。滑动验证码由 tianai-captcha（`ImageCaptchaApplication`）单独管理。

### 5.1 Redis 键结构

| 键模板 | 说明 | TTL |
|--------|------|-----|
| `captcha:{scene}:{type}:{target}` | 验证码正文 | captcha.expire.seconds（默认 300s） |
| `captcha:cooldown:{scene}:{type}:{target}` | 发送冷却 | captcha.cooldown.seconds（默认 60s） |
| `captcha:daily:{scene}:{type}:{target}:{yyyyMMdd}` | 今日发送次数 | 至次日 0 点 |
| `captcha:attempts:{scene}:{type}:{target}` | 校验失败次数 | 同验证码 TTL |
| `captcha:{captchaKey}` | 滑动验证码校验数据（tianai 管理） | 120s（`captcha.expire.default`） |

### 5.2 发送验证码流程

```
sendCaptcha(scene, type, target)
  │
  ├─1. 冷却检查：cooldown key 存在 → 抛出 CAPTCHA_TOO_FREQUENT(637)
  │
  ├─2. 每日限额：daily key 值 >= 10 → 抛出 CAPTCHA_DAILY_LIMIT(638)
  │
  ├─3. 生成 6 位随机数字验证码
  │
  ├─4. 存入 Redis（覆盖旧验证码和失败计数）
  │
  ├─5. 设置冷却 key（TTL = cooldown.seconds）
  │
  ├─6. 每日计数 INCR（首次设置至次日 0 点 TTL）
  │
  └─7. 分发：type=PHONE → SmsService；type=EMAIL → MailService
```

### 5.3 校验验证码流程

```
verifyCaptcha(scene, type, target, code)
  │
  ├─1. 获取失败次数，>= 5 次 → 删除验证码 key → 抛出 CAPTCHA_EXPIRED(639)
  │
  ├─2. Redis GET 验证码；不存在 → 抛出 CAPTCHA_EXPIRED(639)
  │
  ├─3. 比对（不区分大小写）
  │    └─ 不匹配 → failures INCR → 抛出 CAPTCHA_ERROR(640)
  │
  └─4. 匹配 → 删除验证码 key 和失败计数（一次性）
```

## 六、忘记密码流程

### 6.1 发送忘记密码验证码

```
sendForgotPasswordCaptcha(dto)
  │
  ├─1. 查询用户是否存在（按手机号/邮箱）
  │    └─ 不存在 → 静默成功（防止用户枚举攻击）
  │
  └─2. 用户存在 → captchaService.sendCaptcha(FORGOT, type, target)
```

### 6.2 重置密码

```
resetPassword(dto)
  │
  ├─1. captchaService.verifyCaptcha(FORGOT, type, target, captcha)
  │
  ├─2. 查询用户（按手机号/邮箱）
  │    └─ 不存在 → 抛出 USER_NOT_FOUND(600)
  │
  ├─3. 更新密码
  │    └─ BCrypt encode(newPassword) → user.password
  │
  ├─4. 重置锁定状态
  │    └─ loginFailCount=0, lockTime=null
  │
  └─5. updateById(user)
```

## 八、密码修改流程

```
changePassword(userId, dto)
  │
  ├─1. userMapper.selectById(userId) → null → 抛出 USER_NOT_FOUND(600)
  ├─2. passwordEncoder.matches(oldPassword, user.password)
  │    └─ 不匹配 → 抛出 OLD_PASSWORD_ERROR(606)
  ├─3. passwordEncoder.matches(newPassword, user.password)

  ├─4. user.password = encode(newPassword)
  └─5. updateById(user)
```

## 九、Sa-Token 认证架构

### 9.1 Sa-Token 配置

```java
@Configuration
@ConditionalOnProperty(name = "satoken.interceptor.enable",
                         havingValue = "true", matchIfMissing = true)
public class SaTokenConfig implements WebMvcConfigurer {

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        var registration = registry.addInterceptor(
            new SaInterceptor(handle -> StpUtil.checkLogin())
        );
        registration.addPathPatterns("/**");

        // 注意：excludePathPatterns 相对于 context-path，不需要加 /api 前缀
        registration.excludePathPatterns(
```

## 十一、数据范围权限体系

### 11.1 概述

数据范围权限（Data Scope Permission）是医工宝系统中用于控制用户可见业务数据范围的机制，与接口权限（Resource/Permission）共同构成完整的 RBAC 权限体系。

| 权限类型 | 作用层级 | 控制内容 | 实现位置 |
|---------|---------|---------|---------|
| **接口权限** | 功能控制 | 用户能否访问某个功能/菜单/按钮 | `sys_resource` + `sys_role_resource` |
| **数据范围权限** | 数据可见性 | 用户能看哪些具体数据（机构/部门/医院等） | `sys_user_hospital` + 业务查询条件 |

### 11.2 数据范围类型定义

数据范围由 `DataScopeConstants` 常量类定义，共 5 种类型：

| 值 | 常量 | 说明 |
|----|------|------|
| 1 | ALL | 全部数据（系统管理员） |
| 2 | ORG | 本机构数据 |
| 3 | SELF | 仅自己的数据 |
| 4 | HOSPITALS | 医院范围数据（通过 sys_user_hospital 限制） |
| 5 | DEPT | 本部门数据 |

详细说明见 `05_用户管理功能实现方案` 六章。

```java
// 获取客户端 IP（支持多级代理）
private String getClientIp() {
    String ip = request.getHeader("X-Forwarded-For");
    if (ip == null || ip.isEmpty() || "unknown".equalsIgnoreCase(ip)) {
        ip = request.getHeader("X-Real-IP");
    }
    if (ip == null || ip.isEmpty() || "unknown".equalsIgnoreCase(ip)) {
        ip = request.getRemoteAddr();
    }
    if (ip != null && ip.contains(",")) {
        ip = ip.split(",")[0].trim();
    }
    return ip;
}
```

## 十五、安全设计

### 15.1 密码安全

- BCryptPasswordEncoder 加密，强度 `$2a$10$`（默认强度 10）
- 密码校验使用 `matches()` 方法，防止时序攻击
- 不存储明文密码

### 15.2 Token 安全

- Token 存储在 HTTP Header `Authorization` 中
- Token 默认有效期 30 天（Sa-Token `timeout: 2592000`）
- 登出时调用 `StpUtil.logout()` 使 Token 失效

### 15.3 账户安全

- 连续登录失败达到阈值后自动锁定
- 锁定后基于时间自动解锁
- 登录成功自动重置失败计数

### 15.4 验证码安全

- 行为验证码（PASSWORD 登录）：由自实现 `ImageCaptchController` 封装 tianai-captcha 提供，支持 SLIDER/ROTATE/WORD_IMAGE_CLICK/CONCAT 等类型；Redis 存储 TTL 120s，校验后自动失效；响应格式为 tianai-captcha 原生 `ApiResponse`
- 短信/邮箱验证码有冷却保护（60s）和每日限额（10次）
- 校验失败达到 5 次后验证码自动作废
- 忘记密码接口对不存在的目标静默成功（防止用户枚举攻击）
