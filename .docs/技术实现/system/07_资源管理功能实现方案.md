# 07_资源管理功能实现方案

## 一、模块概述

资源管理模块是医工宝系统权限体系的基础支撑模块，统一管理系统中的菜单资源（前端路由）和按钮权限（接口权限）。该模块整合了传统意义上的"菜单管理"和"权限管理"，通过资源编码（resourceCode）统一标识，形成完整的菜单树和按钮权限体系。

### 1.1 核心能力

- 资源（菜单、按钮）的树形结构管理
- 资源的新增、编辑、删除、状态管理
- 资源与角色的关联分配（多对多）
- 用户菜单树的动态生成（根据用户角色分配）
- 用户按钮权限的动态获取（按钮级别权限控制）
- 资源分配状态树的前端展示（用于角色分配界面）

## 二、数据库设计

### 2.1 资源表（sys_resource）

```sql
CREATE TABLE sys_resource (
    id              BIGINT          NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    parent_id       BIGINT          DEFAULT 0 COMMENT '父级ID（0=根节点/一级菜单）',
    resource_name   VARCHAR(64)     NOT NULL COMMENT '资源名称',
    resource_code   VARCHAR(64)     NOT NULL COMMENT '资源编码（唯一标识，如：system:org）',
    resource_type   TINYINT         NOT NULL COMMENT '资源类型（1=一级菜单，2=二级菜单，3=按钮）',

    -- 菜单相关字段（按钮类型可为空）
    icon            VARCHAR(128)    COMMENT '菜单图标',
    path            VARCHAR(256)    COMMENT '路由路径（按钮类型可为空）',
    component       VARCHAR(256)    COMMENT '组件路径（按钮类型可为空）',
    redirect        VARCHAR(256)    COMMENT '重定向路径（可选）',

    -- 排序与状态
    sort            INT             DEFAULT 0 COMMENT '排序（同级内升序）',
    visible         TINYINT         DEFAULT 1 COMMENT '显示状态（0=隐藏，1=显示）',
    status          TINYINT         DEFAULT 1 COMMENT '状态（0=禁用，1=正常）',
    remark          VARCHAR(512)    COMMENT '备注说明',

    -- 通用字段
    create_time     TIMESTAMP       DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time     TIMESTAMP       DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    create_by       BIGINT          DEFAULT NULL COMMENT '创建人ID',
    update_by       BIGINT          DEFAULT NULL COMMENT '更新人ID',
    is_deleted      TINYINT         DEFAULT 0 COMMENT '是否删除（0=否，1=是）',

    PRIMARY KEY (id),
    UNIQUE KEY uk_resource_code (resource_code),
    KEY idx_resource_parent_id (parent_id),
    KEY idx_resource_type (resource_type),
    KEY idx_resource_status (status)
);
```

| component | 一级/二级菜单 | Vue 组件路径 |
| redirect | 一级菜单 | 路由重定向路径 |
| sort | 菜单/按钮 | 同级内升序排列 |
| visible | 菜单/按钮 | 是否显示在侧边栏 |
| status | 菜单/按钮 | 启用/禁用 |

## 四、核心业务逻辑

### 4.1 资源删除流程

```
删除资源（deleteResource）
  │
  ├─1. 校验资源存在
  │    └─ baseMapper.selectById(id)
  │         └─ 抛出 RESOURCE_NOT_FOUND(630)
  │
  ├─2. 校验是否有子资源
  │    └─ baseMapper.countByParentId(id) > 0
  │         └─ 抛出 RESOURCE_HAS_CHILDREN(632)
  │
  ├─3. 校验是否有角色关联
  │    └─ RoleResourceMapper.countByResourceId(id) > 0
  │         └─ 抛出 RESOURCE_HAS_ROLES(633)
  │
  ├─4. 逻辑删除资源
  │    └─ baseMapper.deleteById(id)
  │
  └─5. 记录日志
       └─ log.info("删除资源成功，id={}", id)
```

### 4.2 资源树构建（递归）

```java
private List<ResourceVO> buildResourceTree(List<ResourceEntity> allResources, Long parentId) {
    return allResources.stream()
        // 筛选当前父节点下的直接子节点
        .filter(r -> r.getParentId().equals(parentId))
        // 筛选可见的节点
        .filter(r -> r.getVisible().equals(StatusConstants.NORMAL))
        // 转换为VO
        .map(ResourceConvert::toVO)
        // 递归设置子节点
        .peek(vo -> vo.setChildren(buildResourceTree(allResources, vo.getId())))
        // 按排序字段排序
        .sorted(Comparator.comparing(ResourceVO::getSort))
        .collect(Collectors.toList());
}
```

### 4.3 用户菜单树生成

```
获取用户菜单树（getUserMenuTree）
  │
  ├─1. 查询用户信息
  │    └─ UserMapper.selectById(userId)
  │         └─ 无用户或无角色 → 返回空列表
  │
  ├─2. 获取角色关联的资源ID列表
  │    └─ roleResourceMapper.selectResourceIdsByRoleId(user.roleId)
  │         └─ 无关联资源 → 返回空列表
  │
  ├─3. 查询用户的菜单资源
  │    ├─ 条件：id IN (resourceIds)
  │    ├─ 条件：resourceType IN (1, 2)  — 一级和二级菜单
  │    ├─ 条件：status = 1 — 正常状态
  │    └─ 条件：visible = 1 — 显示状态
  │
  └─4. 构建菜单树
       └─ buildResourceTree(userResources, parentId=0)
```

### 4.4 用户按钮权限获取

```
获取用户按钮权限（getUserPermissions）
  │
  ├─1. 查询用户信息
  │    └─ UserMapper.selectById(userId)
  │         └─ 无用户或无角色 → 返回空列表
  │
  ├─2. 获取角色关联的资源ID列表
  │    └─ roleResourceMapper.selectResourceIdsByRoleId(user.roleId)
  │         └─ 无关联资源 → 返回空列表
  │
  ├─3. 查询用户的按钮权限
  │    ├─ 条件：id IN (resourceIds)
  │    ├─ 条件：resourceType = 3 — 按钮类型
  │    └─ 条件：status = 1 — 正常状态
  │
  └─4. 提取权限编码列表
       └─ 返回 List<String>，如 ["system:org:add", "system:org:edit"]
```

### 4.5 角色资源分配（带 checked 状态）

```
获取带分配状态的资源树（getResourceTreeWithChecked）
  │
  ├─1. 查询所有正常状态资源
  │    └─ LambdaQueryWrapper: status=1
  │
  ├─2. 获取角色已分配的资源ID（如 roleId 不为 null）
  │    └─ roleResourceMapper.selectResourceIdsByRoleId(roleId)
  │
  ├─3. 构建带 checked 状态的资源树
  │    └─ buildResourceTreeWithChecked(allResources, parentId=0, assignedIds)
  │         └─ 每项设置 vo.setChecked(assignedIds.contains(entity.getId()))
  │
  └─4. 递归构建
       └─ 前端根据 checked 字段渲染复选框的选中状态
```

## 五、资源编码规范

### 5.1 编码格式

资源编码采用树形层级命名规范：

| 类型 | 编码格式 | 示例 |
|-----|---------|------|
| 一级菜单 | `{模块}` | `system`、`permission`、`basedata` |
| 二级菜单 | `{模块}:{子模块}` | `system:org`、`system:user`、`permission:resource` |
| 按钮 | `{子模块}:{操作}` | `system:org:add`、`system:org:edit`、`system:org:delete` |

## 七、前端权限控制机制

### 7.1 登录响应中的权限数据

用户登录成功后，系统返回以下权限数据：

```json
{
  "token": "xxx",
  "user": { ... },
  "menus": [ /* 菜单树 */ ],
  "permissions": [
    "system:org:add",
    "system:org:edit",
    "system:org:delete",
    "system:user:add"
  ]
}
```

### 7.2 前端权限控制方式

**方式一：路由守卫**

在路由配置中根据 `permissions` 数组判断是否允许访问：

```javascript
// 根据权限编码判断
const hasPermission = (code) => permissions.includes(code);
```

**方式二：指令封装**

封装 Vue 自定义指令 `v-permission`：

```vue
<el-button v-permission="'system:org:add'">新增机构</el-button>
```

**方式三：条件渲染**

```vue
<template v-if="$hasPermission('system:org:edit')">
  <el-button>编辑</el-button>
</template>
```
