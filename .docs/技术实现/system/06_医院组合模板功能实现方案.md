# 06_医院组合模板功能实现方案

## 一、功能概述

### 1.1 模块定位

医院组合模板（HospitalGroupTemplate）是医工宝系统的系统管理模块功能，用于将多个医院打包成一个可复用的"模板"。管理员在给用户分配医院范围时，可以通过选择模板快速批量设置，无需逐个勾选医院，从而大幅提升工作效率。

模板的核心价值在于：**简化医院范围分配操作，支持批量预设和快速复用**。

> **模块迁移说明**：本模块原位于 `yigongbao-module-basic`，已迁移至 `yigongbao-module-system`。医院概念已合并至 `sys_org` 表（`orgType=1.3`），不再使用独立的 `hospital` 表。

### 1.2 核心设计决策

| # | 决策内容 | 说明 |
|---|---------|------|
| 1 | 模板与医院的关系 | N:1（一个模板包含多个医院，一个医院可属于多个模板） |
| 2 | 模板明细表设计 | 单独一张 `hospital_group_template_detail` 表，极简设计，不继承 BaseEntity |
| 3 | 医院关联 | 明细表通过 `hospital_id` 关联 `sys_org.id`（`orgType=1.3`），无外键约束 |
| 4 | 模板编码 | 系统自动生成，格式为 `TPL-HOS-XXX`（如 TPL-HOS-001），通过 CodeGeneratorService 生成 |
| 5 | 删除逻辑 | 物理删除模板，级联物理删除明细表数据 |
| 6 | 归属模块 | 位于 `yigongbao-module-system/hospitalGroupTemplate/` |
| 7 | 医院数据来源 | 使用 OrgService 查询 `sys_org`（orgType=1.3），不依赖独立 HospitalService |

### 1.3 功能清单

| 功能 | 说明 |
|------|------|
| 分页查询模板列表 | 支持按名称、状态筛选，列表展示包含医院数量 |
| 查询模板详情 | 根据 ID 查询单条模板信息，包含医院明细列表（带医院详细信息） |
| 创建模板 | 自动生成编码，批量保存医院明细 |
| 更新模板 | 支持修改基本信息和医院列表（医院列表为覆盖式更新） |
| 删除模板 | 物理删除模板，级联删除明细表数据 |
| 修改模板状态 | 启用/停用切换（状态值 0/1） |
| 获取模板下拉选项 | 无分页，供前端 select 组件使用（含医院数量显示） |

## 二、数据库设计

### 2.1 表结构

#### 2.1.1 hospital_group_template 医院组合模板主表

```sql
CREATE TABLE hospital_group_template (
    id                  BIGINT          NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    template_name       VARCHAR(64)     NOT NULL COMMENT '模板名称',
    template_code       VARCHAR(32)     NOT NULL COMMENT '模板编码（系统唯一，自动生成）',
    template_desc       VARCHAR(256)    COMMENT '模板描述',
    status              TINYINT         DEFAULT 1 COMMENT '状态（0=禁用，1=正常）',
    remark              VARCHAR(512)    COMMENT '备注说明',
    create_time         DATETIME        DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time         DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    create_by           BIGINT          DEFAULT NULL COMMENT '创建人ID',
    update_by           BIGINT          DEFAULT NULL COMMENT '更新人ID',
    is_deleted          TINYINT         DEFAULT 0 COMMENT '是否删除（0=否，1=是）',
    PRIMARY KEY (id),
    KEY idx_hgt_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='医院组合模板表';

-- 函数唯一索引（兼容逻辑删除，允许同名模板删除后重建）
CREATE UNIQUE INDEX uk_hgt_code
    ON hospital_group_template ((CASE WHEN is_deleted = 0 THEN template_code ELSE NULL END));

CREATE UNIQUE INDEX uk_hgt_name
    ON hospital_group_template ((CASE WHEN is_deleted = 0 THEN template_name ELSE NULL END));
```

#### 2.1.2 hospital_group_template_detail 医院组合模板明细表

```sql
CREATE TABLE hospital_group_template_detail (
    id                  BIGINT          NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    template_id         BIGINT          NOT NULL COMMENT '模板ID（FK → hospital_group_template.id）',
    hospital_id         BIGINT          NOT NULL COMMENT '医院ID（FK → sys_org.id，orgType=1.3）',
    create_time         DATETIME        DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    PRIMARY KEY (id),
    UNIQUE KEY uk_hgtd_template_hospital (template_id, hospital_id),
    KEY idx_hgtd_template_id (template_id),
    KEY idx_hgtd_hospital_id (hospital_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='医院组合模板明细表';
```

#### 主表字段

| 字段名 | 类型 | 必填 | 说明 |

| template_desc | VARCHAR(256) | 否 | 模板描述 |
| status | TINYINT | 是 | 状态（0=禁用，1=正常，默认 1） |
| remark | VARCHAR(512) | 否 | 备注说明 |
| create_time | DATETIME | 是 | 创建时间（自动填充） |
| update_time | DATETIME | 是 | 更新时间（自动填充） |
| create_by | BIGINT | 是 | 创建人 ID（自动填充） |
| update_by | BIGINT | 是 | 更新人 ID（自动填充） |
| is_deleted | TINYINT | 是 | 是否删除（逻辑删除，默认 0） |

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | BIGINT | 是 | 主键（自增） |
| template_id | BIGINT | 是 | 模板 ID |

| 表 | 索引名 | 字段 | 类型 | 说明 |
|----|--------|------|------|------|

## 四、核心逻辑

### 4.1 编码生成规则

模板编码格式为 `TPL-HOS-XXX`，由 `CodeGeneratorService` 自动生成，不可手动修改：

```
生成逻辑（CodeGeneratorService）：
1. 查询当前最大编码（以 "TPL-HOS-" 开头，按编码倒序取第一条）
2. 提取序号部分（如 TPL-HOS-001 中的 "001"）
3. 序号 +1，格式化为 3 位补零字符串
4. 示例：TPL-HOS-001 → TPL-HOS-002 → TPL-HOS-003 ...

调用方式：
codeGeneratorService.generate(CodeRuleConstants.TEMPLATE_NO);
```

### 4.2 模板明细查询逻辑

查询模板详情时，明细列表需要展示医院的详细信息，核心逻辑如下：

```
getDetails(templateId) 逻辑：
1. 根据 templateId 查询明细表，获取所有 hospital_id 列表
2. 调用 OrgService.listByIds(hospitalIds) 批量查询 sys_org 记录
3. 遍历明细记录，匹配 OrgVO 信息填充到 DetailVO：
   - detailVO.hospitalName  = orgVO.orgName
   - detailVO.hospitalCode  = orgVO.orgCode
   - detailVO.areaName      = orgVO.areaName（来自 OrgVO）
   - detailVO.hospitalLevelName = orgVO.hospitalLevelName（来自 OrgVO）
   - detailVO.contact       = orgVO.contact
   - detailVO.phone         = orgVO.phone
```

### 4.3 医院列表更新逻辑

更新模板时，医院列表采用**覆盖式更新**策略：

```
updateTemplate(id, dto) 逻辑：
1. 查询模板是否存在，不存在则抛出 TEMPLATE_NOT_FOUND 异常
2. 校验模板名称唯一性（排除自身）
3. BeanUtils.copyProperties 复制基本字段到 entity
4. 若 dto.hospitalIds != null：
   a. detailMapper.deleteByTemplateId(id)   -- 物理删除所有旧明细
   b. saveDetails(id, hospitalIds)           -- 批量插入新明细
5. 更新主表记录

覆盖式更新的优点：
- 前端无需计算差异，后端直接替换
- 简化前端逻辑，提升操作效率
- 适合医院数量不多（几十到几百）的场景
```

### 4.4 医院数量统计

列表展示时需要显示每个模板包含的医院数量：

```
实现方式：
- toVOWithCount(entity)：列表转换时调用 detailMapper.countByTemplateId(id)
- toSimpleVO(entity)：下拉选项转换时同样统计医院数量

注意：
- 统计的是明细表记录数（明细表已通过 UNIQUE KEY 保证不重复）
- 模板数量较多时存在 N+1 查询风险，可后续优化为 GROUP BY 批量统计
```

### 4.5 saveDetails 医院ID校验

批量保存明细前，校验所有 hospitalId 均为有效医疗机构（orgType=1.3）：

```
saveDetails(templateId, hospitalIds) 逻辑：
1. 调用 orgService.listByIds(hospitalIds) 批量查询
2. 校验：查询结果数量 == 去重后 hospitalIds 数量，且所有 orgType=1.3
3. 不满足则抛出 HOSPITAL_NOT_FOUND(632) 异常
4. 批量插入明细记录（detailMapper.insertBatch）
```

### 5.2 与用户医院分配的关系

```
医院组合模板在用户权限体系中的作用：

管理员给用户分配医院范围时：
1. 方式一：直接勾选医院
   - 调用 PUT /api/system/user/{userId}/hospitals，传入选中的 hospitalIds
2. 方式二：通过模板快速分配
   - 调用 POST /api/system/hospital-group-template/options 获取可用模板列表
   - 选择模板后，调用 GET /api/system/hospital-group-template/{id} 获取模板明细
   - 提取 hospitalIds 列表
   - 调用 PUT /api/system/user/{userId}/hospitals 完成分配
   - 管理员可在模板分配后手动增删个别医院

关键点：
- 模板本身不关联用户，模板只存储"哪些医院可以打包"
- 用户的实际医院范围由 sys_user_hospital 表决定
- 模板只是分配操作时的"快捷工具"
```

### 5.3 具体关联

| 关联模块 | 关联方式 | 作用 |
|---------|---------|------|
| Org（system/org） | 注入 OrgService | 查询 sys_org（orgType=1.3）医院数据，填充明细列表的医院详细信息 |
| User（system/user） | 同模块内调用 | 用户分配医院范围时，通过模板快速选择 |
| CodeGenerator | 注入 CodeGeneratorService | 创建模板时自动生成 TPL-HOS-XXX 编码 |

## 六、错误码

| 错误码 | 枚举名 | 说明 | 触发场景 |
|--------|--------|------|---------|
| 656 | TEMPLATE_NOT_FOUND | 医院组合模板不存在 | 根据 ID 查询时模板不存在 |
| 657 | TEMPLATE_DISABLED | 医院组合模板已停用 | 业务规则校验时模板状态为禁用 |
| 658 | TEMPLATE_EXISTS | 医院组合模板名称已存在 | 创建/更新时模板名称重复 |
| 659 | TEMPLATE_HAS_USERS | 该模板已被用户使用，无法删除 | 删除时模板已被用户关联 |
| 400 | — | 参数错误 | 状态值不合法、hospitalIds 为空 |
