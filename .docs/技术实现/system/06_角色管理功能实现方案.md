# 06_角色管理功能实现方案

## 一、模块概述

角色管理模块是医工宝系统权限体系的核心模块，负责定义系统中的角色及其权限范围。该模块通过与用户管理、资源管理的关联，构建起完整的 RBAC（基于角色的访问控制）体系。

### 1.1 核心能力

- 角色的创建、编辑、删除、状态管理
- 角色与资源（菜单、按钮权限）的关联分配
- 角色账户分类的定义（内部用户/外部用户）
- 角色医院范围权限的开关控制
- 角色编码的唯一性管理

## 二、数据库设计

### 2.1 角色表（sys_role）

```sql
CREATE TABLE sys_role (
    id                      BIGINT          NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    role_name               VARCHAR(64)     NOT NULL COMMENT '角色名称',
    role_code               VARCHAR(32)     NOT NULL COMMENT '角色编码（系统唯一）',
    role_desc               VARCHAR(256)    COMMENT '角色描述',
    account_type            TINYINT         NOT NULL COMMENT '账户分类（1=内部用户，2=外部用户）',
    hospital_scope_enabled  TINYINT         DEFAULT 0 COMMENT '是否启用医院范围权限（0=否，1=是）',
    status                  TINYINT         DEFAULT 1 COMMENT '状态（0=禁用，1=正常）',
    remark                  VARCHAR(512)    COMMENT '备注说明',

    -- 通用字段
    create_time             DATETIME        DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time             DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    create_by               BIGINT          DEFAULT NULL COMMENT '创建人ID',
    update_by               BIGINT          DEFAULT NULL COMMENT '更新人ID',
    is_deleted              TINYINT         DEFAULT 0 COMMENT '是否删除（0=否，1=是）',

    PRIMARY KEY (id),
    UNIQUE KEY uk_role_code (role_code),
    KEY idx_role_account_type (account_type),
    KEY idx_role_status (status)
);
```

### 2.2 角色资源关联表（sys_role_resource）

```sql
CREATE TABLE sys_role_resource (
    id              BIGINT          NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    role_id         BIGINT          NOT NULL COMMENT '角色ID',
    resource_id     BIGINT          NOT NULL COMMENT '资源ID',

    PRIMARY KEY (id),
    UNIQUE KEY uk_role_resource (role_id, resource_id),
    KEY idx_role_id (role_id),
    KEY idx_resource_id (resource_id)
);
```

### 2.3 字段设计说明

| 字段 | 类型 | 说明 |
|-----|------|------|
| role_name | VARCHAR(64) | 角色名称，用于前端展示 |
| role_code | VARCHAR(32) | 角色编码，系统唯一，用于代码中标识角色 |
| role_desc | VARCHAR(256) | 角色描述，说明角色职责 |
| account_type | TINYINT | 账户分类，1=内部用户，2=外部用户 |
| hospital_scope_enabled | TINYINT | 是否启用医院范围权限，0=否，1=是 |

## 三、API 接口设计

## 四、核心业务逻辑

### 4.1 角色创建流程

```
创建角色（createRole）
  │
  ├─1. 校验角色编码唯一性
  │    └─ isRoleCodeExists(roleCode)
  │         └─ 抛出 ROLE_EXISTS(622)
  │
  ├─2. DTO 转换为实体
  │    └─ RoleConvert.toEntity(dto)
  │
  ├─3. 设置默认状态
  │    └─ status = StatusConstants.NORMAL (1)
  │
  ├─4. 保存角色
  │    └─ save(entity)
  │
  └─5. 记录日志
       └─ log.info("创建角色成功，id={}, roleCode={}", entity.getId(), roleCode)
```

### 4.2 角色删除流程

```
删除角色（removeRole）
  │
  ├─1. 校验角色存在
  │    └─ getById(id)
  │         └─ 抛出 DATA_NOT_FOUND(404)
  │
  ├─2. 校验该角色下是否有用户
  │    └─ hasUsers(roleId)
  │         └─ 查询 sys_user 表中 role_id = roleId 的记录数
  │         └─ > 0 则抛出 ROLE_HAS_USERS(623)
  │
  ├─3. 删除角色资源关联
  │    └─ RoleResourceMapper.deleteByRoleId(roleId)
  │
  ├─4. 逻辑删除角色
  │    └─ removeById(id)
  │
  └─5. 记录日志
       └─ log.info("删除角色成功，id={}", id)
```

### 4.3 资源分配流程

```
分配角色资源（ResourceServiceImpl.assignResources）
  │
  ├─1. 删除原有关联
  │    └─ RoleResourceMapper.deleteByRoleId(roleId)
  │
  ├─2. 校验传入资源ID有效性（如有）
  │    ├─ 查询所有 status=1 的资源
  │    ├─ 过滤出存在的资源ID
  │    └─ 无效则记录日志，返回成功
  │
  ├─3. 批量插入新关联
  │    └─ RoleResourceMapper.insertBatch(relations)
  │
  └─4. 记录日志
       └─ log.info("分配角色资源成功，roleId={}, 传入={}个, 有效={}个",
                    roleId, resourceIds.size(), validIds.size())
```

### 4.4 角色查询（带资源分配状态）

```
获取带分配状态的资源树（getResourceTreeWithChecked）
  │
  ├─1. 查询所有正常状态资源
  │    └─ LambdaQueryWrapper: status=1
  │
  ├─2. 获取角色已分配的资源ID
  │    └─ roleId != null → roleResourceMapper.selectResourceIdsByRoleId(roleId)
  │    └─ roleId == null → 空列表（新建角色时）
  │
  └─3. 构建带 checked 状态的资源树
       └─ buildResourceTreeWithChecked(allResources, parentId=0, assignedIds)
            ├─ 递归构建树形结构
            ├─ 每项设置 vo.setChecked(assignedIds.contains(entity.getId()))
            └─ 返回给前端用于角色分配界面的复选框状态展示
```

## 五、关联模块说明

| 关联模块 | 关系 | 作用 |
|---------|------|------|
| UserMapper（用户管理） | 角色 → 用户（1:N） | 删除角色前必须确保没有用户关联该角色 |
| ResourceService（资源管理） | 角色 ↔ 资源（N:N） | 通过 sys_role_resource 表实现多对多关联 |
| ResourceMapper | | 获取角色已分配的资源ID列表 |

## 六、错误码定义

| 错误码 | 枚举值 | 说明 |
|-------|--------|------|
| 404 | DATA_NOT_FOUND | 数据不存在（角色不存在） |
| 622 | ROLE_EXISTS | 角色编码已存在 |
| 623 | ROLE_HAS_USERS | 该角色下存在用户，无法删除 |
| 633 | RESOURCE_HAS_ROLES | 该资源已分配给角色 |

## 七、预置角色说明

系统预置了以下角色：

| 角色编码 | 角色名称 | 账户分类 | 医院范围权限 | 说明 |
|---------|---------|---------|-------------|------|
| ROLE_ADMIN | 公司管理员 | 内部用户 | 禁用 | 系统管理员，拥有全部系统功能 |
| ROLE_DESIGNER | 设计师 | 内部用户 | 禁用 | 负责设计工作 |
| ROLE_PRODUCTION | 生产员 | 内部用户 | 禁用 | 负责生产加工 |
| ROLE_SALES | 业务员 | 内部用户 | 启用 | 负责订单开拓、客户维护 |
| ROLE_DOCTOR | 医生 | 内部用户 | 禁用 | 医生、查看数据 |
| ROLE_ORG_ADMIN | 机构管理员 | 外部用户 | 禁用 | 外部机构的管理员 |
| ROLE_ORG_USER | 机构用户 | 外部用户 | 禁用 | 外部机构普通用户 |
