# 系统配置功能实现方案

## 一、背景与概述

### 1.1 业务背景

系统配置（Config）模块是医工宝系统的基础能力模块之一，用于集中管理系统运行时可动态调整的配置参数。与传统的 Spring Boot 配置文件（如 application.yml）不同，该模块将配置数据存储在数据库中，支持运行时修改、批量管理、分组展示，无需重启服务即可生效。

系统配置模块的核心价值在于：

- **动态调整**：应用程序运行时可修改配置参数，无需重新部署
- **统一管理**：所有系统配置集中存储，便于维护和审计
- **分级保护**：区分系统内置配置（不可修改/删除）和用户自定义配置
- **公开访问**：支持配置项标记为"公开"，无需登录即可获取（如系统名称、Logo 等）

### 1.2 核心功能特性

| 特性 | 说明 |
|-----|------|
| CRUD 完整操作 | 支持配置的创建、查询、更新、删除 |
| 分页与多条件筛选 | 支持按配置键、名称、分组、类型、状态进行分页查询 |
| 配置键唯一性校验 | 确保 configKey 全局唯一 |
| 系统内置配置保护 | 标记为系统内置的配置不可修改、不可删除 |
| 配置值兜底机制 | 数据库配置不存在或禁用时，自动使用配置文件默认值 |
| 公开配置接口 | 提供无需登录的配置查询接口 |
| 配置分组管理 | 预设分组：系统配置、安全配置、文件配置、其他配置 |

## 二、数据库设计

### 2.1 表结构

**表名**：`sys_config`

**设计说明**：系统配置表采用扁平化设计，所有配置项平铺存储，通过 `config_group` 字段进行逻辑分组。

```sql
CREATE TABLE sys_config (
    id              BIGINT          NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    config_key      VARCHAR(64)     NOT NULL COMMENT '配置键（唯一标识）',
    config_name     VARCHAR(128)    NOT NULL COMMENT '配置名称（展示用）',
    config_value    TEXT            COMMENT '配置值',
    config_type     VARCHAR(32)     DEFAULT 'string' COMMENT '配置类型（string/number/boolean/json）',
    config_group    VARCHAR(32)     DEFAULT 'system' COMMENT '配置分组（system/security/file/other）',
    config_desc     VARCHAR(256)    COMMENT '配置说明/描述',
    is_system       TINYINT         DEFAULT 0 COMMENT '是否系统内置（0=否，1=是）',
    is_public       TINYINT         DEFAULT 1 COMMENT '是否公开（0=私密，1=公开）',
    sort            INT             DEFAULT 0 COMMENT '排序（升序）',
    status          TINYINT         DEFAULT 1 COMMENT '状态（0=禁用，1=正常）',

    -- 通用字段（BaseEntity）
    create_time     DATETIME        DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time     DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    create_by       BIGINT          DEFAULT NULL COMMENT '创建人ID',
    update_by       BIGINT          DEFAULT NULL COMMENT '更新人ID',
    is_deleted      TINYINT         DEFAULT 0 COMMENT '是否删除（0=否，1=是）',

    PRIMARY KEY (id),
    UNIQUE KEY uk_config_key (config_key),          -- 配置键唯一索引
    KEY idx_config_group (config_group),             -- 配置分组索引
    KEY idx_config_type (config_type),               -- 配置类型索引
    KEY idx_config_status (status)                   -- 状态索引
);
```

### 2.2 字段说明

| 字段 | 类型 | 默认值 | 说明 |
|-----|------|--------|------|
| `id` | BIGINT | AUTO_INCREMENT | 主键ID |
| `config_key` | VARCHAR(64) | NOT NULL | 配置键，唯一标识，如 `default.password` |
| `config_name` | VARCHAR(128) | NOT NULL | 配置名称，展示用，如"默认密码" |
| `config_value` | TEXT | - | 配置值，支持存储长文本 |
| `config_type` | VARCHAR(32) | string | 配置类型：`string`/`number`/`boolean`/`json` |
| `config_group` | VARCHAR(32) | system | 配置分组：`system`/`security`/`file`/`other` |
| `config_desc` | VARCHAR(256) | - | 配置说明/描述 |
| `is_system` | TINYINT | 0 | 是否系统内置：`0`=否，`1`=是 |
| `is_public` | TINYINT | 1 | 是否公开：`0`=私密，`1`=公开 |
| `sort` | INT | 0 | 排序字段，升序排列 |
| `status` | TINYINT | 1 | 状态：`0`=禁用，`1`=正常 |

### 2.3 索引设计

| 索引名 | 类型 | 字段 | 说明 |
|-------|------|------|------|
| `uk_config_key` | UNIQUE | config_key | 配置键唯一约束 |
| `idx_config_group` | INDEX | config_group | 按分组查询优化 |
| `idx_config_type` | INDEX | config_type | 按类型查询优化 |
| `idx_config_status` | INDEX | status | 按状态查询优化 |

### 2.4 种子数据

系统预置以下内置配置（由 `is_system=1` 标记）：

| ID | config_key | config_name | config_value | config_group | 说明 |
|----|-----------|-------------|--------------|--------------|------|
| 1 | `default.password` | 默认密码 | `123456` | security | 新用户初始密码 |
| 2 | `login.max.failures` | 最大连续登录失败次数 | `5` | security | 连续失败后锁定账号 |
| 3 | `login.lock.duration` | 登录锁定时长 | `15` | security | 自动解锁时间（分钟） |
| 4 | `sms.send.interval` | 短信发送间隔 | `60` | security | 同一手机号发送间隔（秒） |

## 五、核心业务逻辑

### 5.1 配置键唯一性校验

创建配置时，系统会检查 `configKey` 是否已存在。如果已存在，抛出 `CONFIG_KEY_EXISTS`（627）异常。

```java
// ConfigServiceImpl.java - createConfig 方法核心逻辑
if (isConfigKeyExists(dto.getConfigKey(), null)) {
    throw new BusinessException(ErrorCodeEnum.CONFIG_KEY_EXISTS);
}
```

更新配置时，同样检查 `configKey` 是否被其他配置使用（排除自身）：

```java
// ConfigServiceImpl.java - isConfigKeyExists 方法
private boolean isConfigKeyExists(String configKey, Long excludeId) {
    LambdaQueryWrapper<ConfigEntity> wrapper = new LambdaQueryWrapper<>();
    wrapper.eq(ConfigEntity::getConfigKey, configKey);
    if (excludeId != null) {
        wrapper.ne(ConfigEntity::getId, excludeId);
    }
    return this.count(wrapper) > 0;
}
```

### 5.2 系统内置配置保护

系统内置配置（`isSystem=1`）由种子数据导入，是系统运行所必需的配置项，具有以下保护措施：

| 操作 | 系统内置配置行为 |
|-----|----------------|
| 修改 | 禁止，返回 `CONFIG_SYSTEM_NOT_ALLOW_UPDATE`（628） |
| 删除 | 禁止，返回 `CONFIG_SYSTEM_NOT_ALLOW_DELETE`（629） |
| 查询 | 正常，允许 |

```java
// ConfigServiceImpl.java - updateConfig 方法核心逻辑
if (entity.getIsSystem() != null && entity.getIsSystem() == 1) {
    throw new BusinessException(ErrorCodeEnum.CONFIG_SYSTEM_NOT_ALLOW_UPDATE);
}
```

### 5.3 配置值兜底机制

`getConfigValue(configKey)` 方法提供配置值获取功能，优先从数据库获取，如果不存在或已禁用则使用配置文件中的默认值兜底。

**调用链路**：

```
调用方（AuthServiceImpl / UserServiceImpl）
    → ConfigService.getConfigValue(configKey)
    → 查询数据库（status=1）
    → 有值 → 返回数据库值
    → 无值 → 查询 DefaultConfigProperties 兜底值
    → 有兜底值 → 返回兜底值
    → 无兜底值 → 返回 null（记录 ERROR 日志）
```

**兜底配置映射**（`DefaultConfigProperties`）：

| configKey | 类型 | 默认值 | 说明 |
|-----------|------|--------|------|
| `default.password` | String | 123456 | 新用户初始密码 |
| `login.max.failures` | Integer | 5 | 最大连续登录失败次数 |
| `login.lock.duration` | Integer | 15 | 登录锁定时长（分钟） |
| `sms.send.interval` | Integer | 60 | 短信发送间隔（秒） |
| `max.upload.size` | Long | 10485760 | 文件上传最大大小（10MB） |

**使用示例**（AuthServiceImpl 获取登录失败最大次数）：

```java
private int getMaxLoginFailures() {
    String configValue = configService.getConfigValue(SystemConfigKeyEnum.LOGIN_MAX_FAILURES.getKey());
    if (StrUtil.isNotBlank(configValue)) {
        try {
            return Integer.parseInt(configValue);
        } catch (NumberFormatException e) {
            log.warn("配置值格式错误，configKey={}, value={}", SystemConfigKeyEnum.LOGIN_MAX_FAILURES.getKey(), configValue);
        }
    }
    return defaultConfigProperties.getLoginMaxFailures();
}
```

### 5.4 配置键枚举

`SystemConfigKeyEnum` 枚举类集中管理所有系统配置键名，避免魔法值和键名不一致问题：

```java
public enum SystemConfigKeyEnum {
    // 安全配置
    DEFAULT_PASSWORD("default.password", "默认密码"),
    LOGIN_MAX_FAILURES("login.max.failures", "最大连续登录失败次数"),
    LOGIN_LOCK_DURATION("login.lock.duration", "登录锁定时长"),
    SMS_SEND_INTERVAL("sms.send.interval", "短信发送间隔"),

    // 系统配置
    SYSTEM_NAME("system.name", "系统名称"),
    MAX_UPLOAD_SIZE("max.upload.size", "文件上传最大大小");
    
    private final String key;
    private final String name;
}
```

调用方通过枚举获取配置键：

```java
String configKey = SystemConfigKeyEnum.DEFAULT_PASSWORD.getKey();
String value = configService.getConfigValue(configKey);
```

## 六、配置分组管理

### 6.1 预设分组

系统预设四个配置分组，通过 `listConfigGroups()` 方法返回：

| 分组编码 | 分组名称 | 说明 |
|---------|---------|------|
| `system` | 系统配置 | 系统级别的通用配置（订单、流程、设计业务参数等） |
| `security` | 安全配置 | 与安全相关的配置（密码策略、登录策略、短信间隔） |
| `file` | 文件配置 | 文件上传大小限制及各业务类型的允许扩展名配置 |
| `other` | 其他配置 | 不属于上述分组的其他配置 |

### 6.2 分组下拉接口

通过 `SelectController` 的 `/api/system/select/tree` 接口，可获取配置分组下拉选项：

**请求示例**：

```
GET /api/system/select/tree?type=config_group
```

**响应示例**：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": [
    { "value": "system", "name": "系统配置" },
    { "value": "security", "name": "安全配置" },
    { "value": "file", "name": "文件配置" },
    { "value": "other", "name": "其他配置" }
  ]
}
```

## 十、公开配置使用场景

### 10.1 公开配置定义

标记为 `isPublic=1` 且 `status=1` 的配置为公开配置，可通过 `/api/system/config/public` 接口无需登录获取。

### 10.2 典型使用场景

| 配置键 | 配置名称 | 公开 | 使用场景 |
|-------|---------|-----|---------|
| `system.name` | 系统名称 | 是 | 登录页标题、页脚、邮件签名 |
| `system.logo` | 系统Logo | 是 | 登录页、企业微信机器人 |
| `system.version` | 系统版本 | 是 | 页脚显示、关于页面 |

### 10.3 非公开配置

标记为 `isPublic=0` 的配置为私密配置，包含敏感信息（如密码规则、安全策略阈值），仅登录后可查询。

### 10.4 Sa-Token 认证放行配置

公开配置接口 `/api/system/config/public` 无需登录即可访问，因此需要在 Sa-Token 拦截器中进行放行配置。

**配置文件位置**：`SaTokenConfig.java`

```java
// SaTokenConfig.java - 放行路径配置
registration.excludePathPatterns(
        // ... 其他放行路径 ...
        "/api/system/config/public"    // 公开配置接口放行
);
```

**说明**：
- Sa-Token 默认拦截所有请求（`/**`），需要进行登录认证
- 通过 `excludePathPatterns` 方法排除不需要认证的接口
- 公开配置接口用于前端无需登录页面获取系统信息（如登录页的系统名称、Logo 等）

### 10.5 兜底配置示例

在 `application-dev.yml` 中配置系统配置的默认值兜底值：

```yaml
# 医工宝自定义配置
yigongbao:
  # 系统配置兜底默认值（当数据库配置不存在或已禁用时使用）
  config:
    default-values:
      # 默认密码
      default-password: "123456"
      # 最大连续登录失败次数
      login-max-failures: 5
      # 登录锁定时长（分钟）
      login-lock-duration: 15
      # 短信发送间隔（秒）
      sms-send-interval: 60
      # 文件上传最大大小（字节），默认10MB
      max-upload-size: 10485760
```

**说明**：
- 兜底值仅在数据库配置不存在或已禁用时生效
- 推荐在 `application.yml` 中配置开发环境默认值，生产环境可通过环境变量覆盖
- 实际生产环境中，建议将敏感配置（如密码规则）通过数据库管理，避免硬编码

## 十二、常见问题与注意事项

### 12.1 配置键命名规范

- 使用 `.` 分隔层级，如 `login.max.failures`
- 全部小写，禁止大写
- 最大长度 64 字符
- 必须全局唯一

### 12.2 系统内置配置修改

系统内置配置虽然存储在数据库中，但设计为不可修改。如需调整默认值，应修改以下位置：

| 配置项 | 修改位置 |
|-------|---------|
| 代码默认值 | `DefaultConfigProperties.java` |
| 数据库初始值 | `schema.sql` 种子数据 |
| 公开配置接口 | 无需修改 |

### 12.3 配置值类型转换

`getConfigValue()` 方法返回 String 类型，调用方需根据 `configType` 进行类型转换：

```java
String value = configService.getConfigValue(configKey);
if ("number".equals(configType)) {
    int num = Integer.parseInt(value);
} else if ("boolean".equals(configType)) {
    boolean flag = Boolean.parseBoolean(value);
}
```

### 12.4 逻辑删除说明

配置模块使用逻辑删除（`isDeleted=1`），删除操作不会物理删除数据，只会标记 `is_deleted` 字段。
