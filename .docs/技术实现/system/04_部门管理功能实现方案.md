# 部门管理功能实现方案

## 一、背景与概述

### 1.1 业务背景

部门管理是医工宝系统的基础数据管理模块，用于管理系统中的部门组织结构。部门作为系统的基础数据之一，主要用于：
- **人员归属**：用户归属到具体的部门
- **职责划分**：明确各部门职责，便于组织管理
- **业务支撑**：作为业务数据的关联维度

部门与机构的关系：**部门归属于机构**（一个机构可以有多个部门），部门是机构下的细分组织单元。

### 1.2 核心功能特性

| 特性 | 说明 |
|-----|------|
| CRUD 完整操作 | 支持部门的创建、查询、更新、删除 |
| 分页与多条件筛选 | 支持按机构ID、部门名称、状态进行分页查询 |
| 部门名称唯一性校验 | 同一机构下部门名称唯一 |
| 自动编码生成 | 根据部门类型自动生成唯一部门编码（DEPT-001 格式） |
| 机构关联检查 | 创建/更新部门时校验所属机构是否存在 |
| 部门下用户检查 | 删除部门时检查是否有关联用户，防止误删 |
| 状态管理 | 支持部门启用/禁用状态切换 |
| 关联信息填充 | 自动填充机构名称、负责人姓名等关联信息 |

## 二、数据库设计

### 2.1 表结构

**表名**：`sys_dept`

**设计说明**：部门表采用扁平化设计，存储部门的基本信息。

```sql
CREATE TABLE sys_dept (
    id              BIGINT          NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    dept_name       VARCHAR(128)    NOT NULL COMMENT '部门名称',
    dept_code       VARCHAR(32)     NOT NULL COMMENT '部门编码',
    org_id          BIGINT          NOT NULL COMMENT '所属机构ID',
    leader_user_id  BIGINT          COMMENT '部门负责人用户ID',
    status          TINYINT         DEFAULT 1 COMMENT '状态（0=禁用，1=正常）',
    remark          VARCHAR(512)    COMMENT '备注说明',

    -- 通用字段（BaseEntity）
    create_time     DATETIME        DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time     DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    create_by       BIGINT          DEFAULT NULL COMMENT '创建人ID',
    update_by       BIGINT          DEFAULT NULL COMMENT '更新人ID',
    is_deleted      TINYINT         DEFAULT 0 COMMENT '是否删除（0=否，1=是）',

    PRIMARY KEY (id),
    UNIQUE KEY uk_dept_code (dept_code),           -- 部门编码唯一索引
    KEY idx_org_id (org_id),                        -- 机构ID索引（按机构查询部门）
    KEY idx_status (status)                         -- 状态索引
);
```

### 2.2 字段说明

| 字段 | 类型 | 默认值 | 说明 |
|-----|------|--------|------|
| `id` | BIGINT | AUTO_INCREMENT | 主键ID |
| `dept_name` | VARCHAR(128) | NOT NULL | 部门名称 |
| `dept_code` | VARCHAR(32) | NOT NULL | 部门编码，全局唯一，自动生成 |
| `org_id` | BIGINT | NOT NULL | 所属机构ID |
| `leader_user_id` | BIGINT | - | 部门负责人用户ID |
| `status` | TINYINT | 1 | 状态：0=禁用，1=正常 |
| `remark` | VARCHAR(512) | - | 备注说明 |

### 2.3 索引设计

| 索引名 | 类型 | 字段 | 说明 |
|-------|------|------|------|
| `uk_dept_code` | UNIQUE | dept_code | 部门编码唯一约束 |
| `idx_org_id` | INDEX | org_id | 按机构查询部门优化 |
| `idx_status` | INDEX | status | 按状态查询优化 |

### 2.4 种子数据

系统预置以下测试数据：

|----|----------|-----------|--------|----------------|--------|

**路径参数**：

|-----|------|-----|------|
| id | Long | 是 | 部门ID |

**成功响应**：`code=200`，返回 DeptVO 对象，包含关联名称字段

**失败响应**：
- `code=613`：部门不存在

#### 4.2.3 创建部门

**请求方式**：`POST /api/system/dept`

**请求体**（`CreateDeptDTO`）：

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
|-----|------|-----|---------|------|
| deptName | String | 是 | 非空，最大128字符 | 部门名称 |
| orgId | Long | 是 | 非空 | 所属机构ID |
| leaderUserId | Long | 否 | - | 部门负责人用户ID |
| remark | String | 否 | 最大512字符 | 备注说明 |

**成功响应**：`code=200`

**失败响应**：
- `code=400`：参数校验失败
- `code=616`：所属机构不存在
- `code=614`：部门名称已存在

**业务规则**：
- `deptCode` 自动生成，无需传入
- `orgId` 必须在机构表中存在
- 同一机构下部门名称唯一

#### 4.2.4 更新部门

**请求方式**：`PUT /api/system/dept/{id}`

**路径参数**：

| 参数 | 类型 | 必填 | 说明 |
|-----|------|-----|------|
| id | Long | 是 | 部门ID |

**请求体**（`UpdateDeptDTO`）：除 `deptCode`、`orgId` 不可修改外，其他字段均可更新。

**成功响应**：`code=200`

**失败响应**：
- `code=613`：部门不存在
- `code=614`：部门名称与其他部门重复

**业务规则**：
- `deptCode` 不可修改（系统自动生成）
- `orgId` 不可修改（部门归属在创建时确定）
- 更新时需要检查部门名称是否与其他部门重复（同一机构下）

#### 4.2.5 删除部门

**请求方式**：`DELETE /api/system/dept/{id}`

**路径参数**：

| 参数 | 类型 | 必填 | 说明 |
|-----|------|-----|------|
| id | Long | 是 | 部门ID |

**成功响应**：`code=200`

**失败响应**：
- `code=613`：部门不存在
- `code=615`：该部门下存在用户，无法删除

**业务规则**：
- 删除前检查该部门下是否有用户
- 使用逻辑删除（`isDeleted=1`）

#### 4.2.6 修改部门状态

**请求方式**：`PUT /api/system/dept/{id}/status`

**路径参数**：

| 参数 | 类型 | 必填 | 说明 |
|-----|------|-----|------|
| id | Long | 是 | 部门ID |

**请求参数**：

| 参数 | 类型 | 必填 | 校验规则 | 说明 |
|-----|------|-----|---------|------|
| status | Integer | 是 | 0 或 1 | 状态值（0=禁用，1=正常） |

**成功响应**：`code=200`

**失败响应**：
- `code=613`：部门不存在
- `code=400`：状态值超出范围


#### 4.2.7 全量查询部门列表（用于下拉选择）

**请求方式**：GET /api/system/dept/all（可选参数 orgId 传入机构ID则只查询该机构下的部门）

**业务规则**：- 返回所有未删除的部门，按部门名称升序排列- 如果传入 orgId，只返回该机构下的部门

## 五、核心业务逻辑

### 5.1 部门编码自动生成

部门编码格式为 `DEPT-{序号}`，序号为 3 位数字，从 001 开始自动递增。

**生成算法**：

```java
// DeptServiceImpl.java - generateDeptCode 方法
private String generateDeptCode() {
    String prefix = "DEPT-";
    // 查询当前前缀下的最大序号
    LambdaQueryWrapper<DeptEntity> wrapper = new LambdaQueryWrapper<>();
    wrapper.likeRight(DeptEntity::getDeptCode, prefix)
            .orderByDesc(DeptEntity::getDeptCode)
            .last("LIMIT 1");
    DeptEntity lastDept = getOne(wrapper);

    int maxSeq = 0;
    if (lastDept != null) {
        String code = lastDept.getDeptCode();
        String seqStr = code.replace(prefix, "");
        maxSeq = Integer.parseInt(seqStr);
    }
    // 生成新编码
    return prefix + String.format("%03d", maxSeq + 1);
}
```

**编码示例**：`DEPT-001`、`DEPT-002`、`DEPT-003`

### 5.2 部门名称唯一性校验

同一机构下，部门名称必须唯一：

```java
// DeptServiceImpl.java - isDeptNameExists 方法
private boolean isDeptNameExists(String deptName, Long orgId) {
    return count(new LambdaQueryWrapper<DeptEntity>()
            .eq(DeptEntity::getDeptName, deptName)
            .eq(DeptEntity::getOrgId, orgId)) > 0;
}

// 更新时排除自身
private boolean isDeptNameExistsExcludingId(String deptName, Long orgId, Long excludeId) {
    return count(new LambdaQueryWrapper<DeptEntity>()
            .eq(DeptEntity::getDeptName, deptName)
            .eq(DeptEntity::getOrgId, orgId)
            .ne(DeptEntity::getId, excludeId)) > 0;
}
```

### 5.3 机构关联检查

创建部门时，会验证所属机构是否存在：

```java
// DeptServiceImpl.java - createDept 方法核心逻辑
OrgEntity orgEntity = orgService.getById(dto.getOrgId());
if (orgEntity == null) {
    throw new BusinessException(ErrorCodeEnum.ORG_NOT_FOUND);
}
```

### 5.4 删除前用户关联检查

删除部门前，会检查该部门下是否有用户：

```java
// DeptServiceImpl.java - removeDept 方法核心逻辑
if (hasUsers(id)) {
    throw new BusinessException(ErrorCodeEnum.DEPT_HAS_USERS);
}

// DeptServiceImpl.java - hasUsers 方法
private boolean hasUsers(Long deptId) {
    return userMapper.countByDeptId(deptId) > 0;
}
```

`countByDeptId` 方法定义在 `UserMapper` 中：

```java
// UserMapper.java
@Select("SELECT COUNT(*) FROM sys_user WHERE dept_id = #{deptId} AND is_deleted = 0")
Long countByDeptId(Long deptId);
```

### 5.5 关联信息自动填充

查询部门列表和详情时，会自动填充关联信息：

| 关联字段 | 填充内容 | 来源 |
|---------|---------|------|
| `orgName` | 所属机构名称 | `OrgService.getById()` |
| `leaderUserName` | 部门负责人姓名 | `UserMapper.selectById()` |

## 九、常见问题与注意事项

### 9.1 部门编码是否可修改

部门编码由系统自动生成，**不支持手动修改**。在 `UpdateDeptDTO` 中未包含 `deptCode` 字段。

### 9.2 删除部门的限制条件

删除部门前必须满足以下条件：
- 部门本身必须存在
- 该部门下**不能有用户**（`sys_user.dept_id`）

如果部门下有关联用户，需要先删除或迁移用户，再删除部门。

### 9.3 部门归属是否可以修改

部门的 `orgId`（所属机构）在创建后**不可修改**。这是因为：
- 部门与机构是强关联关系
- 修改所属机构可能导致数据一致性问题和权限混乱

如果需要将部门迁移到其他机构，需要删除后重新创建。

### 9.4 逻辑删除说明

部门模块使用逻辑删除（`isDeleted=1`），删除操作不会物理删除数据，只会标记 `is_deleted` 字段。

### 9.5 部门名称唯一性范围

部门名称在同一机构下唯一，不同机构可以有相同名称的部门。例如：
- 机构 A 可以有「研发部」
- 机构 B 也可以有「研发部」
