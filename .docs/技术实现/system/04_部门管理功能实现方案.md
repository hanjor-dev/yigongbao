# 部门管理功能实现方案

## 一、背景与概述

### 1.1 业务背景

部门管理是医工宝系统的基础数据管理模块，用于管理系统中的部门信息。部门作为系统的基础数据之一，主要用于：
- **人员归属**：用户归属到具体的部门
- **职责划分**：明确各部门职责，便于组织管理
- **业务支撑**：作为业务数据的关联维度

部门与机构的关系：**多对多关联**（一个部门可关联多个机构，一个机构可包含多个部门），通过中间表 `sys_dept_org` 维护关联关系。部门分为内部部门（生产企业内部）和外部部门（经销商侧）两种类型。

### 1.2 核心功能特性

| 特性 | 说明 |
|-----|------|
| CRUD 完整操作 | 支持部门的创建、查询、更新、删除 |
| 分页与多条件筛选 | 支持按部门名称、状态进行分页查询 |
| 部门名称全局唯一性校验 | 部门名称在全系统范围内唯一 |
| 自动编码生成 | 自动生成唯一部门编码（DEPT-001 格式） |
| 部门类型管理 | 内部部门（1）/ 外部部门（2），类型决定可关联的机构类型 |
| 机构类型匹配校验 | 内部部门只能关联生产企业，外部部门只能关联经销商 |
| 多机构关联 | 部门可同时关联多个机构（M:M），更新时先删后插 |
| 部门下用户检查 | 删除部门时检查是否有关联用户，防止误删 |
| 级联删除关联 | 删除部门时同步删除 sys_dept_org 关联记录 |
| 状态管理 | 支持部门启用/禁用状态切换 |
| 关联信息填充 | 自动填充机构名称列表、负责人姓名等关联信息 |

## 二、数据库设计

### 2.1 部门主表

**表名**：`sys_dept`

```sql
CREATE TABLE sys_dept (
    id              BIGINT          NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    dept_name       VARCHAR(128)    NOT NULL COMMENT '部门名称',
    dept_code       VARCHAR(32)     NOT NULL COMMENT '部门编码',
    dept_type       TINYINT         NOT NULL COMMENT '部门类型（1=内部，2=外部）',
    leader_user_id  BIGINT          COMMENT '部门负责人用户ID',
    status          TINYINT         DEFAULT 1 COMMENT '状态（0=禁用，1=正常）',
    remark          VARCHAR(512)    COMMENT '备注说明',

    -- 通用字段（BaseEntity）
    create_time     DATETIME        DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time     DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    create_by       BIGINT          DEFAULT NULL COMMENT '创建人ID',
    update_by       BIGINT          DEFAULT NULL COMMENT '更新人ID',
    is_deleted      TINYINT         DEFAULT 0 COMMENT '是否删除（0=否，1=是）',

    PRIMARY KEY (id),
    KEY idx_sys_dept_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='部门表';

-- 部门编码全局唯一（函数索引，兼容逻辑删除）
CREATE UNIQUE INDEX uk_sys_dept_code
    ON sys_dept ((CASE WHEN is_deleted = 0 THEN dept_code ELSE NULL END));

-- 部门名称全局唯一（函数索引，兼容逻辑删除）
CREATE UNIQUE INDEX uk_sys_dept_name
    ON sys_dept ((CASE WHEN is_deleted = 0 THEN dept_name ELSE NULL END));
```

### 2.2 部门-机构关联表

**表名**：`sys_dept_org`

```sql
CREATE TABLE sys_dept_org (
    dept_id     BIGINT  NOT NULL COMMENT '部门ID',
    org_id      BIGINT  NOT NULL COMMENT '机构ID',
    PRIMARY KEY (dept_id, org_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='部门-机构关联表';
```

### 2.3 字段说明

**sys_dept 字段**：

| 字段 | 类型 | 默认值 | 说明 |
|-----|------|--------|------|
| `id` | BIGINT | AUTO_INCREMENT | 主键ID |
| `dept_name` | VARCHAR(128) | NOT NULL | 部门名称，全局唯一 |
| `dept_code` | VARCHAR(32) | NOT NULL | 部门编码，全局唯一，自动生成 |
| `dept_type` | TINYINT | NOT NULL | 部门类型：1=内部，2=外部 |
| `leader_user_id` | BIGINT | - | 部门负责人用户ID |
| `status` | TINYINT | 1 | 状态：0=禁用，1=正常 |
| `remark` | VARCHAR(512) | - | 备注说明 |

**sys_dept_org 字段**：

| 字段 | 类型 | 说明 |
|-----|------|------|
| `dept_id` | BIGINT | 部门ID（联合主键） |
| `org_id` | BIGINT | 机构ID（联合主键） |

### 2.4 索引设计

| 表 | 索引名 | 类型 | 字段 | 说明 |
|----|-------|------|------|------|
| sys_dept | `uk_sys_dept_code` | UNIQUE（函数索引） | dept_code | 编码全局唯一，兼容逻辑删除 |
| sys_dept | `uk_sys_dept_name` | UNIQUE（函数索引） | dept_name | 名称全局唯一，兼容逻辑删除 |
| sys_dept | `idx_sys_dept_status` | INDEX | status | 按状态查询优化 |
| sys_dept_org | PRIMARY KEY | - | (dept_id, org_id) | 联合主键，防止重复关联 |

**失败响应**：
- `code=630`：部门不存在

#### 4.2.3 创建部门

**请求方式**：`POST /api/system/dept`

**请求体**（`CreateDeptDTO`）：

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
|-----|------|-----|---------|------|
| deptName | String | 是 | @NotBlank，最大128字符 | 部门名称 |
| deptType | Integer | 是 | @NotNull，1或2 | 部门类型（1=内部，2=外部） |
| orgIds | List\<Long\> | 否 | - | 关联机构ID列表 |
| leaderUserId | Long | 否 | - | 部门负责人用户ID |
| remark | String | 否 | - | 备注说明 |

**成功响应**：`code=200`

**失败响应**：
- `code=400`：参数校验失败
- `code=631`：部门名称已存在
- `code=622`：机构类型与部门类型不匹配

**业务规则**：
- `deptCode` 自动生成，无需传入
- 内部部门（deptType=1）只能关联 orgType=1.1（生产企业）的机构
- 外部部门（deptType=2）只能关联 orgType=1.2（经销商）的机构
- 部门名称全局唯一

#### 4.2.4 更新部门

**请求方式**：`PUT /api/system/dept/{id}`

**请求体**（`UpdateDeptDTO`）：

| 字段 | 类型 | 必填 | 说明 |
|-----|------|-----|------|
| deptName | String | 否 | 部门名称 |
| deptType | Integer | 否 | 部门类型（1=内部，2=外部） |
| orgIds | List\<Long\> | 否 | 关联机构ID列表（全量替换） |
| leaderUserId | Long | 否 | 部门负责人用户ID |
| remark | String | 否 | 备注说明 |

**成功响应**：`code=200`

**失败响应**：
- `code=630`：部门不存在
- `code=631`：部门名称与其他部门重复
- `code=622`：机构类型与部门类型不匹配

**业务规则**：
- `deptCode` 不可修改（系统自动生成）
- orgIds 为全量替换：更新时先删除旧关联，再插入新关联
- 机构类型匹配校验同创建逻辑

#### 4.2.5 删除部门

**请求方式**：`DELETE /api/system/dept/{id}`

**成功响应**：`code=200`

**失败响应**：
- `code=630`：部门不存在
- `code=632`：该部门下存在用户，无法删除

**业务规则**：
- 删除前检查该部门下是否有用户
- 逻辑删除部门（isDeleted=1）
- 同步物理删除 `sys_dept_org` 中的关联记录

**请求方式**：`PUT /api/system/dept/{id}/status`

**请求参数**：

|-----|------|-----|---------|------|
| status | Integer | 是 | 0 或 1 | 状态值（0=禁用，1=正常） |

**失败响应**：
- `code=630`：部门不存在
- `code=400`：状态值超出范围

#### 4.2.7 全量查询部门列表（下拉选择）

**请求方式**：`GET /api/system/dept/all`

**成功响应**：`code=200`，返回 `List<DeptVO>`，包含关联信息

**业务规则**：返回所有未删除的部门，按部门名称升序排列

## 五、核心业务逻辑

### 5.1 部门编码自动生成

部门编码格式为 `DEPT-{序号}`，序号为 3 位数字，从 001 开始自动递增。

**生成算法**：

```java
private String generateDeptCode() {
    String prefix = "DEPT-";
    LambdaQueryWrapper<DeptEntity> wrapper = new LambdaQueryWrapper<>();
    wrapper.likeRight(DeptEntity::getDeptCode, prefix)
            .orderByDesc(DeptEntity::getDeptCode)
            .last("LIMIT 1");
    DeptEntity lastDept = getOne(wrapper);

    int maxSeq = 0;
    if (lastDept != null) {
        String seqStr = lastDept.getDeptCode().replace(prefix, "");
        maxSeq = Integer.parseInt(seqStr);
    }
    return prefix + String.format("%03d", maxSeq + 1);
}
```

### 5.2 部门名称全局唯一性校验

部门名称在全系统范围内唯一（不区分机构）：

```java
// 创建时校验
private boolean isDeptNameExists(String deptName) {
    return count(new LambdaQueryWrapper<DeptEntity>()
            .eq(DeptEntity::getDeptName, deptName)) > 0;
}

// 更新时排除自身
private boolean isDeptNameExistsExcludingId(String deptName, Long excludeId) {
    return count(new LambdaQueryWrapper<DeptEntity>()
            .eq(DeptEntity::getDeptName, deptName)
            .ne(DeptEntity::getId, excludeId)) > 0;
}
```

### 5.3 机构类型匹配校验

创建或更新部门时，校验关联机构的类型是否与部门类型匹配：

```java
// 内部部门(deptType=1) → 只能关联生产企业(orgType=1.1)
// 外部部门(deptType=2) → 只能关联经销商(orgType=1.2)
private void validateOrgTypeMismatch(Integer deptType, List<Long> orgIds) {
    if (CollUtil.isEmpty(orgIds)) return;
    for (Long orgId : orgIds) {
        OrgEntity org = orgService.getById(orgId);
        if (org == null) throw new BusinessException(ErrorCodeEnum.ORG_NOT_FOUND);
        boolean mismatch = (deptType == 1 && !OrgTypeEnum.MANUFACTURER.getCode().equals(org.getOrgType()))
                        || (deptType == 2 && !OrgTypeEnum.DISTRIBUTOR.getCode().equals(org.getOrgType()));
        if (mismatch) throw new BusinessException(ErrorCodeEnum.ORG_DEPT_TYPE_MISMATCH);
    }
}
```

### 5.4 多机构关联维护（先删后插）

更新部门时，orgIds 采用全量替换策略：

```java
// 先删除旧关联
deptOrgMapper.delete(new LambdaQueryWrapper<DeptOrgEntity>()
        .eq(DeptOrgEntity::getDeptId, deptId));

// 再插入新关联
if (CollUtil.isNotEmpty(orgIds)) {
    List<DeptOrgEntity> relations = orgIds.stream()
            .map(orgId -> {
                DeptOrgEntity rel = new DeptOrgEntity();
                rel.setDeptId(deptId);
                rel.setOrgId(orgId);
                return rel;
            }).collect(Collectors.toList());
    deptOrgMapper.insertBatch(relations);
}
```

### 5.5 删除前用户关联检查及级联删除

```java
// 检查部门下是否有用户
private boolean hasUsers(Long deptId) {
    return userMapper.countByDeptId(deptId) > 0;
}

// 删除部门时级联删除关联记录
removeById(id);  // 逻辑删除 sys_dept
deptOrgMapper.delete(new LambdaQueryWrapper<DeptOrgEntity>()
        .eq(DeptOrgEntity::getDeptId, id));  // 物理删除 sys_dept_org
```

### 5.6 关联信息自动填充

查询部门列表和详情时，自动填充关联信息：

| 关联字段 | 填充内容 | 来源 |
|---------|---------|------|
| `orgIds` | 关联机构ID列表 | `sys_dept_org` 关联表 |
| `orgNames` | 关联机构名称列表 | `OrgService.getById()` |
| `leaderUserName` | 部门负责人姓名 | `UserMapper.selectById()` |
| `statusName` | 状态名称 | `StatusConstants.getStatusName()` |

## 九、常见问题与注意事项

### 9.1 部门编码是否可修改

部门编码由系统自动生成，不支持手动修改。`UpdateDeptDTO` 中未包含 `deptCode` 字段。

### 9.2 删除部门的限制条件

删除部门前必须满足：
- 部门本身必须存在
- 该部门下不能有用户（`sys_user.dept_id`）

删除成功后，`sys_dept_org` 中对应的关联记录会被物理删除。

### 9.3 部门类型与机构类型的匹配规则

| 部门类型 | 可关联机构类型 | 错误码 |
|---------|-------------|-------|
| 内部部门（deptType=1） | 生产企业（orgType=1.1） | 622 |
| 外部部门（deptType=2） | 经销商（orgType=1.2） | 622 |

关联机构不符合类型约束时，抛出 `ORG_DEPT_TYPE_MISMATCH(622)`。

### 9.4 orgIds 更新策略

更新部门时，`orgIds` 采用全量替换：无论传入空列表还是新列表，都会先删除旧的全部关联，再插入新的关联。传入 `null` 时不更新关联关系。

### 9.5 部门名称唯一性范围

部门名称在全系统范围内唯一（不区分机构），与旧版本（同一机构内唯一）不同。

### 9.6 逻辑删除说明

`sys_dept` 使用逻辑删除（`isDeleted=1`），`sys_dept_org` 关联表无逻辑删除字段，删除时物理清除。
