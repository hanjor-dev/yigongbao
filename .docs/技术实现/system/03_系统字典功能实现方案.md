# 系统字典功能实现方案

## 一、背景与概述

### 1.1 业务背景

系统字典（Dict）模块是医工宝系统的基础数据管理模块，采用**单表树形结构**设计，通过 `parent_id` 字段实现层级关系。该模块为系统中所有枚举类数据提供统一的数据管理和查询服务，替代传统的硬编码枚举类，实现业务枚举的可配置化。

字典模块的核心价值在于：

- **可配置化**：字典数据存储在数据库中，无需修改代码即可新增、修改、禁用枚举值
- **层级结构**：支持多级树形结构，满足复杂业务场景
- **统一查询**：提供多种查询接口，满足不同前端场景需求
- **级联控制**：状态修改支持级联，影响所有子节点

### 1.2 数据结构设计

字典表采用单表树形结构，通过 `parent_id` 字段实现层级关系：

```
parent_id = 0: 字典类型（根节点）
parent_id = X: 字典数据（子节点）
```

**字典编码规则**：采用层级数字编码
- 根节点（字典类型）：`1`, `2`, `3` ...
- 一级子节点：`1.1`, `1.2`, `2.1` ...
- 二级子节点：`1.1.1`, `1.1.2` ...

### 1.3 核心功能特性

| 特性 | 说明 |
|-----|------|
| 树形结构管理 | 支持多级层级结构的字典数据 |
| 自动编码生成 | 根据父节点自动生成层级编码 |
| 字典类型查询 | 获取所有字典类型（根节点列表） |
| 类型数据查询 | 根据类型编码获取该类型下的所有字典项 |
| 完整树形查询 | 获取完整的多级树形结构 |
| 指定类型树形 | 获取指定类型的树形结构（包含根节点） |
| 下拉选项查询 | 获取指定类型的叶子节点（用于下拉选择） |
| 名称唯一性校验 | 同一父节点下字典名称唯一 |
| 编码唯一性校验 | 全局字典编码唯一 |
| 级联状态修改 | 修改状态时自动级联修改所有子节点 |
| 子节点保护 | 存在子节点时不允许删除 |

## 二、数据库设计

### 2.1 表结构

**表名**：`sys_dict`

**设计说明**：字典表采用单表树形结构设计，通过 `parent_id` 和 `level` 字段实现层级关系。

```sql
CREATE TABLE sys_dict (
    id              BIGINT          NOT NULL AUTO_INCREMENT COMMENT '主键ID',
    parent_id       BIGINT          NOT NULL DEFAULT 0 COMMENT '父级ID（0=根节点/字典类型）',
    dict_code       VARCHAR(32)     NOT NULL COMMENT '字典编码（层级数字，如：1、1.1、1.1.1）',
    dict_name       VARCHAR(128)    NOT NULL COMMENT '字典名称',
    dict_value      VARCHAR(128)    COMMENT '字典值（叶子节点使用）',
    level           INT             NOT NULL DEFAULT 1 COMMENT '层级（1=字典类型，2=字典数据）',
    sort            INT             DEFAULT 0 COMMENT '排序（同级内排序）',
    status          TINYINT         DEFAULT 1 COMMENT '状态（0=禁用，1=正常）',
    remark          VARCHAR(512)    COMMENT '备注说明',

    -- 通用字段（BaseEntity）
    create_time     DATETIME        DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time     DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    create_by       BIGINT          DEFAULT NULL COMMENT '创建人ID',
    update_by       BIGINT          DEFAULT NULL COMMENT '更新人ID',
    is_deleted      TINYINT         DEFAULT 0 COMMENT '是否删除（0=否，1=是）',

    PRIMARY KEY (id),
    UNIQUE KEY uk_dict_code (dict_code),          -- 字典编码唯一索引
    KEY idx_parent_id (parent_id),                 -- 父级ID索引（树形查询优化）
    KEY idx_status (status)                       -- 状态索引
);
```

### 2.2 字段说明

| 字段 | 类型 | 默认值 | 说明 |
|-----|------|--------|------|
| `id` | BIGINT | AUTO_INCREMENT | 主键ID |
| `parent_id` | BIGINT | 0 | 父级ID，0表示根节点（字典类型） |
| `dict_code` | VARCHAR(32) | NOT NULL | 字典编码，层级数字格式，如 `1`、`1.1`、`1.1.1` |
| `dict_name` | VARCHAR(128) | NOT NULL | 字典名称 |
| `dict_value` | VARCHAR(128) | - | 字典值，叶子节点使用，用于存储业务值 |
| `level` | INT | 1 | 层级深度，1=字典类型，2+=子级 |
| `sort` | INT | 0 | 排序字段，同级内升序排列 |
| `status` | TINYINT | 1 | 状态：0=禁用，1=正常 |
| `remark` | VARCHAR(512) | - | 备注说明 |

### 2.3 索引设计

| 索引名 | 类型 | 字段 | 说明 |
|-------|------|------|------|
| `uk_dict_code` | UNIQUE | dict_code | 字典编码唯一约束 |
| `idx_parent_id` | INDEX | parent_id | 树形查询优化 |
| `idx_status` | INDEX | status | 按状态查询优化 |

## 五、核心业务逻辑

### 5.1 字典编码自动生成

字典编码采用层级数字格式，系统自动生成：

```java
// DictServiceImpl.java - generateDictCode 方法
private String generateDictCode(Long parentId) {
    if (ROOT_PARENT_ID.equals(parentId)) {
        // 根节点：查询最大根编码 + 1
        return String.valueOf(getMaxRootCode() + 1);
    } else {
        // 子节点：父编码 + "." + 最大子编码分段 + 1
        DictEntity parent = super.getById(parentId);
        String parentCode = parent.getDictCode();
        String maxChildCode = getMaxChildCode(parentId);
        if (maxChildCode == null) {
            return parentCode + ".1";
        }
        String[] parts = maxChildCode.split("\\.");
        int lastPart = Integer.parseInt(parts[parts.length - 1]);
        return parentCode + "." + (lastPart + 1);
    }
}
```

**编码示例**：

| 父节点 | 新编码 | 说明 |
|-------|--------|------|
| - (根节点) | `1` | 第一个字典类型 |
| - (根节点) | `2` | 第二个字典类型 |
| `1` | `1.1` | 字典类型 1 的第一个子节点 |
| `1` | `1.2` | 字典类型 1 的第二个子节点 |
| `1.1` | `1.1.1` | 子节点 1.1 的第一个子节点 |

### 5.2 层级自动计算

创建字典时，系统根据父节点自动计算层级：

```java
// DictServiceImpl.java - calculateLevel 方法
private int calculateLevel(Long parentId) {
    if (ROOT_PARENT_ID.equals(parentId)) {
        return 1;
    }
    DictEntity parent = super.getById(parentId);
    return parent.getLevel() + 1;
}
```

### 5.3 字典名称唯一性校验

同一父节点下，字典名称必须唯一：

```java
// DictServiceImpl.java - isDictNameExists 方法
private boolean isDictNameExists(String dictName, Long parentId, Long excludeId) {
    LambdaQueryWrapper<DictEntity> wrapper = new LambdaQueryWrapper<>();
    wrapper.eq(DictEntity::getDictName, dictName)
            .eq(DictEntity::getParentId, parentId);
    if (excludeId != null) {
        wrapper.ne(DictEntity::getId, excludeId);
    }
    return count(wrapper) > 0;
}
```

### 5.4 级联状态修改

修改字典状态时，自动将所有子节点的状态一并修改：

```java
// DictServiceImpl.java - updateStatus 方法核心逻辑
// 递归获取所有子节点ID
List<Long> allIds = getAllChildrenIds(id);
allIds.add(id);
// 逐条更新，确保自动填充生效
for (Long dictId : allIds) {
    DictEntity updateEntity = new DictEntity();
    updateEntity.setId(dictId);
    updateEntity.setStatus(status);
    super.updateById(updateEntity);
}
```

### 5.5 树形结构构建

采用递归方式构建树形结构：

```java
// DictServiceImpl.java - buildTree 方法
private List<DictVO> buildTree(List<DictEntity> allList, Long parentId) {
    return allList.stream()
            .filter(e -> Objects.equals(e.getParentId(), parentId))
            .map(e -> {
                DictVO vo = DictConvert.toVO(e);
                vo.setChildren(buildTree(allList, e.getId()));
                return vo;
            })
            .collect(Collectors.toList());
}
```

### 5.6 叶子节点收集

递归收集指定类型下所有叶子节点：

```java
// DictServiceImpl.java - collectLeafNodes 方法
private void collectLeafNodes(List<DictEntity> allList, Long parentId, List<DictVO> result) {
    for (DictEntity entity : allList) {
        if (Objects.equals(entity.getParentId(), parentId)) {
            boolean hasChild = allList.stream()
                    .anyMatch(e -> Objects.equals(e.getParentId(), entity.getId()));
            if (!hasChild) {
                result.add(DictConvert.toVO(entity));
            } else {
                collectLeafNodes(allList, entity.getId(), result);
            }
        }
    }
}
```

## 九、常见问题与注意事项

### 9.1 字典编码是否可修改

字典编码由系统自动生成，**不支持手动修改**。在 `UpdateDictDTO` 中未包含 `dictCode` 字段。

### 9.2 删除字典的限制条件

删除字典前必须满足以下条件：
- 字典本身必须存在
- 该字典下**不能有子节点**

如果存在子节点，需要先删除子节点，再删除父节点。

### 9.3 字典值的使用场景

`dict_value` 字段用于存储叶子节点的业务值，通常是：
- 与数据库表字段值对应（如 `org_type = 1`）
- 用于代码中的逻辑判断
- 用于前端表单的绑定值

### 9.4 级联状态修改的影响

修改字典状态时，系统会递归修改所有子节点的状态。这意味着：
- 禁用一个字典类型，会禁用其所有子节点
- 启用一个字典类型，不会自动启用其子节点（需要单独操作）
- 级联修改仅影响状态字段，不影响其他字段

### 9.5 逻辑删除说明

字典模块使用逻辑删除（`isDeleted=1`），删除操作不会物理删除数据，只会标记 `is_deleted` 字段。
