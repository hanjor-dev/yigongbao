# 医工宝订单状态流转详细说明

> **创建日期**: 2026-06-04  
> **版本**: v1.0  
> **说明**: 本文档详细说明每个状态转换的触发方式（自动/手动）、触发位置和逻辑

---

## 文档说明

本文档按照订单流转的时间顺序，详细说明每个状态转换点：
- **触发方式**: 自动触发 / 手动触发
- **触发位置**: Controller接口、Service方法、事件监听器等
- **触发逻辑**: 业务逻辑说明
- **代码位置**: 具体的类和方法引用

### 订单分类说明
- **needsPhysicalDelivery**: 是否需要实体交付（1=需要，0=不需要）
- **orderType**: 订单类型（1=医疗器械，2=非医疗器械）

## 一、订单阶段（ORDER Phase）

### 1.1 创建订单：无状态 → DRAFT(1010)

**触发方式**: 手动触发

**触发位置**: 
- **接口**: `POST /order/main/create`
- **Controller**: `OrderMainController.create()`
- **Service**: `OrderMainServiceImpl.create()`

**触发逻辑**:
1. 接收订单创建请求（订单基本信息、患者信息、订单明细等）
2. 生成订单编号
3. 初始化订单状态为 DRAFT(1010)
4. 初始化阶段为 ORDER(10)
5. 保存订单数据到数据库

**代码位置**: 
- `com.yigongbao.module.order.controller.OrderMainController.create()`
- `com.yigongbao.module.order.service.impl.OrderMainServiceImpl.create()`

**状态说明**: 订单创建后处于草稿状态，可以继续编辑修改

---

### 1.2 提交订单：DRAFT(1010) → PENDING_DATA_AUDIT(1020)

**触发方式**: 手动触发

**触发位置**:
- **接口**: `POST /order/main/{orderId}/submit`
- **Controller**: `OrderMainController.submitOrder()`
- **Service**: `OrderMainServiceImpl.submitOrder()`

**触发逻辑**:
1. 校验订单状态必须为 DRAFT(1010)
2. 校验订单必填字段完整性
3. 通过 FlowFacade 执行状态流转：`flowFacade.executeFlow(orderId, FlowActionEnum.SUBMIT_ORDER, operator)`
4. 状态机将订单从 DRAFT → PENDING_DATA_AUDIT
5. 回写订单表的 phase 和 status 字段

**代码位置**:
- `com.yigongbao.module.order.controller.OrderMainController.submitOrder()`
- `com.yigongbao.module.order.service.impl.OrderMainServiceImpl.submitOrder()`

**状态说明**: 订单提交后进入待审核队列，等待管理员审核

### 1.4 自动推进到设计阶段：DATA_AUDIT_PASSED(1030) → PENDING_DESIGN(2010)

**触发方式**: 自动触发（状态机内部）

**触发位置**:
- **触发点**: FlowPhaseTransitionRules.decideNextPhaseAndStatus()
- **触发时机**: DATA_AUDIT_PASS 动作执行时

**触发逻辑**:
1. 状态机在处理 DATA_AUDIT_PASS 动作时，检测到目标状态为 DATA_AUDIT_PASSED(1030)
2. FlowPhaseTransitionRules 判断需要推进阶段：
   ```java
   if (targetStatus == FlowStatusEnum.DATA_AUDIT_PASSED) {
       return new PhaseAndStatus(FlowPhaseEnum.DESIGN, FlowStatusEnum.PENDING_DESIGN);
   }
   ```
3. 自动将阶段推进到 DESIGN(20)，状态变为 PENDING_DESIGN(2010)
4. 订单进入设计队列，等待分配设计师

**代码位置**:
- `com.yigongbao.flow.rules.FlowPhaseTransitionRules.decideNextPhaseAndStatus()` (第155-157行)

**状态说明**: 这是一个自动的跨阶段转换，无需人工干预

### 2.3 设计完成后的分支流转

#### 2.3.1 需要实体交付：生产员下载数据包

**触发方式**: 手动触发（生产员操作）

**触发位置**:
- **接口**: `POST /production/record/download-package/{designPackageId}`
- **Controller**: `ProductionRecordController.downloadDataPackage()`
- **Service**: `ProductionRecordServiceImpl.downloadDataPackage()`

**触发逻辑**:
1. 查询数据包对应的订单
2. 更新当前流转卡状态：DESIGN_COMPLETED → PENDING_PRINT
3. 回写订单的生产员信息（producerId）
4. **聚合判断**：检查该订单的所有流转卡是否都已下载
   - 如果所有流转卡都达到 PENDING_PRINT，调用 `triggerFlowIfAllReach(orderId, PENDING_PRINT, DOWNLOAD_DATA_PACKAGE)`
   - 触发订单级别的状态流转（通过状态机）

**代码位置**:
- `com.yigongbao.module.production.record.controller.ProductionRecordController.downloadDataPackage()`
- `com.yigongbao.module.production.record.service.impl.ProductionRecordServiceImpl.downloadDataPackage()` (第292-326行)

**状态说明**: 
- 流转卡级别：立即推进到 PENDING_PRINT
- 订单级别：需要所有流转卡都下载后才推进

---

### 2.3.2 自动推进到打印阶段：DESIGN_COMPLETED(2030) → PENDING_PRINT(3010)

**触发方式**: 自动触发（聚合条件满足时）

**触发位置**:
- **触发点**: `ProductionRecordServiceImpl.triggerFlowIfAllReach()`
- **触发时机**: 所有流转卡都下载数据包后

**触发逻辑**:
1. 统计订单下的所有活跃流转卡数量（totalActive）
2. 统计已达到 PENDING_PRINT 状态的流转卡数量（reachedCount）
3. 当 totalActive == reachedCount 时，触发订单级别流转：
   ```java
   flowFacade.executeFlow(orderId, FlowActionEnum.DOWNLOAD_DATA_PACKAGE, operator)
   ```
4. 状态机自动推进阶段：DESIGN(20) → PRINT(30)，状态：DESIGN_COMPLETED → PENDING_PRINT

**代码位置**:
- `com.yigongbao.module.production.record.service.impl.ProductionRecordServiceImpl.triggerFlowIfAllReach()` (第349-376行)
- `com.yigongbao.flow.rules.FlowPhaseTransitionRules.decideNextPhaseAndStatus()` (第167-171行)

**状态说明**: 这是一个聚合触发的自动流转，确保多产品订单的所有流转卡都准备好后才推进

### 3.3 自动推进到后处理/质检阶段：PRINT_COMPLETED(3030) → POST_PROCESSING(4010) 或 QC_IN_PROGRESS(5010)

**触发方式**: 自动触发（状态机内部）

**触发位置**:
- **触发点**: FlowPhaseTransitionRules.decideNextPhaseAndStatus()
- **触发时机**: COMPLETE_PRINT 动作执行且聚合条件满足时

**触发逻辑**:
1. 状态机检测到目标状态为 PRINT_COMPLETED(3030)
2. 根据 orderType 判断下一阶段：
   ```java
   if (targetStatus == FlowStatusEnum.PRINT_COMPLETED) {
       boolean isMedical = !Integer.valueOf(2).equals(orderType);
       if (isMedical) {
           // 医疗器械 → 后处理
           return new PhaseAndStatus(FlowPhaseEnum.POST_PROCESSING, FlowStatusEnum.POST_PROCESSING);
       } else {
           // 非医疗器械 → 直接质检
           return new PhaseAndStatus(FlowPhaseEnum.QC, FlowStatusEnum.QC_IN_PROGRESS);
       }
   }
   ```
3. 自动推进阶段和状态

**代码位置**:
- `com.yigongbao.flow.rules.FlowPhaseTransitionRules.decideNextPhaseAndStatus()` (第174-181行)

**状态说明**: 
- 医疗器械（orderType=1）：推进到后处理阶段
- 非医疗器械（orderType=2）：跳过后处理，直接进入质检阶段

2. 通过状态机执行状态流转：`flowFacade.executeFlow(orderId, FlowActionEnum.REWORK_TO_PRINT, operator)`
3. 跨阶段回退：QC(50) → PRINT(30)，状态变为 PENDING_PRINT(3010)

**代码位置**:
- `com.yigongbao.module.production.qc.controller.ProductionQcController.reworkToPrint()`
- `com.yigongbao.module.production.qc.service.impl.ProductionQcServiceImpl.reworkToPrint()`
- `com.yigongbao.flow.rules.FlowPhaseTransitionRules.decideNextPhaseAndStatus()` (第205-207行)

**状态说明**: 这是唯一支持跨阶段回退的操作，用于严重质量问题需要重新打印的场景

## 六、仓储阶段（WAREHOUSE Phase）

### 6.1 完成入库：WAREHOUSE_IN(6010) → WAREHOUSED(6020)

**触发方式**: 手动触发

**触发位置**:
- **接口**: `POST /production/pack/{recordId}/complete-warehouse`
- **Controller**: `ProductionPackController.completeWarehouse()`
- **Service**: `ProductionPackServiceImpl.completeWarehouse()`

**触发逻辑**:
1. 校验流转卡状态必须为 WAREHOUSE_IN(6010)
2. 更新流转卡状态为 WAREHOUSED
3. 记录入库完成时间
4. **聚合判断**：调用 `triggerFlowIfAllReach(orderId, WAREHOUSED, COMPLETE_WAREHOUSE_IN)`
5. 当所有流转卡都入库完成后，触发订单级别状态流转

**代码位置**:
- `com.yigongbao.module.production.pack.controller.ProductionPackController.completeWarehouse()`
- `com.yigongbao.module.production.pack.service.impl.ProductionPackServiceImpl.completeWarehouse()`

**状态说明**: 入库完成后自动进入已完成状态

---

### 6.2 自动推进到完成状态：WAREHOUSED(6020) → COMPLETED(8010)

**触发方式**: 自动触发（聚合条件满足时）

**触发位置**:
- **触发点**: FlowPhaseTransitionRules.decideNextPhaseAndStatus()
- **触发时机**: COMPLETE_WAREHOUSE_IN 动作执行且聚合条件满足时

**触发逻辑**:
1. 状态机检测到目标状态为 WAREHOUSED(6020)
2. 自动推进到完成状态：
   ```java
   if (targetStatus == FlowStatusEnum.WAREHOUSED) {
       return new PhaseAndStatus(FlowPhaseEnum.COMPLETED, FlowStatusEnum.COMPLETED);
   }
   ```
3. 记录订单实际完成时间：`order.setActualCompleteTime(LocalDateTime.now())`
4. 同时更新所有流转卡状态为 COMPLETED

**代码位置**:
- `com.yigongbao.flow.rules.FlowPhaseTransitionRules.decideNextPhaseAndStatus()` (第195-197行)
- `com.yigongbao.module.production.record.service.impl.ProductionRecordServiceImpl.triggerFlowAndSync()` (第663-668行)

**状态说明**: 这是订单流程的最终状态，标志着订单完成

## 七、完成阶段（COMPLETED Phase）

### 7.1 已完成状态：COMPLETED(8010)

**触发方式**: 自动触发或手动触发

**到达方式**:
1. **需要实体交付的订单**：从 WAREHOUSED(6020) 自动推进
2. **不需要实体交付的订单**：从 DESIGN_COMPLETED(2030) 手动完成

**状态说明**: 
- 这是订单流程的终态，订单不再有后续状态转换
- 订单的 actualCompleteTime 字段记录完成时间
- 所有流转卡（如果有）也同步更新为 COMPLETED 状态

## 八、全局状态：已取消（CANCELLED Phase）

3. 更新订单状态为 CANCELLED

- 可以从任何非终态状态取消订单
- 取消后订单进入终态，无法恢复
- 这是一个跨所有阶段的全局操作

## 九、关键设计要点

### 9.1 自动流转 vs 手动流转

**自动流转**（状态机内部触发）：
1. DATA_AUDIT_PASSED → PENDING_DESIGN（审核通过后自动进入设计阶段）
2. DESIGN_COMPLETED → PENDING_PRINT（所有流转卡下载数据包后自动推进）
3. PRINT_COMPLETED → POST_PROCESSING/QC_IN_PROGRESS（打印完成后自动推进）
4. POST_PROCESSING → QC_IN_PROGRESS（后处理完成后自动推进）
5. QC_PASSED → WAREHOUSE_IN（质检合格后自动推进）
6. WAREHOUSED → COMPLETED（入库完成后自动推进）

**手动流转**（需要用户操作接口）：
1. 创建订单、提交订单、审核通过/驳回
2. 开始设计、完成设计
3. 下载数据包（生产员）
4. 手动完成订单（不需要实体交付的订单）
5. 开始打印、完成打印
6. 完成后处理
7. 质检合格/不合格、返工、回退到打印
8. 完成入库
9. 取消订单

---

### 9.2 聚合触发机制

**适用场景**：一个订单包含多个产品，每个产品对应一个生产流转卡

**触发逻辑**：
- 只有当订单的**所有流转卡**都达到目标状态时，才触发订单级别的状态流转
- 使用 `triggerFlowIfAllReach()` 方法实现聚合判断

**应用点**：
1. 下载数据包：所有流转卡都下载后，订单推进到 PENDING_PRINT
2. 完成打印：所有流转卡都打印完成后，订单推进到下一阶段
3. 完成后处理：所有流转卡都完成后处理后，订单推进到质检
4. 质检合格：所有流转卡都质检合格后，订单推进到入库
5. 完成入库：所有流转卡都入库后，订单推进到已完成

**关键代码**：
```java
// ProductionRecordServiceImpl.triggerFlowIfAllReach()
long totalActive = count(...); // 统计活跃流转卡数量
long reachedCount = count(...); // 统计已达到目标状态的流转卡数量
if (totalActive == reachedCount) {
    flowFacade.executeFlow(orderId, action, operator); // 触发订单级别流转
}
```

---

### 9.3 状态机设计

**核心组件**：
- **FlowFacade**: 流程模块的对外统一入口
- **FlowStateMachineService**: 状态机核心服务
- **FlowStatusTransitionRules**: 阶段内状态转换规则
- **FlowPhaseTransitionRules**: 跨阶段转换规则

**工作原理**：
1. 业务代码调用 `flowFacade.executeFlow(orderId, action, operator)`
2. 状态机校验动作是否可执行
3. 执行状态转换，可能同时推进阶段
4. 返回 TransitionResult（包含目标阶段、最终状态）
5. 业务代码回写订单表的 phase 和 status 字段

**优势**：
- 集中管理所有状态转换规则
- 保证状态转换的合法性
- 支持跨阶段自动推进
- 便于扩展和维护

---

### 9.4 订单分类处理

**needsPhysicalDelivery（是否需要实体交付）**：
- **1（需要）**: 完整生产流程（设计 → 打印 → 后处理 → 质检 → 入库 → 完成）
- **0（不需要）**: 简化流程（设计 → 手动完成）

**orderType（订单类型）**：
- **1（医疗器械）**: 打印完成后进入后处理阶段
- **2（非医疗器械）**: 打印完成后直接进入质检阶段（跳过后处理）

## 十一、注意事项

### 11.1 状态转换前置条件

每个状态转换都有严格的前置条件校验：
1. **状态校验**：当前状态必须符合要求
2. **权限校验**：操作人必须有相应权限
3. **数据完整性校验**：必需的数据必须已填写

### 11.2 并发安全

- 使用乐观锁（version字段）防止并发冲突
- 聚合触发时有幂等保护，防止重复触发

### 11.3 事件驱动

- DesignCompletedEvent：设计完成后发布，触发生产流转卡创建
- 事件监听器负责处理跨模块的业务逻辑

### 11.4 日志记录

- 每次状态转换都会记录详细日志
- 日志包含：订单ID、操作人、动作、状态变化、时间戳

### 11.5 流转卡与订单的关系

- 一个订单可以包含多个产品，每个产品对应一个生产流转卡
- 流转卡级别的状态变化不会立即影响订单状态
- 只有当所有流转卡都达到目标状态时，才触发订单级别的状态流转
