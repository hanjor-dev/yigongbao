## 一、背景与目标

### 1.1 背景

医工宝系统服务于医疗器械定制化生产场景。订单经设计审核通过后，进入生产环节。当前生产流程依赖纸质记录，存在追溯困难、信息滞后、异常处理不规范等问题。

### 1.2 目标

构建数字化生产管理模块，覆盖从设计审核通过到产品入库的完整生产链条，实现：

- 生产流转卡电子化，替代纸质记录
- 工序流转扫码化，实时记录责任人和时间
- 产品级别追溯，每个物理产品有唯一编号
- 质检与UDI码管理，满足医疗器械监管要求
- 异常处理标准化，减少操作员决策负担

### 1.3 范围

**本模块覆盖**：设计审核通过 → 打印 → 后处理（医疗器械）→ 质检 → 包装 → 入库

**本模块不覆盖**：订单创建、设计、仓储入库后的交付、不需要实体交付的订单

## 三、核心概念

### 3.1 生产流转卡

一个设计数据包对应一张生产流转卡，是整个生产过程的核心记录载体。

- **批次级别**：一张流转卡管理该批次所有产品
- **逐工序填写**：流转到某工序时，该工序操作员填写
- **全程唯一**：无论发生多少次异常，始终在同一张流转卡上处理（打印失败/检验不合格除外）
- **物理形态**：电子流转卡 + 纸质二维码标签（贴在产品托盘上）

### 3.2 产品编号

每个物理产品的内部唯一标识，生产开始时自动生成。

- 格式：P + 日期 + 流水号（如 P202605270001）
- 一个打印文件打印N份，生成N个不同编号
- 贯穿整个生产过程，用于质检时的产品识别

### 3.3 UDI码

医疗器械产品的正式标识码，质检合格后生成（仅医疗器械订单）。

- 符合医疗器械UDI法规要求（合格品才能赋码）
- 质检合格后系统自动生成，关联产品编号
- 打印UDI标签贴在产品包装上

### 3.4 工序类型

| 订单类型 | 工序数量 | 工序列表 |
|---------|---------|---------|
| 医疗器械 | 5个 | design / print / wash / cure / clean_dry |
| 非医疗器械 | 2个 | design / print |

包装不是工序，是独立环节，在质检合格后执行。

## 四、生产流程

### 4.1 流程总览

**医疗器械订单**（6个阶段）：
```
设计审核通过 → 待打印 → 打印中 → 打印完成 → 后处理中 → 质检中 → 包装中 → 入库中 → 已完成
                                      ↓           ↓
                                   打印失败     已废弃（终态）
```

**非医疗器械订单**（5个阶段）：
```
设计审核通过 → 待打印 → 打印中 → 打印完成 → 质检中 → 包装中 → 入库中 → 已完成
                                      ↓           ↓
                                   打印失败     已废弃（终态）
```

### 4.2 阶段1：生产准备

**触发**：设计审核通过，生产员在生产列表看到该数据包

**操作流程**：

1. 生产员查看生产列表（以数据包为单位，显示订单类型、期望交付时间）
2. 点击"下载设计数据包" → 系统触发状态变更：设计审核通过 → **待打印**
3. 从可用打印机列表选择设备（仅显示 state=0 且 connectionStatus=1 的设备）
4. 填写生产批号（可自动生成）→ 系统自动生成产品编号
5. 确认产品编号列表，进入流转卡填写页面
6. 填写流转卡基础信息（生产数量、原材料批号）
7. 保存流转卡 → 系统生成流转卡二维码，打印二维码标签
8. 生产员在打印机上开始打印（物理操作）
9. 系统通过WebSocket接收设备状态推送（state: 0→1）→ 自动更新状态为**打印中**
10. 超时提醒：超过5分钟未收到推送，系统提示"打印机状态未更新"

**状态变更**：设计审核通过 → 待打印 → 打印中

### 4.3 阶段2：打印工序

**触发**：打印机状态推送（state: 1→0）→ 系统自动更新状态为**打印完成**

**操作流程**：

1. 打印前填写工序信息（层厚、激光器功率等参数）
2. 打印完成后，逐个标记产品检验结果（合格/不合格）
3. 如有不合格产品，生产员选择处理方式：
   - **方式A**：调整参数重打（同一流转卡，重打完成后重新检验）
   - **方式B**：废弃本批次，创建新流转卡（原卡标记 abandoned，原产品编号作废）
4. 所有产品合格后，扫码流转：
   - 医疗器械 → 后处理中
   - 非医疗器械 → 质检中

**超时提醒**：打印开始后超过 processingMinutes + 缓冲时间未收到完成推送，系统提示

### 4.4 阶段3：后处理工序（仅医疗器械）

包含3个子工序，按顺序执行，不允许并行：酒精初洗 → UV固化 → 超声清洗+干燥

**每个子工序操作流程**：

1. 操作员扫描流转卡二维码，进入工序填写页面
2. 填写工序信息（设备、参数、时间、操作人）
3. 完成工序后填写工序结果：
   - 是否有重做：有/无
   - 重做原因（如有）：记录哪个产品、问题描述（过程记录，不驱动流转）
4. 操作员确认整批完成 → 扫码流转到下一工序

**关键说明**：后处理工序采用批次粒度，重做由操作员现场完成后填写记录，不影响流转逻辑。

**状态变更**：后处理中（保持，直到 clean_dry 完成后流转到质检中）

### 4.5 阶段4：质检环节

**触发**：
- 医疗器械：clean_dry 工序完成，扫码流转到质检
- 非医疗器械：打印完成，扫码流转到质检

**操作流程**：

1. 质检员扫描流转卡二维码，查看批次信息和产品列表
2. 逐个扫描产品编号进行质检
3. 记录质检结果：
   - **pass**：合格 → 医疗器械自动生成UDI码，打印UDI标签
   - **redo**：不合格 → 填写不合格原因（质检员不选择返工路径）
4. 填写质检汇总（合格数量、不合格数量、备注）
5. redo 产品处理流程：
   - 生产管理员查看 redo 产品列表，指定每个产品从哪个工序重做
   - 生产员执行重做
   - 重做完成后系统自动将产品状态改回 in_process
   - 质检员刷新页面，重新对该产品质检
6. 所有产品均为 pass → 扫码流转到包装中

**关键规则**：
- 质检员只标记 pass/redo，不做路径决策
- redo 期间订单状态保持 qc_in_progress
- 所有产品均为 pass 后才能流转到包装

### 4.6 阶段5：包装环节

**触发**：质检完成，所有产品均为 pass

**操作流程**：

1. 生产员扫描流转卡二维码，查看产品列表（含产品编号、UDI码）
2. 填写包装信息（封口机设备、热封温度/时间、灭菌方式、灭菌批号）
3. （可选）逐个扫描产品编号确认完整性：
   - 数量不足：提示缺少哪些产品编号
   - 扫到非本批次产品：提示混料错误，禁止继续，需生产管理员核查
4. 扫码流转到入库中

**数据存储**：包装信息存储在 production_record 表的 pack_* 字段，不创建工序记录

## 五、异常处理

### 5.1 打印失败（过程中断）

人工判断打印失败后，生产员选择：

| 处理方式 | 操作 | 流转卡变化 |
|---------|------|-----------|
| 方式A：修复后继续 | 修复设备/补充材料，继续打印 | 原卡不变 |
| 方式B：重新打印 | 废弃原卡，创建新流转卡 | 原卡标记 print_failed（终态） |

### 5.2 打印检验不合格

打印完成后检验发现问题，生产员选择：

| 处理方式 | 操作 | 流转卡变化 |
|---------|------|-----------|
| 方式A：重打 | 调整参数，对不合格产品重新打印，重新检验 | 原卡不变 |
| 方式B：废弃重建 | 废弃原卡，创建新流转卡 | 原卡标记 abandoned（终态） |

### 5.3 后处理工序有问题

操作员现场重做有问题的产品，完成后填写重做记录（过程追溯用），然后正常扫码流转。系统无强制校验。

### 5.4 质检不合格（redo）

| 步骤 | 操作人 | 操作 |
|------|--------|------|
| 1. 标记redo | 质检员 | 标记产品为redo，填写不合格原因 |
| 2. 指定重做工序 | 生产管理员 | 指定从哪个工序重做（打印/酒精初洗/UV固化/超声清洗+干燥） |
| 3. 执行重做 | 生产员 | 执行对应工序 |
| 4. 重新质检 | 质检员 | 产品状态自动变回 in_process，质检员重新检验 |

### 5.5 设备状态异常

| 异常 | 处理 |
|------|------|
| 打印机状态推送超时（>5分钟） | 系统提示，生产管理员手动更新设备状态 |
| 设备连接断开 | 系统自动标记设备离线，生产管理员检查 |
| 状态更新优先级 | WebSocket推送优先，手动更新为辅 |

| 状态代码 | 状态名称 | 触发条件 | 操作人 |

## 七、功能模块详细说明

### 7.1 生产列表

**入口**：生产管理菜单（仅生产员/生产管理员可见）

**展示维度**：以数据包为单位（非订单级别）

**列表字段**：
- 订单号
- 数据包编号
- 产品名称
- 订单类型（医疗器械/非医疗器械）
- 当前状态
- 期望交付时间
- 操作按钮

**筛选条件**：状态、订单类型、时间范围

**状态分组**：待处理（设计审核通过）/ 生产中 / 质检中 / 包装中 / 已完成

### 7.2 生产流转卡

**创建时机**：生产员填写生产批号并保存后

**自动生成内容**：
- 流转卡编号（系统生成，不可修改）
- 产品编号列表（根据打印文件和打印数量）
- 流转卡二维码（包含流转卡ID、数据包编号、生产批号）
- 工序记录（医疗器械5条，非医疗器械2条）

**手动填写内容**：
- 生产批号（可自动生成）
- 生产数量（确认）
- 原材料批号

**流转卡页面展示**：
- 基础信息区：订单号、数据包编号、生产批号、产品列表
- 工序记录区：各工序的填写状态和详情
- 流转记录区：每次流转的时间、操作人
- 包装信息区（质检完成后显示）

### 7.3 工序填写

**通用字段**（所有工序）：
- 设备编号（从设备列表选择）
- 开始/结束时间（打印工序由系统自动记录）
- 操作人员（默认当前用户，可修改）

**各工序专有参数**：

| 工序 | 关键参数 |
|------|---------|
| print（3D打印） | 层厚、激光器功率、打印速度、支撑类型、树脂类型 |
| wash（酒精初洗） | 酒精批号、浸泡程度、浸泡起止时间 |
| cure（UV固化） | 固化模式（HIGH/LOW）、固化起止时间 |
| clean_dry（超声清洗+干燥） | 酒精批号、清洗模式、加热开关、清洗起止时间、干燥方式、干燥时间 |

**后处理工序额外字段**：
- 是否有重做（有/无）
- 重做原因（如有）

### 7.4 质检功能

**质检列表**：质检员看到所有 qc_in_progress 状态的批次

**质检操作**：
- 扫描流转卡二维码进入质检页面
- 逐个扫描产品编号
- 标记 pass 或 redo
- pass 时自动生成UDI码（医疗器械）并提示打印UDI标签
- redo 时填写不合格原因

**redo 管理**（生产管理员）：
- 查看所有 redo 产品列表
- 为每个 redo 产品指定重做工序
- 跟踪重做进度

### 7.5 设备管理

**设备状态**：
- state: 0=空闲，1=占用
- connectionStatus: 0=离线，1=在线

**设备分配规则**：只能分配 state=0 且 connectionStatus=1 的设备

**状态更新机制**：
- 主要：WebSocket推送（`/api/basic/ws/device`）自动更新
- 备用：生产管理员手动更新（`PUT /basic/device/{id}/state`）

**超时提醒配置**：
- 打印开始超时：5分钟（可配置）
- 打印完成超时：processingMinutes + 缓冲时间（可配置）

### 7.6 生产统计报表（生产管理员）

**统计维度**：
- 各状态批次数量
- 日/周/月产量
- 设备利用率
- 不合格率（后处理工序重做率）
- 质检redo率

## 八、数据模型

### 8.1 核心表

| 表名 | 说明 |
|------|------|
| production_record | 生产流转卡（含包装信息） |
| production_product | 生产产品记录（产品编号、UDI码、质检结果） |
| production_process | 工序记录（按订单类型动态创建） |
| production_process_product_result | 质检产品记录（仅质检环节使用） |
| production_process_transfer | 工序流转记录 |
| production_device | 生产设备（由WebSocket自动注册） |

### 8.2 产品状态枚举

| 状态 | 含义 |
|------|------|
| in_process | 生产中（正常流转） |
| redo | 质检标记不合格，等待生产管理员指定重做工序 |
| pass | 质检合格（已生成UDI码） |
| completed | 已完成入库 |

### 8.3 关键业务规则

| 规则 | 说明 |
|------|------|
| 一包一卡 | 一个数据包只能创建一张生产流转卡 |
| 工序顺序 | 工序必须按顺序流转，不可跳过，不可并行 |
| 打印状态自动 | 打印开始/完成由WebSocket推送自动触发，不需要人工点击 |
| 后处理批次粒度 | 后处理工序整批流转，重做为过程记录，不驱动流转 |
| 质检全部pass | 所有产品均为pass才能流转到包装 |
| redo路径决策 | 质检员只标记redo，生产管理员决定重做工序 |
| UDI合规 | UDI码在质检合格后生成，不提前赋码 |
| 产品编号作废 | 打印失败/检验不合格创建新流转卡时，原产品编号标记作废 |

## 九、接口概览

### 9.1 生产流转卡接口

| 接口 | 方法 | 说明 |
|------|------|------|
| /production/record/list | POST | 生产列表（分页） |
| /production/record/{id} | GET | 流转卡详情 |
| /production/record/create | POST | 创建流转卡 |

## 十一、已确认规格

| 编号 | 规格项 | 确认方案 |
|------|--------|---------|
| S1 | 生产批号格式 | `B + 日期 + 4位流水号`，如 `B202605270001` |
| S2 | 产品编号格式 | `P + 日期 + 5位流水号`，如 `P202605270001` |
| S3 | 打印开始超时时间 | 10分钟（超时仅提醒，不阻断流程） |
| S4 | 打印完成超时时间 | `processingMinutes × 1.5`；未填写 processingMinutes 时默认4小时 |
| S5 | UDI码格式 | 暂用内部格式 `UDI + 年份 + 6位流水号`（如 `UDI2026000001`），预留对接国家UDI数据库接口 |
| S6 | 生产员数据权限 | 绑定加工中心，只能查看和操作本中心的任务和设备；生产管理员不绑定，可见所有中心 |
