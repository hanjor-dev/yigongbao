# 用户体系分析报告

## 一、文档概述

本文档详细描述医工宝系统的用户体系设计方案，包括账户分类、角色体系、层级关系、权限模型、账户创建流程等核心内容。

整个用户体系采用**动态可配置化设计**，通过后台管理系统实现分类、角色、权限的灵活配置，以满足业务发展过程中的需求变化。

---

## 二、核心设计理念

### 2.1 设计目标

- **灵活性**：分类、角色、权限均可通过后台动态配置，无需代码修改
- **扩展性**：所有账户分类预留层级关系，支持未来业务扩展
- **多角色**：一个账户可同时拥有多个角色
- **审批流**：用户注册需后台审核，确保账户合规性
- **数据隔离**：按角色+层级控制数据可见范围

### 2.2 后台管理系统模块

```
┌─────────────────────────────────────────────────────────────────────┐
│                        后台权限管理系统                              │
├─────────────────────────────────────────────────────────────────────┤
│  账户分类管理  │  角色管理  │  账户分类-角色绑定  │  菜单/权限管理  │
│       ↓       │     ↓      │         ↓          │        ↓       │
│  生产企业     │  业务员    │  生产企业 ↔ 业务员  │  菜单可见配置   │
│  经销商       │  区域管理员│  生产企业 ↔ 设计师  │  按钮权限配置   │
│  医疗机构     │  医生      │  经销商 ↔ 业务员    │                 │
│  监管         │  病人      │  医疗机构 ↔ 医生   │                 │
│  患者         │  ...       │  患者 ↔ 病人        │                 │
└─────────────────────────────────────────────────────────────────────┘
```

## 三、账户分类

### 3.1 分类说明

账户分类是对用户身份的基本划分，每个分类代表一类业务主体。

| 账户分类 | 说明 | 是否有子级 | 备注 |
|---------|------|-----------|------|
| 生产企业 | 公司内部员工 | ✓ 有（可配置启用） | 义齿生产加工企业 |
| 经销商 | 销售渠道合作方 | ✓ 有（可配置启用） | 代理商、经销商 |
| 医疗机构 | 医院、诊所等 | ✓ 有（可配置启用） | 口腔医院、诊所 |
| 监管机构 | 政府部门监管 | ✓ 有（可配置启用） | 药监局、卫生部门 |
| 患者 | 个人用户 | ✓ 有（可配置启用） | 预留，后期开放 |

> **重要说明**：所有账户分类都预留子级功能，通过后台配置决定是否启用。后期任何分类需要启用层级关系时，可直接在后台配置。

### 3.2 分类属性

| 属性 | 说明 | 必填 |
|------|------|------|
| 分类名称 | 分类的显示名称 | ✓ |
| 分类编码 | 分类的系统标识（唯一） | ✓ |
| 描述 | 分类的说明信息 | - |
| 是否启用层级 | 是否启用子账户功能 | ✓ |
| 状态 | 启用/禁用 | ✓ |

## 四、角色体系

### 4.1 角色说明

角色代表用户在系统中的职能身份，一个账户可以拥有多个角色。

### 4.2 账户分类与角色的绑定关系

采用**一对多**关系，一个账户分类可以绑定多个角色，一个角色也可以被多个分类使用。

| 账户分类 | 可选角色 |
|---------|---------|
| 生产企业 | 业务员、区域管理员、设计师、设计管理员、生产员、生产管理员、质管、库管、财务、公司管理员 |
| 经销商 | 业务员、区域管理员 |
| 医疗机构 | 医生（暂定）、预留子级配置 |
| 监管机构 | 监管员、预留子级配置 |
| 患者 | 病人、预留子级配置 |

### 4.3 角色说明

| 角色 | 归属分类 | 说明 |
|------|---------|------|
| 业务员 | 生产企业/经销商 | 负责订单开拓、客户维护 |
| 区域管理员 | 生产企业/经销商 | 管理下属业务员 |
| 设计师 | 生产企业 | 负责义齿设计工作 |
| 设计管理员 | 生产企业 | 管理设计团队、审核设计 |
| 生产员 | 生产企业 | 负责义齿生产加工 |
| 生产管理员 | 生产企业 | 管理生产流程、调度 |
| 质管 | 生产企业 | 质量检验、质量管理 |
| 库管 | 生产企业 | 仓库管理、库存管理 |
| 财务 | 生产企业 | 财务对账、收款管理 |
| 公司管理员 | 生产企业 | 系统最高权限管理 |
| 医生 | 医疗机构 | 口腔医生、下单采购 |
| 监管员 | 监管机构 | 监管执法 |
| 病人 | 患者 | 患者个人端（预留） |

## 五、层级关系

### 5.1 通用层级结构

所有账户分类都预留子级概念，支持后期灵活配置。

```
┌─────────────────────────────────────────────────────────────────────┐
│ 通用层级结构                                                        │
├─────────────────────────────────────────────────────────────────────┤
│  父账户（区域管理员/组长/负责人/科室主任等）                         │
│      └── 子账户（业务员/组员/成员/医生等，可多个，仅一级）           │
└─────────────────────────────────────────────────────────────────────┘
```

### 5.2 层级示例

```
示例1：生产企业
       区域管理员（父）→ 业务员（子）
       
示例2：经销商
       区域管理员（父）→ 业务员（子）

示例3：医疗机构（后期可启用）
       科室负责人（父）→ 医生（子）

示例4：生产企业-生产部门（后期可启用）
       生产管理员（父）→ 生产员（子）
```

### 5.3 层级规则

- 子账户只支持**一级**层级，不支持子账户下再创建子账户
- 父账户可以管理多个子账户
- 子账户的数据对父账户可见（用于对账、管理）
- 父账户的数据对子账户不可见

## 六、权限模型

### 6.1 权限组成

权限由两部分组成：
- **菜单权限**：控制用户可见的菜单项
- **功能按钮权限**：控制用户在菜单下的操作能力

### 6.2 权限配置方式

权限配置到**角色**级别，每个角色可以独立配置菜单可见性和功能按钮权限。

```
权限配置 = 菜单权限 + 功能按钮权限

示例 - 区域管理员角色权限配置：
├── 菜单可见
│   ├── 首页（统计报表）
│   ├── 订单管理（全部）
│   ├── 案例管理（全部）
│   ├── 财务管理
│   └── 下属管理
└── 按钮功能
    ├── [新增] ✓
    ├── [编辑] ✓
    ├── [删除] ✓
    ├── [审核] ✓
    └── [导出] ✓

示例 - 业务员角色权限配置：
├── 菜单可见
│   ├── 首页（统计报表）
│   ├── 我的订单
│   ├── 我的案例
│   └── 个人中心
└── 按钮功能
    ├── [新增订单] ✓
    ├── [编辑订单] ✓
    ├── [删除订单] ✗
    ├── [导出数据] ✗
    └── [审核] ✗
```

### 6.3 功能按钮权限类型

| 权限类型 | 说明 |
|---------|------|
| can_view | 可查看 |
| can_add | 可新增 |
| can_edit | 可编辑 |
| can_delete | 可删除 |
| can_audit | 可审核 |
| can_export | 可导出 |

## 七、数据权限控制

### 7.1 数据可见范围

| 角色类型 | 数据可见范围 |
|---------|-------------|
| 子账户（业务员/医生/生产员等） | 仅自己的数据 |
| 父账户（区域管理员/科室负责人等） | 所属子账户的所有数据（用于管理/对账） |
| 普通角色（设计师/质管/库管等） | 按角色定义的权限范围 |
| 公司管理员 | 全部数据 |

### 7.2 数据隔离原则

- 子账户只能查看和操作自己创建的数据
- 父账户可以查看和管理所有下属子账户的数据
- 不同角色之间默认数据隔离

## 九、账户创建流程

### 9.1 创建方式

账户创建分为两种方式：

```
┌─────────────────────────────────────────────────────────────────────┐
│                     账户创建方式                                     │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│   方式一：后台管理员创建                                            │
│   ┌──────────┐     ┌──────────┐                                    │
│   │ 管理员   │ ──→ │ 创建账户  │ ──→ 账户可直接登录                │
│   │ 直接创建 │     └──────────┘                                    │
│   └──────────┘                                                    │
│                                                                     │
│   方式二：用户主动注册 + 审批                                       │
│   ┌──────────┐     ┌──────────┐     ┌──────────┐     ┌────────┐ │
│   │ 用户     │ ──→ │ 提交注册 │ ──→ │ 管理员   │ ──→ │ 审核   │ │
│   │ 注册     │     │ 资料     │     │ 审核     │     │ 通过   │ │
│   └──────────┘     └──────────┘     └──────────┘     └────────┘ │
│                                        │                          │
│                                        ↓                          │
│                                   ┌────────┐                      │
│                                   │ 拒绝   │                      │
│                                   └────────┘                      │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 9.2 用户注册所需资料

用户主动注册时，需要提交以下资料进行审核：

- 营业执照（企业）/ 个人身份证（个人）
- 经营许可证
- 开票信息
- 合同复印件
- 其他资质证明材料

### 9.3 审批流程

```
┌─────────────────────────────────────────────────────────────────────┐
│                       注册审批流程                                  │
├─────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  1. 用户提交注册申请                                                │
│     ├── 填写账户信息（手机号、单位名称、密码等）                     │
│     ├── 选择账户分类                                                │
│     ├── 选择角色                                                    │
│     └── 上传资质材料                                                │
│                                                                         │
│  2. 进入待审核状态                                                  │
│     └── 账户不可登录，等待管理员审核                                 │
│                                                                         │
│  3. 管理员审核                                                      │
│     ├── 审核通过 → 账户激活，可正常登录                             │
│     └── 审核拒绝 → 通知用户，拒绝原因                               │
│                                                                         │
└─────────────────────────────────────────────────────────────────────┘
```
