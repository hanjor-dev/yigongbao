# 生产管理模块需求分析（v2.0）

## 一、文档概述

### 1.1 文档目的

本文档描述医工宝系统**生产管理模块**的详细需求分析。本模块覆盖从设计审核通过到产品质检完成的完整生产链条，包括生产流转卡管理、工序流转、设备管理、产品追溯等核心功能。

### 1.2 文档范围

**生产管理模块**覆盖的流程节点为：

```
待打印 → 打印中 → 打印完成 → 后处理中 → 质检中 → 入库中 → 已完成
```

即：自订单流转至生产部起，直至产品生产完成、质检、入库的**全流程**，均属于本模块需求范围。

### 1.3 核心特点

- **批次级别管理**：以数据包为单位进行生产管理，一个数据包对应一张生产流转卡
- **逐工序填写**：流转卡随产品在各工序间流转，每个工序的操作员填写该工序信息
- **产品级别追溯**：每个物理产品有唯一的产品编号，质检合格后生成UDI码
- **扫码流转**：通过扫描流转卡二维码实现工序间流转，记录流转时间和责任人

### 1.4 重要说明

- 生产管理是订单流程中「设计之后、质检之前」的核心环节
- **医疗器械订单**与**非医疗器械订单**的生产流程完全一致，区别仅在于质检合格后是否生成UDI码
- **不需要实体交付的订单**不涉及实物生产，不经过本模块（设计完成后直接进入已完成）
- 生产管理入口独立于订单管理，仅生产员/生产管理员可见

## 二、模块边界与前置条件

### 2.1 模块边界

```
订单模块（创建/审核） → 设计模块（设计/审核） → 生产模块（本文档）
                                                    ↓
                                本模块覆盖的流程节点：
                                待打印 → 打印中 → 打印完成 → 后处理中 → 质检中 → 入库中 → 已完成
                                                    ↓
                                                质检/仓储/交付
```

### 2.2 前置条件

生产模块开始的前提条件：

| 前置模块 | 前置状态 | 说明 |
|----------|----------|------|
| 设计模块（需实体交付订单） | 设计审核通过 | 设计师完成设计 → 设计管理员审核通过 → 订单流转至「待打印」 |
| 订单模块（不需实体交付） | 设计完成+客户确认 | 设计审核通过后进入「待客户确认」→ 客户确认后进入「已完成」，不经过生产模块 |
| 订单信息 | 完整 | 订单包含生产所需信息（产品、材质等） |
| 设计文件 | 已上传 | 设计师已上传打印文件（STL/3MF/OBJ等） |

### 2.3 订单分类与生产流程对应

| 订单分类 | 是否经过生产模块 | 说明 |
|----------|:----------------:|------|
| 医疗器械订单（需实体交付） | ✓ 是 | 设计审核通过 → 待打印 → ... → 质检中（生成UDI码）→ 已完成 |
| 非医疗器械订单（需实体交付） | ✓ 是 | 设计审核通过 → 待打印 → ... → 质检中（不生成UDI码）→ 已完成 |
| 医疗器械/非医疗器械订单（不需实体交付） | ✗ 否 | 设计审核通过 → 待客户确认 → 已完成 |

## 三、核心概念定义

### 3.1 生产流转卡（产品流转卡/生产作业记录表）

**定义**：批次级别的生产记录，随产品在各工序间流转，逐工序填写。

**核心特征**：
- **批次级别**：一个数据包 → 一张流转卡 → 包含该批次所有产品
- **逐工序填写**：流转到某工序时，该工序操作员填写该工序信息
- **批次检验**：每个工序记录批次级别的检验结果、合格数量、检验员
- **物理形态**：电子流转卡 + 纸质二维码标签（贴在产品托盘或容器上）

**包含内容**：
1. 基础信息：订单号、数据包编号、生产批号、版本号、产品列表
2. 工序记录：7个工序的详细信息（设备、参数、时间、人员、检验结果）
3. 流转记录：每次工序流转的时间、扫码人、交接人

### 3.2 产品编号

**定义**：每个物理产品的唯一标识，在开始生产时生成。

**生成时机**：生产员填写生产批号并保存后，系统立即根据打印文件列表和各文件的打印数量自动生成（即阶段1步骤3完成时触发，步骤4展示的是已生成的结果）。

**作用**：
- 产品唯一标识（用于后续UDI关联）
- 关联到流转卡（通过流转卡追溯生产过程）
- 包装/质检时的产品识别

**生成规则**：待定（建议格式：P + 日期 + 流水号，如 P202605110001）

**重要说明**：
- 一个打印文件如果打印数量为2，则生成2个不同的产品编号
- 每个物理产品都有独立的产品编号和UDI码（医疗器械）
- 产品编号不参与工序流转扫码，工序流转扫的是流转卡二维码

### 3.3 UDI码（唯一器械标识）

**定义**：医疗器械产品的唯一标识码，符合医疗器械监管要求。

**生成时机**：质检合格后生成（仅医疗器械订单）

**作用**：
- 医疗器械产品的正式标识
- 产品追溯（从生产到使用的全生命周期）
- 监管合规（符合医疗器械UDI法规要求）

**与产品编号的关系**：
- 产品编号：内部追溯码，生产开始时生成
- UDI码：正式标识码，质检合格后生成，关联产品编号

### 3.4 工序类型

生产流转卡包含7个固定工序：

| 序号 | 工序代码 | 工序名称 | 说明 |
|:----:|---------|---------|------|
| 1 | design | 设计 | 设计阶段已完成，流转卡中仅记录 |
| 2 | print | 3D打印成型 | 打印机打印产品 |
| 3 | wash | 酒精初洗（含打磨） | 酒精清洗和打磨处理 |
| 4 | cure | UV固化 | UV固化处理 |
| 5 | clean | 超声清洗 | 超声波清洗 |
| 6 | dry | 干燥 | 空气干燥或烘干 |
| 7 | pack | 包装 | 产品包装 |

**工序特点**：
- 工序顺序固定，不可跳过
- 每个工序需要填写：设备、参数、时间、人员、检验结果
- 工序完成后扫码流转到下一工序

## 四、角色与权限

### 4.1 生产模块角色定义

| 角色 | 账户类型 | 职责范围 | 数据可见范围 |
|------|----------|----------|--------------|
| 生产员 | 内部用户 | 执行具体生产操作、扫码流转、填写流转卡 | 分配给自己的生产任务 |
| 生产管理员 | 内部用户 | 生产管理、任务分配、设备管理、异常处理 | 所有生产任务 |
| 质检员 | 内部用户 | 执行最终质检、记录质检结果、决定返工方案、生成UDI码 | 质检中状态的批次 |

> **说明**：质检员属于生产模块的下游角色，在包装完成后介入。质检员账号由系统管理员分配，不具备生产操作权限。

### 4.2 角色功能矩阵

| 功能 | 生产员 | 生产管理员 | 质检员 |
|------|:------:|:----------:|:------:|
| 查看待打印订单列表 | ✓ | ✓ | ✗ |
| 分配打印机 | ✓ | ✓ | ✗ |
| 创建生产流转卡 | ✓ | ✓ | ✗ |
| 填写工序信息 | ✓ | ✓ | ✗ |
| 扫码流转（生产工序） | ✓ | ✓ | ✗ |
| 执行最终质检 | ✗ | ✗ | ✓ |
| 标记返工/重做 | ✗ | ✗ | ✓ |
| 生成UDI码 | ✗ | ✗ | ✓ |
| 查看生产统计报表 | ✗ | ✓ | ✗ |
| 设备管理 | ✗ | ✓ | ✗ |
| 异常处理（生产异常） | ✗ | ✓ | ✗ |

> **生产统计报表包含**：各状态批次数量、日/周/月产量、设备利用率、不合格率、返工率。

### 4.3 与其他模块的权限对比

| 功能 | 订单模块 | 设计模块 | 生产模块 | 质检模块 |
|------|:--------:|:--------:|:--------:|:--------:|
| 订单管理入口 | 业务员/管理员可见 | - | **隐藏** | - |
| 生产管理入口 | - | - | 生产员/生产管理员可见 | - |
| 我的工单 | - | 设计师可见 | - | - |

## 五、详细业务流程

### 5.1 流程概览

```
┌─────────────────────────────────────────────────────────────────────────┐
│                          生产流程（统一）                                 │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│   阶段1      阶段2      阶段3      阶段4      阶段5                      │
│   ┌───┐    ┌───┐    ┌───┐    ┌───┐    ┌───┐                          │
│   │准备│ →  │打印│ →  │后处理│ → │包装│ →  │质检│                          │
│   └───┘    └───┘    └───┘    └───┘    └───┘                          │
│                                                                         │
│   待打印   打印中   后处理中   包装    质检中                            │
│   分配设备  工序填写  4个子工序  工序填写  产品质检                       │
│   创建流转卡 扫码流转  扫码流转   扫码流转  生成UDI                       │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### 5.2 阶段1：生产准备（待打印 → 打印中）

**触发条件**：设计审核通过，订单流转至「待打印」状态

**操作步骤**：

```
步骤1：生产员查看生产列表
      - 列表以数据包为单位展示（不是订单级别）
      - 显示：订单号、数据包编号、产品信息、期望交付时间等

步骤2：选择数据包 → 分配打印机
      - 从可用打印机列表中选择（仅显示状态为"空闲"的设备）
      - 系统检查打印机状态（空闲/使用中/故障）
      - 并发控制：系统使用乐观锁，若提交时设备已被他人占用，提示重新选择

步骤3：点击"开始生产" → 填写生产批号
      - 生产批号可系统自动生成或手动输入
      - 生产批号格式：待定
      - 保存生产批号后，系统立即根据打印文件列表和打印数量自动生成产品编号

步骤4：系统展示打印文件列表及已生成的产品编号
      示例：
      - 打印文件1：左侧导板.stl（打印数量：2）
        → 产品1：P202605110001
        → 产品2：P202605110002
      - 打印文件2：右侧导板.stl（打印数量：1）
        → 产品3：P202605110003

步骤5：点击"流转卡" → 进入流转卡填写页面
      系统自动带出：
      - 订单号、数据包编号、版本号
      - 产品信息、材质
      - 操作人员（当前用户）

步骤6：填写流转卡基础信息
      手动填写：
      - 生产数量（确认）
      - 原材料批号

步骤7：保存流转卡 → 系统生成流转卡二维码
      - 二维码包含：流转卡ID、数据包编号、生产批号
      - 打印二维码标签（贴在产品托盘或容器上）

步骤8：生产员在打印机上操作开始打印

步骤9：系统读取设备状态 → 订单状态更新为"打印中"
      - 第一阶段：手动点击"开始打印"按钮（模拟）
      - 后续阶段：对接打印机API，自动读取状态
```

**状态变更**：待打印 → 打印中

---

### 5.3 阶段2：打印工序（打印中 → 打印完成 → 后处理中）

**操作步骤**：

```
步骤1：打印操作员在流转卡中填写"3D打印成型"工序信息
      - 关键设备：光固化3D打印机
      - 设备编号：从设备列表选择（已在阶段1分配）
      - 关键参数：
        * 层厚：___ mm
        * 激光器功率：___ mW
        * 其他参数...
      - 打印起止时间：
        * 开始时间：系统记录或手动填写
        * 结束时间：系统记录或手动填写
      - 操作人员：系统自动带出当前用户

步骤2：打印完成 → 系统读取设备状态 → 订单状态更新为"打印完成"

步骤3：打印操作员填写检验信息
      - 检验结果：合格/不合格
      - 合格数量：___ 个
      - 检验员：选择或当前用户

步骤4：扫描流转卡二维码 → 选择"流转到下一工序（酒精初洗）"
      - 系统记录：
        * 流转时间
        * 扫码人
        * 从"打印"工序流转到"酒精初洗"工序

步骤5：系统更新订单状态为"后处理中"
```

**状态变更**：打印中 → 打印完成 → 后处理中

---

### 5.4 阶段3：后处理工序（后处理中）

后处理包含4个子工序：酒精初洗、UV固化、超声清洗、干燥。每个子工序流程相同，以"酒精初洗"为例：

**操作步骤**：

```
步骤1：清洗操作员扫描流转卡二维码
      - 系统显示该批次信息
      - 显示产品列表、当前工序、上一工序完成情况

步骤2：点击"开始酒精初洗工序" → 进入工序填写页面

步骤3：填写工序信息
      - 关键设备：酒精容器
      - 设备编号：从设备列表选择
      - 关键参数：
        * 酒精批号：___
        * 浸泡程度：完全浸泡/部分浸泡
        * 浸泡开始时间：___
        * 浸泡结束时间：___
      - 操作人员：系统自动带出

步骤4：完成清洗 → 填写检验信息
      - 检验结果：合格/不合格
      - 合格数量：___ 个
      - 检验员：选择或当前用户

步骤5：扫描流转卡二维码 → 选择"流转到下一工序（UV固化）"
      - 系统记录流转信息

步骤6：系统保持订单状态为"后处理中"
```

**其他后处理工序**：

**UV固化工序**：
- 关键设备：UV固化机
- 关键参数：固化模式（HIGH/LOW）、固化开始/结束时间

**超声清洗工序**：
- 关键设备：超声清洗机
- 关键参数：酒精批号、清洗模式（变波/脱气）、加热（开/关）、清洗起止时间

**干燥工序**：
- 关键设备：空气压缩机或烘干设备
- 关键参数：干燥方式、干燥时间

**状态变更**：后处理中（保持不变，直到包装工序）

---

### 5.5 阶段4：包装工序（后处理中 → 质检中）

**操作步骤**：

```
步骤1：包装操作员扫描流转卡二维码
      - 系统显示该批次信息
      - 显示产品列表（含产品编号）

步骤2：点击"开始包装工序" → 进入工序填写页面

步骤3：系统显示该批次的产品列表
      示例：
      - P202605110001（左侧导板）
      - P202605110002（左侧导板）
      - P202605110003（右侧导板）

步骤4：填写工序信息
      - 关键设备：封口机
      - 设备编号：从设备列表选择
      - 关键参数：
        * 热封温度：___ ℃
        * 热封时间：___ 秒
        * 灭菌方式：过氧化氢等离子灭菌/其他（如有）
      - 操作人员：系统自动带出

步骤5：（可选）逐个扫描产品编号，确认产品完整性
      - 防止产品遗漏或混料
      - 系统记录每个产品的包装确认
      - 若扫描数量不足：提示缺少哪些产品编号，操作员需找回产品或报告生产管理员
      - 若扫描到非本批次产品编号：提示混料错误，禁止继续，需人工核查后重新扫描

步骤6：完成包装 → 填写检验信息
      - 检验结果：合格/不合格
      - 合格数量：___ 个
      - 检验员：选择或当前用户

步骤7：扫描流转卡二维码 → 选择"流转到质检"

步骤8：系统更新订单状态为"质检中"
```

**状态变更**：后处理中 → 质检中

---

### 5.6 阶段5：质检与UDI生成（质检中 → 入库中）

**操作步骤**：

```
步骤1：质检员扫描流转卡二维码
      - 系统显示该批次信息
      - 显示产品列表、生产流转卡详情

步骤2：逐个产品质检
      - 扫描产品编号（如P202605110001）
      - 系统显示该产品的生产记录
      - 进行质检检验（外观、尺寸、功能等）
      - 记录质检结果：合格/不合格

步骤3：质检合格的产品 → 生成UDI码（仅医疗器械订单）
      - 系统自动生成UDI码
      - UDI码关联产品编号
      - 打印UDI标签（贴在产品包装上）
      - 记录UDI生成时间

步骤4：质检不合格的产品 → 标记为返工
      - 填写不合格原因
      - 系统标记产品状态为"返工"
      - 可选：将整个批次标记为返工

步骤5：批次质检完成 → 填写质检汇总信息
      - 质检合格数量：___ 个
      - 质检不合格数量：___ 个
      - 质检员：系统自动带出
      - 质检备注：___

步骤6：扫描流转卡二维码 → 选择"流转到入库"

步骤7：系统更新订单状态为"入库中"
```

**状态变更**：质检中 → 入库中（或返工）

**特殊说明**：
- 医疗器械订单：质检合格后生成UDI码
- 非医疗器械订单：质检合格后不生成UDI码，直接流转到入库

## 六、订单状态流转规则

### 6.1 生产阶段状态定义

| 状态代码 | 状态名称 | 说明 | 可流转到的状态 |
|---------|---------|------|---------------|
| pending_print | 待打印 | 设计审核通过，等待生产员接单 | printing |
| printing | 打印中 | 打印机正在打印 | print_completed, print_failed |
| print_completed | 打印完成 | 打印完成，等待后处理 | post_processing |
| post_processing | 后处理中 | 后处理工序进行中（酒精初洗/UV固化/超声清洗/干燥） | qc_in_progress |
| qc_in_progress | 质检中 | 质检员检验中 | warehouse_in |
| warehouse_in | 入库中 | 等待入库 | completed |
| completed | 已完成 | 订单完成交付 | - |
| print_failed | 打印失败 | 打印过程中断，原流转卡终态，不再流转 | - |
| abandoned | 已废弃 | 打印工序检验不合格，原流转卡终态，不再流转 | - |

> **说明**：
> - `rework`（返工）不再作为订单级状态。返工操作体现在**产品级别**（`production_product.status`）和**新流转卡的创建**上，订单状态直接由质检中的合格产品流转到 `warehouse_in`，不合格产品分离后创建新流转卡重新进入 `pending_print`。
> - 原流转卡在打印失败/打印不合格场景下进入终态（`print_failed`/`abandoned`），保留用于追溯，不再参与流转。

### 6.2 状态流转图

```
                                                    打印失败（终态）
                                                    ↑
待打印 → 打印中 → 打印完成 → 后处理中 → 质检中 → 入库中 → 已完成
           ↓                                  ↓
        打印失败                           已废弃（终态）
        （终态）

不合格产品分离后 → 创建新流转卡 → 新流转卡进入"待打印"（独立流程）
```

> 说明：返工不是订单状态，而是产品级别操作。不合格产品从当前批次分离，创建新流转卡后以新的独立批次重新进入待打印。

### 6.3 状态流转触发条件

| 状态流转 | 触发条件 | 操作人 |
|---------|---------|--------|
| 待打印 → 打印中 | 生产员点击"开始打印"或系统读取设备状态 | 生产员 |
| 打印中 → 打印完成 | 系统读取设备状态（打印完成） | 系统自动 |
| 打印中 → 打印失败 | 生产员记录打印失败，选择"重新打印"方式B | 生产员 |
| 打印完成 → 后处理中 | 打印工序检验全部合格，扫码流转到酒精初洗 | 生产员 |
| 打印完成 → 已废弃 | 打印工序检验不合格，选择"重新打印"创建新流转卡 | 生产员 |
| 后处理中 → 质检中 | 包装工序完成，扫码流转到质检 | 生产员 |
| 质检中 → 入库中 | 批次内所有产品均为"合格"或"已分离"，扫码流转到入库 | 质检员 |
| 入库中 → 已完成 | 入库完成 | 仓管员 |

### 6.4 工序状态与订单状态的关系

**订单状态**：粗粒度，便于管理和查询
**工序状态**：细粒度，详细追溯

| 订单状态 | 对应的工序状态 |
|---------|---------------|
| 待打印 | 无工序记录 |
| 打印中 | 打印工序：进行中 |
| 打印完成 | 打印工序：已完成 |
| 后处理中 | 酒精初洗/UV固化/超声清洗/干燥：进行中或已完成 |
| 质检中 | 包装工序：已完成，质检进行中 |
| 入库中 | 所有工序：已完成，等待入库 |
| 已完成 | 所有工序：已完成，已入库 |

## 八、关键业务规则

### 8.1 生产流转卡规则

| 规则编号 | 规则描述 | 约束条件 |
|---------|---------|---------|
| BR-001 | 一个数据包只能创建一张生产流转卡 | 数据包ID唯一 |
| BR-002 | 流转卡编号由系统自动生成，不可修改 | 使用编码生成器 |
| BR-003 | 流转卡必须包含7个固定工序记录 | 创建流转卡时自动创建7条工序记录 |
| BR-004 | 流转卡二维码在保存流转卡时生成 | 二维码包含流转卡ID、数据包编号、生产批号 |
| BR-005 | 流转卡的产品总数 = 所有打印文件的打印数量之和 | 系统自动计算 |

### 8.2 产品编号规则

| 规则编号 | 规则描述 | 约束条件 |
|---------|---------|---------|
| BR-101 | 产品编号在填写生产批号后自动生成 | 根据打印文件和打印数量生成 |
| BR-102 | 一个打印文件如果打印数量为N，则生成N个不同的产品编号 | 每个物理产品都有唯一编号 |
| BR-103 | 产品编号全局唯一，不可重复 | 数据库唯一索引约束 |
| BR-104 | 产品编号生成后不可修改 | 系统控制 |
| BR-105 | 产品编号格式：待定（建议P+日期+流水号） | 使用编码生成器 |

### 8.3 工序流转规则

| 规则编号 | 规则描述 | 约束条件 |
|---------|---------|---------|
| BR-201 | 工序必须按顺序流转，不可跳过 | 系统检查上一工序是否完成 |
| BR-202 | 工序流转必须扫描流转卡二维码 | 扫码验证流转卡ID |
| BR-203 | 工序流转时记录流转时间、扫码人、交接人 | 系统自动记录 |
| BR-204 | 工序完成后才能流转到下一工序 | 检查工序状态为"已完成" |
| BR-205 | 每次工序流转生成一条流转记录 | 用于追溯 |

### 8.4 工序填写规则

| 规则编号 | 规则描述 | 约束条件 |
|---------|---------|---------|
| BR-301 | 工序信息由该工序的操作员填写 | 不能提前填写所有工序 |
| BR-302 | 工序必填字段：设备、操作人员、检验结果、合格数量 | 系统校验 |
| BR-303 | 工序参数根据工序类型不同而不同 | 使用JSON格式存储 |
| BR-304 | 操作人员默认为当前登录用户 | 可修改 |
| BR-305 | 检验员可以是操作人员本人或其他人 | 可选择 |

### 8.5 质检与UDI规则

| 规则编号 | 规则描述 | 约束条件 |
|---------|---------|---------|
| BR-401 | 质检必须逐个产品进行 | 扫描产品编号 |
| BR-402 | 医疗器械订单质检合格后生成UDI码 | 订单类型判断 |
| BR-403 | 非医疗器械订单不生成UDI码 | 订单类型判断 |
| BR-404 | UDI码全局唯一，不可重复 | 数据库唯一索引约束 |
| BR-405 | UDI码生成后关联产品编号 | 一对一关系 |
| BR-406 | 质检不合格的产品可标记为返工 | 产品状态更新 |
| BR-407 | 批次质检完成后记录合格数量和不合格数量 | 系统统计 |

### 8.6 设备管理规则

| 规则编号 | 规则描述 | 约束条件 |
|---------|---------|---------|
| BR-501 | 打印机分配时检查设备状态 | 只能分配空闲状态的设备 |
| BR-502 | 设备使用中时不能分配给其他任务 | 状态互斥 |
| BR-503 | 设备故障时不能使用 | 状态检查 |
| BR-504 | 设备状态由系统自动更新或手动更新 | 第一阶段手动，后续对接API |
| BR-505 | 设备编号全局唯一 | 数据库唯一索引约束 |

### 8.7 重做与返工规则

> **概念区分**：
> - **重做（Redo）**：针对后处理工序中不合格产品，在**当前工序**重新执行操作，保留原流转卡和原产品编号。
> - **返工（Rework）**：不合格产品从当前批次**分离**，创建新流转卡，回到打印工序或指定后处理工序重新生产。

| 规则编号 | 规则描述 | 约束条件 |
|---------|---------|---------|
| BR-601 | 后处理工序检验不合格的产品可选择重做或返工 | 质检员/生产员操作 |
| BR-602 | 重做：保留原流转卡，保留原产品编号，新增工序产品检验记录（attempt_no递增） | 不创建新流转卡 |
| BR-603 | 返工到打印：不合格产品从批次分离，创建新流转卡，原产品编号作废，生成新产品编号 | 原流转卡标记为 abandoned |
| BR-604 | 返工到后处理：不合格产品从批次分离，创建新流转卡，保留原产品编号，回到指定工序 | 原流转卡保持当前状态继续流转 |
| BR-605 | 流转条件：批次内所有产品均为"合格"或"已分离"时，才能流转到下一工序 | 系统校验 |
| BR-606 | 返工/重做原因必须填写 | 系统校验 |
| BR-607 | 打印过程中失败选择重新打印时，原流转卡状态标记为 print_failed，创建新流转卡 | 原编号作废，生成新编号 |
| BR-608 | 打印工序检验不合格选择重新打印时，原流转卡状态标记为 abandoned，创建新流转卡 | 原编号作废，生成新编号 |

## 九、异常处理与返工流程

### 9.1 设备异常处理

| 异常情况 | 处理方式 | 责任人 |
|---------|---------|--------|
| 打印中设备故障 | 暂停生产，提示切换设备或等待修复 | 生产管理员 |
| 设备长时间故障 | 通知生产管理员，重新分配设备 | 生产管理员 |
| 设备状态读取失败 | 提示手动更新状态 | 生产员 |

### 9.2 打印失败处理（详细流程）

#### 9.2.1 打印过程中失败

**触发条件**：打印机故障、材料用尽、打印中断等

```
打印中 → 打印失败
  ↓
记录失败原因（设备故障/材料问题/其他）
  ↓
  方式A：修复后继续（同一流转卡）
    - 修复设备/补充材料 → 继续打印 → 流转卡保持不变，订单状态保持"打印中"

  方式B：重新打印（创建新流转卡）
    - 原流转卡状态标记为 print_failed（终态，保留用于追溯）
    - 原产品编号作废
    - 创建新流转卡，生成新产品编号
    - 重新开始打印
```

**规则**：原流转卡保留用于追溯；创建新流转卡时原产品编号作废；失败原因必须记录。

#### 9.2.2 打印工序检验不合格

**触发条件**：打印完成，检验发现尺寸偏差、表面缺陷等

**检验粒度**：产品级别（逐个标记哪个产品不合格）

```
打印完成 → 逐个标记产品检验结果
  P001：合格
  P002：合格
  P003：不合格 → 填写原因
  ↓
对不合格产品（P003）选择处理方式：
  方式A：重新打印（调整参数）
    - 原流转卡状态标记为 abandoned（终态，保留用于追溯）
    - 原P003编号作废
    - 创建新流转卡，生成新产品编号
    - 调整打印参数，重新打印
  ↓
整批等待，直到所有产品处理完毕后继续流转
```

**规则**：打印不合格不能进入后处理；必须创建新流转卡，重新生成产品编号。

### 9.3 扫码异常处理

| 异常情况 | 处理方式 | 责任人 |
|---------|---------|--------|
| 二维码无法识别 | 提示重新扫描或手动输入流转卡编号 | 生产员 |
| 扫描错误的流转卡 | 提示错误，不允许流转 | 生产员 |
| 重复扫码 | 提示已处理，不允许重复流转 | 生产员 |
| 工序顺序错误 | 提示当前工序状态，不允许跳过工序 | 生产员 |

### 9.4 后处理工序检验不合格（详细流程）

**触发条件**：酒精初洗、UV固化、超声清洗、干燥等工序检验不合格

**检验粒度**：产品级别（逐个标记哪个产品不合格）

```
工序完成 → 逐个标记产品检验结果
  P001：合格
  P002：合格
  P003：不合格 → 填写原因
  ↓
对不合格产品（P003）选择处理方式：

  方式A：重做当前工序（只重做P003）
    - P003标记为"重做中"
    - 操作员对P003重新执行该工序（调整参数）
    - 重新检验P003
      - 合格 → 整批（P001+P002+P003）流转到下一工序
      - 不合格 → 再次选择处理方式
    - 新增工序产品检验记录（attempt_no递增）

  方式B：返工P003到打印工序
    - P003从本批次分离，创建新流转卡，生成新产品编号
    - 原P003编号作废
    - 整批（P001+P002）继续流转到下一工序
  ↓
流转条件：所有产品均为"合格"或"已分离返工"时，才能流转
```

**规则**：
- 重做只针对不合格产品，不整批重置
- 整批等待，直到每个产品的处理方式都确定后才能流转
- 重做记录保留历史（attempt_no），用于追溯

### 9.5 最终质检不合格（详细流程）

**触发条件**：包装完成后，质检员检验发现产品不合格

**检验粒度**：产品级别（逐个扫描产品编号）

```
质检中 → 逐个扫描产品编号进行质检
  P001：合格 → 生成UDI码（医疗器械）
  P002：合格 → 生成UDI码（医疗器械）
  P003：不合格 → 填写原因
  ↓
对不合格产品（P003）选择处理方式：

  方式A：返工到打印工序（问题严重，如尺寸偏差）
    - P003从本批次分离，创建新流转卡，生成新产品编号
    - 原P003编号作废，不生成UDI码
    - P001+P002正常流转到入库

  方式B：返工到某个后处理工序（问题轻微，如固化不足）
    - P003从本批次分离，回到指定后处理工序重新处理
    - 保留P003原产品编号
    - P001+P002正常流转到入库
  ↓
流转条件：所有产品均为"合格"或"已分离返工"时，才能流转到入库
```

**规则**：质检员根据不合格原因决定返工方案；返工到打印时原产品编号作废；返工到后处理时保留原产品编号。

### 9.6 返工流程汇总

| 场景 | 操作类型 | 起点 | 原流转卡处理 | 产品编号处理 |
|------|---------|------|------------|------------|
| 打印过程中失败（方式B） | 返工 | 待打印 | 标记为 print_failed（终态） | 原编号作废，生成新编号 |
| 打印工序检验不合格 | 返工 | 待打印 | 标记为 abandoned（终态） | 原编号作废，生成新编号 |
| 后处理工序检验不合格（重做当前工序） | 重做 | 当前工序 | 保留，继续流转 | 保留原编号 |
| 后处理工序检验不合格（返工到打印） | 返工 | 待打印 | 不合格产品分离，原流转卡继续流转剩余产品 | 原编号作废，生成新编号 |
| 最终质检不合格（返工到打印） | 返工 | 待打印 | 不合格产品分离，原流转卡继续流转合格产品 | 原编号作废，生成新编号 |
| 最终质检不合格（返工到后处理） | 返工 | 指定后处理工序 | 不合格产品分离，原流转卡继续流转合格产品 | 保留原编号 |

### 9.7 数据异常处理

| 异常情况 | 处理方式 | 责任人 |
|---------|---------|--------|
| 流转卡数据丢失 | 从备份恢复或手动补录 | 系统管理员 |
| 产品编号重复 | 系统拒绝，重新生成 | 系统自动 |
| 工序记录缺失 | 提示补充工序信息 | 生产员 |
| UDI生成失败 | 记录错误日志，重新生成 | 系统管理员 |

## 十、与其他模块的关系

### 10.1 与订单模块的关系

**数据依赖**：
- 生产模块读取订单基本信息（订单号、产品信息、客户信息等）
- 生产模块更新订单状态（待打印 → 打印中 → ... → 已完成）

**业务关联**：
- 订单创建 → 设计审核通过 → 流转到生产模块
- 生产完成 → 订单状态更新为"已完成"

### 10.2 与设计模块的关系

**数据依赖**：
- 生产模块读取设计数据包信息（数据包编号、版本号、打印文件等）
- 生产模块读取打印文件列表（文件名、文件路径、打印数量等）
- 生产模块读取设计信息（材质、产品信息等）

**业务关联**：
- 设计审核通过 → 订单流转到生产模块（待打印）
- 生产模块下载打印文件（设计师上传的STL/3MF/OBJ文件）

### 10.3 与质检模块的关系

**数据依赖**：
- 质检模块读取生产流转卡信息（用于质检参考）
- 质检模块读取产品编号（用于产品识别）
- 生产模块记录质检结果（合格/不合格）

**业务关联**：
- 包装完成 → 流转到质检模块
- 质检合格 → 生成UDI码（医疗器械）
- 质检不合格 → 返工（回到生产模块）

### 10.4 与仓储模块的关系

**数据依赖**：
- 仓储模块读取产品信息（产品编号、UDI码、数量等）
- 仓储模块读取流转卡信息（用于入库参考）

**业务关联**：
- 质检完成 → 流转到仓储模块（入库）
- 入库完成 → 订单状态更新为"已完成"

### 10.5 数据流转图

```
订单模块 → 设计模块 → 生产模块 → 质检模块 → 仓储模块
   ↓          ↓          ↓          ↓          ↓
订单信息   设计文件   流转卡     质检结果   入库记录
           数据包     产品编号   UDI码
```

## 十三、总结

本需求分析文档详细描述了医工宝系统生产管理模块的完整需求，包括：

1. **核心概念**：生产流转卡（批次级别）、产品编号（产品级别）、UDI码（医疗器械标识）
2. **业务流程**：从待打印到质检完成的5个阶段、7个工序的详细操作步骤
3. **数据模型**：5个核心表的结构和关系
4. **业务规则**：60+条业务规则，覆盖流转卡、产品编号、工序流转、质检、设备管理等
5. **异常处理**：设备异常、打印失败、扫码异常、质检异常等场景的处理方式
6. **模块关系**：与订单、设计、质检、仓储模块的数据依赖和业务关联

**关键特点**：
- 批次级别管理，以数据包为单位
- 逐工序填写，流转卡随产品流转
- 扫码流转，记录流转时间和责任人
- 产品级别追溯，每个产品有唯一编号和UDI码

本文档将作为后续设计和开发的依据。
