# 生产管理模块需求分析（v3.0）

## 一、文档概述

### 1.1 文档目的

本文档描述医工宝系统**生产管理模块**的详细需求分析。本模块覆盖从设计审核通过到产品质检完成的完整生产链条，包括生产流转卡管理、工序流转、设备管理、产品追溯等核心功能。

### 1.2 文档范围

**生产管理模块**覆盖的流程节点根据订单类型分为两种：

**医疗器械订单流程：**
```
待打印 → 打印中 → 打印完成 → 后处理中 → 质检中 → 包装中 → 入库中 → 已完成
```

**非医疗器械订单流程：**
```
待打印 → 打印中 → 打印完成 → 质检中 → 包装中 → 入库中 → 已完成
```

即：自订单流转至生产部起，直至产品生产完成、质检、包装、入库的**全流程**，均属于本模块需求范围。

### 1.3 核心特点

- **批次级别管理**：以数据包为单位进行生产管理，一个数据包对应一张生产流转卡
- **逐工序填写**：流转卡随产品在各工序间流转，每个工序的操作员填写该工序信息
- **产品级别追溯**：每个物理产品有唯一的产品编号，质检合格后生成UDI码（医疗器械）
- **扫码流转**：通过扫描流转卡二维码实现工序间流转，记录流转时间和责任人
- **订单类型分叉**：医疗器械订单需要后处理工序，非医疗器械订单打印完直接质检

### 1.4 重要说明

- 生产管理是订单流程中「设计之后、入库之前」的核心环节
- **医疗器械订单**与**非医疗器械订单**的生产流程在后处理环节存在分叉：
  - 医疗器械：打印 → 后处理（3个工序）→ 质检 → 包装 → 入库
  - 非医疗器械：打印 → 质检 → 包装 → 入库
- **包装是独立环节**，不属于工序体系，在质检合格后由生产员执行
- **不需要实体交付的订单**不涉及实物生产，不经过本模块（设计完成后直接进入已完成）
- 生产管理入口独立于订单管理，仅生产员/生产管理员可见

## 二、模块边界与前置条件

### 2.1 模块边界

```
订单模块（创建/审核） → 设计模块（设计/审核） → 生产模块（本文档）
                                                    ↓
                                本模块覆盖的流程节点：
                        医疗器械：待打印 → 打印中 → 打印完成 → 后处理中 → 质检中 → 包装中 → 入库中 → 已完成
                        非医疗器械：待打印 → 打印中 → 打印完成 → 质检中 → 包装中 → 入库中 → 已完成
                                                    ↓
                                                仓储/交付
```

### 2.2 前置条件

生产模块开始的前提条件：

| 前置模块 | 前置状态 | 说明 |
|----------|----------|------|
| 设计模块（需实体交付订单） | 设计审核通过 | 设计师完成设计 → 设计管理员审核通过 → 订单状态为「设计审核通过」→ **生产员下载设计数据包时触发状态变更为「待打印」** |
| 订单模块（不需实体交付） | 设计完成+客户确认 | 设计审核通过后进入「待客户确认」→ 客户确认后进入「已完成」，不经过生产模块 |
| 订单信息 | 完整 | 订单包含生产所需信息（产品、材质、订单类型等） |
| 设计文件 | 已上传 | 设计师已上传打印文件（STL/3MF/OBJ等） |

### 2.3 订单分类与生产流程对应

| 订单分类 | 是否经过生产模块 | 流程说明 |
|----------|:----------------:|------|
| 医疗器械订单（需实体交付） | ✓ 是 | 设计审核通过 → 待打印 → 打印 → **后处理（3工序）** → 质检（生成UDI码）→ 包装 → 入库 → 已完成 |
| 非医疗器械订单（需实体交付） | ✓ 是 | 设计审核通过 → 待打印 → 打印 → **跳过后处理** → 质检（不生成UDI码）→ 包装 → 入库 → 已完成 |
| 医疗器械/非医疗器械订单（不需实体交付） | ✗ 否 | 设计审核通过 → 待客户确认 → 已完成 |

## 三、核心概念定义

### 3.1 生产流转卡（产品流转卡/生产作业记录表）

**定义**：批次级别的生产记录，随产品在各工序间流转，逐工序填写。

**核心特征**：
- **批次级别**：一个数据包 → 一张流转卡 → 包含该批次所有产品
- **逐工序填写**：流转到某工序时，该工序操作员填写该工序信息
- **批次检验**：每个工序记录批次级别的检验结果、合格数量、检验员
- **物理形态**：电子流转卡 + 纸质二维码标签（贴在产品托盘或容器上）

**包含内容**：
1. 基础信息：订单号、数据包编号、生产批号、版本号、产品列表
2. 工序记录：根据订单类型动态创建工序记录（医疗器械4个工序，非医疗器械1个工序）
3. 包装信息：包装设备、热封参数、灭菌方式等（存储在流转卡表字段上）
4. 流转记录：每次工序流转的时间、扫码人、交接人

### 3.2 产品编号

**定义**：每个物理产品的唯一标识，在开始生产时生成。

**生成时机**：生产员填写生产批号并保存后，系统立即根据打印文件列表和各文件的打印数量自动生成。

**作用**：
- 产品唯一标识（用于后续UDI关联）
- 关联到流转卡（通过流转卡追溯生产过程）
- 包装/质检时的产品识别

**生成规则**：P + 日期 + 5位流水号，如 P202605270001

**重要说明**：
- 一个打印文件如果打印数量为2，则生成2个不同的产品编号
- 每个物理产品都有独立的产品编号和UDI码（医疗器械）
- 产品编号不参与工序流转扫码，工序流转扫的是流转卡二维码

### 3.3 UDI码（唯一器械标识）

**定义**：医疗器械产品的唯一标识码，符合医疗器械监管要求。

**生成时机**：质检合格后生成（仅医疗器械订单）

**为什么在质检后生成而非生产开始时生成？**
1. **监管合规**：医疗器械UDI法规要求只有合格品才能赋码，提前赋码不符合监管要求
2. **避免废码**：质检不合格/返工时无需作废UDI，数据干净
3. **逻辑简洁**：生产过程用产品编号追溯已足够，UDI是最终合格品的正式标识

**作用**：
- 医疗器械产品的正式标识
- 产品追溯（从生产到使用的全生命周期）
- 监管合规（符合医疗器械UDI法规要求）

**与产品编号的关系**：
- 产品编号：内部追溯码，生产开始时生成，贯穿整个生产过程
- UDI码：正式标识码，质检合格后生成，关联产品编号

### 3.4 工序类型

> **概念说明**：「工序」指生产操作工序，记录在 `production_process` 表中。「阶段」是更粗粒度的流程节点，包含工序和独立环节（质检、包装）。医疗器械有5个工序、6个阶段；非医疗器械有2个工序、5个阶段。

生产流转卡包含的工序根据订单类型动态创建：

**医疗器械订单工序（5个）：**

| 序号 | 工序代码 | 工序名称 | 说明 |
|:----:|---------|---------|------|
| 1 | design | 设计 | 设计阶段已完成，流转卡中仅记录 |
| 2 | print | 3D打印成型 | 打印机打印产品 |
| 3 | wash | 酒精初洗（含打磨） | 酒精清洗和打磨处理 |
| 4 | cure | UV固化 | UV固化处理 |
| 5 | clean_dry | 超声清洗+干燥 | 超声波清洗 + 空气干燥或烘干 |

**非医疗器械订单工序（2个）：**

| 序号 | 工序代码 | 工序名称 | 说明 |
|:----:|---------|---------|------|
| 1 | design | 设计 | 设计阶段已完成，流转卡中仅记录 |
| 2 | print | 3D打印成型 | 打印机打印产品 |

**工序特点**：
- 工序顺序固定，不可跳过
- 每个工序需要填写：设备、参数、时间、人员、检验结果
- 工序完成后扫码流转到下一工序或下一环节

**包装环节（独立于工序体系）：**
- 包装不是工序，是独立环节，在质检合格后执行
- 包装数据存储在 `production_record` 表的包装字段上
- 包装完成后流转到入库

## 四、角色与权限

### 4.1 生产模块角色定义

| 角色 | 账户类型 | 职责范围 | 数据可见范围 |
|------|----------|----------|--------------|
| 生产员 | 内部用户 | 执行具体生产操作、扫码流转、填写流转卡、执行包装 | 分配给自己的生产任务 |
| 生产管理员 | 内部用户 | 生产管理、任务分配、设备管理、异常处理 | 所有生产任务 |

### 5.2 阶段1：生产准备（设计审核通过 → 待打印 → 打印中）

**触发条件**：设计审核通过，订单状态为「设计审核通过」

**操作步骤**：

```
步骤1：生产员查看生产列表
      - 列表以数据包为单位展示（不是订单级别）
      - 显示：订单号、数据包编号、产品信息、订单类型（医疗器械/非医疗器械）、期望交付时间等
      - 订单状态：设计审核通过

步骤2：生产员点击"下载设计数据包"
      - 系统触发订单状态变更：设计审核通过 → 待打印
      - 下载设计文件（STL/3MF/OBJ等）

步骤3：选择数据包 → 分配打印机
      - 从可用打印机列表中选择（仅显示状态为"空闲"且"在线"的设备）
      - 系统检查打印机状态（state=0 且 connectionStatus=1）
      - 并发控制：系统使用乐观锁，若提交时设备已被他人占用，提示重新选择

步骤4：点击"开始生产" → 填写生产批号
      - 生产批号可系统自动生成或手动输入
      - 生产批号格式：B + 日期 + 4位流水号，如 B202605270001（可手动输入覆盖）
      - 保存生产批号后，系统立即根据打印文件列表和打印数量自动生成产品编号

步骤5：系统展示打印文件列表及已生成的产品编号
      示例：
      - 打印文件1：左侧导板.stl（打印数量：2）
        → 产品1：P202605270001
        → 产品2：P202605270002
      - 打印文件2：右侧导板.stl（打印数量：1）
        → 产品3：P202605270003

步骤6：点击"流转卡" → 进入流转卡填写页面
      系统自动带出：
      - 订单号、数据包编号、版本号、订单类型
      - 产品信息、材质
      - 操作人员（当前用户）
      - 分配的打印机信息

步骤7：填写流转卡基础信息
      手动填写：
      - 生产数量（确认）
      - 原材料批号

步骤8：保存流转卡 → 系统生成流转卡二维码
      - 二维码包含：流转卡ID、数据包编号、生产批号
      - 打印二维码标签（贴在产品托盘或容器上）
      - 系统根据订单类型自动创建工序记录：
        * 医疗器械：创建 design/print/wash/cure/clean_dry 5条工序记录
        * 非医疗器械：创建 design/print 2条工序记录

步骤9：生产员在打印机上操作开始打印（物理操作）

步骤10：系统通过WebSocket接收设备状态推送 → 自动判断打印开始
      - 监听设备状态：当分配的打印机 state 从 0（空闲）变为 1（占用）时
      - 系统自动更新订单状态为"打印中"
      - 记录打印开始时间
      
步骤11：超时提醒机制
      - 如果生产员操作开始打印后，超过配置时间（建议5分钟）仍未收到设备状态变更推送
      - 系统提示："打印机状态未更新，请检查设备连接或手动确认打印状态"
      - 生产管理员可手动更新设备状态（调用 PUT /basic/device/{id}/state 接口）
```

**状态变更**：设计审核通过 → 待打印（下载数据包时触发）→ 打印中（设备状态推送触发）

### 5.3 阶段2：打印工序（打印中 → 打印完成 → 后处理中/质检中）

**操作步骤**：

```
步骤1：打印操作员在流转卡中填写"3D打印成型"工序信息（打印开始前填写）
      - 关键设备：光固化3D打印机
      - 设备编号：从设备列表选择（已在阶段1分配）
      - 关键参数（打印前设定）：
        * 层厚：___ mm
        * 激光器功率：___ mW
        * 其他参数...
      - 打印起止时间：
        * 开始时间：系统自动记录（设备状态变为占用时）
        * 结束时间：系统自动记录（设备状态变为空闲时）
      - 操作人员：系统自动带出当前用户

步骤2：系统通过WebSocket接收设备状态推送 → 自动判断打印完成
      - 监听设备状态：当分配的打印机 state 从 1（占用）变为 0（空闲）时
      - 系统自动更新订单状态为"打印完成"
      - 记录打印结束时间
      
步骤3：超时提醒机制
      - 如果打印开始后，超过预期打印时间（可根据设备 processingMinutes 字段 + 缓冲时间）仍未收到设备状态变更推送
      - 系统提示："打印超时，请检查设备状态或联系生产管理员"
      - 生产管理员可手动更新设备状态或处理异常

步骤4：打印操作员填写检验信息
      - 检验结果：合格/不合格（产品级别，逐个标记）
      - 合格数量：___ 个
      - 检验员：选择或当前用户
      - **说明**：系统不自动判断打印质量，由人工检验判断

步骤4.1：如有不合格产品 → 生产员选择处理方式
      方式A：修复后重打（同一流转卡）
        - 调整参数，对不合格产品重新打印
        - 重打完成后重新填写检验结果
        - 所有产品合格后继续流转
      方式B：废弃本批次，重新打印（创建新流转卡）
        - 原流转卡状态标记为 abandoned（终态，保留追溯）
        - 原产品编号作废
        - 创建新流转卡，生成新产品编号，重新开始

步骤5：扫描流转卡二维码 → 根据订单类型选择流转目标
      医疗器械订单：
        - 选择"流转到下一工序（酒精初洗）"
        - 系统更新订单状态为"后处理中"
      
      非医疗器械订单：
        - 选择"流转到质检"
        - 系统更新订单状态为"质检中"
```

**状态变更**：
- 医疗器械：打印中 → 打印完成（设备状态推送触发）→ 后处理中（人工扫码流转）
- 非医疗器械：打印中 → 打印完成（设备状态推送触发）→ 质检中（人工扫码流转）

**关键说明**：
- 打印开始和打印完成由设备状态推送自动触发，不需要人工点击
- 打印质量检验由人工判断，系统不自动判断
- 设备异常（材料耗尽、设备故障等）由人工处理，系统不自动处理

### 5.4 阶段3：后处理工序（后处理中）【仅医疗器械订单】

后处理包含3个子工序：酒精初洗、UV固化、超声清洗+干燥。每个子工序流程相同，以"酒精初洗"为例：

**操作步骤**：

```
步骤1：清洗操作员扫描流转卡二维码
      - 系统显示该批次信息
      - 显示当前工序、上一工序完成情况

步骤2：点击"开始酒精初洗工序" → 进入工序填写页面

步骤3：填写工序信息
      - 关键设备：酒精容器
      - 设备编号：从设备列表选择
      - 关键参数：
        * 酒精批号：___
        * 浸泡程度：完全浸泡/部分浸泡
        * 浸泡开始时间：___
        * 浸泡结束时间：___
      - 操作人员：系统自动带出

步骤4：完成工序 → 填写工序结果
      - 本批次是否有重做：有/无
      - 重做原因（如有）：___（记录哪个产品、什么问题、重做了几次）
      - 检验员：选择或当前用户
      说明：重做由操作员在现场完成后再填写，不驱动流转逻辑

步骤5：操作员确认整批完成 → 扫描流转卡二维码 → 选择"流转到下一工序（UV固化）"
      - 系统记录流转信息

步骤6：系统保持订单状态为"后处理中"
```

**其他后处理工序**：

**UV固化工序**：
- 关键设备：UV固化机
- 关键参数：固化模式（HIGH/LOW）、固化开始/结束时间

**超声清洗+干燥工序（clean_dry）**：
- 关键设备：超声清洗机 + 空气压缩机或烘干设备
- 关键参数：
  * 酒精批号：___
  * 清洗模式：变波/脱气
  * 加热：开/关
  * 清洗起止时间：___
  * 干燥方式：空气干燥/烘干
  * 干燥时间：___

**状态变更**：后处理中（保持不变，直到最后一个工序完成后流转到质检）

### 5.5 阶段4：质检环节（后处理中/打印完成 → 质检中）

**触发条件**：
- 医疗器械：后处理最后一个工序（clean_dry）完成，扫码流转到质检
- 非医疗器械：打印工序完成，扫码流转到质检

**操作步骤**：

```
步骤1：质检员扫描流转卡二维码
      - 系统显示该批次信息
      - 显示产品列表、生产流转卡详情

步骤2：逐个产品质检
      - 扫描产品编号（如P202605270001）
      - 系统显示该产品的生产记录
      - 进行质检检验（外观、尺寸、功能等）
      - 记录质检结果：合格/不合格

步骤3：质检合格的产品 → 生成UDI码（仅医疗器械订单）
      - 系统自动生成UDI码
      - UDI码关联产品编号
      - 打印UDI标签（贴在产品包装上）
      - 记录UDI生成时间

步骤4：质检不合格的产品 → 标记为 redo
      - 填写不合格原因
      - 系统标记产品状态为 redo
      - 质检员不需要选择返工路径，由生产管理员后续指定

步骤5：批次质检完成 → 填写质检汇总信息
      - 质检合格数量：___ 个
      - 质检不合格数量：___ 个
      - 质检员：系统自动带出
      - 质检备注：___

步骤6：流转条件检查
      - 系统检查：批次内所有产品均为 pass 状态
      - 如有 redo 产品，禁止流转，提示"存在待重做产品"
      - redo 处理流程：
        * 生产管理员查看 redo 产品列表，指定每个产品从哪个工序重做
          （返回打印 / 返回酒精初洗 / 返回UV固化 / 返回超声清洗+干燥）
        * 生产员收到重做任务，执行对应工序
        * 重做完成后，系统自动将产品状态改回 in_process
        * 质检员在同一张流转卡的质检页面看到该产品重新出现，继续质检
        * 质检通过 → pass，生成UDI码（医疗器械）

步骤7：所有产品均为 pass → 扫描流转卡二维码 → 选择"流转到包装"

步骤8：系统更新订单状态为"包装中"
```

**状态变更**：
- 医疗器械：后处理中 → 质检中 → 包装中
- 非医疗器械：打印完成 → 质检中 → 包装中

**关键规则**：
- 质检员只需标记 pass/redo，不需要决定返工路径
- redo 产品的重做工序由生产管理员指定
- redo 期间订单状态保持 `qc_in_progress`，不产生新状态
- 产品重做完成后系统自动将产品状态改回 `in_process`，质检员刷新页面即可继续质检
- 所有产品均为 pass 后，整批流转到包装

---

### 5.6 阶段5：包装环节（质检中 → 包装中 → 入库中）

**触发条件**：质检完成，批次内所有产品全部合格

**操作步骤**：

```
步骤1：包装操作员扫描流转卡二维码
      - 系统显示该批次信息
      - 显示产品列表（含产品编号、UDI码）

步骤2：点击"开始包装" → 进入包装信息填写页面

步骤3：系统显示该批次的产品列表
      示例：
      - P202605270001（左侧导板）- UDI: 01234567890123（医疗器械）
      - P202605270002（左侧导板）- UDI: 01234567890124（医疗器械）
      - P202605270003（右侧导板）- UDI: 01234567890125（医疗器械）

步骤4：填写包装信息
      - 关键设备：封口机
      - 设备编号：从设备列表选择
      - 关键参数：
        * 热封温度：___ ℃
        * 热封时间：___ 秒
        * 灭菌方式：过氧化氢等离子灭菌/其他（如有）
        * 灭菌批号：___（如有）
      - 操作人员：系统自动带出
      - 包装时间：系统自动记录

步骤5：（可选）逐个扫描产品编号，确认产品完整性
      - 防止产品遗漏或混料
      - 系统记录每个产品的包装确认
      - 若扫描数量不足：提示缺少哪些产品编号，操作员需找回产品或报告生产管理员
      - 若扫描到非本批次产品编号：提示混料错误，禁止继续，需生产管理员核查产品归属后重新扫描

步骤6：完成包装 → 保存包装信息
      - 系统将包装信息保存到 production_record 表的包装字段

步骤7：扫描流转卡二维码 → 选择"流转到入库"

步骤8：系统更新订单状态为"入库中"
```

**状态变更**：包装中 → 入库中

**数据存储**：
- 包装信息存储在 `production_record` 表，不在 `production_process` 工序表
- 包装相关字段：pack_device_id, pack_device_no, pack_seal_temperature, pack_seal_time, pack_sterilization_method, pack_sterilization_batch_no, pack_operator_id, pack_operator_name, pack_time

## 六、订单状态流转规则

### 6.1 生产阶段状态定义

| 状态代码 | 状态名称 | 说明 | 可流转到的状态 |
|---------|---------|------|---------------|
| design_approved | 设计审核通过 | 设计审核通过，等待生产员下载数据包 | pending_print |
| pending_print | 待打印 | 生产员已下载数据包，等待分配设备开始生产 | printing |
| printing | 打印中 | 打印机正在打印 | print_completed, print_failed |
| print_completed | 打印完成 | 打印完成，等待流转 | post_processing, qc_in_progress |
| post_processing | 后处理中 | 后处理工序进行中（酒精初洗/UV固化/超声清洗+干燥）【仅医疗器械】 | qc_in_progress |
| qc_in_progress | 质检中 | 质检员检验中（含 redo 产品重做等待期） | packing |
| packing | 包装中 | 包装操作进行中 | warehouse_in |
| warehouse_in | 入库中 | 等待入库 | completed |
| completed | 已完成 | 订单完成交付 | - |
| print_failed | 打印失败 | 打印过程中断，原流转卡终态，不再流转 | - |
| abandoned | 已废弃 | 打印工序检验不合格，原流转卡终态，不再流转 | - |

> **说明**：
> - `rework`（返工）不再作为订单级状态。质检 redo 产品在原流转卡上处理，流转卡状态保持 `qc_in_progress`。
> - 原流转卡在打印失败/打印不合格场景下进入终态（`print_failed`/`abandoned`），保留用于追溯，不再参与流转。
> - `design_approved` 是生产模块的入口状态，由设计模块流转过来，生产员下载数据包后变为 `pending_print`。

### 6.2 状态流转图

**医疗器械订单流转路径：**
```
设计审核通过 → 待打印 → 打印中 → 打印完成 → 后处理中 → 质检中 → 包装中 → 入库中 → 已完成
                           ↓           ↓
                        打印失败     已废弃
                        （终态）     （终态）
```

**非医疗器械订单流转路径：**
```
设计审核通过 → 待打印 → 打印中 → 打印完成 → 质检中 → 包装中 → 入库中 → 已完成
                           ↓           ↓
                        打印失败     已废弃
                        （终态）     （终态）
```

> 说明：质检 redo 产品在原流转卡上处理，流转卡状态保持 `qc_in_progress`，不产生新流转卡。

### 6.3 状态流转触发条件

| 状态流转 | 触发条件 | 操作人 |
|---------|---------|--------|
| 设计审核通过 → 待打印 | 生产员下载设计数据包 | 生产员 |
| 待打印 → 打印中 | 系统接收到分配的打印机状态变更推送（state: 0→1） | 系统自动 |
| 打印中 → 打印完成 | 系统接收到分配的打印机状态变更推送（state: 1→0） | 系统自动 |
| 打印中 → 打印失败 | 生产员记录打印失败，选择"重新打印"方式B | 生产员 |
| 打印完成 → 后处理中 | 打印工序检验全部合格，扫码流转到酒精初洗（医疗器械） | 生产员 |
| 打印完成 → 质检中 | 打印工序检验全部合格，扫码流转到质检（非医疗器械） | 生产员 |
| 打印完成 → 已废弃 | 打印工序检验不合格，选择"重新打印"创建新流转卡 | 生产员 |
| 后处理中 → 质检中 | 最后一个后处理工序（clean_dry）完成，扫码流转到质检 | 生产员 |
| 质检中 → 包装中 | 批次内所有产品全部合格，扫码流转到包装 | 质检员 |
| 包装中 → 入库中 | 包装完成，扫码流转到入库 | 生产员 |
| 入库中 → 已完成 | 入库完成 | 仓管员 |

### 6.4 工序状态与订单状态的关系

**订单状态**：粗粒度，便于管理和查询  
**工序状态**：细粒度，详细追溯

**医疗器械订单：**

| 订单状态 | 对应的工序状态 |
|---------|---------------|
| 待打印 | 无工序记录 |
| 打印中 | 打印工序：进行中 |
| 打印完成 | 打印工序：已完成 |
| 后处理中 | 后处理工序按顺序执行，当前工序进行中，前置工序已完成（不允许并行） |
| 质检中 | 所有工序：已完成，质检进行中 |
| 包装中 | 所有工序：已完成，质检完成，包装进行中 |
| 入库中 | 所有工序：已完成，包装完成，等待入库 |
| 已完成 | 所有工序：已完成，已入库 |

**非医疗器械订单：**

| 订单状态 | 对应的工序状态 |
|---------|---------------|
| 待打印 | 无工序记录 |
| 打印中 | 打印工序：进行中 |
| 打印完成 | 打印工序：已完成 |
| 质检中 | 打印工序：已完成，质检进行中 |
| 包装中 | 打印工序：已完成，质检完成，包装进行中 |
| 入库中 | 打印工序：已完成，包装完成，等待入库 |
| 已完成 | 所有工序：已完成，已入库 |

## 七、数据模型说明

### 7.1 核心表结构

生产模块包含6个核心表：

| 表名 | 说明 | 关键字段 |
|------|------|---------|
| production_record | 生产流转卡表 | 流转卡编号、订单ID、数据包ID、生产批号、状态、包装信息 |
| production_product | 生产产品记录表 | 产品编号、流转卡ID、UDI码、质检结果 |
| production_process | 工序记录表 | 流转卡ID、工序类型、设备、参数、检验结果 |
| production_process_product_result | 质检产品记录表 | 质检工序ID、产品ID、质检结果、重做次数 |
| production_process_transfer | 工序流转记录表 | 流转卡ID、来源工序、目标工序、扫码信息 |
| production_device | 生产设备表 | 设备编号、设备类型、状态、API配置 |

### 7.2 表关系说明

```
订单（order）
  └─ 设计数据包（design_data_package）
      └─ 生产流转卡（production_record）【1对1】
          ├─ 生产产品记录（production_product）【1对多】
          ├─ 工序记录（production_process）【1对多，根据订单类型动态创建】
          │   └─ 质检产品记录（production_process_product_result）【1对多，仅质检工序关联】
          └─ 工序流转记录（production_process_transfer）【1对多】

生产设备（production_device）
  ├─ 被流转卡引用（分配的打印机）
  └─ 被工序记录引用（各工序使用的设备）
```

**关键关系**：
- 一个数据包 → 一张流转卡
- 一张流转卡 → 多个产品（根据打印文件数量和打印数量）
- 一张流转卡 → 根据订单类型动态创建工序记录（医疗器械5条，非医疗器械2条）
- 一张流转卡 → 多条流转记录（每次工序流转一条）
- 包装信息存储在流转卡表字段上，不在工序表

## 八、关键业务规则

### 8.1 生产流转卡规则

| 规则编号 | 规则描述 | 约束条件 |
|---------|---------|---------|
| BR-001 | 一个数据包只能创建一张生产流转卡 | 数据包ID唯一 |
| BR-002 | 流转卡编号由系统自动生成，不可修改 | 使用编码生成器 |

### 8.2 产品编号规则

## 九、异常处理与返工流程

### 9.1 设备异常处理

| 异常情况 | 处理方式 | 责任人 |
|---------|---------|--------|
| 打印机状态推送超时 | 系统提示"设备状态未更新"，生产管理员手动更新设备状态或检查设备连接 | 生产管理员 |
| 设备连接断开 | 系统自动标记设备为离线（connectionStatus=0），生产管理员检查设备连接 | 生产管理员 |
| 设备状态异常 | 生产管理员手动更新设备状态（调用 PUT /basic/device/{id}/state 接口） | 生产管理员 |

**重要说明**：
- **系统不处理打印设备的物理异常**（材料耗尽、设备故障、打印失败等），全部由人工判断和处理
- 系统仅负责监听设备状态推送，自动更新订单状态
- 设备异常由生产员/生产管理员在现场判断，通过人工操作处理
- **状态更新优先级**：WebSocket推送为主，手动更新为辅。手动更新后若再收到推送，以推送为准（推送反映设备真实状态）

### 9.2 打印失败处理（简化）

**触发条件**：人工判断打印失败（材料耗尽、设备故障、打印中断、打印质量不合格等）

**处理方式**：

```
打印失败（人工判断）
  ↓
生产员/生产管理员选择处理方式：
  
  方式A：修复后继续（同一流转卡）
    - 修复设备/补充材料/调整参数
    - 继续打印
    - 流转卡保持不变，订单状态保持当前状态
    - 无需系统操作

  方式B：重新打印（创建新流转卡）
    - 原流转卡状态标记为 print_failed（终态，保留用于追溯）
    - 原产品编号作废
    - 创建新流转卡，生成新产品编号
    - 重新开始打印
    - 系统记录失败原因
```

**规则**：
- 系统不自动判断打印失败，由人工判断
- 原流转卡保留用于追溯
- 创建新流转卡时原产品编号作废
- 失败原因必须记录

#### 9.2.1 打印工序检验不合格

**触发条件**：打印完成，检验发现尺寸偏差、表面缺陷等

**检验粒度**：产品级别（逐个标记哪个产品不合格）

```
打印完成 → 逐个标记产品检验结果
  P001：合格
  P002：合格
  P003：不合格 → 填写原因
  ↓
对不合格产品（P003）选择处理方式：
  方式A：重新打印（调整参数）
    - 原流转卡状态标记为 abandoned（终态，保留用于追溯）
    - 原P003编号作废
    - 创建新流转卡，生成新产品编号
    - 调整打印参数，重新打印
  ↓
整批等待，直到所有产品处理完毕后继续流转
```

**规则**：打印不合格不能进入后处理；必须创建新流转卡，重新生成产品编号。

### 9.3 扫码异常处理

| 异常情况 | 处理方式 | 责任人 |
|---------|---------|--------|
| 二维码无法识别 | 提示重新扫描或手动输入流转卡编号 | 生产员 |
| 扫描错误的流转卡 | 提示错误，不允许流转 | 生产员 |
| 重复扫码 | 提示已处理，不允许重复流转 | 生产员 |
| 工序顺序错误 | 提示当前工序状态，不允许跳过工序 | 生产员 |

### 9.4 后处理工序重做记录【仅医疗器械】

**说明**：后处理工序采用批次粒度流转，重做为过程记录，不驱动流转逻辑。

```
工序完成 → 操作员确认整批结果
  全部OK → 直接扫码流转到下一工序
  有问题 → 现场重做有问题的产品 → 重做完成后填写重做记录 → 扫码流转
```

**重做记录内容**（填写在工序记录的备注字段）：
- 哪个产品有问题（产品编号）
- 问题描述
- 重做次数

**流转条件**：操作员主动扫码确认，无系统强制校验。

### 9.5 质检不合格处理（详细流程）

**触发条件**：质检员检验发现产品不合格

```
质检中 → 逐个扫描产品编号进行质检
  P001：pass → 生成UDI码（医疗器械）
  P002：pass → 生成UDI码（医疗器械）
  P003：redo → 填写不合格原因
  ↓
P003 标记 redo 后，由生产管理员指定从哪个工序重做：
  - 返回打印（问题严重，如尺寸偏差）
  - 返回某个后处理工序（问题轻微，如固化不足）【仅医疗器械】
  ↓
P003 重做完成 → 重新进入质检
  pass → 生成UDI码（医疗器械）
  ↓
所有产品均为 pass → 整批流转到包装
```

**规则**：
- 质检员只标记 pass/redo，不做路径决策
- 重做路径由生产管理员指定
- 所有产品均为 pass 后整批流转，不允许部分流转

### 9.6 不合格处理汇总

| 场景 | 谁操作 | 处理方式 | 流转卡变化 | 产品编号变化 |
|------|--------|---------|-----------|------------|
| 打印过程中失败（重新打印） | 生产员 | 废弃原流转卡，创建新流转卡 | 原卡标记 print_failed | 原编号作废，生成新编号 |
| 打印检验不合格（重新打印） | 生产员 | 废弃原流转卡，创建新流转卡 | 原卡标记 abandoned | 原编号作废，生成新编号 |
| 后处理工序有问题 | 操作员现场 | 现场重做，填写重做记录 | 原卡不变，继续流转 | 保留原编号 |
| 质检不合格 | 质检员标记，管理员指定路径 | redo 标记，重做后重新质检 | 原卡不变，等待重做完成 | 保留原编号 |

### 9.7 数据异常处理

| 异常情况 | 处理方式 | 责任人 |
|---------|---------|--------|
| 流转卡数据丢失 | 从备份恢复或手动补录 | 系统管理员 |
| 产品编号重复 | 系统拒绝，重新生成 | 系统自动 |
| 工序记录缺失 | 提示补充工序信息 | 生产员 |
| UDI生成失败 | 记录错误日志，重新生成 | 系统管理员 |

## 十、与其他模块的关系

### 10.1 与订单模块的关系

**数据依赖**：
- 生产模块读取订单基本信息（订单号、产品信息、客户信息、订单类型等）
- 生产模块更新订单状态（待打印 → 打印中 → ... → 已完成）

**业务关联**：
- 订单创建 → 设计审核通过 → 流转到生产模块
- 生产完成 → 订单状态更新为"已完成"

### 10.2 与设计模块的关系

**数据依赖**：
- 生产模块读取设计数据包信息（数据包编号、版本号、打印文件等）
- 生产模块读取打印文件列表（文件名、文件路径、打印数量等）
- 生产模块读取设计信息（材质、产品信息等）

**业务关联**：
- 设计审核通过 → 订单流转到生产模块（待打印）
- 生产模块下载打印文件（设计师上传的STL/3MF/OBJ文件）

### 10.3 与质检模块的关系

**数据依赖**：
- 质检模块读取生产流转卡信息（用于质检参考）
- 质检模块读取产品编号（用于产品识别）
- 生产模块记录质检结果（合格/不合格）

**业务关联**：
- 后处理完成（医疗器械）或打印完成（非医疗器械）→ 流转到质检模块
- 质检合格 → 生成UDI码（医疗器械）
- 质检不合格 → 返工（回到生产模块）

### 10.4 与仓储模块的关系

**数据依赖**：
- 仓储模块读取产品信息（产品编号、UDI码、数量等）
- 仓储模块读取流转卡信息（用于入库参考）

**业务关联**：
- 包装完成 → 流转到仓储模块（入库）
- 入库完成 → 订单状态更新为"已完成"

### 10.5 数据流转图

```
订单模块 → 设计模块 → 生产模块 → 质检模块 → 仓储模块
   ↓          ↓          ↓          ↓          ↓
订单信息   设计文件   流转卡     质检结果   入库记录
           数据包     产品编号   UDI码
           订单类型   包装信息
```

## 十三、总结

本需求分析文档（v3.0）详细描述了医工宝系统生产管理模块的完整需求，包括：

1. **核心概念**：生产流转卡（批次级别）、产品编号（产品级别）、UDI码（医疗器械标识）、包装环节（独立于工序）
2. **业务流程**：根据订单类型分叉的两条流程路径
   - 医疗器械：待打印 → 打印 → 后处理（3工序）→ 质检 → 包装 → 入库
   - 非医疗器械：待打印 → 打印 → 质检 → 包装 → 入库
3. **数据模型**：6个核心表的结构和关系，包装数据存储在流转卡表
4. **业务规则**：70+条业务规则，覆盖流转卡、产品编号、工序流转、质检强约束、包装、设备管理等
5. **异常处理**：设备异常、打印失败、扫码异常、质检异常等场景的处理方式
6. **模块关系**：与订单、设计、质检、仓储模块的数据依赖和业务关联

**关键特点**：
- 批次级别管理，以数据包为单位
- 逐工序填写，流转卡随产品流转
- 扫码流转，记录流转时间和责任人
- 产品级别追溯，每个产品有唯一编号和UDI码（医疗器械）
- 订单类型分叉，医疗器械与非医疗器械流程差异化
- 包装独立环节，质检强约束保证产品质量

本文档将作为后续设计和开发的依据。
