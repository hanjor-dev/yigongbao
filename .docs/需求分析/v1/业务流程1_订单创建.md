# 订单模块需求分析

## 一、文档概述

本文档详细描述医工宝系统**订单模块**的需求分析，包括订单分类、流程定义、角色权限等核心概念设计。

> **重要说明**：
> - 订单字段内容及操作流程待后续详细讨论
> - 本文档主要记录已确认的框架性内容

---

## 二、订单分类

### 2.1 分类定义

| 订单分类 | 说明 | 流程复杂度 |
|----------|------|------------|
| 医疗器械 | 个性化医疗器械定制生产 | 完整流程 |
| 非医疗器械 | 非个性化医疗器械或其他可简化生产的订单 | 简化流程 |
| 服务 | 仅提供设计服务，不涉及实物生产和交付 | 设计服务流程 |

### 2.2 流程差异对比

#### 2.2.1 医疗器械订单流程

```
订单创建 → 待审核 → 数据审核通过 → 设计中 → 设计完成 → 设计审核中 → 待打印 → 打印中 → 打印完成 → 后处理 → 质检中 → 入库中 → 已完成
                                      ↓
                                数据审核不通过 → 驳回修改 → 重新提交
```

#### 2.2.2 非医疗器械订单流程

```
订单创建 → 待审核 → 审核通过 → 提交生产任务单 → 生产模块（简化流程）
                      ↓
                审核不通过 → 驳回修改 → 重新提交
                                              ↓
                                        生产任务完成 → 订单完成
```

#### 2.2.3 服务订单流程

```
订单创建 → 待审核 → 审核通过 → 设计中 → 设计完成 → 提单人确认 → 已完成
                    ↓
              审核不通过 → 驳回修改 → 重新提交
```

#### 2.2.4 流程差异汇总

| 流程阶段 | 医疗器械 | 非医疗器械 | 服务 |
|----------|:--------:|:----------:|:----:|
| 订单创建 | ✓ | ✓ | ✓ |
| 待审核 | ✓ | ✓ | ✓ |
| 数据审核 | ✓ | ✓ | ✓ |
| 设计 | ✓ | - | ✓ |
| 设计审核 | ✓ | - | - |
| 提交生产任务单 | - | ✓ | - |
| 生产（打印/后处理/质检/入库） | ✓ | ✓ | - |
| 订单完成 | ✓ | ✓ | ✓（提单人确认） |

> **说明**：
> - **医疗器械订单**：需要经过完整的审核、设计、生产、质检流程
> - **非医疗器械订单**：创建订单后需要经过审核，审核通过后提交生产任务单，流转到生产模块
> - **服务订单**：创建订单后需要经过审核，审核通过后进入设计环节，设计完成后由提单人确认完成

### 2.3 模块归属

| 分类 | 模块归属 | 备注 |
|------|----------|------|
| 医疗器械订单 | 订单模块 | 标准订单流程 |
| 非医疗器械订单 | 订单模块 | 创建后转入生产模块 |
| 服务订单 | 订单模块 | 设计即完成 |
| 生产任务单 | 生产模块 | 生产模块内区分：医疗器械生产任务单 / 非医疗器械生产任务单 |

## 三、角色权限

### 3.1 可创建订单的角色

| 角色 | 账户分类 | 组织归属 | 说明 |
|------|----------|----------|------|
| 业务员 | 内部用户 | 经销商 | 负责订单开拓、客户维护 |
| 区域管理员 | 内部用户 | 经销商 | 管理下属业务员 |
| 公司管理员（一级） | 内部用户 | 生产企业 | 系统最高权限 |
| 公司管理员（二级） | 内部用户 | 生产企业 | 业务管理员 |
| 外部机构管理员 | 外部机构用户 | 经销商/医疗机构/其他 | 机构管理员 |
| 机构用户 | 外部机构用户 | 经销商/医疗机构/其他 | 机构普通用户 |

| 角色 | 数据范围 | 说明 |
|------|----------|------|
| 业务员 | self | 仅看自己创建的订单 |

### 4.3 订单创建流程

订单创建的具体操作步骤，包括基本信息填写、文件上传等环节。

#### 4.3.1 流程概述

```
填写订单基本信息 → 保存 → 关闭信息填写弹窗 → 弹出文件上传弹窗 → 上传影像数据/影像报告等文件 → 提交订单
```

> **说明**：保存订单基本信息后，必须上传相关文件（影像数据、影像报告等）后才能正式提交订单。

#### 4.3.2 基本信息填写

- 用户在订单信息填写弹窗中填写订单基本信息（参考 4.1 订单字段）
- 填写完成后，点击"保存"按钮

#### 4.3.3 文件上传弹窗

当用户点击"保存"后，系统执行以下操作：

1. **保存订单信息**：将填写的订单基本信息保存到数据库（状态为"草稿"或"待提交"）
2. **关闭信息填写弹窗**：自动关闭当前的信息填写弹窗
3. **弹出文件上传弹窗**：自动弹出新的文件上传弹窗

#### 4.3.4 文件上传要求

|| 文件类型 | 说明 | 必填 |
|----------|--------|------|
|| 影像数据 | 患者的影像资料（如CT、MRI等） | ✓ 必填 |
|| 影像报告 | 医生出具的影像分析报告 | ✓ 必填 |
|| 其他附件 | 其他相关资料 | 可选 |

> **说明**：不同订单类型可能需要不同类型的文件，具体文件要求可在后台配置。

#### 4.3.5 文件上传操作

|| 操作 | 说明 |
||------|------|
|| 选择文件 | 点击选择本地文件进行上传 |
|| 上传进度 | 显示文件上传进度 |
|| 上传结果 | 成功/失败提示 |
|| 删除文件 | 已上传的文件可删除 |

#### 4.3.6 提交订单

- 当必填文件（影像数据、影像报告）均已上传完成后，"提交"按钮变为可用
- 用户点击"提交"后，订单状态变为"待审核"
- 如有未上传的文件，系统提示用户

#### 4.3.7 取消操作

- 用户点击"取消"按钮时，询问用户是否保存为草稿
- 选择"是"：保存为草稿，关闭弹窗
- 选择"否"：不保存，直接关闭弹窗

### 4.4 草稿功能

订单创建过程中的草稿暂存功能。

#### 4.4.1 草稿应用场景

| 场景 | 说明 |
|------|------|
| 信息不完整 | 订单信息填写到一半，当前无法继续完成提交 |
| 临时中断 | 用户需要处理其他事项，稍后回来继续 |

#### 4.4.2 草稿存储方式

- **服务端存储**：使用独立的草稿表，不占用业务订单流水号
- 草稿数据与正式订单数据分离管理

#### 4.4.3 草稿保存机制

- 采用**手动保存**方式，用户主动点击"保存草稿"按钮
- 草稿保存成功时给予用户明确提示

#### 4.4.4 草稿列表与管理

| 功能 | 说明 |
|------|------|
| 草稿列表 | 显示用户暂存的所有草稿订单 |
| 草稿信息 | 显示草稿创建时间、订单分类、关联医院等关键信息 |
| 恢复草稿 | 点击后可继续编辑未完成的订单 |
| 删除草稿 | 用户可手动删除不需要的草稿 |
| 草稿有效期 | 超过30天未使用的草稿自动清理 |

#### 4.4.5 草稿权限

- 仅订单创建者本人可以查看和操作自己的草稿
- 其他用户无权访问他人草稿

### 4.5 订单审核

订单提交后的审核功能，适用于**所有类型订单**（医疗器械、非医疗器械、服务）。

#### 4.5.1 审核角色

|| 角色 | 审核权限 |
||------|----------|
|| 公司管理员 | ✓ 可审核 |
|| 业务管理员 | ✓ 可审核 |

> **说明**：审核角色在开发阶段可视实际情况调整。

#### 4.5.2 审核操作

|| 操作 | 说明 |
||------|------|
|| 审核通过 | 订单进入下一流程（根据订单类型进入对应流程） |
|| 审核不通过 | 填写驳回原因，订单变为"审核被拒"状态 |

#### 4.5.3 驳回原因

- 审核不通过时，**必须**填写驳回原因
- 驳回原因将记录在订单中，供创建者查看

#### 4.5.4 审核被拒订单的处理

- **审核被拒状态的订单**：创建者可以进行编辑修改
- 修改完成后：重新提交 → 再次进入"待审核"状态

#### 4.5.5 审核状态流转

```
┌─────────────┐     审核通过      ┌─────────────┐
│  待审核     │ ──────────────→  │ 数据审核通过│
└─────────────┘                   └─────────────┘
        ↑
        │ 审核不通过 + 填写驳回原因
        │
┌─────────────┐     修改后重新提交
│  审核被拒   │ ─────────────────→ 待审核
└─────────────┘
```

#### 4.5.6 审核信息记录

|| 字段 | 说明 |
|------|------|
|| 审核时间 | 系统自动记录 |
|| 审核人 | 系统自动记录当前审核者 |
|| 审核结果 | 通过/不通过 |
|| 驳回原因 | 审核不通过时必填 |

### 4.6 订单信息修改申请审核

订单在审核通过后，如需进行修改，可通过"订单修改申请"功能实现。该功能是对已提交的订单在后续阶段需要修改时的审核流程。

> **说明**：此功能与 4.5 订单审核的区别：
> - 4.5 订单审核：订单创建时的首次审核（待审核 → 数据审核通过/不通过）
> - 4.6 订单信息修改申请审核：订单在后续阶段（设计中、生产中、完成后等）需要修改字段内容比如患者名/医生名等信息时的审核

#### 4.6.1 功能开关

- 后台可配置是否启用"订单信息修改申请"功能
- 当功能**关闭**时，按 4.7.2 修改权限约束执行

#### 4.6.2 可申请的修改范围

所有类型订单在审核通过后的任意阶段均可申请修改。

|| 订单状态 | 是否可申请修改 |
|:--------:|:----------:|
|| 待审核 | ✓ 可（创建者在预设时间内直接修改重新提交，无需申请） |
|| 审核被拒 | ✓ 可（创建者直接修改重新提交，无需申请） |
|| 审核通过后的任意阶段 | ✓ 可申请修改 |

> **说明**：
> - 医疗器械订单：在数据审核通过、设计中、设计完成、待打印、打印中、打印完成、后处理、质检中、入库中、已完成等阶段均可申请修改
> - 非医疗器械订单：在审核通过后、提交生产任务单、生产中、生产完成等阶段均可申请修改
> - 服务订单：在审核通过后、设计中、设计完成、提单人确认、已完成等阶段均可申请修改

#### 4.6.3 申请流程

```
业务员填写修改内容/理由 → 管理员审核 → 审核通过后允许修改
```

|| 步骤 | 说明 |
|:----:|------|
|| 1. 发起申请 | 业务员选择需要修改的字段，填写修改内容和修改理由 |
|| 2. 提交申请 | 提交后进入"待审核"状态 |
|| 3. 管理员审核 | 审核通过/拒绝 |
|| 4. 审核通过 | 业务员可修改订单 |
|| 5. 审核拒绝 | 申请结束，业务员可重新发起申请 |

#### 4.6.4 审核角色

|| 角色 | 审核权限 |
||------|----------|
|| 公司管理员 | ✓ 可审核 |
|| 业务管理员 | ✓ 可审核 |

#### 4.6.5 审核操作

|| 操作 | 说明 |
||------|------|
|| 审核通过 | 允许业务员修改订单 |
|| 审核不通过 | 填写驳回原因，申请结束 |

#### 4.6.6 申请信息记录

|| 字段 | 说明 |
|------|------|
|| 申请编号 | 系统自动生成唯一流水号 |
|| 申请人 | 系统自动记录 |
|| 申请时间 | 系统自动记录 |
|| 申请修改的字段 | 记录需要修改哪些字段 |
|| 修改前值 | 记录字段原值 |
|| 修改后值 | 记录期望修改的值 |
|| 修改理由 | 申请人填写 |
|| 审核状态 | 待审核/通过/拒绝 |
|| 审核时间 | 系统自动记录 |
|| 审核人 | 系统自动记录 |
|| 驳回原因 | 审核不通过时必填 |

#### 4.6.7 审核通过后的修改

- 审核通过后，业务员可在订单详情页面修改申请中指定的字段
- 修改完成后，订单状态保持不变
- 系统记录修改前后的值，形成留痕

#### 4.6.8 修改留痕

|| 字段 | 说明 |
|------|------|
|| 修改记录ID | 系统自动生成 |
|| 修改字段 | 字段名称 |
|| 修改前值 | 修改前的值 |
|| 修改后值 | 修改后的值 |
|| 修改人 | 系统自动记录 |
|| 修改时间 | 系统自动记录 |

### 4.7 订单约束条件

#### 4.7.1 删除约束

- **提交后的订单不允许任何角色删除**
- 草稿状态下的订单仅创建者可删除

#### 4.7.2 修改权限约束

| 角色 | 修改权限 | 可修改字段 |
|------|----------|------------|
| 业务员/区域管理员 | 提交后10分钟内可修改 | 所有字段（待确认） |
| 设计管理员 | 可修改部分字段 | 所需部位、重建项目、项目说明 |
| 公司管理员 | 可修改所有信息 | 全部字段 |

##### 4.7.2.1 订单修改申请功能

当订单修改申请功能**开启**时，没有直接修改订单权限的账户（如业务员）如需修改已提交的订单，必须发起修改申请。

| 内容 | 说明 |
|------|------|
| 功能开关 | 后台可配置是否启用 |
| 申请流程 | 业务员填写修改内容或理由 → 管理员审核 → 审核通过后才允许修改 |
| 申请信息 | 修改内容、修改理由等 |
| 审核流程 | 管理员审核通过/拒绝 |

当功能**关闭**时，按上述角色默认权限执行或可直接进行权限范围内的内容修改。

#### 4.7.3 订单确认链接分享功能

| 功能 | 说明 |
|------|------|
| 触发时机 | 填写好订单创建信息后，或在草稿状态/已提交待审核状态下 |
| 分享内容 | 生成订单确认链接，可发给客户或业务员确认 |
| 链接有效期 | 默认1天，可后台配置 |
| 身份验证 | 无需身份验证（公开链接） |
| 链接操作 | 仅支持查看订单信息 + 点击确认 |

> **确认后操作**：客户点击确认后，系统通知订单创建者可以进行正式创建或修改
