# 工单设计阶段需求分析

## 一、文档概述

本文档描述医工宝系统**订单模块中设计阶段**的需求分析，包括设计师操作流程、设计审核、不需要实体交付订单特殊处理等内容。

> **重要说明**：
> - 订单是唯一的数据实体，贯穿整个业务流程
> - 「工单」是订单在设计阶段的**状态表现**，并非独立数据
> - 设计师操作的「我的工单」列表 = 状态为「待设计/设计中」的订单列表
> - 设计阶段处理所有类型订单：医疗器械（非实体交付/需实体交付）、非医疗器械（非实体交付/需实体交付）
> - 所有类型订单都需要经过设计审核（审核通过后根据是否需要实体交付进入不同流程）

---

## 三、编号规则设计

### 3.1 编号类型汇总

| 编号名称 | 说明 | 生成时机 | 规则说明 |
|----------|------|----------|----------|
| 订单流水号（订单编号） | 订单的唯一标识 | 订单提交后 | 系统编码生成器生成，支持配置规则 |
| 数据包编号（packageCode） | 打印文件数据包的唯一标识 | 上传打印文件包时 | 系统编码生成器生成（`DATA_PACKAGE_NO` 规则） |
| 影像数据包编号 | 影像数据包的唯一标识 | 上传影像资料时 | 系统编码生成器生成 |
| 产品编码（UDI码） | 生产环节生成 | 每个重建项目一个UDI，设计阶段仅记录产品标识用于追溯，生产环节生成 |

### 3.2 指令单与图纸的文件命名

指令单和图纸**不单独设置编号**，以文件名区分：

| 文件 | 命名规则 | 示例 |
|------|----------|------|
| 指令单 | `指令单-{数据包编号}.xlsx` | `指令单-PKG20260310001.xlsx` |
| 图纸 | `图纸-{数据包编号}.xlsx` | `图纸-PKG20260310001.xlsx` |

> **说明**：每个打印文件数据包对应一份指令单和一份图纸，以数据包编号区分，无独立的 ZL/TZ 编号。

### 3.3 版本号规则

指令单和图纸均采用**封版策略**管理版本，版本号格式为 `A/{序号}`：

| 情形 | 版本号 | 说明 |
|------|--------|------|
| 首次生成 | `A/1` | 新建版本记录，序号从1开始 |
| 再次生成（未封版） | `A/1`（不变） | 覆盖当前版本的模板文件，版本号不变 |
| 上传修订版后再次生成 | `A/2` | 修订版上传代表封版，新建版本，序号+1 |
| 再次封版后继续生成 | `A/3` | 依此类推 |

**封版条件**：上传修订版文件（`upload-revised`）后，该版本记录的 `revisedFileId` 非空，视为已封版，下次生成时才新建版本号。

### 3.4 编码生成器设计

系统提供统一的编码生成器，支持按配置规则自动生成各类编号。

**编码生成器能力**：

| 能力 | 说明 |
|------|------|
| 前缀配置 | 支持配置固定前缀 |
| 日期格式 | 支持配置日期格式（年、月、日等） |
| 流水号位数 | 支持配置流水号位数（4-8位） |
| 起始值 | 支持配置起始值 |
| 步长 | 支持配置递增步长 |
| 分隔符 | 支持配置分隔符（-、_等） |

## 四、设计师操作步骤详解

### 第1步：接收待处理订单

**触发条件**：订单审核通过后（数据审核通过），系统自动/手动分配给设计师

**适用订单类型**：「医疗器械（需实体交付/不需实体交付）」、「非医疗器械（需实体交付/不需实体交付）」

> **说明**：此时订单状态变为「待设计」

**设计师操作**：

1. 在「我的工单」（待设计订单列表）中查看待处理订单
2. 可以看到订单基本信息：订单流水号（订单编号）、患者姓名、部位、项目、期望交付时间等

**系统行为**：

- 订单状态显示为「待设计」
- 系统推送消息通知设计师有新订单待处理

**订单分配方式**：

| 方式 | 说明 |
|------|------|
| 自动分配 | 按设计师专业方向（部位）、负载均衡、随机、轮询等规则自动匹配 |
| 手动分配 | 管理员手动指定设计师 |

**设计师查看的订单列表**：

```
我的工单列表 = 订单状态为「待设计」或「设计中」的订单
```

### 第3步：开始设计

**设计师操作**：

1. 点击「开始设计」按钮
2. 订单状态从「待设计」变为「设计中」

> **说明**：
> - 「开始设计」按钮用于标记设计师正式开始处理此订单
> - 系统记录设计开始时间，用于后续工时统计

---

### 第4步：上传设计文件

**设计师操作**：

点击「上传设计文件」按钮，上传以下文件：

| 文件类型 | 说明 | 必填 | 格式要求 |
|----------|------|:----:|----------|
| 打印文件（数据包） | 用于3D打印的设计文件包，**每个数据包对应一份指令单和一份图纸** | ✓ 是 | **ZIP格式**（包含STL/3MF/OBJ等打印文件） |
| 设计报告 | 设计说明、设计参数等 | ✓ 是（提交前必须上传） | PDF/Word |
| 可视化模型 | 用于展示的三维模型 | ✓ 是（提交前必须上传） | 3DPDF/PLY/STL等 |

**操作说明**：

- 打印文件（数据包）为必填，**每个数据包单独上传**，系统按编码规则自动生成数据包编号
- **重要**：一个订单可以上传多个打印文件数据包，**每个数据包对应生成一份指令单和一份图纸**
- 设计报告和可视化模型在提交前也是必填项（缺失会阻止提交）
- 上传成功后显示文件列表（文件名、大小、上传时间、数据包编号）

**打印文件数据包内部结构**：

上传 ZIP 压缩包后，系统自动解析包内文件，每个文件（如 STL/3MF 等）成为一条 `design_package_file` 记录，后续打印产品信息的填写以包内文件为粒度关联。

---

### 第5步：填写打印信息

**设计师操作**：

点击「填写打印信息」按钮，按**数据包**维度填写。每个数据包下可有多个打印产品（`design_product`），每条产品记录对应指令单中的一行。每个产品可关联包内的一个或多个文件（`design_product_file`），每个关联文件在 Excel 中对应一行。

#### 5.1 系统自动填充（订单级，无需手动填写）

| 字段 | 数据来源 | 说明 |
|------|----------|------|
| 订单流水号（订单编号） | 订单.订单流水号 | 订单提交后系统自动生成 |
| 打印文件数据包编号 | design_package.packageCode | 上传打印文件包时自动生成 |
| 客户 | 订单.提单机构.机构名称 | 订单提单机构自动带出 |
| 联系人 | 订单.doctorName | 取医生姓名（指令单"联系人"字段） |
| 医院 | 订单.医院.医院名称 | 订单信息自动带出 |
| 预交货时间 | 订单.期望交付时间 | 订单时效要求自动带出 |
| 患者姓名 | 订单.患者.姓名 | 订单信息自动带出 |
| 是否邮寄 | 订单.是否邮寄 | 订单信息自动带出 |
| 邮寄地址 | 订单.邮寄地址 | 仅当订单.是否邮寄="是"时显示 |

#### 5.2 设计师按打印产品填写（生产产品信息列表）

每个数据包下，设计师需**为每个打印产品填写一行**。每行字段如下：

| 字段 | 填写要求 | 说明 |
|------|----------|------|
| 产品名称 | 必填，从下拉列表选择 | 后台产品型号管理维护 |
| 型号规格 | 必填，从下拉列表选择 | 根据所选产品名称动态显示 |
| 材质 | 必填，从下拉列表选择 | 与产品型号关联 |
| 颜色 | 必填，从下拉列表选择 | 与产品型号关联 |
| 注册证号 | 必填，从下拉列表选择 | 与产品型号关联 |
| 数量 | 必填，数字 | 本产品的生产数量 |
| 时效 | 必填 | 普通（0）或加急（1），影响指令单对应行显示 |
| 关联包内文件 | 必填，可多选 | 从该数据包内文件列表中勾选，每个文件对应指令单一行 |

> **产品型号级联关系**（每条产品行内）：
> ```
> 选择产品名称 → 自动带出可选型号规格
>                → 选择型号规格后，自动带出可选材质、颜色、注册证号
> ```

#### 5.3 数据包级补充信息

| 字段 | 填写要求 | 说明 |
|------|----------|------|
| 产品标识 | 选填 | 用于产品追溯，写入指令单底部 |
| 包装数量 | 选填 | 写入指令单底部 |
| 备注 | 选填 | 写入指令单备注区域 |

**填写完成后**：

- 点击「保存」按钮保存打印信息
- 可随时修改、增删行
- **注意**：修改或删除打印信息后，该数据包已生成的指令单和图纸的确认状态会自动重置（`isConfirmed=0`），需重新确认后方可提交

---

### 第6步：生成指令单/图纸并确认

**设计师操作**：

系统根据订单信息和填写的打印产品信息，自动生成指令单和图纸（Excel 格式）。生成后，设计师须审阅并确认文件内容，才允许提交。

> **重要说明**：一个订单可以有多个数据包，**每个数据包分别生成一份指令单和一份图纸**。

#### 6.1 生成指令单

点击「生成指令单」按钮，系统根据 Excel 模板自动填充并生成。

**每份指令单包含内容**（模板结构）：

| 区域 | 字段 | 数据来源 |
|------|------|----------|
| 表头 | 版本号 | 当前版本号（如 `A/1`） |
| **基本信息** | 订单编号 | 订单.订单流水号 |
| 基本信息 | 客户 | 订单.提单机构.机构名称 |
| 基本信息 | 联系人 | 订单.doctorName（医生姓名） |
| 基本信息 | 打印文件数据包编号 | design_package.packageCode |
| 基本信息 | 医院 | 订单.医院.医院名称 |
| 基本信息 | 预交货时间 | 订单.期望交付时间 |
| **生产产品信息（表格，多行）** | 序号 | 系统按行自动编号（1,2,3…） |
| 生产产品信息 | 注册证编号 | design_product.certNo |
| 生产产品信息 | 产品名称 | design_product.productName |
| 生产产品信息 | 数据文件名称 | design_product_file 关联的包内文件名 |
| 生产产品信息 | 型号/规格 | design_product.specName |
| 生产产品信息 | 材质 | design_product.materialName |
| 生产产品信息 | 数量 | design_product.quantity |
| 生产产品信息 | 时效 | design_product.isUrgent（0=普通/1=加急） |
| 生产产品信息 | 颜色 | design_product.colorName |
| **底部信息** | 产品标识 | design_package.productMark |
| 底部信息 | 包装数量 | design_package.packQuantity |
| 底部信息 | 患者姓名 | 订单.患者.姓名 |
| 底部信息 | 是否邮寄 | 订单.是否邮寄 |
| 底部信息 | 邮寄地址 | 订单.邮寄地址 |
| 底部信息 | 备注 | design_package.remark |
| **签批** | 指令/日期、复核/日期 | 签名行（设计阶段留白） |

**版本管理**：

- 指令单版本序号独立于图纸版本序号
- 首次生成：`A/1`；上传修订版后再次生成：`A/2`，以此类推
- 重新生成未封版的指令单只更新模板文件，版本号不变

#### 6.2 生成图纸

点击「生成图纸」按钮，系统根据内置 Excel 模板自动生成图纸。

**图纸生成规则**：

- 每个打印文件数据包生成一份图纸（Excel 文件）
- 图纸包含多个槽位（模板支持最多11个内容格位），每个槽位对应一个产品×文件组合
- 若产品文件组合超过11条，**自动分页**（同一 Excel 文件中生成 Sheet2、Sheet3…）
- 分页后每页底部标注「第X页/共Y页」——**X = 当前 Sheet 序号，Y = 该 Excel 文件的总 Sheet 数**（表示同一份图纸文件内的页数，与订单数据包总数无关）

**图纸内容**（以实际 Excel 模板为准）：

| 区域/位置 | 字段 | 说明与数据来源 |
|-----------|------|----------------|
| **主体格位（多槽）** | 序号 | 自动编号（1、2、3…） |
| 主体格位 | 文件名称 | 包内文件名（design_package_file.fileName） |
| 主体格位 | 产品名称 | design_product.productName |
| 主体格位 | **截图图片区** | 若已上传在线标注截图，自动嵌入；否则留空 |
| **右上角** | 二维码区域 | 预留，系统配置链接 |
| **底部信息区** | 订单编号 | 订单.订单流水号 |
| 底部信息区 | 数据包编号 | design_package.packageCode |
| 底部信息区 | 设计/日期 | 签名行（留白） |
| 底部信息区 | 审批/日期 | 签名行（留白） |
| 底部信息区 | 第X页/共Y页 | X=当前页，Y=本文件总页数 |
| 底部信息区 | 生产机构名称 | 系统配置 |

**在线截图功能**（可选路径）：

系统支持在线 viewer 中查看3D模型、完成标注后截图，截图与对应包内文件绑定（每个文件最多一张有效截图，新截图覆盖旧截图）。生成图纸时，后端自动将截图嵌入对应槽位的图片区域。

截图不做格式校验，PNG/JPG均支持。截图下载失败时，该槽位图片区留空，图纸照常生成。

#### 6.3 文件确认机制

生成指令单/图纸后，文件处于「未确认」状态（`isConfirmed=0`）。设计师须确认文件内容方可提交，**确认有以下两条等价路径**：

| 路径 | 操作 | 确认状态变化 |
|------|------|-------------|
| **路径A（离线路径）** | 上传修订版文件（`upload-revised`） | 自动置 `isConfirmed=1` |
| **路径B（在线路径）** | 调用手动确认接口（`POST .../confirm/{id}`） | 置 `isConfirmed=1` |

两条路径**可并存**，无需区分模式。上传修订版是在线部署时的有效兜底方案（即使配置了在线 viewer，若标注效果不理想，仍可线下修改后上传修订版）。

**确认状态重置时机**：

| 触发动作 | 重置范围 |
|----------|----------|
| 重新生成指令单/图纸 | 当前版本 `isConfirmed` 重置为0 |
| 保存或删除打印信息 | 该数据包下所有版本的指令单和图纸 `isConfirmed` 重置为0 |

> **`design.mode` 配置说明**：系统支持 `design.mode` 配置项（如 `online`/`offline`），该配置**仅供前端 UI 使用**（如是否显示在线 viewer 入口），**后端不依赖此配置做任何分支处理**。不管哪种模式，两条确认路径均始终可用，提交校验也始终检查 `isConfirmed` 字段。

#### 6.4 版本列表与下载

每次生成操作均产生或更新版本记录，历史版本均保留。版本列表接口返回各版本的模板文件（`templateFileId`）和修订版文件（`revisedFileId`，可为空）供前端下载。

文件下载统一通过 `GET /basic/file/download/{fileId}` 完成，设计模块无独立下载接口。

### 第7步：提交设计

**设计师操作**：

当以上步骤完成后，点击「提交设计」按钮。

**提交条件检查（9项）**：

| # | 检查项（字段） | 要求 | 不满足时提示 |
|---|----------------|------|-------------|
| 1 | `hasPackage` | 已上传至少一个打印文件数据包 | 请先上传打印文件数据包 |
| 2 | `hasPrintInfo` | 每个数据包下至少填写一条打印产品信息 | 请完善数据包的打印信息 |
| 3 | `hasInstruction` | 每个数据包均已生成指令单 | 请生成指令单 |
| 4 | `hasDrawing` | 每个数据包均已生成图纸 | 请生成图纸 |
| 5 | `hasModel` | 可视化模型文件已上传 | 请上传可视化模型文件 |
| 6 | `hasReport` | 设计报告已上传 | 请上传设计报告 |
| 7 | `hasRevisedDocs` | 保留字段，始终为 true，不参与校验（已废弃） | — |
| 8 | `hasDrawingConfirmed` | 每个数据包最新版图纸 `isConfirmed=1` | 请确认图纸 |
| 9 | `hasInstructionConfirmed` | 每个数据包最新版指令单 `isConfirmed=1` | 请确认指令单 |

> 第7项 `hasRevisedDocs` 已废弃，始终返回 `true`，不阻止提交（原用于检查修订版文件是否上传，现已由第8、9项图纸/指令单确认替代）。

**提交后**：

- 订单状态从「设计中」变为「设计审核中」
- 系统自动创建一条「设计审核」任务，分配给审核人员

## 五、设计审核流程

### 5.1 审核角色

设计师提交设计后，需要进行设计审核，审核角色包括：

| 角色 | 审核权限 |
|------|----------|
| 设计管理员 | ✓ 可审核 |
| 业务管理员 | ✓ 可审核 |
| 系统管理员 | ✓ 可审核 |

### 5.2 审核操作

审核人员在「设计审核」任务列表中点击订单进行审核：

| 操作 | 说明 |
|------|------|
| 审核通过 | 填写审批意见，订单自动进入「待打印」状态（需实体交付）或「待客户确认」状态（不需实体交付） |
| 审核不通过 | 填写驳回原因，订单状态变为「设计审核不通过」，设计师可继续修改后重新提交 |

### 5.3 驳回处理

如果审核不通过：

1. 设计师收到驳回通知
2. 查看驳回原因
3. 点击「继续修改」按钮，订单状态从「设计审核不通过」恢复为「设计中」
4. 修改设计文件/打印信息/指令单/图纸
5. 重新确认指令单和图纸（`isConfirmed=1`）
6. 重新点击「提交设计」，再次进入「设计审核中」状态

### 5.4 审核信息记录

| 字段 | 说明 |
|------|------|
| 审核时间 | 系统自动记录 |
| 审核人 | 系统自动记录（当前登录用户） |
| 审核结果 | 通过/不通过 |
| 审批意见 | 审核通过时填写（可选） |
| 驳回原因 | 审核不通过时必填 |

## 六、不需要实体交付订单特殊处理

### 6.1 什么是"不需要实体交付"订单

不需要实体交付订单 = 仅提供设计服务，不涉及实物生产和交付（即原旧版"服务订单"的概念）

### 6.2 不需要实体交付订单流程

```
设计中 → 设计审核中 → 设计审核通过 → 待客户确认 → 已完成
                           ↓
                  业务员点击「确认完成」按钮
```

> **说明**：不需要实体交付的订单同样需要经过设计审核环节。审核通过后进入「待客户确认」状态，由提单人确认后订单完成。

### 6.3 确认操作

| 项目 | 说明 |
|------|------|
| 触发条件 | 设计成果已完成，服务订单需要提单人确认 |
| 操作角色 | 业务员/区域管理员/经销商（订单创建者） |
| 操作动作 | 在订单详情点击「确认完成」按钮 |
| 状态变更 | 待客户确认 → 已完成 |
| 确认记录 | 确认时间、确认人自动记录 |

## 七、流程图汇总

### 7.1 订单状态流转总览

```
┌──────────┐    数据审核通过     ┌──────────┐
│  待设计   │ ─────────────────→│  设计中   │
└──────────┘                    └──────────┘
                                        │
                                  提交设计
                                        ↓
                                 ┌─────────────┐
                                 │ 设计审核中   │
                                 └─────────────┘
                                        │
                    ┌───────────────────┼───────────────────┐
                    ↓                                       ↓
          ┌─────────────────┐                     ┌─────────────────┐
          │ 审核通过：       │                     │ 审核不通过：     │
          │ 待打印（需实体）  │                     │ 设计审核不通过   │
          │ 待客户确认（不需）│                     │ → 继续修改 →    │
          └─────────────────┘                     │    设计中        │
                                                  └─────────────────┘
```

### 7.2 需要实体交付订单 - 完整流程（医疗器械/非医疗器械）

```
订单 → 数据待审核 → 数据审核通过 → 待设计 → 设计中 → 设计审核中 → 设计审核通过 → 待打印 → 打印中 → 打印完成 → 后处理中 → 质检中 → 入库中 → 已完成
```

### 7.3 设计阶段确认流程

```
生成指令单/图纸（isConfirmed=0）
        │
        ├─ 路径A：下载文件，线下修改后上传修订版
        │         → 系统自动置 isConfirmed=1
        │
        └─ 路径B：在线审阅满意后，调用确认接口
                  → 手动置 isConfirmed=1
                  
（两路径等价，均满足提交条件）

保存/删除打印信息 → 重置 isConfirmed=0（需重新确认）
重新生成文件     → 重置 isConfirmed=0（需重新确认）
```

```
order（订单）
  └── design_package（打印文件数据包，一对多）

## 十、电子签名功能（规划中，当前版本未实现）

> **当前状态**：电子签名功能在当前版本中**尚未实现**，以下内容为规划阶段的需求描述，供后续版本参考。当前指令单和图纸的签批区域（设计/日期、复核/日期）在生成时留空，需手工填写。

### 10.1 设计目标

电子签名用于在设计阶段生成的指令单和图纸文档上进行签名确认，确保文档的真实性和可追溯性。

### 10.2 签名角色

| 角色 | 签名场景 | 签名时机 |
|------|----------|----------|
| 设计师 | 设计文档签名 | 提交设计审核时自动签章 |
| 审核人员 | 设计文档签名 | 审核通过时自动签章 |

### 10.3 签名预设（账户设置）

每位设计师和审核人员需在账户设置中预设签名图片（支持上传手写签名、网页绘制、字体生成）。

### 10.4 防伪与追溯

签名记录包含：签名人、签名时间、签名IP、文档关联、审批意见等，支持完整链路追溯。
