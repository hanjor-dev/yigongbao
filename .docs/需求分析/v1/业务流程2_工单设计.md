# 工单设计阶段需求分析

## 一、文档概述

本文档描述医工宝系统**订单模块中设计阶段**的需求分析，包括设计师操作流程、设计审核、不需要实体交付订单特殊处理等内容。

> **重要说明**：
> - 订单是唯一的数据实体，贯穿整个业务流程
> - 「工单」是订单在设计阶段的**状态表现**，并非独立数据
> - 设计师操作的「我的工单」列表 = 状态为「待设计/设计中」的订单列表
> - 设计阶段处理所有类型订单：医疗器械（非实体交付/需实体交付）、非医疗器械（非实体交付/需实体交付）
> - 所有类型订单都需要经过设计审核（审核通过后根据是否需要实体交付进入不同流程）

---

## 二、设计师操作流程概览

```
┌────────────────────────────────────────────────────────────────────────────────┐
│                           设计师订单处理流程                                      │
├────────────────────────────────────────────────────────────────────────────────┤
│                                                                                │
│   第1步        第2步        第3步        第4步        第5步        第6步     │
│   ┌───┐       ┌───┐       ┌───┐       ┌───┐       ┌───┐       ┌───┐          │
│   │接单│   →   │查看│   →   │开始│   →   │上传│   →   │填写│   →   │提交│          │
│   └───┘       └───┘       └───┘       └───┘       └───┘       └───┘          │
│                                                                                │

```

> **说明**：设计师共需执行6个步骤，其中第5步包含「填写打印信息」和「生成指令单/图纸」两个子操作。

## 三、编号规则设计

### 3.1 编号类型汇总

| 编号名称 | 说明 | 生成时机 | 规则说明 |
|----------|------|----------|----------|
| 订单流水号（订单编号） | 订单的唯一标识 | 订单提交后 | 系统编码生成器生成，支持配置规则 |
| 指令单编号 | 生产指令单的唯一标识 | 设计师生成指令单时 | 规则：ZL-{订单流水号}-{序号}（一个订单可生成多份指令单，按数据包序号编排） |
| 数据包编号 | 打印文件数据包的唯一标识 | 上传打印文件包时 | 规则：{订单流水号}-{序号}（每个打印文件包一个编号） |
| 影像数据包编号 | 影像数据包的唯一标识 | 上传影像资料时 | 系统编码生成器生成 |
| 产品编码（UDI码） | 生产环节生成 | 每个重建项目一个UDI，设计阶段仅记录产品标识用于追溯，生产环节生成 |
| 图纸编号 | 设计图纸的唯一标识 | 生成图纸时 | 规则：TZ-{订单流水号} |

### 3.2 编码生成器设计

系统提供统一的编码生成器，支持按配置规则自动生成各类编号。

**编码生成器能力**：

| 能力 | 说明 |
|------|------|
| 前缀配置 | 支持配置固定前缀（如 ZL、TZ） |
| 日期格式 | 支持配置日期格式（年、月、日等） |
| 流水号位数 | 支持配置流水号位数（4-8位） |
| 起始值 | 支持配置起始值 |
| 步长 | 支持配置递增步长 |
| 分隔符 | 支持配置分隔符（-、_等） |

**编码规则配置示例**：

| 编号类型 | 规则配置 | 生成示例 |
|----------|----------|----------|
| 订单流水号 | {年}{月}{日}-{6位流水} | 20260310-000001 |
| 打印文件数据包编号 | {订单流水号}-{序号} | 20260310-000001-1、20260310-000001-2 |
| 指令单编号 | ZL-{订单流水号}-{序号} | ZL-20260310-000001-1、ZL-20260310-000001-2 |
| 影像数据包编号 | SJB-{年}{月}{日}-{4位流水} | SJB-20260310-0001 |
| 图纸编号 | TZ-{订单流水号}-{序号} | TZ-20260310-000001-1、TZ-20260310-000001-2 |
| 产品编码（UDI） | 生产环节根据产品型号配置规则生成的唯一器械编码 | 详见产生产管理模块 |

## 四、设计师操作步骤详解

### 第1步：接收待处理订单

**触发条件**：订单审核通过后（数据审核通过），系统自动/手动分配给设计师

**适用订单类型**：「医疗器械（需实体交付/不需实体交付）」、「非医疗器械（需实体交付/不需实体交付）」

> **说明**：此时订单状态变为「待设计」

**设计师操作**：

1. 在「我的工单」（待设计订单列表）中查看待处理订单
2. 可以看到订单基本信息：订单流水号（订单编号）、患者姓名、部位、项目、期望交付时间等

**系统行为**：

- 订单状态显示为「待设计」
- 系统推送消息通知设计师有新订单待处理

**订单分配方式**：

| 方式 | 说明 |
|------|------|
| 自动分配 | 按设计师专业方向（部位）、负载均衡、随机、轮询等规则自动匹配 |
| 手动分配 | 管理员手动指定设计师 |

**设计师查看的订单列表**：

```
我的工单列表 = 订单状态为「待设计」或「设计中」的订单
```

---

### 第3步：开始设计

**设计师操作**：

1. 点击「开始设计」按钮
2. 订单状态从「待设计」变为「设计中」

> **说明**：
> - 「开始设计」按钮用于标记设计师正式开始处理此订单
> - 系统记录设计开始时间，用于后续工时统计

---

### 第4步：上传设计文件

**设计师操作**：

点击「上传设计文件」按钮，上传以下文件：

| 文件类型 | 说明 | 必填 | 格式要求 |
|----------|------|:----:|----------|
| 打印文件（数据包） | 用于3D打印的设计文件包，**每个数据包对应一份指令单和一份图纸** | ✓ 是 | **ZIP格式**（包含STL/3MF/OBJ等打印文件） |
| 设计报告 | 设计说明、设计参数等 | ✗ 否 | PDF/Word |
| 可视化模型 | 用于展示的三维模型 | ✗ 否 | 3DPDF/PLY/STL等 |

**操作说明**：

- 打印文件（数据包）为必填，**每个数据包单独上传**，系统自动编号
- 打印文件数据包**编号规则**：`{订单流水号}-{序号}`，如 `20260310-000001-1`、`20260310-000001-2`
- **重要**：一个订单可以上传多个打印文件数据包，**每个数据包对应生成一份指令单和一份图纸**
- 设计报告和可视化模型为选填
- 每种文件类型可以上传多个
- 支持文件删除和重新上传
- 上传成功后显示文件列表（文件名、大小、上传时间、数据包编号）；多项目时建议为每个项目指定关联的打印文件数据包，供第5步「数据文件名称」使用


---

### 第5步：填写打印信息

**设计师操作**：

点击「填写打印信息」按钮，按订单中的**重建项目**逐行填写。一个订单可包含多个重建项目（多个设计模型），每个项目对应指令单「生产产品信息」表格中的一行。

此信息将作为订单的「设计信息」组成部分保存，并用于生成指令单中的产品列表。

#### 5.1 系统自动填充（订单级，无需手动填写）

| 字段 | 数据来源 | 说明 |
|------|----------|------|
| 订单流水号（订单编号） | 订单.订单流水号 | 订单提交后系统自动生成 |
| 指令单编号 | 系统.编码生成器 | 预生成，按数据包序号编排（如 ZL-{订单流水号}-1），生成指令单时确定 |
| 打印文件数据包编号 | 订单.设计文件.打印文件数据包编号 | 上传打印文件包时自动生成，格式：{订单流水号}-{序号} |
| 客户 | 订单.提单机构.机构名称 | 订单提单机构自动带出 |
| 联系人 | 订单.操作员.姓名 | 订单操作员自动带出 |
| 影像数据包编号 | 订单.影像资料.数据包编号 | 上传影像时自动生成 |
| 医院 | 订单.医院.医院名称 | 订单信息自动带出 |
| 期望交付时间 | 订单.期望交付时间 | 订单时效要求自动带出 |
| 患者姓名 | 订单.患者.姓名 | 订单信息自动带出 |
| 是否邮寄 | 订单.是否邮寄 | 订单信息自动带出 |
| 邮寄地址 | 订单.邮寄地址 | 仅当订单.是否邮寄="是"时显示，由订单创建时填写的信息带出 |

#### 5.2 设计师按重建项目填写（生产产品信息列表）

订单创建时业务员已选择多个重建项目时，设计师需**为每个重建项目填写一行**，行数与订单中的重建项目数量一致。每行字段如下：

| 字段 | 填写要求 | 关联说明 | 数据来源 |
|------|----------|----------|----------|
| 产品名称 | 必填，从下拉列表选择 | 选择产品后，自动带出该产品可选的型号规格 | 后台产品型号管理 |
| 型号规格 | 必填，从下拉列表选择 | 根据所选产品名称，动态显示可选规格 | 后台产品型号管理 |
| 材质 | 必填，从下拉列表选择 | 与产品型号关联 | 后台物料管理 |
| 颜色 | 必填，从下拉列表选择 | 与产品型号关联 | 后台配置 |
| 注册证号 | 必填，从下拉列表选择 | 与产品型号关联 | 后台注册证管理 |
| 数据文件名称 | 必填，选择或自动带出 | 该行对应的设计打印文件（上传的第4步中与本项目关联的文件） | 订单.设计文件.打印文件 |
| 数量 | 必填，数字 | 本项目的生产数量 | 设计师输入 |
| 时效 | 选填 | 可与订单期望时效一致或按项目填写 | 订单或设计师输入 |
| 打印模型 | 必填，可多选 | 根据产品型号关联 | 后台产品型号管理 |
| 产品标识 | 选填，手动填写 | 用于产品追溯 | 设计师输入 |
| 产品编码（UDI码） | 生产环节生成 | 设计阶段不生成UDI，仅记录产品标识用于追溯；UDI在后续生产环节生成 |

> **产品型号级联关系**（每个项目行内）：
> ```
> 选择产品名称 → 自动带出可选型号规格
>                → 选择型号规格后，自动带出可选材质、颜色
>                                   → 选择材质后，自动带出可选打印模型
> ```
> **数据文件名称**：设计师在第4步上传的打印文件数据包需与重建项目一一对应（或勾选关联），每个数据包对应一个指令单，生成指令单时该列展示对应设计文件的名称（数据包编号-文件名）。

**填写完成后**：

- 点击「保存」按钮保存打印信息（按项目列表保存）
- 可随时修改、增删行（与订单重建项目变更策略保持一致）

---

### 第6步：生成指令单和图纸

**设计师操作**：

系统根据订单信息和填写的设计信息，自动生成指令单和图纸。

> **重要说明**：一个订单可能对应多个打印文件数据包（设计师上传了多个设计文件包），**每个数据包对应一份指令单和一份图纸**。例如：订单有3个打印文件包，则生成3份指令单（ZL-订单号-1、ZL-订单号-2、ZL-订单号-3）和3份图纸（TZ-订单号-1、TZ-订单号-2、TZ-订单号-3）。

#### 6.1 生成指令单

点击「生成指令单」按钮，系统根据模板自动生成指令单。

**指令单与订单、打印文件数据包的关系**：

- **一个订单可以对应多份指令单**，具体数量取决于设计师上传的**打印文件数据包数量**
- 每个打印文件数据包（zip格式）对应生成**一份指令单**和**一份图纸**
- 指令单编号规则：`ZL-{订单流水号}-{序号}`，如 `ZL-20260310-000001-1`、`ZL-20260310-000001-2`
- 订单在创建时可包含**多个重建项目**（即多个设计模型）；每份指令单内的「生产产品信息」表格中，**每一行对应一个重建项目**，每行有数据文件名称等，便于生产按行执行

**指令单编号生成规则**：`ZL-{订单流水号}-{序号}`

**每份指令单包含内容**（与用户提供的生产指令单模板一致）：

| 区域 | 字段 | 数据来源 |
|------|------|----------|
| 表头 | 编号 | 指令单编号（ZL-{订单流水号}-{序号}） |
| 表头 | 版本号 | 系统.当前版本号（如 V1.0） |
| **基本信息** | 订单编号 | 订单.订单流水号 |
| 基本信息 | 客户 | 订单.提单机构.机构名称 |
| 基本信息 | 联系人 | 订单.操作员.姓名 |
| 基本信息 | 打印文件数据包编号 | 订单.设计文件.打印文件数据包编号（如 20260310-000001-1） |
| 基本信息 | 影像数据包编号 | 订单.影像资料.数据包编号 |
| 基本信息 | 医院 | 订单.医院.医院名称 |
| 基本信息 | 预交货时间 | 订单.期望交付时间 |
| **生产产品信息（表格，多行）** | 序号 | 系统按行自动编号（1,2,3…） |
| 生产产品信息 | 注册证编号 | 订单.设计信息.项目列表[].注册证号 |
| 生产产品信息 | 产品名称 | 订单.设计信息.项目列表[].产品名称 |
| 生产产品信息 | 数据文件名称 | 订单.设计信息.项目列表[].打印文件名称（该行对应的设计文件） |
| 生产产品信息 | 型号/规格 | 订单.设计信息.项目列表[].型号规格 |
| 生产产品信息 | 材质 | 订单.设计信息.项目列表[].材质 |
| 生产产品信息 | 数量 | 订单.设计信息.项目列表[].数量 |
| 生产产品信息 | 时效 | 订单.期望时效或项目级时效 |
| 生产产品信息 | 颜色 | 订单.设计信息.项目列表[].颜色 |
| 生产产品信息 | 产品编码（UDI码） | 生产环节生成，设计阶段不显示 |
| **其他信息** | 产品标识 | 按需填写，或从项目列表带出 |
| 其他信息 | 包装数量 | 订单.设计信息.包装数量（可选） |
| 其他信息 | 患者姓名 | 订单.患者.姓名 |
| 其他信息 | 是否邮寄 | 订单.是否邮寄 |
| 其他信息 | 邮寄地址 | 订单.邮寄地址 |
| 其他信息 | 开始时间/结束时间 | 生产环节填写，设计阶段可留空 |
| **签批** | 指令/日期、复核/日期 | 设计审核时填写；备注区可选 |
| **设计/审批** | 设计师签名、设计日期 | 设计师账户.签名图片、系统.当前日期 |
| 设计/审批 | 审批签名、审批日期 | 设计审核时填写 |

**版本管理**：

- 首次生成版本号为 V1.0
- 每次重新生成/修改后版本号递增（如 V1.0 → V1.1）
- 版本号显示在指令单右上角

**指令单操作**：

| 操作 | 说明 |
|------|------|
| 生成预览 | 点击后预览指令单内容 |
| 下载 | 下载指令单PDF文件 |
| 打印 | 直接打印指令单 |
| 上传修订版 | 如需手动修改，上传修订后的指令单文件 |
| 电子签名 | 点击签名按钮进行电子签名，签名后状态变为「已签名」 |

#### 6.2 生成图纸

点击「生成图纸」按钮，系统根据**内置图纸模板**自动生成图纸。

**图纸生成规则**：

- **每个打印文件数据包生成一份图纸**（一份图纸即一份独立文档），图纸编号规则：`TZ-{订单流水号}-{序号}`
- 例如：订单有 2 个打印文件包，则生成 2 份图纸（TZ-订单号-1、TZ-订单号-2），每份图纸为单页文档
- **页码含义**：每份图纸底部标注「第X页/共Y页」——**X = 当前数据包在该订单中的序号，Y = 该订单下打印文件数据包总数**。例如订单有 2 个数据包，则第一份图纸为「第一页/共二页」，第二份图纸为「第二页/共二页」；并非指同一 PDF 内的多页

**图纸编号生成规则**：`TZ-{订单流水号}-{序号}`

**图纸模板内容**（以实际图纸模板为准，系统自动填充）：

| 区域/位置 | 字段 | 说明与数据来源 |
|-----------|------|----------------|
| **主体网格（模型格位）** | 序号 | 系统按该数据包内模型数量自动编号（1、2、3…），模板可支持多个格位（如最多 11 个） |
| 主体网格 | 文件名称 | 该格位对应模型的设计文件名称（如「左髋」「左股骨」等），来自订单.设计信息/设计文件 |
| 主体网格 | 产品名称 | 该格位对应模型的产品名称（如「定制式3D打印骨模型」），来自订单.设计信息.项目列表[].产品名称 |
| 主体网格 | **3D 模型图片** | **每个格位需放置该数据包内对应模型的 3D 渲染图/效果图**，与序号、文件名称、产品名称一一对应；数据包内有几个模型则填充几个格位 |
| **右上角** | 二维码 | 二维码贴图窗口，旁注文案：「识别二维码在线查看三维模型」；链接可为在线 3D 模型查看或影像阅片器（实现时在系统配置中维护） |
| **底部信息区** | 订单编号 | 订单.订单流水号 |
| 底部信息区 | 数据包编号 | 订单.设计文件.打印文件数据包编号（格式：{订单流水号}-{序号}，如 00672603760062-2） |
| 底部信息区 | 设计/日期 | 系统.当前日期（设计日期） |
| 底部信息区 | 审批/日期 | 设计审核时填写 |
| 底部信息区 | 第X页/共Y页 | X=当前数据包序号，Y=该订单数据包总数（见上文页码含义） |
| 底部信息区 | 生产机构名称 | 系统配置.生产企业名称 |
| 底部信息区 | 备注 | 预留大文本框，可自动带出订单.设计信息.产品标识等，或供人工填写 |
| 可选 | 版本号 | 若模板有独立版本号字段，则系统填充当前版本号（如 V1.0）；否则可在备注或表头中体现 |

**二维码**：

- 位置：图纸右上角；说明文字建议为「识别二维码在线查看三维模型」
- 内容：可为「在线 3D 模型查看」链接或「影像阅片器」链接（含订单流水号与访问令牌），具体以系统配置为准

**图纸操作**：

| 操作 | 说明 |
|------|------|
| 生成预览 | 点击后预览图纸内容 |
| 下载 | 下载图纸文件（如 PDF） |
| 上传修订版 | 在订单功能中提供上传修订后的图纸，以流转至生产部 |
| 电子签名 | 点击签名按钮进行电子签名，签名后状态变为「已签名」 |

> **说明**：指令单和图纸都是必须生成的，用于后续生产流程。

### 第7步：提交设计

**设计师操作**：

当以上步骤完成后，点击「提交设计」按钮。

**提交条件检查**：

| 检查项 | 要求 |
|--------|------|
| 设计文件 | 每个重建项目至少关联 1 个打印文件数据包（多项目时需一一对应，每个数据包对应一份指令单和图纸） |
| 打印信息 | 每个重建项目行填写完整（必填字段不能为空），含数据文件名称、数量等 |
| 指令单 | 必须生成（每个打印文件数据包对应一份指令单，如订单有N个数据包则需生成N份指令单） |
| 图纸 | 必须生成 |

**提交后**：

- 订单状态从「设计中」变为「设计完成」
- 系统自动创建一条「设计审核」任务，分配给审核人员
- 订单状态变为「设计审核中」

## 五、设计审核流程

### 5.1 审核角色

设计师提交设计后，需要进行设计审核，审核角色包括：

| 角色 | 审核权限 |
|------|----------|
| 设计管理员 | ✓ 可审核 |
| 业务管理员 | ✓ 可审核 |
| 系统管理员 | ✓ 可审核 |

### 5.2 审核操作

审核人员在「设计审核」任务列表中点击订单进行审核：

| 操作 | 说明 |
|------|------|
| 审核通过 | 填写审批意见，订单自动进入「待打印」状态（医疗器械/非医疗器械），流转至生产模块 |
| 审核不通过 | 填写驳回原因，订单状态变为「设计审核不通过」，设计师可修改后重新提交 |

### 5.3 驳回处理

如果审核不通过：

1. 设计师收到驳回通知
2. 查看驳回原因
3. 修改设计文件/打印信息/指令单/图纸
4. 重新点击「提交设计」
5. 重新进入「设计审核中」状态
6. 再次审核通过后进入下一阶段

### 5.4 审核信息记录

| 字段 | 说明 |
|------|------|
| 审核时间 | 系统自动记录 |
| 审核人 | 系统自动记录（当前登录用户） |
| 审核结果 | 通过/不通过 |
| 审批意见 | 审核通过时填写（可选） |
| 驳回原因 | 审核不通过时必填 |

## 六、不需要实体交付订单特殊处理

### 6.1 什么是"不需要实体交付"订单

不需要实体交付订单 = 仅提供设计服务，不涉及实物生产和交付（即原旧版"服务订单"的概念）

### 6.2 不需要实体交付订单流程

```
设计中 → 设计完成 → 设计审核中 → 设计审核通过 → 待客户确认 → 已完成
                                        ↓
                               业务员点击「确认完成」按钮
```

> **说明**：不需要实体交付的订单同样需要经过设计审核环节。审核通过后进入「待客户确认」状态，由提单人确认后订单完成。

### 6.3 确认操作

| 项目 | 说明 |
|------|------|
| 触发条件 | 设计成果已完成，服务订单需要提单人确认 |
| 操作角色 | 业务员/区域管理员/经销商（订单创建者） |
| 操作动作 | 在订单详情点击「确认完成」按钮 |
| 状态变更 | 设计完成 → 已完成 |
| 确认记录 | 确认时间、确认人自动记录 |

## 九、电子签名功能设计

### 8.1 设计目标

### 8.2 签名角色

| 角色 | 签名场景 | 签名时机 |
|------|----------|----------|
| 设计师 | 设计文档签名 | 提交设计审核时自动签章 |
| 审核人员 | 设计文档签名 | 审核通过时自动签章 |

### 8.3 签名预设（账户设置）

#### 8.3.1 签名图片管理

| 项目 | 说明 |
