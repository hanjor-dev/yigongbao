# 工单设计阶段需求分析

## 一、文档概述

本文档描述医工宝系统**订单模块中设计阶段**的需求分析，包括设计师操作流程、设计审核、服务订单特殊处理等内容。

> **重要说明**：
> - 订单是唯一的数据实体，贯穿整个业务流程
> - 「工单」是订单在设计阶段的**状态表现**，并非独立数据
> - 设计师操作的「我的工单」列表 = 状态为「待设计/设计中」的订单列表
> - 设计阶段仅处理「医疗器械订单」和「服务订单」
> - 「非医疗器械订单」审核通过后直接进入生产模块，不经过设计阶段

---


## 三、编号规则设计

### 3.1 编号类型汇总

| 编号名称 | 说明 | 生成时机 | 规则说明 |
|----------|------|----------|----------|
| 订单流水号（订单编号） | 订单的唯一标识 | 订单提交后 | 系统编码生成器生成，支持配置规则 |
| 指令单编号 | 生产指令单的唯一标识 | 设计师生成指令单时 | 规则：ZL-{订单流水号} |
| 数据包编号 | 影像数据包的唯一标识 | 上传影像资料时 | 系统编码生成器生成 |
| 产品编码（UDI码） | 医疗器械产品的唯一标识码 | 设计师填写打印信息时 | 根据产品型号自动生成 |
| 图纸编号 | 设计图纸的唯一标识 | 生成图纸时 | 规则：TZ-{订单流水号} |

### 3.2 编码生成器设计

系统提供统一的编码生成器，支持按配置规则自动生成各类编号。

**编码生成器能力**：

| 能力 | 说明 |
|------|------|
| 前缀配置 | 支持配置固定前缀（如 ZL、TZ） |
| 日期格式 | 支持配置日期格式（年、月、日等） |
| 流水号位数 | 支持配置流水号位数（4-8位） |
| 起始值 | 支持配置起始值 |
| 步长 | 支持配置递增步长 |
| 分隔符 | 支持配置分隔符（-、_等） |

**编码规则配置示例**：

| 编号类型 | 规则配置 | 生成示例 |
|----------|----------|----------|
| 订单流水号 | {年}{月}{日}-{6位流水} | 20260310-000001 |
| 指令单编号 | ZL-{订单流水号} | ZL-20260310-000001 |
| 数据包编号 | SJB-{年}{月}{日}-{4位流水} | SJB-20260310-0001 |
| 图纸编号 | TZ-{订单流水号} | TZ-20260310-000001 |
| 产品编码（UDI） | 根据产品型号配置规则生成 | 详见产品型号管理 |

## 四、设计师操作步骤详解

### 第1步：接收待处理订单

**触发条件**：订单审核通过后（数据审核通过），系统自动/手动分配给设计师

**适用订单类型**：仅限「医疗器械订单」和「服务订单」

> **说明**：
> - 「非医疗器械订单」审核通过后直接进入生产模块，不经过设计阶段
> - 此时订单状态变为「待设计」

**设计师操作**：

1. 在「我的工单」（待设计订单列表）中查看待处理订单
2. 可以看到订单基本信息：订单流水号（订单编号）、患者姓名、部位、项目、期望交付时间等

**系统行为**：

- 订单状态显示为「待设计」
- 系统推送消息通知设计师有新订单待处理

**订单分配方式**：

| 方式 | 说明 |
|------|------|
| 自动分配 | 按设计师专业方向（部位）、负载均衡、随机、轮询等规则自动匹配 |
| 手动分配 | 管理员手动指定设计师 |

**设计师查看的订单列表**：

```
我的工单列表 = 订单状态为「待设计」或「设计中」的订单
```

### 第3步：开始设计

**设计师操作**：

1. 点击「开始设计」按钮
2. 订单状态从「待设计」变为「设计中」

> **说明**：
> - 「开始设计」按钮用于标记设计师正式开始处理此订单
> - 系统记录设计开始时间，用于后续工时统计

---

### 第4步：上传设计文件

**设计师操作**：

点击「上传设计文件」按钮，上传以下文件：

| 文件类型 | 说明 | 必填 | 格式要求 |
|----------|------|:----:|----------|
| 打印文件 | 用于3D打印的设计文件 | ✓ 是 | STL/3MF/OBJ等 |
| 设计报告 | 设计说明、设计参数等 | ✗ 否 | PDF/Word |
| 可视化模型 | 用于展示的三维模型 | ✗ 否 | 3DPDF/PLY/STL等 |

**操作说明**：

- 打印文件为必填，至少上传1个
- 设计报告和可视化模型为选填
- 每种文件类型可以上传多个
- 支持文件删除和重新上传
- 上传成功后显示文件列表（文件名、大小、上传时间）


---

**设计师操作**：

点击「填写打印信息」按钮，填写以下内容。

此信息将作为订单的「设计信息」组成部分保存。

| 字段 | 数据来源 | 说明 |

| 订单流水号（订单编号） | 订单.订单流水号 | 订单提交后系统自动生成 |
| 指令单编号 | 系统.编码生成器（规则：ZL-{订单流水号}） | 自动生成 |
| 客户 | 订单.提单机构.机构名称 | 订单提单机构自动带出 |
| 联系人 | 订单.操作员.姓名 | 订单操作员自动带出 |
| 数据包编号 | 订单.影像资料.数据包编号 | 上传影像时自动生成 |
| 医院 | 订单.医院.医院名称 | 订单信息自动带出 |
| 期望交付时间 | 订单.期望交付时间 | 订单时效要求自动带出 |
| 患者姓名 | 订单.患者.姓名 | 订单信息自动带出 |
| 是否邮寄 | 订单.是否邮寄 | 订单信息自动带出 |
| 邮寄地址 | 订单.邮寄地址 | 订单信息自动带出 |

#### 5.2 设计师手动填写

| 字段 | 填写要求 | 关联说明 | 数据来源 |
|------|----------|----------|----------|
| 产品名称 | 必填，从下拉列表选择 | 选择产品后，自动带出该产品可选的型号规格 | 后台产品型号管理 |
| 型号规格 | 必填，从下拉列表选择 | 根据所选产品名称，动态显示可选规格 | 后台产品型号管理 |
| 材质 | 必填，从下拉列表选择 | 与产品型号关联 | 后台物料管理 |
| 颜色 | 必填，从下拉列表选择 | 与产品型号关联 | 后台配置 |
| 注册证号 | 必填，从下拉列表选择 | 与产品型号关联 | 后台注册证管理 |
| 打印模型 | 必填，可多选 | 根据产品型号关联 | 后台产品型号管理 |
| 产品标识 | 必填，手动填写 | 用于产品追溯 | 设计师输入 |
| 产品编码（UDI码） | 自动填充 | 根据产品型号自动生成 | 系统.编码生成器（根据产品型号配置规则） |

> ```
> 选择产品名称 → 自动带出可选型号规格
>                → 选择型号规格后，自动带出可选材质、颜色
>                                   → 选择材质后，自动带出可选打印模型
> ```

**填写完成后**：

- 点击「保存」按钮保存打印信息
- 可随时修改保存后的信息

**指令单编号生成规则**：ZL-{订单流水号}

**指令单包含内容**：

| 信息分类 | 具体内容 | 数据来源 |
|----------|----------|----------|

| 基本信息 | 指令单编号 | 系统.编码生成器（ZL-{订单流水号}） |
| 基本信息 | 客户 | 订单.提单机构.机构名称 |
| 基本信息 | 联系人 | 订单.操作员.姓名 |
| 医院信息 | 医院名称 | 订单.医院.医院名称 |
| 医院信息 | 科室 | 订单.科室.科室名称 |
| 患者信息 | 患者姓名 | 订单.患者.姓名 |
| 产品信息 | 产品名称 | 订单.设计信息.产品名称 |
| 产品信息 | 型号规格 | 订单.设计信息.型号规格 |
| 产品信息 | 材质 | 订单.设计信息.材质 |
| 产品信息 | 颜色 | 订单.设计信息.颜色 |
| 产品信息 | 注册证号 | 订单.设计信息.注册证号 |
| 打印信息 | 打印模型列表 | 订单.设计信息.打印模型 |
| 订单信息 | 数据包编号 | 订单.影像资料.数据包编号 |
| 订单信息 | 期望交付时间 | 订单.期望交付时间 |

| 审批信息 | 审批日期 | 设计审核时填写 |

**版本管理**：

- 首次生成版本号为 V1.0

**指令单操作**：

| 操作 | 说明 |
|------|------|
| 生成预览 | 点击后预览指令单内容 |
| 下载 | 下载指令单PDF文件 |
| 打印 | 直接打印指令单 |
| 上传修订版 | 如需手动修改，上传修订后的指令单文件 |

#### 6.2 生成图纸

点击「生成图纸」按钮，系统根据模板自动生成图纸。

**图纸生成规则**：

- 每个订单生成一份图纸（不是每个产品）
- 同一份图纸可能包含多页（多页管理）
- 图纸编号规则：TZ-{订单流水号}

**图纸包含内容**：

| 信息分类 | 具体内容 | 数据来源 |
|----------|----------|----------|
| 基本信息 | 序号 | 系统自动编号（1,2,3...） |
| 基本信息 | 文件名称 | 订单.设计文件.打印文件.原始文件名 |
| 基本信息 | 产品名称 | 订单.设计信息.产品名称 |
| 标识信息 | 二维码 | 扫描跳转影像阅片器，包含订单流水号和访问令牌 |
| 标识信息 | 版本号 | 系统.当前版本号（如 V1.0） |
| 订单信息 | 订单流水号（订单编号） | 订单.订单流水号 |
| 订单信息 | 数据包编号 | 订单.影像资料.数据包编号 |
| 日期信息 | 设计日期 | 系统.当前日期 |
| 日期信息 | 审批日期 | 设计审核时填写 |
| 页码信息 | 第X页/共Y页 | 系统自动计算 |
| 生产信息 | 生产机构名称 | 系统配置.生产企业名称 |
| 生产信息 | 备注 | 订单.设计信息.产品标识 |

**二维码内容（链接形式）**：

```json
{
  "url": "影像阅片器访问地址?orderNo=订单流水号&token=访问令牌"
}
```

> **说明**：
> - 二维码扫描后跳转到影像阅片器查看对应订单的影像资料
> - URL包含订单流水号和访问令牌，确保安全访问
> - 影像阅片器地址在系统配置中维护

**图纸操作**：

| 操作 | 说明 |
|------|------|
| 生成预览 | 点击后预览图纸内容 |
| 下载 | 下载图纸PDF文件 |
| 多页管理 | 支持多页图纸，自动生成分页标记 |
| 上传修订版 | 如需手动修改，上传修订后的图纸文件 |
| 电子签名 | 点击签名按钮进行电子签名，签名后状态变为「已签名」 |

> **说明**：指令单和图纸都是必须生成的，用于后续生产流程。

---

### 第7步：提交设计

**设计师操作**：

当以上步骤完成后，点击「提交设计」按钮。

**提交条件检查**：

| 检查项 | 要求 |
|--------|------|
| 设计文件 | 必须上传至少1个打印文件 |
| 打印信息 | 必须填写完整（必填字段不能为空） |
| 指令单 | 必须生成 |
| 图纸 | 必须生成 |

**提交后**：

- 订单状态从「设计中」变为「设计完成」
- 系统自动创建一条「设计审核」任务，分配给审核人员
- 订单状态变为「设计审核中」

## 五、设计审核流程

### 5.1 审核角色

设计师提交设计后，需要进行设计审核，审核角色包括：

| 角色 | 审核权限 |
|------|----------|
| 设计管理员 | ✓ 可审核 |
| 业务管理员 | ✓ 可审核 |
| 系统管理员 | ✓ 可审核 |

### 5.2 审核操作

审核人员在「设计审核」任务列表中点击订单进行审核：

| 操作 | 说明 |
|------|------|
| 审核通过 | 填写审批意见，订单进入「待打印」状态，流转至生产模块 |
| 审核不通过 | 填写驳回原因，订单状态变为「设计审核不通过」 |

### 5.3 驳回处理

如果审核不通过：

1. 设计师收到驳回通知
2. 查看驳回原因
3. 修改设计文件/打印信息/指令单/图纸
4. 重新点击「提交设计」
5. 重新进入「设计审核中」状态

### 5.4 审核信息记录

| 字段 | 说明 |
|------|------|
| 审核时间 | 系统自动记录 |
| 审核人 | 系统自动记录（当前登录用户） |
| 审核结果 | 通过/不通过 |
| 审批意见 | 审核通过时填写（可选） |
| 驳回原因 | 审核不通过时必填 |

## 六、服务订单特殊处理

### 6.1 什么是服务订单

服务订单 = 仅提供设计服务，不涉及实物生产和交付

### 6.2 服务订单流程

```
设计中 → 设计完成 → 提单人确认 → 已完成
                  ↓
         业务员点击「确认完成」按钮
```

> **说明**：服务订单在设计完成后，不需要经过设计审核环节，直接由提单人确认即可完成。

### 6.3 确认操作

| 项目 | 说明 |
|------|------|
| 触发条件 | 设计成果已完成，服务订单需要提单人确认 |
| 操作角色 | 业务员/区域管理员/经销商（订单创建者） |
| 操作动作 | 在订单详情点击「确认完成」按钮 |
| 状态变更 | 设计完成 → 已完成 |
| 确认记录 | 确认时间、确认人自动记录 |

## 九、电子签名功能设计

### 8.1 设计目标

电子签名用于在设计阶段生成的指令单和图纸文档上进行签名确认，确保文档的真实性和可追溯性。

### 8.2 签名角色

| 角色 | 签名场景 | 签名时机 |
|------|----------|----------|
| 设计师 | 设计文档签名 | 提交设计审核时自动签章 |
| 审核人员 | 设计文档签名 | 审核通过时自动签章 |

### 8.3 签名预设（账户设置）

#### 8.3.1 签名图片管理

每位设计师和审核人员需要在账户设置中预设签名图片：

| 项目 | 说明 |
|------|------|
| 签名图片上传 | 支持上传手写签名照片（PNG/JPG，透明背景为佳） |
| 签名绘制 | 支持在网页上直接手写绘制签名 |
| 签名字体 | 支持选择字体生成签名样式 |
| 签名预览 | 上传/绘制后可预览效果 |
| 签名审核 | 管理员审核签名图片真实性后生效 |
| 签名状态 | 待审核/已生效/已禁用 |

#### 8.3.2 签名图片存储

```
设计师账户.签名图片 = 签名图片文件路径
审核人员账户.签名图片 = 签名图片文件路径
```

### 8.4 签名流程

#### 8.4.1 设计师签名流程

```
┌─────────────────────────────────────────────────────────────────┐
│                     设计师电子签名流程                             │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  设计师点击「提交设计」                                           │
│                        ↓                                         │
│  系统检查：设计文件完整 + 打印信息完整 + 指令单已生成 + 图纸已生成  │
│                        ↓                                         │
│  系统自动将设计师签名图片嵌入指令单和图纸的指定位置                │
│                        ↓                                         │
│  同时添加签名信息：                                                │
│  ├── 签名人：设计师.姓名                                          │
│  ├── 签名时间：系统.当前时间                                       │
│  └── 签名类型：设计签名                                           │
│                        ↓                                         │
│  文档状态变为「已签名」                                            │
│                        ↓                                         │
│  进入设计审核流程                                                 │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

#### 8.4.2 审核人员签名流程

```
┌─────────────────────────────────────────────────────────────────┐
│                     审核人员电子签名流程                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  审核人员点击「审核通过」                                         │
│                        ↓                                         │
│  系统自动将审核人员签名图片嵌入指令单和图纸的指定位置              │
│                        ↓                                         │
│  同时添加签名信息：                                                │
│  ├── 签名人：审核人员.姓名                                        │
│  ├── 签名时间：系统.当前时间                                       │
│  ├── 签名类型：审核签名                                           │
│  └── 审批意见（如有）                                             │
│                        ↓                                         │
│  文档状态变为「已审核签名」                                       │
│                        ↓                                         │
│  订单流转至生产模块                                               │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 8.5 文档格式支持

| 文档格式 | 签名方式 | 说明 |
|----------|----------|------|
| PDF | 自动嵌入签名图片 | 系统生成PDF时自动添加 |
| Word | 自动嵌入签名图片 | 系统生成Word时自动添加 |
| Excel | 自动嵌入签名图片 | 系统生成Excel时自动添加 |
| 其他格式 | 待定 | 根据技术实现评估 |

> **说明**：指令单和图纸可能为PDF/Word/Excel或其他格式，签名功能需适配多种文档格式。

### 8.6 签名信息记录

每次签名操作，系统自动记录签名信息：

| 字段 | 说明 |
|------|------|
| 签名ID | 系统自动生成唯一ID |
| 文档类型 | 指令单/图纸 |
| 文档编号 | 指令单编号/图纸编号 |
| 订单流水号 | 关联的订单流水号 |
| 签名人 | 签名账户.姓名 |
| 签名人ID | 签名账户.ID |
| 签名时间 | 系统自动记录 |
| 签名类型 | 设计签名/审核签名 |
| 签名图片 | 签名图片文件路径 |
| 签名IP | 签名时的IP地址 |
| 审批意见 | 审核签名时的审批意见（可选） |

### 8.7 签名状态管理

| 文档状态 | 说明 |
|----------|------|
| 未生成 | 指令单/图纸尚未生成 |
| 已生成未签名 | 文档已生成，等待设计师签名 |
| 已设计签名 | 设计师已签名，等待审核 |
| 已审核签名 | 审核人员已签名，流程完成 |
| 已失效 | 文档被修改后，原签名失效 |
