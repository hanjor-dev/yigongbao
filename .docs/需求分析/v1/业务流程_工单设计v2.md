> **版本说明**：本文档为 v2 版本，基于客户访谈确认结果（2026-04-14）全面修订，替代原 `业务流程2_工单设计.md`。

## 一、概述

### 1.1 核心定位

工单设计阶段是订单流程中连接「订单接收」与「生产/交付」的关键环节。设计师负责：
1. 下载影像数据，在本地完成三维重建设计
2. 将设计结果（打印文件、可视化模型等）上传至系统
3. 针对每个数据包填写打印信息
4. 生成指令单和图纸（系统填充基础信息后，设计师线下补充图片等内容）
5. 上传最终修订版文件，提交设计审核

### 1.2 术语说明

| 术语 | 含义 |
|------|------|
| 工单 | 订单在设计阶段的状态表现，并非独立数据实体 |
| 重建项目 | 订单创建时业务员选择的需要重建的部位+项目，如「左髋关节 - 骨模型」|
| 打印文件数据包 | 设计师上传的包含 STL/3MF 等打印文件的压缩包（ZIP/RAR/7Z），订单级，可包含多个重建项目的文件 |
| 打印信息行 | 设计师填写的每种产品的生产参数（产品名称、型号、材质、颜色、打印模型等），挂在数据包下 |
| 打印模型 | 打印信息中的多选字段，从数据包内文件列表选择，一个产品可选多个文件（如被切割的模型由多个子部件组成） |
| 指令单 | 按数据包生成的生产指令单（一包一份），系统自动填充基础内容后由设计师线下补充完整 |
| 图纸 | 按数据包生成的含模型格位的图纸文件（一包一份），格位数 = 包内文件数，系统填充文字信息后由设计师线下粘贴 3D 图片 |
| 修订版文件 | 设计师线下补充内容后重新上传的指令单/图纸，作为最终版本流转到生产 |

## 二、数据关系模型

```
订单（order_main）
  ├── 重建项目（order_item × N）
  │     └──（仅记录部位+项目信息，不挂打印信息）
  ├── 打印文件数据包（order_design_package × 1~M，必填）
  │     ├── 包内文件列表（解析后记录）
  │     └── 打印信息行（order_print_info × K，该包需要生产的产品）
  ├── 指令单（order_instruction × 1~M，每个数据包对应一份，必填）
  ├── 图纸（order_drawing × 1~M，每个数据包对应一份，必填）
  ├── 可视化模型文件（order_visual_model × N，必填）
  └── 设计报告（order_design_report × 1，整单一份，必填）
```

**关键关系说明**：
- 打印文件数据包是**订单级**，与重建项目无强制对应关系。设计师可以把多个重建项目的文件打成一个包，也可以分多个包上传
- 打印信息行是**数据包级**（1 个数据包 → K 行打印信息），填写入口是数据包而非重建项目
- 打印信息行的「打印模型」字段支持多选（一个产品可由多个文件组成，如被切割的模型）
- 指令单和图纸是**数据包级**（1 个数据包 → 1 份指令单 + 1 份图纸）
- **指令单行数 = 图纸格位数 = 数据包内文件数**（按文件展开，一个文件一行/一个格位）

## 三、状态流转

### 3.1 状态定义

| 状态值 | 状态名 | 说明 |
|--------|--------|------|
| 2010 | 待设计 | 订单数据审核通过后进入此状态，等待分配或设计师接单 |
| 2020 | 设计中 | 设计师点击「开始设计」后进入，正在处理中（包括驳回后修改） |
| 2040 | 设计审核中 | 设计师提交后等待审核人员审核 |
| 2050 | 设计审核通过 | 不可见状态，系统自动根据 needsPhysicalDelivery 推进 |
| 2060 | 设计审核不通过 | 审核驳回，设计师需修改后重新提交 |

> **说明**：无需「设计完成」中间状态，设计师提交后直接进入审核中。

### 3.2 状态转换规则

```
待设计(2010)
  → [START_DESIGN] → 设计中(2020)

设计中(2020)
  → [SUBMIT_DESIGN] → 设计审核中(2040)

设计审核中(2040)
  → [DESIGN_REVIEW_PASS]   → 设计审核通过(2050)
      → needsPhysicalDelivery=1 → 待打印(3010)
      → needsPhysicalDelivery=0 → 待客户确认(7010)
  → [DESIGN_REVIEW_REJECT] → 设计审核不通过(2060)

设计审核不通过(2060)
  → [CONTINUE_DESIGN] → 设计中(2020)
  → 设计师修改后 → [SUBMIT_DESIGN] → 设计审核中(2040)
```

> **动作说明**：
> - `START_DESIGN`：首次接单，待设计 → 设计中
> - `CONTINUE_DESIGN`：驳回后继续修改，审核不通过 → 设计中
> - `SUBMIT_DESIGN`：提交设计审核，设计中 → 审核中

## 四、设计师完整操作流程

### Step 1：接收待设计订单

**触发条件**：订单数据审核通过，系统自动或管理员手动分配给设计师

**设计师操作**：
- 在「我的工单」列表查看待处理订单（状态为「待设计」或「设计中」的订单）
- 可查看订单基本信息：订单编号、患者姓名、重建项目列表、期望交付时间、是否加急

**系统行为**：
- 推送消息通知设计师有新工单
- 订单状态为「待设计(2010)」

---

### Step 2：查看订单详情

**设计师可查看的信息**：

| 区域 | 字段 |
|------|------|
| 订单基础 | 订单编号、订单类型、是否需要实体交付、提单机构、操作员、联系电话 |
| 机构信息 | 医院、科室、所属地区 |
| 医生/患者 | 医生姓名、医生电话、患者姓名、患者年龄、患者性别 |
| 业务信息 | 是否加急、是否邮寄、邮寄地址、期望交付时间 |
| 重建项目 | 部位名称、项目名称、项目说明、成形需求、其他要求（逐项列出） |
| 影像资料 | 影像数据包、影像数据包编号、影像报告（订单阶段上传） |

---

### Step 3：开始设计

**设计师操作**：点击「开始设计」按钮

**状态变更**：待设计(2010) → 设计中(2020)

**系统记录**：设计开始时间（`design_start_time`）

> 「开始设计」是必要步骤，作为设计师正式接单的标记，系统据此记录工时起点。

---

### Step 4：上传设计文件

设计师在订单级别上传设计文件，所有文件类型均为**必填**：

#### 4.1 打印文件数据包

| 项目 | 说明 |
|------|------|
| 必填 | **是**，整个订单至少上传 1 个 |
| 格式 | ZIP / RAR / 7Z 等压缩包格式 |
| 包内内容 | STL / 3MF / OBJ 等 3D 打印文件，一个包内可包含多个重建项目的文件 |
| 数量 | 一个订单可上传多个数据包（如数据包-1 先上传，发现缺少内容后再补充上传数据包-2） |
| 系统行为 | 上传后自动解析包内文件列表，供后续填写打印信息时选择具体文件 |
| 编号规则 | `{订单编号}-{序号}`，如 `52022656031463-1`、`52022656031463-2` |

#### 4.2 可视化模型文件

| 项目 | 说明 |
|------|------|
| 必填 | **是** |
| 格式 | 3DPDF / PLY / STL 等 |
| 对应关系 | 订单级，可上传多个 |
| 用途 | 供临床审核设计效果 |

#### 4.3 设计报告

| 项目 | 说明 |
|------|------|
| 必填 | **是**，整个订单一份 |
| 格式 | PDF / Word |
| 对应关系 | 整个订单一份 |
| 用途 | 设计说明、参数记录 |

---

### Step 5：填写打印信息

**前置条件**：订单已上传至少一个打印文件数据包

**操作说明**：针对每个数据包，填写该包内文件对应的产品生产信息。一个数据包可包含多个产品（多行），每个产品可关联包内的一个或多个模型文件。

**操作入口**：选择某个数据包 → 填写该包的打印信息

#### 5.1 自动带入字段（系统从订单信息自动填充，无需手动输入）

| 字段 | 数据来源 |
|------|----------|
| 订单编号 | 订单.orderCode |
| 客户 | 订单.orgName |
| 联系人 | 订单.operatorName |
| 影像数据包编号 | 订单文件.影像数据包编号 |
| 医院 | 订单.hospitalName |
| 预交货时间 | 订单.expectedDeliveryDate |
| 患者姓名 | 订单.patientName |
| 是否邮寄 | 订单.isPostal |
| 邮寄地址 | 订单.postalAddress（仅当 isPostal=1 时显示） |

#### 5.2 设计师填写字段（每行一种产品）

| 字段 | 必填 | 填写方式 | 说明 |
|------|:----:|----------|------|
| 产品名称 | ✓ | 下拉选择 | 来自产品管理，选择后联动型号规格 |
| 型号规格 | ✓ | 下拉选择 | 根据产品名称自动过滤可选项 |
| 材质 | ✓ | 下拉选择 | 默认树脂，可修改；不按型号过滤，全量选择 |
| 颜色 | ✓ | 下拉选择 | 按产品大类过滤（模型类→白色，导板类→透明） |
| 注册证号 | ✓ | 自动带出 | 根据型号规格自动带出，不需手动选择 |
| 打印模型 | ✓ | 多选 | 从该数据包内解析的文件列表中选择，一个产品可选多个文件（如被切割的模型由多个子部件组成） |
| 数量 | ✓ | 数字输入 | 该产品的生产数量 |
| 时效 | ✗ | 选填 | 可与订单期望时效一致，或按产品单独填写 |
| 产品标识 | ✗ | 文本输入 | 用于产品追溯，手动填写 |

#### 5.3 产品字段级联关系

```
选择产品名称
  → 自动过滤：型号规格（只显示该产品下的型号）
  → 选择型号规格后：
      → 自动带出：注册证号（一个型号对应一个注册证号）
  → 颜色：按大类过滤（模型白色 / 导板透明），与具体型号无关
  → 材质：全量可选（默认树脂），与型号无强制关联
  → 打印模型：从当前数据包内文件列表中多选
```

#### 5.4 操作规则

- 支持增删行（在数据包下添加或删除产品行）
- 提交设计时再做完整性校验

#### 5.5 示例

```
数据包-1 内有4个文件：左髋骨.stl, 左髋盖.stl, 右髋导板A.stl, 右髋导板B.stl

数据包-1 的打印信息（2行）：
┌────────────────────────────────────────────────────────────────┐
│ 行1: 产品=骨模型, 打印模型=[左髋骨.stl, 左髋盖.stl], 颜色=白色   │
│ 行2: 产品=导板,   打印模型=[右髋导板A.stl, 右髋导板B.stl], 颜色=透明│
└────────────────────────────────────────────────────────────────┘

说明：4个文件 → 2行打印信息（每行1个产品，每个产品包含2个文件）
```

### Step 6：生成指令单和图纸

**前置条件**：该数据包关联的打印信息已填写完整

#### 6.1 生成逻辑

每个数据包生成**一份指令单 + 一份图纸**，与重建项目数量无关。

| 文件类型 | 编号规则 | 示例 |
|----------|----------|------|
| 指令单 | `QR-SC-{流水号}` | `QR-SC-001` |
| 图纸 | 无独立编号，通过数据包编号和页码标识 | 数据包编号 + 第X页/共Y页 |

#### 6.2 系统生成内容（部分填充模板）

系统生成一份**预填充的模板文件**（Word/Excel 格式），自动写入以下内容：

**指令单自动填充字段**：

| 区域 | 字段 | 来源 |
|------|------|------|
| 表头 | 编号 | 系统生成（规则待定，暂用 QR-SC-流水号） |
| 表头 | 版本号 | A/1（首次生成），修订后递增 A/2、A/3... |
| 基本信息 | 订单编号、客户名称、联系人 | 订单信息 |
| 基本信息 | 数据包编号 | 本份指令单对应的数据包编号 |
| 基本信息 | 医院、预交货时间 | 订单信息 |
| 生产产品信息（表格） | 序号、注册证号、产品名称、数据文件名称、型号/规格、材质、数量、时效、颜色 | 按文件展开：一行一个打印文件 |
| 其他信息 | 产品标识、包装数量、是否邮寄 | 打印信息/订单信息 |
| 其他信息 | 患者姓名、开始时间、结束时间 | 订单信息/系统记录 |
| 其他信息 | 邮寄地址、备注 | 订单信息 |
| 签批区 | 指令/日期、复核/日期 | 留空（线下签字） |

**图纸自动填充字段**：

| 区域 | 字段 | 来源 |
|------|------|------|
| 主体格位（文字部分） | 序号、文件名称、产品名称 | 该数据包内的文件列表及对应产品信息 |
| 主体格位（图片位置） | **留空**，设计师线下粘贴带标注的 3D 效果图 |
| 右上角 | 二维码 | 动态生成，扫描后在线查看三维模型（需订单表增加二维码链接字段） |
| 底部信息 | 数据包编号、订单编号 | 订单信息 |
| 底部信息 | 设计/日期 | 设计完成日期 |
| 底部信息 | 审核/日期 | 留空（审核时填写） |
| 底部信息 | 页码（第X页/共Y页） | X=当前页序号，Y=本份图纸总页数 |
| 底部信息 | 生产机构名称 | 系统配置（如：武汉嘉一三维技术应用有限公司） |
| 左下角 | 备注 | 留空，可手写补充 |

**图纸布局说明**：
- 每页 4列 × 3行 = 12 个格位
- 右上角格位固定放二维码，实际内容格位最多 **11 个**
- 格位数 = 数据包内文件数（每个文件占一个格位）
- 文件数 ≤ 11：单页图纸
- 文件数 > 11：自动分页（如 15 个文件 → 第1页 11 格位 + 第2页 4 格位）

> **指令单与图纸的一致性**：指令单生产产品信息表格的行数 = 图纸格位数 = 数据包内文件数。两者都是按「文件」维度展开，一个文件对应指令单一行、图纸一个格位。

#### 6.3 指令单/图纸处理模式

系统支持两种处理模式，由**后台系统配置**控制：

| 模式 | 说明 | 适用阶段 |
|------|------|----------|
| **模式A：线下修改** | 系统生成部分填充模板，设计师下载后线下补充内容，再上传修订版 | **第一阶段（当前）** |
| **模式B：在线编辑** | 系统内嵌三维查看窗口，支持旋转摆位、添加标注，自动生成完整文件 | 后续版本 |

**第一阶段流程（模式A）**：

```
系统生成部分填充模板
    ↓ 设计师下载文件
    ↓ 设计师在本地补充内容：
        指令单：核对信息，补充手写签名区等
        图纸：在格位中粘贴 3D 模型截图/渲染图，添加标注文字和线条
    ↓ 设计师上传「修订版」文件
```

修订版文件上传后，作为最终版本的指令单/图纸，随订单流转到生产环节。

> **后续版本（模式B）**：在系统内嵌三维查看窗口，支持旋转摆位，并可直接添加文字、线条等标注，系统自动将标注后的模型截图填充到图纸中，设计师无需下载后人工处理，实现全流程在线操作。届时可通过后台配置切换到模式B。

#### 6.4 版本管理

| 操作 | 版本号变化 |
|------|-----------|
| 首次生成 | A/1 |
| 修改打印信息后重新生成 | A/1 → A/2 |
| 上传修订版文件 | 保留版本记录，标记为「修订版」 |
| 审核驳回后重新生成 | 版本号继续递增（A/2 → A/3） |

---

### Step 7：提交设计

**提交前置校验**：

| 校验项 | 级别 | 说明 |
|--------|------|------|
| 已上传打印文件数据包 | 强制 | 订单至少上传 1 个数据包 |
| 已上传可视化模型文件 | 强制 | 订单至少上传 1 个可视化模型文件 |
| 已上传设计报告 | 强制 | 订单必须上传设计报告 |
| 打印信息完整填写 | 强制 | 每个数据包的打印信息必填字段不能为空 |
| 指令单已生成 | 强制 | 每个数据包对应的指令单必须已生成 |
| 图纸已生成 | 强制 | 每个数据包对应的图纸必须已生成 |
| 修订版指令单已上传 | 强制（模式A） | 线下修改模式时必须上传修订版 |
| 修订版图纸已上传 | 强制（模式A） | 线下修改模式时必须上传修订版 |

**提交后状态变更**：
```
设计中(2020) → [SUBMIT_DESIGN] → 设计审核中(2040)
```

**系统行为**：
- 记录设计提交时间（`design_submit_time`）
- 创建设计审核任务，通知审核人员

## 五、设计审核流程

### 5.1 审核角色

| 角色 | 是否可审核 |
|------|-----------|
| 设计管理员 | ✓ |
| 业务管理员 | ✓ |
| 系统管理员 | ✓ |

### 5.2 审核操作

| 操作 | 说明 | 状态变更 |
|------|------|----------|
| 审核通过 | 填写审批意见（选填） | 2040 → 2050（系统内部）→ 3010 或 7010 |
| 审核驳回 | 必填驳回原因 | 2040 → 2060 |

**审核通过后的分支**：

```
设计审核通过(2050)
  → needsPhysicalDelivery = 1 → 待打印(3010)，进入生产模块
  → needsPhysicalDelivery = 0 → 待客户确认(7010)
```

### 5.3 驳回处理

1. 设计师收到驳回通知，查看驳回原因
2. 订单状态变为「设计审核不通过(2060)」
3. 设计师点击「继续修改」，状态回到「设计中(2020)」
4. 设计师根据驳回原因修改：数据包 / 打印信息 / 指令单和图纸
5. 完成修改后点击「提交设计」重新提交审核

**驳回后状态流转**：
```
设计审核不通过(2060) → [CONTINUE_DESIGN] → 设计中(2020) → [SUBMIT_DESIGN] → 设计审核中(2040)
```

**驳回后的校验规则**：
- 如果打印信息有变更 → 必须重新生成指令单和图纸，并重新上传修订版
- 如果仅补充签名等内容 → 可直接上传新的修订版覆盖原文件

### 5.4 审核信息记录

| 字段 | 说明 |
|------|------|
| 审核时间 | 系统自动记录 |
| 审核人 | 当前登录用户 |
| 审核结果 | 通过 / 不通过 |
| 审批意见 | 通过时填写（选填） |
| 驳回原因 | 不通过时必填 |

## 六、不需要实体交付订单的特殊处理

### 6.1 定义

不需要实体交付 = 仅提供设计服务，不涉及实物生产（`needsPhysicalDelivery = 0`）

### 6.2 流程

```
设计审核通过 → 待客户确认(7010)
  → 业务员/订单创建者在系统内点击「确认完成」
  → 已完成(8010)
```

### 6.3 确认操作说明

## 八、编号规则

| 编号类型 | 规则 | 示例 |
|----------|------|------|
| 订单编号 | `{14位数字流水}` | `52022656031463` |
| 打印文件数据包编号 | `{订单编号}-{序号}` | `52022656031463-1` |
| 指令单编号 | 待定（暂用 `QR-SC-{流水号}`） | `QR-SC-001`（具体规则待与客户确认） |
| 图纸 | 无独立编号，通过数据包编号+页码标识 | `52022656031463-1` + 第1页/共2页 |
| 影像数据包编号 | `SJB-{年}{月}{日}-{4位流水}` | `SJB-20260407-0001` |

> **序号说明**：
> - 数据包编号的「序号」：整个订单内所有数据包的上传顺序（1, 2, 3...）
> - 指令单编号独立流水，与数据包编号无直接关系
> - 示例：一个订单上传了 3 个数据包，则生成 3 份指令单（QR-SC-001/002/003）和 3 份图纸

## 十、与 v1 文档的主要变更

| 维度 | v1 描述 | v2 修正（基于客户确认） |
|------|---------|----------------------|
| 数据包粒度 | 每个重建项目一个包（项目级） | **订单级**，与重建项目无强制对应，一个订单可有多个数据包 |
| 打印信息归属 | 挂在重建项目下，需手动选择关联数据包 | **挂在数据包下**，填写入口是数据包，无需关联字段 |
| 打印模型字段 | 「数据文件名称」单选 + 「打印模型」多选（两个字段） | **合并为「打印模型」一个多选字段**，从数据包内文件列表选择 |
| 指令单/图纸粒度 | 每个数据包一份（但数据包是项目级） | **每个数据包一份**（数据包改为订单级后，数量由数据包数量决定） |
| 打印文件格式 | 仅 ZIP | **ZIP / RAR / 7Z 均支持** |
| 数据包内容 | 系统不解析包内文件 | **需解析包内文件列表**，供选择打印模型 |
| 指令单/图纸生成 | 系统完整生成最终 PDF | **系统生成部分填充模板，设计师线下补充后上传修订版** |
| 图纸 3D 图片 | 系统自动填充渲染图 | **本期不做，图片位置留空，设计师线下粘贴** |
| 一产品对应文件数 | 每产品一个文件 | **一产品可选多个文件**（如被切割的模型由多个子部件组成） |
| 材质过滤 | 与型号规格联动过滤 | **不过滤，全量可选，默认树脂** |
| 颜色过滤 | 与型号规格联动过滤 | **按产品大类过滤**（模型白色 / 导板透明） |
| 客户确认操作人 | 未明确 | **订单创建者（业务员）在系统内操作** |
