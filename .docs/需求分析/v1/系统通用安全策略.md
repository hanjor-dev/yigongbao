# 医工宝系统通用安全策略

## 一、账户与认证安全

### 1.1 登录方式：手机号+密码

用户使用手机号作为账号，密码登录。密码传输采用编码加密，存储使用不可逆加密算法。

### 1.2 密码复杂度策略

密码需满足基本复杂度要求。

**建议值**：

- 最小长度：8位
- 需包含：大写字母 + 小写字母 + 数字
- 特殊字符：不强制

### 1.3 短信验证码

用于注册、忘记密码等场景的验证。验证码有有效期和错误次数限制。

**建议值**：

- 验证码长度：6位数字
- 有效期：5分钟
- 发送间隔：60秒内不可重复发送
- 错误允许次数：3次后失效

### 1.4 登录IP、设备记录

记录登录时的IP、设备信息，用于安全审计。


### 1.5 登录会话有效期

登录后生成会话，有有效期，无操作超时后自动失效。

**建议值**：

- 会话有效期：7天
- 有操作自动续期

### 1.6 多端登录策略

控制同一账户同时在线的设备数量。

**建议值**：

- 不允许多端同时登录
- 新登录时自动踢掉旧设备

### 1.7 连续登录失败锁定

密码连续错误多次后锁定账户，防止暴力破解。

**建议值**：

- 连续失败5次后锁定
- 锁定时长：15分钟
- 自动解锁

## 二、API接口防护方案

### 2.1 分层防护思路

| 防护层级 | 防护目标 | 实现复杂度 |
|---------|---------|-----------|
| 基础层 | 身份验证、频率限制 | 低 |
| 增强层 | 参数篡改、重放攻击 | 中 |
| 可选层 | 爬虫识别、恶意IP | 低 |

---

### 2.2 基础层（必选）

#### 2.2.1 Token身份验证

所有接口请求携带有效Token，验证用户登录状态。

**实现方式**：

- 请求Header携带：`Authorization: Bearer <token>`
- Token有效期：7天
- 无Token或Token无效：返回401

#### 2.2.2 请求频率限制

对接口请求进行频率限制。

**建议值**：

- 通用接口：60次/分钟
- 登录接口：10次/分钟
- 超出限制：返回429，提示"操作过于频繁"

---

### 2.3 增强层（推荐）

#### 2.3.1 请求签名验证

对请求参数进行签名，防止参数篡改和重放攻击。

**签名参数（建议放在 Header 中传递）**：

| 参数名 | 说明 | 示例 |
|-------|------|------|
| appKey | 应用标识 | web |
| timestamp | 请求时间戳（秒） | 1709510400 |
| nonce | 随机字符串（6位） | a1b2c3 |
| sign | 签名结果 | 8f4e2d1c... |

**Header命名建议**：

- `X-App-Key`: appKey
- `X-Timestamp`: timestamp
- `X-Nonce`: nonce
- `X-Signature`: sign

> 说明：签名参数放在Header里更利于统一拦截校验，不与业务Body耦合；如前端为浏览器，还需要在CORS里放行这些Header。

**签名算法**：

```
sign = MD5(appKey + timestamp + nonce + appSecret)
```

**验证流程**：

1. 检查timestamp是否在5分钟内
2. 检查nonce是否已使用（Redis存储，5分钟过期）
3. 重新计算sign，比对是否一致
4. 验证通过 → 处理请求

**适用接口**：

- 企业核心业务数据查询
- 财务相关接口
- 文件上传相关接口
- 用户关键数据修改等

#### 2.3.2 Referer来源验证

验证请求来源，防止简单爬虫和盗链。

**实现方式**：

- 检查Referer头是否来自允许的域名
- 允许的域名：医工宝Web端、移动端APP、合作的第三方平台等
- 验证失败：返回403

**适用接口**：文件下载、图片预览等

---

### 2.4 可选层

#### 2.4.1 User-Agent检测

识别非浏览器/APP客户端的请求。

**实现方式**：

- 常见浏览器和APP的User-Agent有特征
- 无User-Agent或明显是脚本工具（如Python-urllib、curl）
- 可选择拦截或放行并记录日志

#### 2.4.2 IP维度的简单防护

对恶意IP进行限制。

**实现方式**：

- 同一IP请求频率异常高 → 临时封禁
- 被识别为恶意爬虫的IP → 加入黑名单
- 黑名单IP所有请求直接拒绝

---

### 2.5 方案对比与选择

| 方案 | 防护目标 | 性能影响 | 建议启用 |
|-----|---------|---------|---------|
| Token验证 | 身份冒充 | 低 | 全量 |
| 频率限制 | 刷接口 | 低 | 全量 |
| 签名验证 | 参数篡改 | 中 | 核心接口 |
| Referer验证 | 盗链/爬虫 | 低 | 文件类接口 |
| User-Agent | 简单脚本 | 低 | 可选 |
| IP封禁 | 恶意攻击 | 低 | 发现问题时 |

**推荐方案组合**：

| 组合 | 说明 |
|-----|------|
| 最简方案 | Token验证 + 频率限制 |
| **标准方案（推荐）** | Token验证 + 频率限制 + 签名验证（核心接口） + Referer验证（文件接口） |
| 完整方案 | 标准方案 + User-Agent检测 + IP封禁 |

---


#### 签名参数说明

| 参数 | 说明 |
|-----|------|
| appKey | 应用标识 |
| timestamp | 时间戳（秒），5分钟内有效 |
| nonce | 6位随机字符串 |
| sign | 签名结果 |

#### 签名计算公式

```
sign = MD5(appKey + timestamp + nonce + appSecret)
```

#### 请求示例

```
POST /api/order/create
Content-Type: application/json
Authorization: Bearer eyJhbGciOiJIUzI1Ni...
X-App-Key: web
X-Timestamp: 1709510400
X-Nonce: a1b2c3
X-Signature: d41d8cd98f00b204e9800998ecf8427e

{
  "productId": "123",
  "quantity": 1
}
```

#### 服务端验证流程

1. 验证Token有效
2. 验证timestamp在5分钟内（防止重放）
3. 验证nonce未使用（Redis存储5分钟，防止重放）
4. 验证sign正确（防止参数篡改）
5. 通过后处理请求，删除nonce

---

### 2.7 敏感参数数据禁止明文传输

敏感字段（如密码、验证码）需要避免明文传输。

**建议值**：

- 敏感字段传输采用编码加密
- 敏感字段不在日志中记录
- 敏感字段范围：密码、支付密码、短信验证码、银行卡号、身份证号等

## 三、文件安全

### 3.1 上传文件类型、大小、恶意文件名限制

对上传文件进行安全校验。

**建议值**：

- 允许类型：jpg、jpeg、png、pdf、doc、docx、xls、xlsx、zip等
- 单个文件大小：不超过500MB
- 文件名强制重命名（使用UUID）

### 3.2 文件存储隔离

上传文件存储在独立存储区域，与应用代码分离。

**建议值**：

- 存储目录禁用脚本执行权限
- 按业务类型分目录存储

### 3.3 文件访问权限

文件通过接口访问，不直接暴露文件路径。

**建议值**：

- 启用接口鉴权访问
- 启用Referer防盗链

### 3.4 压缩包炸弹防护

限制解压后文件大小和数量。

**建议值**：

- 解压后大小：不超过1024MB
- 文件数量：不超过200个
